# 客户端备弹HUD刷新链路断裂修复

- 日期：2026-09-10
- 计划提交说明：`修复：Inventory组件初始化未启用导致客户端备弹HUD不刷新`
- 变更类型：生产代码 / 测试

## 目的

修复玩家客户端上备弹 HUD 的三类刷新异常：拾取武器后不刷新（确定性）、换弹提交后不刷新（概率性）、只有开火 100% 刷新。用户把备弹显示改为纯蓝图后反馈该症状，干净重启编辑器后依旧复现，确认是代码缺陷而非会话问题。

## 本提交完成内容

- **根因修复**：`UShooterInventoryComponent` 构造函数新增 `bWantsInitializeComponent = true`。UE5.6（本地引擎源码 `ActorComponent.cpp:1924`、`ActorComponent.h:857` 核实）不会因子类重写 `InitializeComponent` 就自动调用它；该标志从未置位，导致 `InitializeComponent` 在服务器和客户端都从未执行，其中绑定的 FastArray 客户端回调（`OnInstanceChanged`/`OnInstanceRemoved` → `HandleInstanceChanged/Removed` → `RefreshAmmoMirror`）一直是死代码。服务器侧此前能刷新只是因为 `ConsumeMagazineAmmo`/`ReloadMagazine` 等写路径硬编码直调 `HandleInstanceChanged`。
- **拾取路径补推**：`AShooterCharacter::EnsureWeaponPresentation` else 分支（武器到达客户端时 bHidden 已是服务器 Equip 同帧解除后的 false，永远走不到 `ActivateWeapon/OnWeaponActivated` 的 HUD 推送）在 `!bMatchesLastApplied && BoundInstanceId 有效` 时补一次 `UpdateWeaponHUD`，保持"重复 Ensure 不重复推送"的幂等语义；BoundInstanceId 未到达时跳过，避免把回退值 0 推上 HUD。
- **回归测试**：新增 `Tests/Equipment/ShooterAmmoHudRefreshAutomationTests.cpp`（`ShootGame.Inventory.AmmoHudRefresh.PickupReloadFire`：拾取立即装备/开火扣弹/换弹提交三个服务器权威事务都必须立即广播 `OnBulletCountUpdated` 且数值正确）；`ShooterWeaponPresentationTestTypes.h` 监听器增加最近一次广播值记录（对既有测试为增量改动）。

## 验证结果

- 诊断过程（临时日志已全部移除，`ShooterInventoryTypes.h`/`ShooterWeapon.cpp` 与上一提交无差异）：
  - 受控世界自动化测试证明服务器侧三场景链路本来正常；
  - MCP 读取 `UI_ShooterBulletCounter` 蓝图接线完整且顺序正确（事件 → Set 变量 → SetText 读新值）；
  - 带临时日志的双客户端网络会话（`RunNetworkSession.ps1`，专用服务器 + 2 客户端）抓到决定性证据：客户端 `EntryPostAdd/Change` 正常触发且数据新鲜，但 `NotifyChanged Bound=0`、`InitializeComponent` 日志在服务器与客户端均为 0 条；换弹提交时 `OnRep_CurrentBullets` 读到旧备弹且无任何纠正推送。
- 修复后仪器化网络会话：客户端 `RefreshAmmoMirror`（Mirror）恢复执行且推送新鲜备弹（真实授权武器 Rifle 实测 `Reserve=120` 连续正确），重新装备补推数值正确。
- `RunAutomation.ps1 -TestFilter ShootGame`：83 通过 / 0 失败（含新增 `AmmoHudRefresh.PickupReloadFire` 成功）。
- `RunNetworkSession.ps1`（Dedicated + 2 客户端 + 网络测试协调器）：通过，2 个 `AUTOMATION_TEST_CLIENT_SUCCESS`。

## 遇到的问题

- 排查初期误判为编辑器热重载会话陈旧模块（重启复测后排除）。
- 换弹"概率刷新"是双通道竞态表象：武器通道 `OnRep_CurrentBullets` 读 `GetReserveAmmo()`（依赖角色通道 FastArray 是否已应用）与 FastArray 回调纠正推送的到达顺序不定；FastArray 回调死亡后无纠正者，竞态结果直接可见。
- 临时验证版本曾在 else 分支无守卫补推，把 `BoundInstanceId` 未到达时的回退 0 覆盖到正确值之后，加有效性守卫后消除。
- 协调器 5B 合成武器在客户端读取显示 `ReserveNow=0`：其"替换实例并生成测试武器"流程中武器绑定与实例替换存在固有瞬态，协调器自身断言不受影响，与玩家路径无关。

## 处理方式

- 根因与表象按"受控复现 → 仪器化实测 → 引擎源码核对标志位语义"闭环定位；所有临时诊断日志验证后全部剥离。
- 拾取补推通过 `bMatchesLastApplied` 守卫保持既有幂等测试语义，装备表现自动化测试全量回归通过。

## 遗留项

- 用户工作区未提交改动（备弹显示改纯蓝图、`UI_ShooterBulletCounterUI` 移除原生文本、Content 资产移动等）未纳入本提交，需用户自行整理提交；`ShooterBulletCounterReserveAutomationTests.cpp` 当前断言被注释成空壳，建议恢复为蓝图契约断言或删除。
- 换弹提交瞬间理论上仍可能出现一帧旧备弹（OnRep 先于 FastArray 应用、同帧内被纠正），视觉不可感知；如需彻底消除可让 `OnRep_CurrentBullets` 只推弹匣、备弹完全走 FastArray 回调，本轮未做。
