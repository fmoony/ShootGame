## 目的

在删除 FirstPerson 模板和根目录基础类之前，用源码关系与 UE Asset Registry 建立可验证的保留边界，避免把 Shooter 仍在使用的动画、Control Rig、材质或共享基类一并删除。

本提交只记录审计结论，不修改运行时代码、配置或资产。

## 本提交完成内容

- 新增 `Docs/FirstPerson清理与架构审计.md`。
- 记录 73 个 FirstPerson 包的组成，以及目录外引用和递归依赖形成的 4 资产最小保留闭包。
- 记录根目录基础 C++ 类与 Shooter 类型的真实继承关系和建议去留。
- 记录残留配置及后续六步清理顺序。
- 在 `AGENTS.md` 文档入口中增加本审计文档导航。

## 验证结果

- CodeGraph 确认：`AShooterCharacter` 与 `AShooterNPC` 直接继承 `AShootGameCharacter`；Shooter Controller、GameMode、GameState 直接继承对应引擎类型。
- UE Asset Registry 确认 FirstPerson 包数量为 73，存在目录外直接引用的包数量为 3。
- 依赖闭包审计确认需要迁移的最小集合为 4 个资产：`ABP_FP_Copy`、`CtrlRig_FPWarp`、`BP_FirstPersonCharacter`、`MI_FirstPersonColorway`。
- `git diff --check` 将在暂存前后执行。
- 本提交没有运行完整七阶段验证，因为不包含 C++、配置或 `.uasset/.umap` 运行时变更。

## 遇到的问题

- 直接扫描 `.uasset` 字符串会把间接类名和普通字符串都视为命中，无法可靠区分真实资产依赖。
- Headless Python Commandlet 在受限环境中报告 Derived Data Cache 无可写节点，但审计脚本本身执行成功并输出完整 Asset Registry 结果。

## 处理方式

- 使用 CodeGraph 判断 C++ 继承与引用，使用 UE 自身 Asset Registry 判断资产依赖，不依据二进制字符串命中直接做删除决策。
- 审计脚本只放在 `Saved/Automation` 临时运行，完成后已经删除，不进入版本控制。
