# 节拍取证指针安全与射速统计口径修正

- 日期：2026-10-06
- 计划提交说明：
  `修复：修正节拍取证的悬空指针与射速统计口径`
- 变更类型：诊断 / 测试口径（不改任何 Fire Gameplay 行为）

## 本轮范围

只处理诊断与测试口径两件事：

1. cadence 采样里的 TArray 元素指针失效；
2. Client / Server 射速统计口径。

未改动：GA_Fire 单发语义、Weapon Authority Fire Gate、15ms Server tolerance、
Prediction / Pending、PredictionKey 裁决、Ammo、Reload、Equip、
Confirmed Feedback、FullAuto 输入策略。

## 一、TArray 扩容后的悬空指针：成立

`AShooterWeapon::RecordLocalFireCadenceSampleForAutomationTest` 旧实现：

```cpp
const FShooterLocalFireCadenceSample* Previous =
    LocalFireCadenceSamples.Num() > 0 ? &LocalFireCadenceSamples.Last() : nullptr;
...
FShooterLocalFireCadenceSample& Sample = LocalFireCadenceSamples.AddDefaulted_GetRef();
...
Sample.IntervalSeconds = Previous ? ActivationTime - Previous->ActivationTime : -1.0f;
```

`Previous` 指向数组元素，随后 `AddDefaulted_GetRef` 可能触发扩容，
扩容后 `Previous->ActivationTime` 读的是已释放内存——**路径确实存在**，
属于未定义行为；`IntervalMs` 是射速取证的核心列，被污染后统计不可信。

最小修复（只改诊断代码，不碰时序）：

- Add **之前**按值取出真正需要的上一条数据：

```cpp
const bool bHasPreviousSample = LocalFireCadenceSamples.Num() > 0;
const float PreviousActivationTime =
    bHasPreviousSample ? LocalFireCadenceSamples.Last().ActivationTime : 0.0f;
```

- `IntervalSeconds` 改用 `bHasPreviousSample / PreviousActivationTime`。

没有使用 `Reserve` 掩盖问题，没有假设容量足够，没有跨 Add 保存元素指针，
也没有改动采样数据结构。

同文件另一处 `LocalFireCadenceSamples.Last()` 在只读统计函数里、Add 之前使用，
不存在失效路径，未改动。

## 二、ClientRequestRps 口径

旧公式（混用两个域，并带 N / N-1 偏差）：

```text
ClientRequestRps = ClientActivationCount(累计计数)
                 / (LastAuthorityCommitTime - FirstAuthorityCommitTime)   ← 服务器时钟
```

新公式（只使用拥有端自己的采样；计数与首末时间在同一次激活回调里更新）：

```text
ClientRequestRps = (OwnerWindowActivationCount - 1)
                 / (LastOwnerActivationTime - FirstOwnerActivationTime)
```

新增字段由夹具在拥有端激活回调里同步更新：
`OwnerWindowActivationCount` / `FirstOwnerActivationTime` / `LastOwnerActivationTime`，
每个步骤起点一起复位。

## 三、AuthorityCommitRps 口径

旧公式把权威发数（`AuthorityShotCount` 增量）与 observer 的提交时刻跨度拼在一起：

```text
AuthorityCommitRps = (AuthorityShotCountDelta - 1) / (提交末 - 提交首)
```

新公式改为权威自己的一套采样（计数与首末提交时刻在同一次被接受激活时更新）：

```text
AuthorityCommitRps = (AuthorityCommitSamples - 1)
                   / (LastAuthorityCommitTime - FirstAuthorityCommitTime)
```

两者数值通常一致（`AuthorityCommitSamples` 与发数增量应相等，报告行会同时输出以便发现分歧），
但分子分母现在同域、同计数来源。

统一实现为一个共用函数，样本不足两次或跨度非正时返回 -1：

```cpp
float ComputeEventRps(int32 SampleCount, float FirstTime, float LastTime)
{
    if (SampleCount < 2 || FirstTime < 0.0f || LastTime <= FirstTime)
    {
        return -1.0f;
    }
    return static_cast<float>(SampleCount - 1) / (LastTime - FirstTime);
}
```

报告行在样本不足时输出 `-1`，并同时输出 `ClientRequestSamples` /
`AuthorityCommitSamples`，明确表示"样本不足"而不是给一个看似合理的假射速。

三个指标分别输出、互不替代：

```text
ClientRequestRps     客户端自己产生 Fire Activation 的节奏
AuthorityCommitRps   服务器真正成功 Commit Shot 的节奏
AuthorityRejectCount 服务器拒绝了多少请求（计数，不是速率）
```

## 四、参与 Pass / Fail 的指标与阈值

读取当前 `Rate600Rpm` / `Rate900Rpm` 用例后，判定口径如下
（阈值统一 `RateToleranceRatio` = **±15%**）：

| 判据 | 是否参与判定 | 阈值 | 存在原因 |
| --- | --- | --- | --- |
| ClientRequestRate | 是 | ±15% | 本仓库唯一能控制的量；能抓住"请求节拍被拖慢"这一类回归 |
| AuthorityCommitRate | 是 | ±15% | 权威达成率必须显式出现在结果里，不因拒绝而静默变差 |
| Accepted == Shots | 是 | 相等 | 一次被接受 Activation 恰好一发 |
| Accepted + Rejects == ClientActivations | 是 | 相等 | 没有"接受了却没发"或被静默吞掉的请求 |
| Pending == 0 / Shot 记录 == 0 | 是 | 相等 | 窗口结束必须收敛 |
| 逐间隔最小 / 最大、拒绝探针、网络字节与速率 | 否（仅观测） | — | 只用于定位，不决定通过与否 |
| 矩阵 10 行 | 只断言结构性不变量 | — | 射速误差只上报 |

上一轮文档里"权威达成射速只作为数据上报"与实现不符（`bRequestPaceOk` 一直包含
`RateErrorRatio`），本轮按"先修文档、再修命名与输出"处理：保留该判据与阈值不变，
删除错误描述，并新增 `AMMO_PREDICTION_RATE_ASSERT` 行显式列出每项判据的取值与阈值，
避免再次出现"文档说仅上报、实现却在判定"的偏差。

本轮没有放宽任何阈值；只纠正了统计定义。

## 六、旧报告中需要修正的数字

以下旧表述需要修正（原文保留，已在旧记录顶部加修订说明）：

1. "10 行中 6 行进入 ±0.3%" —— **错误**。
   同一会话按同一公式实际为 **3/10**；修正口径后为 **1/10**
   （放宽到 ±1% 才 3/10）。该句废弃。
2. 矩阵表"客户端请求/s"列 —— **公式错误**。
   该列原为 `N / 服务器跨度`，已废弃；改用 `(N-1) / 客户端跨度`。
   例：30/600 由 10.116 变为 10.000。
3. "权威达成射速本身只作为数据上报" —— **与实现不符**。
   权威提交射速一直参与 ±15% 判定（见第四节）；文档改为如实描述。
4. "平均误差从 -11.04% 收敛到 -4.23%" —— **口径混合**。
   修复前 -11.04%（权威口径）数值仍有效；
   修复后均值按本轮会话为 **-3.55%**（10 行）。
   原句里"客户端 / 权威混算"的部分废弃。

仍然有效、不需要废弃的数据：

- 所有 `FIRE_CADENCE_LOCAL` / `FIRE_CADENCE_SERVER_ACCEPT` /
  `FIRE_CADENCE_AUTHORITY_COMMIT` / `FIRE_CADENCE_REFIRE_REJECT` 原始逐发日志；
- 本地节拍统计列（本地平均间隔、最小 / 最大间隔、Lag、累计相位误差）——
  它们本就来自客户端自己的 `(N-1) / 跨度` 口径；
- 权威拒绝计数与"拒绝间隔塌缩到服务器帧时间整数倍"的证据；
- 修复前权威侧均值 -11.04% 这一结论（当时权威公式已是 N-1）。

只能收窄、不能继续声称的结论：

1. 不能说"修复后权威达成射速恢复到 ±0.3% 量级"——修正口径后仅 1/10 行进入 ±0.3%。
2. 不能说"权威射速只是观测"——它一直是判定项。
3. 不能说"客户端请求射速与权威达成射速用同一分母、可直接相减"——
   两者现在各用自己的域，只能分别与理论射速比较。
