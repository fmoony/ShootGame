# GAS 实现服务器权威换弹事务

- 日期：2026-08-21
- 计划提交说明：`GAS：实现服务器权威换弹事务`
- 变更类型：生产代码 / 测试 / 资产 / 脚本

## 目的

执行 `Docs/执行计划/GA_Reload与GA_Equip_ServerOnly执行计划.md` 的子阶段 5B：把 `IA_Reload` 接入 ASC `Input.Reload`，让 GA_Reload 从 5A 壳体变成完整的 ServerOnly 换弹事务，并验证满弹匣 / 无备弹拒绝、单次原子转移、切枪 / 死亡 / 断线取消与重生不携带。

## 本提交完成内容

- `AShooterCharacter` 新增 `ReloadAction` 与 `DoReload()`：`IA_Reload Started` 只向 ASC 提交 `Input.Reload`；Switch 输入继续走旧 `ServerSwitchWeapon`。
- `UShooterGameplayAbility_Reload` 完成 ServerOnly 闭环：
  - 激活时服务器校验当前 WeaponActor、Inventory Active Instance、弹匣未满且 ReserveAmmo 大于 0；
  - 记录 `TargetInstanceId` 事务快照并取消 GA_Fire；
  - 以 `WeaponActor.ReloadDuration` 为 `UAbilityTask_WaitDelay` 权威时钟；
  - 提交前二次确认目标仍是 Inventory Active 与 `Character.CurrentWeapon`；
  - 通过 `Inventory.ReloadMagazine` 一次性提交，`bReloadCommitted` 保证一次 Ability 最多提交一次；
  - 完成 / 取消 / 失败共用 `EndAbility` 清理 WaitDelay、Weapon 引用与快照。
- `AShooterCharacter` 死亡、切枪、EndPlay 时幂等取消 GA_Reload；重生清理 `State.Reloading` 与活动 Reload Ability，不携带上一生命换弹状态。
- 通过 UE Editor Python 资产系统更新 `BP_ShooterCharacter` 的 `ReloadAction=IA_Reload`，并给 `IMC_Weapons` 增加 R → `IA_Reload` 映射。
- Feature Tests 新增 `ShootGame.Ability.Reload.*` 8 项：ServerOnly、TransferOnce、Reject.FullMagazine、Reject.NoReserve、Cancel.Death、Cancel.Equip、Cancel.Disconnect、RespawnNoCarry；静态部分覆盖 Ability 配置、Inventory 原子拒绝、BP/IMC 资产配置。
- `ShooterNetworkTestCoordinator` 扩展 5B 运行时观测：
  - 测试武器固定 30 发容量与 1.5s ReloadDuration；
  - 满弹匣 / 无备弹输入拒绝且 Ammo 不变；
  - 25/20 → 30/15 只转移一次；
  - 换弹等待中旧切枪取消，Ammo 不变并切回手枪；
  - 部分伤害后致死伤害在提交窗口内取消 GA_Reload，死亡后无活动 Ability / Tag；
  - 重生后 Inventory 为空、活动 Reload 为零、`State.Reloading` 不残留。
- `ShooterGameMode` DisconnectCleanup 检查只针对真正断线连接的 PlayerState，确认没有活动 GA_Reload 或 `State.Reloading`；断线协调器会提前制造活动 Reload。
- `RunAll.ps1` 默认网络会话时长从 25s 调整为 45s，覆盖 5B 换弹事务等待链。

## 遇到的问题

- 首次 EmulatedNetwork 在 TransferOnce 后的 EquipCancel 阶段超时：`State.Reloading` 的移除复制晚于新的 `ReloadInputRequestId`，客户端本地预检误吞了换弹输入。
- 首次 DisconnectCleanup 误报 `ActiveReload=1`：按 TeamId 猜测断线客户端不可靠，计划被断开的连接没有拿到活动 Reload；同时 GameMode 在下一帧检查过早，Pawn EndPlay 尚未完成取消。
- 调试过程中还出现三处编译问题：协调器头文件 RPC 插到参数列表中间、`PollTimer` / `ActorSpawnedHandle` 及客户端开关成员重复定义、测试文件误用不存在的 `Test` 变量与 `FNativeGameplayTag::IsValid()`。
- UE Python 创建 `IMC_Weapons` 映射时误用 `InputActionKeyMapping`，实际 5.6 资产中的映射类型是 `EnhancedActionKeyMapping`；且数组修改后需要 `modify()` + `save_asset(path, False)` 才会落盘。

## 处理方式

- 客户端在新 RequestId 首次提交后，在 2 秒窗口内每 0.25s 重试一次 `DoReload()`；切枪动作触发时清零重试计数，避免向新武器继续发送换弹输入。
- 断线阶段改为每个协调器都制造活动 Reload；GameMode 只检查真正断线连接 `Exiting` 的 PlayerState，并延迟 0.5s 等 Pawn EndPlay 完成后再判定。
- 逐项修正头文件声明位置、删除重复成员，并把测试内的 `Test` 改为 `this->`；删除对 FNativeGameplayTag 不存在 API 的断言。
- IMC 资产修改改用 `EnhancedActionKeyMapping`，通过 `imc.modify()` 标记脏并强制保存；每次修改后重新加载验证 R 映射存在。
- 每轮修复后重新执行 Build / Automation / 对应网络阶段，最终再运行完整七阶段回归。
