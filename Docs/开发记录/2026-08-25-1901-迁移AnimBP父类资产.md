## 目的

执行《Shooter 核心玩法架构解耦重构执行计划》R6.2：在 R6.1 C++ AnimInstance 体系建立后，把目标 AnimBP 的 Parent Class 迁移到对应 C++ 适配层，编译并保存资产。本提交只改父类和编译冲突所需的最小变量改名，不修改 Control Rig、AimOffset、Montage、Slot 或姿势资源；EventGraph 数据来源迁移留给 R6.3。

## 本提交完成内容

- 新增 `Source/ShootGameEditor/Migration/ShooterAnimBPReparentCommandlet`：
  - 只处理计划明确列出的四个资产，不批量重保存。
  - `ABP_FP_Weapon`、`ABP_FP_Pistol` → `UShooterFirstPersonAnimInstance`。
  - `ABP_TP_Rifle`、`ABP_TP_Pistol` → `UShooterThirdPersonAnimInstance`。

  - 对 `ABP_TP_Rifle` 旧蓝图变量 `GroundSpeed` 自动改名 `LegacyGroundSpeed`，消除与新基类属性同名冲突。

- 资产迁移结果：
  - `ABP_FP_Weapon` / `ABP_FP_Pistol`：父类为 `UShooterFirstPersonAnimInstance`，编译 0 Error。
  - `ABP_TP_Rifle` / `ABP_TP_Pistol`：父类为 `UShooterThirdPersonAnimInstance`，编译 0 Error。

  - `ShootGame.Weapon.Configuration`：断言 FP 武器 AnimBP 派生自 `UShooterFirstPersonAnimInstance`、TP 武器 AnimBP 派生自 `UShooterThirdPersonAnimInstance`。

## 遇到的问题

- 首次迁移时 `ABP_TP_Rifle` 保存报 Error 32：文件被一个 `-RespawnedInstance` 的旧崩溃编辑器进程占用。核实该进程是此前自动化崩溃后自动重启的残留（父进程已退出），终止该残留编辑器后重跑迁移，四个资产全部保存成功。
- `ABP_TP_Rifle` 加载时出现 `AnimGraphNode_ShooterLeftHandIK` 结构体序列化告警，以及 EventGraph 中 `CurrentWeapon` 变量引用告警；两处均为迁移前已存在的资产问题（14:52 网络基线日志已有 LeftHandIK 节点加载告警），编译仍为 0 Error，计划在 R6.3 数据来源迁移时修复节点并重新保存。
- 自动化启动时会加载 `BP_ShooterCharacter` 并报告旧的 `Current Weapon` 蓝图变量属性缺失；该节点属于 R4 移除 Character 写权后的待迁蓝图引用，测试未受影响，已登记到 R6.3/R8 处理清单。

## 处理方式

- 对崩溃残留编辑器只终止进程，不触碰任何用户文档或未提交文件；迁移工具在无人值守 Commandlet 中完成全部资产修改与保存。
- Commandlet 采用严格保存门：只有 `NumErrors == 0` 且 `Status != BS_Error` 才保存；`BS_BeingCreated` 只记录不当作失败。

- `BP_ShooterCharacter` 中遗留的 `Current Weapon` 蓝图变量属性错误，等待兼容接口退出阶段或资产修复决策。
