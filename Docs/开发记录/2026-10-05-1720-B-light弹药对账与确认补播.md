# 实现 Ammo Prediction 按 Activation 对账与确认补播（B-light）

- 日期：2026-10-05
- 计划提交说明：`修复：实现AmmoPrediction按Activation对账与确认补播`
- 变更类型：生产代码 / 测试 / 文档

## 目的

Phase C 复现已确认：`PendingPredictedShots` 只按 `MagazineAmmo` 差值吸收时，
同值快照会遗留预测消费（H-A1）；本地预算基于旧快照否决 Owner 表现时，
服务器接受并提交的射击在拥有端没有对应表现（H-A3）。

本轮按用户确认的范围实施 B-light：用 Activation 结果对账取代数值吸收，
服务器结果领先时补播一次已确认表现；不扩大预测内容。

## 本提交完成内容

- `AShooterWeapon` 新增 OwnerOnly 的最近 4 轮 `FShooterFireActivationResult` 环：
  `{ActivationKey, ProcessedShots, bSettled, ActivationSerial}`；
  `ProcessedShots` 只在服务器 `ConsumeAmmo` 成功提交后递增，`bSettled` 在服务器
  `EndAbility` 置位；结果只服务拥有端 `GA_Fire` 对账，不记录 per-shot id。
- 拥有端 `GA_Fire` 新增按 ActivationKey 索引的预测账本：
  预测发数、已见服务器结果、已补播、已对账预测、补播序号游标与本地尝试序号游标。
- `OnRep_MagazineAmmo` 不再吸收或重订 `PendingPredictedShots`；
  Pending 只由账本确认、phantom 清理、Reject 退还与生命周期复位修改。
- 结清规则：
  - `Processed <= Predicted`：确认对应预测发数并清空剩余 Pending，不补播；
  - `Processed > Predicted`：先确认全部已预测发数，再按缺口调用
    `PlayOwnerConfirmedShotFeedback()` 补播恰好一次；
  - 服务器最终未提交的预测按 phantom 清理，不回滚已播表现。
- 服务器是否认可本次 Activation 以 `OnConfirmDelegate` / Rejected 为准，
  CaughtUp 不再参与结清。
- `PlayOwnerConfirmedShotFeedback()` 只播放四路纯表现：
  不消费 Pending、不推进本地节拍、不发 RPC、不生成 Projectile、不写 Ammo。
- 生命周期边界（Owner 变化、归还池、Destroy、重新绑定）清空结果环与 Pending；
  账本在新激活时清理已结清与超额条目（未结清上限 4），
  `FPredictionKey::Current` 为 int16，槽位键以 int32 存储，不按数值大小判断新旧。
- 不新增 per-shot RPC / ShotId、不预测空弹、不推测换弹转移，
  不改 HUD / Phase B / Projectile / Damage / Manager / Subsystem。

## 不变量定向结论

以下 PASS 只指本轮触及的维度，不代表全项目完整五不变量回归。

- Invariant 1 / PASS：服务器领先的每发权威射击都有一次拥有端表现来源
  （预测或确认补播），合计等于权威发数。
- Invariant 2 / PASS：Pending 不再由过期数值吸收；预测仍遵守本地射速与弹药门控。
- Invariant 3 / PASS：ProcessedShots 只读服务器提交计数；客户端不写权威字段。
- Invariant 4 / PASS：新结果记录 OwnerOnly；补播不出拥有端，不新增远端通道。
- Invariant 5 / PASS：预测、补播与退还各恰好一次，账本结清后不再消费。
- 未覆盖：Dedicated、丢包与断线矩阵、重生与切枪、长时间 FullAuto 归因、
  结果环 4 轮覆盖后的旧轮补播、账本上限 4 的现场压力。

## 遇到的问题

- 夹具原 Backfill 断言要求 `FeedbackDelta == ShotDelta`；B-light 下本地预算
  仍会先否决部分预测消费，改为 `FeedbackDelta + BackfillDelta == ShotDelta`。
- 夹具采样会被 Held 输入的重复激活冲刷：增加步骤内 pinned ActivationKey、
  只读的最近结清快照与结清后松开输入的收敛释放，避免误读其他轮结果。
- ReloadLifecycle 起初备弹不足导致超时；改为给足备弹并保留短缺起点。
- 编译期出现两处可见性问题（测试使用私有枚举、Weapon 调用私有方法），
  改为公开声明后通过。
- 提交前版式门禁报 23 处冗余折行与参数换行；按规则合并或展开后重编译并通过。
