# 收敛本地开火表现节拍与确认回退

- 日期：2026-09-16
- 计划提交说明：`射击：收敛本地开火表现节拍与确认回退`
- 变更类型：生产代码 / 网络测试 / 计划同步

## 目的

Dedicated 弱网场景中，换弹已在服务器完成，但客户端仍可能保留迟到的 `State.Reloading`。
客户端仍必须把开火请求交给服务器，不能重新收紧 `CanActivateAbility`。
但当前本地表现门控会跳过首帧，Owner Multicast 又固定跳过可见反馈，
最终形成服务器已经生成弹丸、拥有者稍后才听见枪声的窗口。

同时，半自动快速连点此前会让每次预测激活都立即播放一次纯表现，即使服务器随后因
`RefireRate` Reject，也会形成连续枪口、声音或后坐力而没有真实弹丸。本轮在不改变权威射击时钟的
前提下，为普通预测补上按武器隔离的纯表现节拍。

## 本提交完成内容

### 生产修复

`UShooterGameplayAbility_Fire` 新增服务器接受确认回退：

- 每次激活独立记录“是否已经成功播放拥有者反馈”和“确认回退宽限是否仍有效”；
- 初始本地门控仍排除本机已知的 Reloading / Equipping / Dead，不吞掉发往服务器的请求；
- `ConfirmActivateSucceed` 收到服务器接受后，如果本次激活尚未成功播放且当前武器仍有效，
  通过现有无状态 Owner 表现入口只补播一次；
- 已经预测播放过的激活不补播，服务器 Reject 不进入确认回调，也不会产生误反馈；
- 确认回退后的全自动激活在迟到 Tag 首次清除前获得短暂宽限；清除后恢复门控，
  避免未来真正的新 Reload / Equip / Dead 状态被忽略；
- 新增 `FIRE_OWNER_CONFIRMED_FALLBACK` 开发日志标记，区分正常首帧预测与确认回退。

`AShooterWeapon` 新增按实体隔离的纯表现冷却：

- 每个 WeaponActor 独立保存 `OwnerFeedbackCooldownEndTime`，普通预测成功播放后按自身
  `RefireRate` 推进；没有全局、ASC 或 GA 共享状态；
- 冷却不复制、不建 Timer，不写 `TimeOfLastShot`、权威 `RefireTimer`、Ammo 或 Projectile；
- 服务器接受确认使用显式 `PlayOwnerConfirmedShotFeedback()` 旁路冷却，只补播一次并重新推进冷却；
- Reject 不进入确认回调，半自动冷却自身也不安排延迟事件，因此不会在 Reject 后补出尾部反馈；
- 池取用、归还和客户端 Owner 复制变化时复位该字段，避免跨玩家或跨租用继承；
- 网络测试继续使用真实 Rifle / Pistol 配置，没有通过反射篡改客户端 `bFullAuto`。

### 端到端验证增强

复用既有 Fire-after-Reload 网络阶段，不新建第二套状态机：

- 客户端在单次开火前记录 Owner 本地反馈与权威确认计数；
- 明确上报开火输入发生时客户端仍带有 `State.Reloading`，保证覆盖迟到 Tag 窗口；
- 服务器接受并产生一发权威射击后，客户端等待两项计数收敛或一秒超时，再停止开火；
- 服务端要求 `OwnerFeedbackDelta == 1` 且 `OwnerConfirmationDelta == 1`，否则直接失败；
- 既有 Ammo、Projectile、活动 Ability、`State.Firing` 与静默收敛断言保持不变。

Feature Test 直接从运行时池取出两把真实 WeaponActor，验证：

- 同一武器第一次普通预测成功，紧接的第二、第三次尝试被本地冷却挡下；
- 另一把武器在同一时刻仍能播放，证明冷却没有跨武器共享；
- 确认回退可在冷却内补播一次；
- 上述过程不改变 `TimeOfLastShot`、权威 `RefireTimer`、Ammo、Projectile、Lifecycle 或权威射击计数。

## 遇到的问题与处理

1. 首版确认宽限覆盖了当前激活剩余生命周期，可能短暂忽略之后真正的新阻塞 Tag。
   最终实现收紧为“只到迟到 Tag 首次清除”；随后重新完成编译、Fire 自动化和 Dedicated 验证。
2. 首次为测试冷却到期而对未初始化的临时 World 调用一次 `Tick`，但该夹具不会推进
   `TimeSeconds`，导致唯一新增断言失败。删除无效的时间模拟后重跑，17 项全部通过；限速、隔离、
   确认旁路与权威字段不变仍由真实生产入口覆盖。
3. 首次直接运行网络脚本时沿用了已删除的 `/Game/FirstPerson/Lvl_FirstPerson` 默认地图，
   服务器正常退出但没有进入测试。随后改用既有 P1-C 包装器和正式
   `/Game/Shooter/Maps/Lvl_Shooter` 重跑通过。
4. `apply_patch` 写入后产生 LF 行尾，按代码规范机械统一为 CRLF；
   `CheckTextLayout.ps1 -Scope WorkingTree` 与 `git diff --check` 均通过。
