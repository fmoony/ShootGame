# 补齐 GA_Equip 死亡断线取消并归档 Reload Equip 计划

- 日期：2026-08-21
- 计划提交说明：`修复：补齐 GA_Equip 死亡断线取消并归档阶段计划`
- 变更类型：生产代码 / 测试 / 文档

## 目的

按用户要求复查 `GA_Reload与GA_Equip_ServerOnly执行计划.md` 是否还有未完成项。复查发现：

1. 生产代码缺口：`AShooterCharacter::Die()` 与 `EndPlay()` 会取消 GA_Fire / GA_Reload，但没有取消 GA_Equip；装备等待中的死亡或断线会短暂残留活动 Equip 事务与 `State.Equipping`。
2. 重生防御性清理没有移除 `State.Equipping`。
3. 重生与断线自动化断言只检查 Reload 残留，不检查 Equip 残留。
4. 文档导航仍把 GA_Reload / GA_Equip 计划标为“当前下一阶段”，且计划未按项目惯例归档到 `Docs/已完成计划`。

本提交关闭以上缺口，并正式标记该阶段完成。

## 遇到的问题

- `ShooterGameMode.cpp` 首次编译失败：`GetActiveAbilityCountForClass` 无法从 `TSubclassOf<UShooterGameplayAbility_Equip>` 转换到 `TSubclassOf<UGameplayAbility>`。
- 原因：GameMode 已包含 Reload Ability 头文件，但未包含 Equip Ability 头文件，只有前置声明。
- 计划复查时发现 Die / EndPlay 缺 GA_Equip 取消：这不是测试问题，而是 5C 提交时遗漏的生产路径，必须先补生产逻辑，再扩展残留断言。

## 处理方式

- 在 `ShooterGameMode.cpp` 补 `#include "ShooterGameplayAbility_Equip.h"`，重新编译通过。
- 新增 `CancelEquipAbility()` 与 Fire / Reload 使用同一 `CancelAbilitiesByTag` 机制；在死亡、角色销毁与新 Avatar 初始化三条路径统一覆盖 Equip。
- 重生与断线断言按“活动 Ability 数量 + Owned Tag 残留”双条件扩展，避免只检查 Tag 而漏掉 WaitDelay Task。
- 文档按 2026-08-20 归档 GA_Fire 的既有模式归档：移动计划、更新路线、更新 AGENTS 导航、更新架构基线。

## 遗留项

- 当前自动化没有单独制造“Equip 等待中恰好在断线瞬间”的网络阶段；本次通过共享的 `EndPlay` 取消路径和断线后 Equip/Tag 残留断言覆盖清理结果。若后续需要更严格的时序证明，可增加第二个 DisconnectCleanup 阶段专门激活 GA_Equip 后断线。
- Montage 候选仍为 AnimSequence，Demo Polish 表现接入未实施。
- 阶段已暂停复盘，不进入 P1 Local Predicted；后续必须先形成新的详细计划。
