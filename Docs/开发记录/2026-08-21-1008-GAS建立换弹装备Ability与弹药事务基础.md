- 日期：2026-08-21

- 变更类型：生产代码 / 测试 / 资产 / 文档

## 目的

执行 `Docs/执行计划/GA_Reload与GA_Equip_ServerOnly执行计划.md` 的子阶段 5A：先建立 ReserveAmmo → MagazineAmmo 的 Inventory 原子事务、Reload/Equip 的 GameplayTag 互斥合同、两个 ServerOnly Ability 壳体和服务器幂等授予生命周期。本提交不改变实际换弹与切枪行为。

## 本提交完成内容

- `FShooterWeaponInventoryList` 新增 `ReloadMagazine(InstanceId, MagazineCapacity, OutTransferredAmmo)`：单次校验并计算 `Min(Need, ReserveAmmo)`，同时写入两类弹药并 `MarkItemDirty`；弹匣已满、无备用弹药或实例不存在时不产生变化。
- `UShooterInventoryComponent` 新增服务器专用 `ReloadMagazine(InstanceId, OutTransferredAmmo)`：从绑定 WeaponActor 读取 `MagazineSize` 作为唯一容量来源，提交后统一刷新 WeaponActor 弹药镜像与 Owner HUD；客户端无远程调用入口。
- `AShooterWeapon` 新增 `ReloadDuration=1.5s`、`EquipDuration=0.5s` 配置与 Getter；它们是后续服务器权威事务时钟，Montage 不反向决定事务结果。
- `ShooterGameplayTags` 新增 `Input.Reload`、`Input.Equip.Next`、`State.Reloading`、`State.Equipping`。
- 新增 `UShooterGameplayAbility_Reload` 与 `UShooterGameplayAbility_Equip` 5A 壳体：`InstancedPerActor`、`ServerOnly`、输入 AssetTags、ActivationBlockedTags / ActivationOwnedTags 与测试观察接口；服务器激活后立即 EndAbility，不修改弹药或当前武器。
- `GA_Fire` 的 `ActivationBlockedTags` 补入 `State.Reloading` / `State.Equipping`，形成 Fire / Reload / Equip 三者互斥合同。
- `AShooterPlayerState` 新增 Reload / Equip Ability 类配置、幂等授予入口与 Spec 计数；PostInitializeComponents 中与 GA_Fire 一起只授予一次，重生仅更新 Avatar。
- 通过 UE Editor Python 资产系统创建 `/Game/Shooter/Input/Actions/IA_Reload`；5A 不绑定输入，Switch 输入仍走旧 `ServerSwitchWeapon` 路径。
- Feature Tests 新增 `ShootGame.Inventory.Reload.*` 五个事务测试与 `ShootGame.Ability.ReloadEquip.Grant.*` 两个授予测试；现有 `ShootGame.Ability.Fire.Grant.Player` 同步断言新互斥标签。
- `ShooterNetworkTestCoordinator` 扩展 5A 运行时验证：服务器出生与重生后 Reload / Equip 各有且只有一个 Spec、重复 Grant 不增长、重生 Spec Handle 不变、拥有者客户端收到各一个 Spec、远端客户端不收到完整 Spec；成功 / 超时标记新增 `ReloadEquipGrant`。
- 纳入用户预置的 `AGENTS.md` 已完成计划导航精简，以及本执行计划中记录该约定的说明；`ShooterAbilitySystemComponent.cpp` 的用户既有注释修改不属于 5A，未暂存。

## 遇到的问题

- 首次编译失败：`ShooterNetworkTestCoordinator.h` 插入新 RPC 时位置选择错误，产生重复 `UFUNCTION` 声明，UHT 报 `Function return type: Expected name`。
- 首次编译还失败于两处测试代码：`ShooterAbilityFireAutomationTests.cpp` 的新断言插在 `return true` 之后（C4702 不可达代码）；`ShooterAbilityReloadEquipAutomationTests.cpp` 误写 `UShooterPlayerState`（实际类名是 `AShooterPlayerState`）。
- `ShooterInventoryComponent.cpp` 插入 ReloadMagazine 时按旧行号插入，在 `HandleInstanceChanged` 签名中间留下重复行，导致 C2751 / C2143。
- 首次 Automation 的 `RespawnNoDuplicate` 失败：测试假设 CDO 无权威所以重复 Grant 一定被拒绝，实际 EditorContext 中 `GetMutableDefault` CDO 的 `HasAuthority()` 成立并真的授予了 Spec，污染了 CDO 状态。

## 处理方式

- 用 UHT 报错定位头文件声明区，把新 RPC 放到 FullAutoReleased 声明之前并恢复其独立 `UFUNCTION`。
- 移动 Fire 测试断言到 `return true` 之前；把 `UShooterPlayerState` 修正为 `AShooterPlayerState`；删除 Inventory 中重复的函数签名行。
- 静态测试不再修改 CDO：只断言 CDO 零 Spec、授予方法不是远程可调用 UFUNCTION；运行时重复授予与重生 Handle 不变由网络协调器在 Dedicated / Listen 中验证。
- 每轮修复后重新执行 `BuildEditor.ps1` 与 `RunAutomation.ps1 -TestFilter ShootGame`，最终再运行完整七阶段回归。
