# 测试能力编译边界收口

- 日期：2026-10-07
- 计划提交说明：`重构：收口生产代码的测试能力编译边界`
- 变更类型：生产代码 / 构建

## 目的

生产代码此前无条件携带测试能力与测试头依赖，具体有两处：

1. `AShooterGameMode::PostLogin` 的测试启动代码位于
   `WITH_DEV_AUTOMATION_TESTS` 内，但
   `#include "Tests/Network/ShooterNetworkTestCoordinator.h"`
   在文件顶部无条件存在；非测试配置虽然不会 Spawn 夹具，
   却仍被迫解析 Coordinator 头及其测试类型依赖链
   （`Tests/Network/ShooterRemoteBatchForTest.h` 等）。
2. `UShooterWeaponRuntimeSubsystem` 的三个只服务自动化夹具的入口
   （`SetWeaponTableOverride` / `GetWeaponTableOverride` /
   `InitializeWeaponRuntimeForTest`）作为普通 Runtime 公共 API 长期暴露；
   其中最后一个会销毁全部未租出实体、按注入表重建快照与预热，
   绕过「运行时禁止重读表」的冻结语义，不应出现在非测试构建中。

本提交只收窄「谁在什么编译配置下能看到测试能力」，
不改变任何 Gameplay 行为、不重构测试启动架构、不新增抽象。

## 本提交完成内容

- `Source/ShootGame/GameFramework/GameMode/ShooterGameMode.cpp`：
  Coordinator 的 include 收进 `#if WITH_DEV_AUTOMATION_TESTS`，
  与同文件 `PostLogin` 内的启动代码处于同一编译边界。
- `Source/ShootGame/Weapons/Subsystems/ShooterWeaponRuntimeSubsystem.h/.cpp`：
  三个测试注入 / 重建入口的声明与定义包进同一
  `#if WITH_DEV_AUTOMATION_TESTS`；`WeaponTableOverride` 成员保留
  无条件 UPROPERTY 声明（原因见「处理方式」）。
- 正常 Runtime API 零 diff：`InitializeWeaponRuntime` / `Deinitialize` /
  `AcquireWeapon` / `ReleaseWeapon` / 全部观测访问器与私有实现未改动，
  没有把测试重建逻辑塞进 `InitializeWeaponRuntime`。
- 未新增任何宏，沿用项目既有 `WITH_DEV_AUTOMATION_TESTS`
  （与 `ShooterPlayerController.h`、`ShooterWeapon.cpp` 的用法一致）。

## 遇到的问题

1. 编译边界不一致：类型依赖无条件、使用点有条件，即本提交要修的主问题。
2. UHT 不允许包裹 UPROPERTY：UHT 只把 `WITH_TESTS` 认作可包裹成员属性的
   define scope（`UhtHeaderFileParser.cs:989`、`UhtNames.WithTests`）；
   若用 `WITH_DEV_AUTOMATION_TESTS` 包 `WeaponTableOverride`，
   非测试配置下生成代码会引用不存在的成员。
3. 探针工具链连续三次失败：`C1853`（vcvars 默认选中 14.44 工具集，
   与共享 PCH 不匹配）、改用 `/Y-` 绕过 PCH 后 `C1083`
   （找不到 `UnrealEdSharedPCH.h`）、`CoreMinimal.h` 找不到
   （响应文件里的 include 路径相对 UBT 的工作目录 `Engine\Source`）。
4. 探针脚本首版含中文 `Write-Host` 字面量，被解释器按 ANSI 解码后
   语法报错，脚本无法执行。

## 处理方式

- include 移入与使用点相同的 `#if WITH_DEV_AUTOMATION_TESTS`，
  使「类型依赖」与「测试启动代码」处于同一编译边界。
- `WeaponTableOverride` 保持无条件 UPROPERTY 声明，并在成员注释中写明
  原因：写入入口随宏收口后，非测试配置下该指针恒为 `nullptr`，
  正常 `InitializeWeaponRuntime` 行为不变。
- 探针改为固定 `-vcvars_ver=14.38.33130`；在 `cmd` 内先
  `cd /d <Engine>\Engine\Source` 再调用 cl；保留 UBT 的 `/Yu`、`/Fp`
  共享 PCH 用法；被测 TU 包在「`#undef` 后 `#define` 宏再 include
  真实 .cpp」的包装文件里，从宏层面模拟非测试配置。
- 探针脚本改为纯 ASCII，并给「预期失败」的探针增加错误码断言，
  避免「因为别的原因失败」被误判为通过。
- 探针只用于本轮证据，不进入仓库、不新增构建矩阵。

  按「不重构测试启动架构 / 不碰 Coordinator 大头文件」本轮保持不动，

- `WeaponTableOverride` 成员及其在 `InitializeWeaponRuntime` 中的读取
  保留（原因见上），非测试配置下成为死分支。

  `TimerManager.h` 仍无条件包含，而使用点都在开发块内；
