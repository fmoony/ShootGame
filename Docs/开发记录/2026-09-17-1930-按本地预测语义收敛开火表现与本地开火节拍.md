# 按本地预测语义收敛开火表现与本地开火节拍

- 日期：2026-09-17
- 计划提交说明：`射击：按本地预测语义收敛开火表现与本地开火节拍`
- 变更类型：生产代码 / 网络测试 / 语义简化

## 目的

按契约语义收敛网络开火路径，消除长期存在的表现与权威不一致：

- 客户端只预测 Owner 的开火表现与本地射击节拍；
- 服务器始终决定真实 Shot / Ammo / Projectile / Hit-Damage；
- Remote 只消费服务器确认后的结果；
- 不做 Ammo Prediction，不让复制的 Ammo / Reloading / Equipping / Dead 破坏首次 Owner 表现。

要消除的具体现象：半自动快速连点只有第一发有特效、有弹无特效、无弹药但有开火特效、
换弹窗口的开火 cosmetic 不受约束、全自动快速重按缺首拍。

## 本提交完成内容

### 生产：本地开火节拍（`AShooterWeapon`）

- `OwnerFeedbackCooldownEndTime` → `LocalFireCooldownEndTime`，配套
  `IsLocalFireCooldownReady` / `GetLocalFireCooldownRemaining` / `AdvanceLocalFireCooldown`
  / `ResetLocalFireCooldown`；语义是"距上一次本地有效开火"。
- 节拍**只由"本地 Shot Attempt 被接受"推进一次**，与 Montage / Niagara / Sound 是否播放成功无关；
  表现入口 `PlayOwnerShotFeedback` 只负责四路 cosmetic，不再判定或推进节拍。
- 节拍只读本地时钟，不读也不写权威 `TimeOfLastShot` / `RefireTimer`；5ms 浮点容差只保留给全自动。
- `StopFiring()` 只对全自动清除 `RefireTimer`：半自动的它承载 `FireCooldownExpired`，
  是服务器"距上一次真实射击是否已满 RefireRate"的权威判据，松开扳机不得取消。
- `FireCooldownExpired()` 补 `WeaponOwner` 空判（该 Timer 现在可跨过释放与卸下）。
- 删除只为"用复制 Ammo 二次压制表现"存在的 `bMagazineAmmoReplicated` /
  `HasReplicatedMagazineAmmo` / `MarkMagazineAmmoReplicatedForTest`。

### 生产：Ability 语义（`UShooterGameplayAbility_Fire`）

- 客户端本地资格（`CanActivateAbility` 客户端分支）统一为：
  ASC/Avatar → 本机拥有者视图 → **当前武器有效且未隐藏** → 半自动本地节拍 Ready。
  未到 `RefireRate` 直接返回 false；引擎在 `CallServerTryActivateAbility` 之前返回，
  因此既不发请求也不本地激活。
- 该分支刻意先于 `Super` 且不读 `ActivationBlockedTags`，保留"不因迟到复制状态吞输入"的语义。
- 表现门控收敛为"表现目标是否成立"（武器有效 / 未隐藏 / 仍是当前装备），
  **不再读取** Ammo / Reloading / Equipping / Dead：这些复制状态一旦过期，
  会把服务器已经接受并生成弹丸的那一发压成永久无反馈。
- 全自动首拍按**剩余 cooldown**安排：刚播过等一个完整 `Interval`，上一 Burst 未结束只等剩余时间，
  不再惩罚一个完整 `RefireRate`。
- 全自动 Tick 每拍同样先推进节拍再只播 cosmetic；Reject / Release 只停未来表现并清理
  Timer / `CachedWeapon` / Ability 状态，不回滚已播 cosmetic。
- 删除 `ConfirmActivateSucceed` 覆写与整套确认回退机制（冷却旁路、迟到 Tag 宽限、
  释放后延后收口、`EOwnerFeedbackBlock` 及其测试钩子）。
- `UShooterGameplayAbility::GetShooterAvatarActor()` 补上"实例存在但没有 `CurrentActorInfo`"分支。

### 测试

- 新增 `ShootGame.Ability.Fire.Prediction.LocalFireCadence`：证明节拍只读本地时钟、
  只由 Shot Attempt 推进、不写服务器权威射速，且表现入口不推进节拍。
- `Prediction.KnownBlockers` 反转为"复制 Ammo 与 Reloading / Equipping / Dead 不得抑制表现"。
- `Prediction.LocalFeedbackCosmeticOnly` / `LocalFeedbackStateless` 改为按新契约断言：
  表现入口只负责 cosmetic，不再自我限速。
- 网络侧：
  - 半自动连点窗口改为验证"本地节拍是发请求的门"，新增请求数上限断言
    （15 次真实点击只应有 4~5 次到达服务器）；
  - 分通道断言由"四路各 ≥1"收紧为"四路各自等于本次本地表现次数"；
  - 本地表现次数下界收紧为 `Feedback >= Authority`，使"权威出弹、Owner 无反馈"必然失败；
  - 全自动拆分为"本地节拍"与"权威一一对应"两项断言，不再强配对 `Feedback == Authority`
    （两侧 Timer 允许相位差）；
  - `ReloadFire` 已知阻塞分支允许一次不可撤销的 cosmetic phantom（上界为 1）；
  - `FireAfterReload` 恢复严格断言：本地表现必须恰好一次。

## 遇到的问题与处理

1. **两次错误归因（重要）**：
   - 曾判定"确认回退旁路冷却"是快速连点特效的根因；实际根因是 `StopFiring()` 无条件清除半自动
     权威冷却 Timer，使服务器"接受但不发射"，再由确认回退把每一次点击都补播成表现。
   - 曾判定"权威端 ASC 上一次激活会调用两次 `ActivateAbility`"；按引擎源码
     `NetMode` 取 PlayerController 的 LocalRole，主机/单机为 `ROLE_Authority`，
     只走权威分支，LocalPredicted 是 `else if`，**一次激活只调用一次**。
     基于该错误结论写的注释与补推进判定已删除。
2. 表现门控的取舍反复：先删 `State.*`，又恢复 Ammo 判定并加事务豁免，
   最终确认"Ammo 与复制状态都不得二次否决首次表现"，整段判定删除。
3. 新增 Automation 用例首次编译失败（`ResetLocalFireCooldown` 为 protected）：
   判断为不应为测试放宽生产 API，改为调整断言顺序。
4. 网络脚本用 `pwsh -File` 传多元素 `-ServerExtraArgs` 时数组被外层解析成独立 token，
   被脚本参数绑定误认；改为在 `Saved/` 下的临时包装脚本内用变量传参（不进入版本库）。
5. 一个网络会话（`20260917_191459`）失败于既有 `Remote invariant invalid`
   （远端确认与对手权威射击的窗口对齐抖动），与本轮改动无关。

## 遗留项

- **换弹期间半自动仍会持续出现开火 cosmetic**：客户端两道门都不读 `State.Reloading`，
  节拍只由本地 attempt 推进，因此换弹期间每次点击只要距上次 ≥ `RefireRate` 就播一次，
  服务器全部 Reject。这是"不让复制状态破坏首次表现"的直接代价，本轮接受。
  若要改为静默，需要本地"换弹事务"状态（由弹药增加 / Tag 消失 / 超时退出），
  属于新设计，本轮不做。
- 空枪连点同样会播放开火 cosmetic（同上，服务器 Reject）。
- 客户端资格要求武器有效且未隐藏：换枪复制窗口内可能本地丢掉一次输入。
- 本地节拍与服务器门控在连点边界上仍有 0~2 次相位差。
- 远端客户端上"Server 接受的射击被本地节拍误挡"这一类残余只在
  `Feedback >= Authority` 下界内被约束，未做逐发对齐。
- 既有不稳定阶段 `Remote invariant invalid` 与 `Timed out waiting for network state`
  仍未修复，会以一定概率让完整网络回归出现红点。
- 契约文档 `Docs/架构/网络射击AI自主验证契约.md` 的 Invariant 2 仍写着
  "确认回退只补播一次"，与当前语义冲突，尚未同步。
- 全自动支仍保留 5ms 节拍容差（其节拍由 Timer 驱动，需要吸收浮点边界）。
