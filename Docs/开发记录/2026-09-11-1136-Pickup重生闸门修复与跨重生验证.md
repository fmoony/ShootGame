# Pickup 重生闸门修复与跨重生验证

- 日期：2026-09-11
- 计划提交说明：`修复：Pickup 重生后恢复授予闸门并补充跨重生自动化验证`
- 变更类型：生产代码 / 测试

## 目的

Pickup 被拾取后隐藏并关闭 `bPickupAvailable` 授予闸门，但 `RespawnPickup()` 重生时只恢复了可见性，没有恢复闸门标志。结果是每个 Pickup 在第一次拾取后永久失效，重生后任何玩家都无法再次拾取。本提交修复该缺陷，并作为《武器与 Inventory 正式架构实施计划》第 5 节的前置验证：开始大阶段 A 之前，必须证明 Pickup 重生逻辑门在跨玩家重生场景下正确工作。

## 本提交完成内容

- `AShooterPickup::RespawnPickup()` 在恢复可见性前先恢复 `bPickupAvailable = true`（用户完成的生产修复，本提交原样纳入，未改动其逻辑）。
- `ShooterInventoryComponent.cpp` 的既有格式整理（多行调用合并），无逻辑变化。
- 测试类型 `AShooterWeaponPresentationTestPickup` 新增 `TriggerRespawnForTest()`（直接驱动重生回调，等价于 RespawnTimer 到期）与 `IsPickupAvailableForTest()`（读取服务器授予闸门）。
- 新增自动化测试 `Tests/Pickup/ShooterPickupRespawnGateAutomationTests.cpp`：
  - `ShootGame.Pickup.RespawnGate.CrossRespawnGrant`：玩家 A 拾取成功并立即装备 → Pickup 隐藏、闸门关闭、碰撞关闭 → 隐藏期间 A/B 连续 Overlap 不重复授予 → 重生恢复闸门与可见性 → 玩家 B 再次拾取成功 → A、B 持有独立 WeaponInstance → 第二次拾取后 Pickup 重新进入隐藏状态。
  - `ShootGame.Pickup.RespawnGate.SlotFullKeepsAvailable`：满背包玩家拾取被 SlotFull 拒绝后 Pickup 不隐藏、闸门保持开启，空背包玩家可立即成功拾取同一 Pickup。

## 遇到的问题

- 首次通过 bash 调用 `RunNetworkSession.ps1` 时 PowerShell 数组实参 `@("-ShootGameNetworkTest")` 触发 bash 语法错误（exit code 2，未启动任何进程）。
- 第二次调用遗漏 `-MapPath`，服务器回落到默认 `/Game/FirstPerson/Lvl_FirstPerson` 加载失败提前退出（exit code 0 早退被脚本判定失败）；补上 `/Game/Shooter/Maps/Lvl_Shooter` 后正常。

## 处理方式

- bash 中改为整条命令经 `powershell -Command` 执行，数组参数以单字符串传入（PowerShell 自动绑定到 `string[]`）。
- 网络会话统一显式传入 `-MapPath /Game/Shooter/Maps/Lvl_Shooter`，与 `RunAll.ps1` 的 DedicatedNetwork 阶段参数保持一致。

## 遗留项

- 跨重生验证中的"重生"由直接调用 `RespawnPickup()` 模拟，未驱动真实 RespawnTimer 到期帧；定时器到 RespawnPickup 的接线是引擎标准路径，未单独构造 ticking world。
- 两名真人客户端在地图上争抢同一 Pickup 的端到端表现（隐藏状态复制到客户端观察）仍属操作手册声明未自动化范围；本验证覆盖服务器权威授予端逻辑。
