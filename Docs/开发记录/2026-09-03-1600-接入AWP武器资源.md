## 目的

将外部 AWP 资源接入现有 Weapon、Pickup、Inventory 与第三人称瞄准表现链路，完成网格、骨架、枪口、材质和测试关卡配置，并保证服务器权威弹丸从可靠的世界表现枪口生成。

## 本提交完成内容

- 导入 AWP 的 StaticMesh、SkeletalMesh、独立 Skeleton、纹理与原始材质，并新增完成调色后的枪身、玻璃、金属和零件材质。
- 新增 `BP_ShooterWeapon_AWP`、`BP_ShooterProjectile_Bullet_AWP` 与 AWP Pickup，更新 `DT_WeaponData` 和 `Lvl_Test`，使 AWP 能通过现有拾取、Inventory 与 Equipment 链路进入游戏。
- 将通用及各武器 Pickup 资产整理到 `/Game/Shooter/Blueprints/Pickups`，保留迁移生成的引用重定向资产。
- 校准 AWP 的尺寸、骨架与 Socket。项目所有武器 Mesh 的几何朝向保持本地 `+Y`；`Muzzle` Socket 的局部 `+X` 单独作为 Aim IK 与枪口 Forward，不把两种约定混为一谈。
- 调整 AWP 的 `Muzzle` 朝向和左手握持配置，消除启用 Aim IK / LeftHand IK 后的手臂扭结与枪支侧偏。
- 将 `FAnimNode_ShooterAimIK::MaxCorrectionAngle` 默认值设为 `0`，表示不对完整瞄准校正角做额外限制。
- `AShooterWeapon::CalculateProjectileSpawnTransform` 优先采用第三人称 `Muzzle` 的世界位置作为服务器权威弹丸生成基点；旧资产缺少该 Socket 时保留第一人称枪口回退。
- 扩展武器配置自动化断言，要求第一、第三人称武器 Mesh 均配置有效的枪口 Socket。
- 纳入当前已保存的 `ABP_TP_Pistol`、编辑器预览配置和测试地图资产改动，以及后续 Agent 执行计划时使用的 `Docs/ds prompt.txt` 提示词。

## 遇到的问题

- AWP 初始导入尺寸过大，骨架和 Socket 参考方向与现有武器表现契约不一致。
- 新骨架使 `Muzzle` 与左手握把 Socket 变为有效后，Aim IK 和 LeftHand IK 开始消费其完整 Transform；错误的枪口朝向导致手臂扭结和枪支向右侧偏转。
- 外部原始材质的颜色、金属感与现有 Shooter 武器风格不一致。
- 项目武器 Mesh 实际以本地 `+Y` 为几何前向，而 Aim IK 数学约定 `Muzzle` Socket 的局部 `+X` 为枪口 Forward，排查时曾需要明确区分两套坐标约定。

## 处理方式

- 在 SkeletalMesh 与 Skeleton 资产中校准 AWP 尺寸、参考骨架和 Socket，不在 AnimBP 中堆叠 90 度补偿。
- 保持武器 Mesh 的项目既有 `+Y` 几何朝向，只旋转 `Muzzle` Socket，使其局部 `+X` 沿枪管向外。
- 调整握把 Socket 的位置和旋转，使程序化左手 IK 消费有效的完整握持参考帧。
- 基于 AWP 原有纹理完成独立材质调色，并通过测试关卡与现有武器并排进行视觉确认。
- 通过武器配置自动化测试固定第一、第三人称枪口 Socket 的最低资产契约。

## 遗留项

- 当前 AWP 复用现有 Rifle 角色动画表现；尚未建立 AWP 专属拉栓、换弹或弹匣动画。
- 本提交未改变服务器权威开火、伤害与弹药事务边界；后续若加入狙击镜开镜或独立弹道参数，应单独形成可验证闭环。
