# 自动化提交记录规范

- 日期：2026-08-13
- 计划提交说明：`文档：增加提交前开发记录门禁`
- 变更类型：文档

## 目的

为后续自动化开发增加提交级可追溯要求：每次提交前先记录该提交做了什么、怎样验证、遇到了什么问题以及还有哪些边界。已有提交保持不变，本规则只约束新提交。

## 本提交完成内容

- 在根目录 `AGENTS.md` 增加提交前开发记录的强制协作约定。
- 在 `Docs/代码规范.md` 增加提交前记录与暂存检查要求。
- 在 `Docs/Agent自动化验证操作手册.md` 增加开发记录门禁、阻止提交的条件和执行顺序。
- 新建 `Docs/开发记录/README.md`，定义一提交一记录的结构、必填模板和检查命令。
- 新建本记录，使规则引入提交本身从一开始就遵循新规范。

## 验证结果

- 读取并核对根导航、代码规范和 Agent SOP 的现有内容后再修改。
- 使用 `git diff --check` 检查 Markdown 格式问题。
- 使用显式文件列表暂存，仅包含本次五个文档文件；不包含工作区内已有的蓝图、C++、插件和外部 Actor 改动。
- 本次仅修改 Markdown 文档，未运行 Unreal 编译和网络矩阵。

## 遇到的问题

- 工作区已经存在多项与本任务无关的未提交蓝图、C++、插件和 External Actor 改动，存在误暂存风险。
- 提交记录必须在提交哈希产生前完成，因此不能把“提交哈希”设计为提交前必填字段。

## 处理方式

- 暂存时显式列出本次文档文件，并在提交前使用 `git status --short` 与 `git diff --cached --name-only` 复核范围。
- 使用“计划提交说明”关联记录与提交；不通过 amend 或后续补丁回填哈希。

## 遗留项

- 当前门禁由 Agent 流程和文档约束执行，尚未增加 Git hook 或 CI 的机器强制检查。
- 已有历史提交按用户要求不补写记录、不 amend、不 rebase。
