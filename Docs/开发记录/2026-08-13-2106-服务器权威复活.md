# 服务器权威复活

- 日期：2026-08-13
- 计划提交说明：`修复：由服务器 GameMode 统一复活玩家`
- 变更类型：生产代码 / 测试 / 文档

## 目的

修复远端玩家死亡后只保留最后视角、没有实体且无法操作的问题。原实现由 `ShooterPlayerController` 的本地 Pawn 销毁回调手动生成角色，服务器上的远端 Controller 不会绑定该回调，因此无法完成权威生成和重新占有。

## 本提交完成内容

- 在 `AShooterGameMode` 增加 `RestartPlayerAfterDeath`，由服务器解除旧 Pawn 占有、销毁死亡 Pawn，并通过 `RestartPlayer` 使用 GameMode 的 `DefaultPawnClass` 重新生成角色。
- `AShooterCharacter::OnRespawn` 在死亡计时结束后请求权威 GameMode 执行复活。
- 删除 `AShooterPlayerController` 中手动查找出生点、`SpawnActor` 和 `Possess` 的复活逻辑；Pawn 销毁回调只保留本地 HUD 清理职责。
- 删除不再需要的 PlayerController `CharacterClass` 复活配置，避免它与 GameMode 的 `DefaultPawnClass` 形成两个角色类型来源。
- 扩展 `ShooterNetworkTestCoordinator`：只有客户端确认新 Pawn 存活、由本地 Controller 占有且移动模式不是 `MOVE_None`，服务器也确认 Pawn 已更换并重新占有后，才输出成功标记。
- 成功日志增加 `Respawn=true` 和 `RespawnHP`，并保留开火后的实际弹量作为证据。
- 更新自动化操作手册和测试文档中的网络流程及成功标记格式。

## 遇到的问题

- 首次增加可操作性断言时使用了 UE 5.6 不存在的 `UCharacterMovementComponent::IsMovementEnabled()`，导致 C2039 编译错误。
- 第一次监听测试把两个 `ServerExtraArgs` 合并成一个参数，测试协调器没有识别 `-ShootGameNetworkTest`，因此没有成功标记；直接调用脚本又受到本机 PowerShell 执行策略限制。
- 正确启动的一次监听测试被既有随机弹道断言 `Projectile aim differs from server control rotation; dot=-0.270` 提前判定失败，尚未进入复活验收。
- 工作树中存在用户已有的地图、蓝图、武器、插件和外部 Actor 改动。

## 处理方式

- 将移动能力断言改为 UE 5.6 可用的 `MovementMode != MOVE_None`，随后重新编译通过。
- 使用带 `ExecutionPolicy Bypass` 的 PowerShell 子进程，并在子进程内部构造字符串数组，确保监听测试参数被独立传入。
- 不扩大本提交范围修改随机弹道逻辑；使用相同监听配置重跑，复活完整流程通过，并将该波动保留为遗留风险。
- 暂存时显式列出本提交的源码、测试、文档和本记录，不暂存用户已有的无关改动。

## 遗留项

- 自动化已确认新 Pawn 的本地占有、生命值和移动模式，但带渲染 PIE 中的键盘移动手感仍建议由用户做一次人工复验。
- 监听模式的既有随机弹道方向断言存在偶发波动，本提交未修改该无关逻辑。
