# Inventory 与死亡清理接入对象池（B3）

- 日期：2026-09-11
- 计划提交说明：`池：Inventory 授予、移除与死亡清理接入对象池`
- 变更类型：生产代码 / 测试

## 目的

执行
[武器与 Inventory 正式架构实施计划](../已完成计划/武器与Inventory正式架构实施计划.md)
大阶段 B3：
把玩家武器世界实体的创建与回收从「直接 SpawnActor / Destroy」切换为「对象池 Acquire / Release」。

本提交建立在单表武器配置纠偏（`DT_WeaponData` + `WeaponRowName`）与 B1 通用池、B2 生命周期状态机之上，
不恢复任何 Definition / PrimaryAsset 配置层，也不改 `InstanceId` 语义：

```text
Inventory.TryAddWeaponRow(WeaponRowName)
→ 写入 WeaponInstance（InstanceId / WeaponRowName / Ammo / Slot）
→ Pool.Acquire(Row.WeaponActorClass)（池命中复用，未命中生成）
→ WeaponActor.SetInstanceBinding(InstanceId, WeaponRowName)

Inventory.RemoveWeaponInstance / ClearInventory
→ 冻结待归还 Actor → 清 Entries 并广播 → Equipment 清空 Active/Current → Pool.Release(WeaponActor)
```

## 遇到的问题

1. **`ShootGame.Pool.WeaponRelease.*` 首轮失败，且失败原因不是池逻辑**：`Character->Destroy()` 与
   `OwnerActor->Destroy()` 之后，`Character::EndPlay` 与 `AShooterWeapon::OnOwnerDestroyed` 都没有执行。
   通过测试侧与生产侧双向临时日志（`EndPlay` / `OnOwnerDestroyed` 入口 ACI 日志）确认为：
   在 `UWorld::CreateWorld` 构造、没有 GameMode 的 Editor 自动化测试世界中，Actor 销毁通知不会投递
   （`HasActorBegunPlay()==1`、`HasAuthority()==1`、`OnDestroyed.IsBound()==1`，但 `EndPlay` 与
   `OnDestroyed` 回调都不到达），而 `IsValid(Actor)` 仍会因 PendingKill 变 false。
2. 运行 `ShootGame` 全量过滤时 `UnrealEditor-Cmd` 以 exit code 3 崩溃，调用栈落在
   `ShootGame.Tools.WeaponConfig.ClearBlueprintDefaults` → `UPackage::SavePackage` → `FinalizeFile`。
3. 一次临时诊断编辑让 `ShooterCharacter.cpp` 丢失 UTF-8 BOM，产生与本次改动无关的 diff。
4. 两次 `apply_patch` 写入报 `ReplaceFileW EIO (Win32 1175)`（文件被外部句柄短暂占用），写入未生效。

## 处理方式

1. 不再让 Editor 自动化测试依赖引擎销毁通知投递：
   - 死亡 / 断线清理改为直接驱动 `Inventory->ClearInventory()`（`Character::Die` 与 `Character::EndPlay`
     共用的清理入口），并在测试注释中写明通知投递由网络阶段覆盖；
   - 拥有者销毁边界改为经测试壳 `SimulateOwnerDestroyedForTest()` 驱动，只验证「通知到达后的归还边界」。
   通知投递本身已由本提交的 Dedicated Server + 2 Clients 场景覆盖（归还池日志齐全）。
2. 崩溃根因是**当前有 Unreal Editor 实例在运行并占用武器蓝图资产**（`SavePackage` 断言），
   该一次性工具每次运行都会重写并保存 `BP_ShooterWeapon_*`；核对 `git status Content` 与资产时间戳
   （仍是 16:43:18）确认**没有资产被改写或损坏**。B4 将按纠偏记录「下一次武器表结构变更前应删除」
   的约定处理这三个一次性工具，完整回归前需要用户关闭编辑器。
3. 恢复 BOM 并确认 `git diff` 对该文件为空。
4. 重试写入成功；确认最终文件内容完整后继续。
