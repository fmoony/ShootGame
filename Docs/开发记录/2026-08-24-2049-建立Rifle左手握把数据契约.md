- 日期：2026-08-24

- 变更类型：生产代码 / 测试 / 文档

## 目的

按《Rifle 左手 IK 与瞄准同步提速实施计划》完成 L0 只读审计和 L1 C++ 数据契约：先确认第三人称 AnimBP 的实际节点顺序、旧左臂求解路径和 Blueprint CDO 参数，再在武器与 AnimInstance 中建立左手握把 Socket 只读接口、`LeftHandGripInRightHandSpace` 缓存与 `bLeftHandIKEnabled` 开关。本提交只解决数据契约闭环，不修改任何 `.uasset`，也不声称左手已在 AnimBP 中生效。

## 本提交完成内容

- L0 只读审计：
  - `ABP_TP_Rifle` AnimGraph 实际链路为 `LocomotioStateMachine → Layered blend per bone → Local To Component → Shooter Aim IK → Component To Local → Output Pose`；左手 Two Bone IK 的最终插入点应在 `Shooter Aim IK` 与 `Component To Local` 之间。
  - 旧 `Control Rig` 节点（`Ctrl_TP_Aim_Rifle`）的 `Source` 与 `Pose` 均未连线，`LeftHandWeight=0.0`、`RightHandWeight=0.0`，当前输出链中不存在重复左臂求解路径。
  - `BP_ShooterCharacter` CDO 实际参数与 C++ 默认值一致：`PresentationAimSampleInterval=0.1s`、`PresentationAimSmoothingRate=8/s`、`PresentationAimMinChangeAngle=3°`、`PresentationAimMinChangeDistance=50cm`；`NetUpdateFrequency=100Hz`。
  - Rifle 第三人称 Skeleton `SK_Rifle` 现有 Socket 为 `GripPoint`、`Muzzle`、`GripPoint_002`，尚无 `LeftHandGrip`；Rifle 第一/第三人称 Mesh 均为 `SKM_Rifle`，`MuzzleSocketName=Muzzle` 从 `BP_ShooterWeaponBase` 继承。
  - 第一人称 `Ctrl_HandAdjusment` 的左臂 Basic IK 链为 `upperarm_l → lowerarm_l → hand_l`，Effector 来自全局空间 `Ctrl_Hand_L` 的位置与旋转，Pole Vector 为 root 空间 `(0,0,100)`、`bEnableStretch=False`，作为 L3 Joint Target 的预览参考。
- 在 `AShooterWeapon` 增加 `ThirdPersonLeftHandGripSocketName` 配置及 `GetThirdPersonLeftHandGripSocketName`、`HasThirdPersonLeftHandGripSocket`、`GetThirdPersonLeftHandGripWorldTransform` 只读接口；无配置或 Socket 缺失时返回 Identity，不回退 Actor 变换。
- 在 `UShooterThirdPersonAnimInstance` 增加 `LeftHandGripInRightHandSpace` 与 `bLeftHandIKEnabled` 数据出口。
- 左手握把缓存只在缓存未建立、武器变化、同一武器第三人称 Mesh 附着状态变化或缓存无效时重建；已确认缺失 Socket 的稳定 Identity 状态不逐帧重建。
- 增加 `ComputeLeftHandGripInRightHandSpace`、`IsLeftHandIKEnabledForState`、`ShouldRefreshLeftHandGripCache` 纯计算入口。
- 新增 `Source/ShootGame/Tests/ShooterLeftHandIKAutomationTests.cpp`，覆盖握把相对 Transform 计算、左手 IK 状态矩阵和缓存重建判定。
- 创建本开发记录；本提交不包含 `.uasset`，因此运行时 Rifle 左手 IK 仍保持关闭。

## 遇到的问题

- L0 首次使用 `UnrealEditor-Cmd.exe -ExecCmds` 做 CDO dump 时，用分号分隔多个命令。引擎的 `ParseExecCmds` 实际按逗号拆分命令，导致整串内容被当成一个 `obj dump` 对象名，查询无结果且 `Quit` 未执行。

## 处理方式

- 将 `-ExecCmds` 中的命令分隔符改为逗号后重新执行 CDO、Skeleton 与 Socket 只读 dump，得到完整审计数据；清理了首次遗留的临时 `UnrealEditor-Cmd` 进程，未影响用户已打开的 UnrealEditor 会话。
