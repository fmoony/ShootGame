# B-light 最终结清与生命周期收敛

- 日期：2026-10-05；基线：`023d76d`；引擎：本机 UE 5.6.1。
- 计划提交说明：`修复：保证开火最终结清并隔离旧武器确认表现`。
- 变更类型：生产代码 / 测试 / 文档；无资产改动。
- 当前为待提交记录，不改写已有提交或历史开发记录。

## 目的

四槽属性结果可能覆盖尚未观察的最终裁决，造成 Pending 长期残留。
同一个武器 Actor 回池复用后，旧账本可能减少新预算；迟到确认还可能在旧武器上播放。
本轮收敛这些路径，并把批量补播改为按武器间隔播放。
预测仍受现有弹药规则约束，不进入 HUD、Reload 相位补偿或空弹预测。

## 本提交完成内容

- `ShooterWeapon` 保留四槽属性进度，每 Activation 结清另发一次可靠 Client RPC。
  Host / Standalone 保留本地直发，不依赖自己的属性复制回流。
  槽位覆盖不再以缓存值伪造旧轮 Settled。
- `GA_Fire` 保留有效未结清账本，等待最终结果或明确 Reject。
  删除按任意容器顺序淘汰账本并提前清 Pending 的容量路径。
- 账本校验来源武器及本地上下文代次；Owner 清理主动作废旧账本。
  相同 Actor 的新租用不会被旧退款减少 Pending。
- 切枪、取消、回池清理确认队列；每次播放校验当前装备、Owner 与隐藏状态。
  旧目标失效时抑制表现，但当前有效账本仍按裁决结算预算。
- 确认缺发逐发入队，共享武器反馈间隔，避免同帧叠加声音与后坐力。
  已覆盖序号仍跳过本地重播；队列未播放完时暂缓新增本地预测反馈。
  队列不发射击 RPC，不推进本地 cooldown，不生成 Projectile，不写权威弹药。
- 账本 `BackfilledShots` 表示成功提交的队列发数；实际播放另由反馈计数观测。
  无法提交记录为 `SuppressedShots`；入队后取消以 `FIRE_CONFIRMED_QUEUE_CANCEL` 记录。
- 新增 `LedgerLifetime`、`ConfirmedQueueLifecycle` Automation。
  前者打开八轮真实服务器结果槽，覆盖四槽后停止输入，再逐轮重复结清。
  后者分帧推进世界，验证间隔播放、隐藏拒绝、取消及弹药不变。
- 网络夹具扩展至六场景；增加八次真实输入、最终 RPC 数量及未结清峰值观测。
  ConfirmedBackfill 分别核对 Montage / Muzzle / Sound / Recoil。
  ReloadLifecycle 必须观察真实 Fire 与服务器 refire timer，且权威发数大于零。
  独立观察者及 Listen 主机验证远端武器补播与最终 RPC 计数均为零。
- 夹具等待真实最终状态，再检查收敛断言；不匹配不能再被 DONE 标记掩盖。
  单步骤仍有 30 秒超时，未收到终态会失败。

## 实现依据

官方资料说明可靠 RPC 的有序送达边界与属性复制执行顺序。
本机 UE5.6 `NetDriver.cpp` 核对 `FUNC_NetReliable` 对可靠 bunch 的处理。
本机 GAS 核对 Success / Reject 的 PredictionKey 匹配。
自定义预算仍需项目自行维护，不把 PredictionKey CaughtUp 当作最终裁决。

- [Epic RPC](https://dev.epicgames.com/documentation/en-us/unreal-engine/remote-procedure-calls-in-unreal-engine)
- [Epic 复制顺序](https://dev.epicgames.com/documentation/en-us/unreal-engine/replicated-object-execution-order-in-unreal-engine)

官方网页当前为 UE5.8；签名与实际行为按安装的 UE5.6 核对。
每 Activation 一次最终 RPC 是本项目的缺口修复，并非 Epic 强制架构。
可靠送达的结论限于连接和相关 Actor 通道有效，不承诺断线后的旧结果回放。

## 五不变量评估

- Invariant 1：FAIL（原契约即时性未完成）；本轮修复旧目标与同帧叠加。
  时机：未预测发仍晚于确认；来源：纯表现入口；次数：逐路计数对应权威发数。
  最终 Listen 三发补播 LocalTime=2.061 / 2.263 / 2.466 秒，间隔约 0.202 秒。
  测试：ConfirmedBackfill 网络场景与 ConfirmedQueueLifecycle。
  B-light 仍是确认后补播，原契约要求的确认前即时反馈未完全满足。
  队列存在时会暂缓新增预测反馈；无头计数不能证明主观音画质量。
- Invariant 2：PASS（本轮预算对账与租用隔离范围）。
  服从：当前装备与 Owner 校验；不越权：只写本地预算；收敛：停止输入后八轮全部结清。
  Semi-auto：无新增专用网络场景；既有首枪就绪与冷却拒绝门控随全量 Automation 通过。
  Full-auto：生产 Rifle 持续按住，补播与预测合计三发；换弹取消观察到真实活动计时器。

  新增切枪、回池为单元级证据；死亡及重生不宣称本轮专项网络通过。

  空弹、换弹期间预测仍禁止；不把拥挤当拒绝提前清预算。

## 处理方式

- 删除重复声明；队列测试改为跨引擎帧的 latent world tick。
- 编译结束后重新启动定向会话，严格匹配六场景收敛且零不匹配。
  FailureMarker 同时覆盖 MISMATCH、EVIDENCE_GAP 与 AUTOMATION_TEST_FAILURE。
- 等待账本终态与队列排空，再核对原断言；超时仍失败。
  服务器 timer 在每次服务器步骤更新中直接观察。
- 样本必须含本场景新增 Activation / 最终通知；每次采样 RPC 留存 Fire 活动证据。
  即使多个样本在同帧到达，也不会只剩最后一个非活动样本。
- 夹具增加真实本地 ActorInfo、当前 Avatar 与 Fire 实例就绪门控。
  这只消除在未就绪上下文提交测试输入，不声称修复启动期所有输入丢失。
- 日志按秒命名的脚本不宜同秒并行启动；后续错开调用保证唯一目录。
- 全量报告的 warning 项是成功带警告，不合并称为无警告通过。

- 未结清账本不设任意容量淘汰；连接长期阻塞时可持续增长。
  本轮未增加超时重同步协议，不能宣称内存严格有界。
- 网络重生、同 Actor 快速回池再租用与切枪完整矩阵仍未覆盖。
  这些边界当前证据主要来自生产路径单元测试。
- 长时间 FullAuto、频繁切枪及低帧率下队列的主观表现需人工验收。
- 断线、相关 Actor 通道失效后不保证旧确认补播回放。
  世界销毁或 Owner 清理作废账本，不伪造权威最终射击结果。
- 本轮无待用户裁决的新增设计取舍；后续即时性、HUD 与相位补偿需独立闭环。
- Listen Host / Standalone 自身射击的本地直发，仅有既有回归与单元证据。
  本轮观察者检查不等价于该路径的专项网络验收。
