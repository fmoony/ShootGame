# WeaponActor 生命周期状态机与池化清理

- 日期：2026-09-11
- 计划提交说明：`武器：WeaponActor 接入生命周期状态机与池化清理`
- 变更类型：生产代码 / 测试

## 目的

实施《武器与 Inventory 正式架构实施计划》大阶段 B2：把 `AShooterWeapon` 的 `ActivateWeapon / DeactivateWeapon` 收敛为明确的 `InPool / Holstered / Equipping / Equipped` 状态转换，并让 WeaponActor 实现 B1 的 `IShooterPoolableActor` 契约，保证「每次 Acquire 重新绑定、每次 Release 完整清理」。本子阶段仍不改变 Inventory 的创建与销毁路径（B3 负责）。

## 本提交完成内容

- `Weapons/ShooterWeapon.h/.cpp`：
  - 新增 `EShooterWeaponLifecycleState`（`InPool / Holstered / Equipping / Equipped`）与只读观测口 `GetLifecycleState()`；状态不复制，服务器权威、客户端镜像。
  - `SetBoundInstanceId`：由内联赋值改为状态转换入口，有效绑定进入 `Holstered`、解绑回到 `InPool`。
  - 新增 `BeginEquipTransaction()`：`Holstered -> Equipping`；同事务重复提交幂等；`Equipment` 在原子提交入口调用它。
  - `ActivateWeapon()`：`Holstered/Equipping -> Equipped`；重复激活幂等。
  - `DeactivateWeapon()`：`Equipped/Equipping -> Holstered`；重复卸下幂等。
  - 实现 `IShooterPoolableActor`：
    - `OnAcquiredFromPool` 清零 `TimeOfLastShot / bIsFiring`，并重新执行 `InitializeWeaponOwner()` 绑定新 Owner 与销毁委托；
    - `OnReleasedToPool` 幂等清理：停开火、清 RefireTimer、解除 Owner 销毁委托、清 `WeaponOwner / PawnOwner` 缓存、清 `BoundInstanceId` 与 `CurrentBullets` 镜像、清空 `OnOutOfAmmo` 委托，回到 `InPool`。
  - **客户端不参与状态拒绝**：`BoundInstanceId` 是 `COND_OwnerOnly`，远端客户端读不到；若在那里拒绝 `ActivateWeapon`，远端第三人称武器会在 `EnsureWeaponPresentation` 的分支里永久丢失 AnimClass 与激活表现。因此三处拒绝（改写绑定、InPool 激活、重复卸下）都只由 `HasAuthority()` 一端执行，客户端只镜像状态、保持池化前的本地隐藏时机。
  - 可见性不属于状态机契约：隐藏由池归还清理、Inventory 授予后隐藏、表现收敛激活时解除，状态本身只表达身份与装备语义。
- `Characters/Equipment/ShooterEquipmentComponent.cpp`：`EquipWeapon` 在真实转移当前武器时调用 `TargetWeapon->BeginEquipTransaction()`，同一武器重复提交不重复进入事务；`ActiveWeaponInstanceId / CurrentWeaponActor` 的原子提交语义保持不变。
- 新增测试 `Tests/Weapon/ShooterWeaponLifecycleAutomationTests.cpp`（`ShootGame.Weapon.Lifecycle.*`）：
  - `Transitions`：初始 `InPool` 且无绑定/无 Owner；`InPool` 激活被拒绝；绑定→`Holstered`；事务→`Equipping`；激活→`Equipped`；`Equipping/Equipped` 下改写绑定被拒绝；重复激活与重复卸下幂等；解绑回到 `InPool`。
  - `PoolReleaseClearsState`：绑定并布置 RefireTimer 后归还，断言状态回到 `InPool`、绑定清空、池内计数与 `IsManaged` 正确、Timer 已停；再次 Acquire 得到同一实例且不继承旧绑定，并重新绑定到新 Owner（`GetOwner` 与新 Owner 缓存都成立）。
  - `SwitchKeepsHolstered`：Inventory 内两把武器切枪只发生 `Equipped <-> Holstered`，被切下的武器仍绑定且仍注册在 Inventory，池内计数为 0。
- `Tests/Equipment/ShooterWeaponPresentationTestTypes.h`：新增 `AShooterWeaponLifecycleTestWeapon`，暴露 RefireTimer 与 `WeaponOwner` 缓存供池化断言。

## 遇到的问题

1. `Lifecycle.Transitions` 首轮失败：`InPool weapon stays hidden` 断言不成立。测试对「未经过池、直接 Spawn 的武器」断言了隐藏，但可见性从来不由状态机保证（武器 Actor 默认可见，池归还与 Inventory 授予各自负责隐藏）。
2. 首版拒绝判定对所有端生效，存在真实回归风险：远端客户端拿不到 `BoundInstanceId`，状态会停在 `InPool`；`AShooterCharacter::EnsureWeaponPresentation` 在武器仍隐藏时会调用 `ActivateWeapon`，一旦在客户端拒绝，远端第三人称武器将无法补齐 AnimClass 与激活表现，且不会再有重试入口。`DeactivateWeapon` 的提前返回同理会让远端切枪后旧武器短暂残留。
3. 首版 `OnAcquiredFromPool` 只复位开火节拍，没有重新绑定 Owner：池归还清空了 `WeaponOwner / PawnOwner`，复用后武器会保留空 `WeaponOwner`，HUD 与表现回调静默丢失。

## 处理方式

- 问题 1：把该断言替换为 `InPool` 的身份前置条件（无 Instance 绑定、无 Owner），并在测试注释与枚举注释中写明「可见性不属于状态机契约」；隐藏相关断言保留在 `PoolReleaseClearsState`（池归还后确实隐藏）。
- 问题 2：三处状态拒绝全部加 `HasAuthority()` 前置条件，客户端只镜像状态、不拒绝；枚举与 `ShooterWeapon.h` 注释写明该权威边界。
- 问题 3：`OnAcquiredFromPool` 在池写入新 Owner 之后调用 `InitializeWeaponOwner()`，重新建立 Owner/Instigator 缓存与销毁委托；测试新增「复用后重新绑定新 Owner」断言。

## 遗留项

- WeaponActor 仍由 Inventory 直接 `SpawnActor` / `Destroy()` 创建与销毁，池仍无生产消费者；B3 切换为 Acquire / Release。
- `Equipping` 在 Equipment 原子提交内是瞬态状态，尚未接入 `GA_Equip` 时序；按计划属于后续扩展点。
- `ActivateWeapon` 的 `InPool` 拒绝在权威端会覆盖「直接 Spawn 且未绑定」的旧调用者；当前生产路径只有 NPC 直接 Spawn 武器，NPC 不调用 `ActivateWeapon`，因此暂未受影响，B4 需随 NPC 兼容边界一并审计。
