# 建立玩家与 NPC ASC 生命周期

- 日期：2026-08-17
- 计划提交说明：`GAS：建立玩家与 NPC ASC 生命周期`
- 变更类型：生产代码 / 测试

## 目的

执行 GAS 第一阶段执行计划子阶段 1B：建立 GAS 身份与生命周期，但暂不承载真实 Gameplay 数值。重点是理解并机器验证 ASC 的 Owner Actor / Avatar Actor 关系，覆盖 Standalone、Listen 主机、远程客户端、专用服务器、玩家重生与 NPC。

## 本提交完成内容

- `ShooterPlayerState`：实现 `IAbilitySystemInterface`，构造函数创建 `UAbilitySystemComponent` 子对象（`SetIsReplicated(true)` + `Mixed` 复制模式），提供 `InitializeAbilityActorInfo` 幂等入口。玩家 ASC 的唯一宿主，Character 不拥有第二个玩家 ASC。
- `ShooterCharacter`：
  - 新增 `GetAbilitySystemComponent()`（转发到 PlayerState ASC）。
  - `PossessedBy`（服务器/监听主机）与 `OnRep_PlayerState`（客户端）中调用幂等的 `InitializeAbilityActorInfo()`：Owner=PlayerState，Avatar=本角色；重生后的新 Pawn 会再次进入。
  - `EndPlay` 时若仍是 ASC 的 Avatar，调用 `ClearActorInfo()` 解除引用，避免残留旧 Pawn。
- `ShooterNPC`：实现 `IAbilitySystemInterface`，构造函数创建自身 ASC（`Minimal` 复制模式）；`BeginPlay` 中 `InitAbilityActorInfo(this, this)`，不依赖 PlayerController / PlayerState / Local Player，专用服务器独立初始化成功；`EndPlay` 清理。
- 网络测试协调器扩展（只在 `-ShootGameNetworkTest` 下生效）：
  - 服务器侧：玩家 ASC Owner/Avatar/网络连接检查、测试 NPC（`AShooterNetworkTestNPC`，无控制器，验证后立即销毁）的 Owner=Avatar=NPC 检查、重生后 ASC 本体不变 + Avatar 切换到新角色检查。
  - 客户端侧：本地 ASC Owner/Avatar 检查、重生后 Avatar 切换检查，经新 RPC 上报服务器。
  - 成功标记新增 `GasServer/GasNPC/GasRespawn/GasClient/GasClientRespawn` 字段；超时诊断同步扩展。
- 新增 Automation 测试 `ShootGame.GAS.Configuration`（`Tests/ShooterGASAutomationTests.cpp`）：验证 PlayerState/NPC 实现接口、默认 ASC 存在且复制、复制模式分别为 Mixed / Minimal。

## 遇到的问题

1. UE 5.6 中 `UAbilitySystemComponent::ClearAbilityActorInfo` 不存在，首次编译报 C2039。
2. 第一次 Full Regression 的 Listen 阶段失败：监听服务器主机玩家的 `PlayerState::GetNetConnection()` 返回空，导致服务器侧 GAS 检查误报 `ConnectionOk=false`。
3. 第二次 Full Regression 的 Dedicated 阶段超时：会话 25 秒内只有 1/2 成功标记；日志显示地图 NPC 在本次运行中主动射击测试玩家（玩家 256 被命中 16 次、玩家 257 加入 5 秒后即被击杀），打断了协调器流程。

## 处理方式

1. 查询 5.6 引擎头文件确认 API 为 `ClearActorInfo()`，替换两处调用后编译通过。
2. 依据运行时事实修正检查预期：连接要求只对远程客户端成立，监听主机（`IsLocalController()`）豁免。聚焦重跑 Listen 通过，标记 `GasServer=true/true/true`。
3. 判定为旧基线固有不确定性（地图 NPC 会攻击测试玩家，与 1B 改动无关；此前同样的 GAS 检查在 09:29 运行中 13 秒内双双完成）。原样重跑 Full Regression 全绿，作为正式验收记录；该问题计入遗留项。

## 遗留项

- GAS 插件初始化时提示 `GameplayCueNotifyPaths` 未在 `DefaultGame.ini` 配置（回退扫描全 `/Game/`），属性能警告，本阶段未配置 GameplayCue，暂不处理。
- 地图 NPC 会随机攻击网络测试玩家：若玩家在测试流程中途死亡，协调器可能无法在会话窗口内完成。属于旧基线测试不确定性（多人网络改造计划已声明同帧竞态类场景未自动化），保持人工回归边界，不在本阶段处理。
- 远端（模拟代理）角色在本机客户端也会以各自的 PlayerState 建立本地 ActorInfo，这是 PS 宿主 ASC 的标准行为，无副作用。
- `GAS ActorInfo init` / `GAS NPC ActorInfo init` 两条 Display 日志保留为自动化证据，供后续阶段定位生命周期问题。
- 1C 将在此基础上加入 `ShooterAttributeSet` 与初始化 GameplayEffect，本阶段未创建任何属性或效果。
