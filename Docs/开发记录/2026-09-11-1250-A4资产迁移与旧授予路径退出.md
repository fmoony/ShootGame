# A4 资产迁移与旧授予路径退出

- 日期：2026-09-11
- 计划提交说明：`武器：Pickup 与全部授予路径切换 Definition 资产并删除 WeaponClass 适配`
- 变更类型：生产代码 / 测试 / 资产

## 目的

实施《武器与 Inventory 正式架构实施计划》大阶段 A4：为所有当前可达武器创建正式 Definition 资产，Pickup DataTable 迁移到 Definition 软引用，生产与测试的全部授予路径切换到 `TryAddWeaponDefinition`，并删除"由 WeaponClass 名伪造 DefinitionId"的适配入口与旧 CDO 依赖，满足大阶段 A 收口门槛。

## 本提交完成内容

- 资产（经编辑器资产系统由迁移工具创建/更新）：
  - 新增 `WD_Rifle` / `WD_Pistol` / `WD_AWP` / `WD_GrenadeLauncher`（`/Game/Shooter/Weapons/Definitions`）：弹匣/备弹/开火节奏/射击噪声从各武器蓝图 CDO 反射读取一次性迁入；表现配置（动画类、Montage、特效、音效、后坐力、散布、FP/TP 网格、Pickup 预览网格）归档；`FireBehavior` 为 `UShooterProjectileFireBehavior`（弹丸类迁自 CDO）。
  - `DT_WeaponData` 四行迁移为 `WeaponDefinition` 软引用（Rifle/Pistol/AWP/GrenadeLauncher）。
- 生产代码：
  - `AShooterPickup`：授予数据源改为 `TSoftObjectPtr<UShooterWeaponDefinition>`（BeginPlay 从数据表行复制，授予时服务器同步加载）；`FWeaponTableRow` 删除 `WeaponToSpawn` 列与 Pickup 的 `WeaponClass` 成员；Definition 丢失/非法时明确 Reject 不消费 Pickup；
  - `UShooterInventoryComponent`：删除 `TryAddWeapon(WeaponClass)` 适配入口、`ShooterInventory::MakeDefinitionIdForWeaponClass`、`GetInitialReserveAmmoForWeaponClass` 与 `InvalidWeaponClass` 枚举值；`TryAddWeaponDefinition` 成为唯一授予入口；
  - `AShooterWeapon::GetMagazineCapacity()`：换弹容量优先 Definition、兼容路径回落 CDO；Inventory 换弹事务只经该入口取容量。
- 测试迁移：Pickup 重生闸门、Lifecycle、HUD 刷新、表现基线/幂等、逻辑装备事件、架构基线、第一人称捕获、网络协调器（Rifle/Pistol 改用 WD 资产，SlotFull 用内存 Definition）全部切换 Definition 授予；`ShooterWeaponPresentationTestTypes.h` 新增 `MakeShooterTestWeaponDefinition` 内存 Definition 工厂与 `SetWeaponDefinitionForTest`；备弹声明测试重写为 `AmmoConfig` 语义并加载四个生产 Definition 校验；FireBehavior 兼容用例改用不可解析内存 Definition。
- 迁移工具：新增 `ShootGame.Tools.WeaponDefinition.MigrateProductionAssets`（幂等短路：DataTable 已迁移时跳过写盘，避免运行中编辑器的文件句柄导致保存失败）。

## 遇到的问题

- DataTable 与 WD_TestAuto 资产保存持续失败（Win32 错误 32，文件被占用）：定位为用户正在运行的编辑器进程（9:47 启动，`-skipcompile`）持有已加载资产的文件句柄。
- 全量自动化套件曾因迁移工具重复写 DataTable 触发 Critical error（exit code 3）。
- 期间 computer-use 会话因截图取消导致帧绑定损坏，无法用 UI 操作编辑器菜单。

## 处理方式

- 经用户授权后处理编辑器会话：先经 MCP `get_class_defaults` 抽查 8 个武器/Pickup 蓝图（packageDirty 全部 false）并确认关卡"All Saved"，`taskkill`（温和 WM_CLOSE）关闭编辑器，无保存提示、干净退出；文件锁释放后由后台监视循环自动执行 DataTable 迁移成功；随后按用户要求重启编辑器并确认 MCP 桥接恢复（unreal-mcp 0.3.0-editor-tools）。
- 迁移工具加幂等短路（DT 已迁移 / 测试资产已是目标配置时不写盘），重复运行不再触碰被锁定文件；同时 `FSavePackageArgs` 不再传 `GError`。
- computer-use 不可用后改用 MCP 桥接与进程级手段完成检查与关闭。

## 遗留项

- `DT_WeaponData.uasset` 序列化数据中残留旧 `WeaponToSpawn` 字节：加载时按 tagged property 安全丢弃，无行为影响；下次该资产因正常编辑保存时自然清除。
- WeaponActor CDO 的表现配置字段（动画类、Montage、特效、音效、网格模板等）仍被表现堆栈消费，按计划 6.A4"仍有真实调用者则延后"保留，B 阶段与 P1 表现入口收口时迁移。
- NPC 未绑定 Inventory 的旧弹药/弹丸兼容路径保留为明确 PvE 遗留边界，B4 统一审计记录。
- 临时迁移工具（`ShootGame.Tools.WeaponDefinition.*`）将在 B4 删除；Cook 真实打包验证仍不在自动化矩阵内（沿用 A1 记录的证据边界）。
