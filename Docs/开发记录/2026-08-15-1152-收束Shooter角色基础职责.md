# 收束 Shooter 角色基础职责

- 日期：2026-08-15

- 变更类型：生产代码 / 构建 / 文档

## 目的

让 Shooter 成为项目唯一主玩法代码链路。先从仍被玩家和 NPC 共用的 `AShootGameCharacter` 中移除早期网络教学实验，使基础类只负责第一人称组件与基础输入，并删除随之失去用途的旧 GameState。

## 本提交完成内容

- 从 `ShootGameCharacter.h/.cpp` 移除 NetCounter、RPC Matrix、Reliable/Unreliable、所有权实验输入及其复制和日志实现。
- 保留第一人称 Mesh、摄像机、移动、视角和跳跃，使 `AShooterCharacter`、`AShooterNPC` 的现有继承关系不变。
- 删除只服务 MatchCounter 实验的 `ShootGameGameState.h/.cpp`；正式比赛状态继续由 `AShooterGameState` 承担。
- 将 `DefaultGame.ini` 中的项目显示名称从 `First Person Template` 改为 `ShootGame`。
- 修复自动化暴露的武器 Owner 复制初始化竞态：新增幂等 `InitializeWeaponOwner`，由 `BeginPlay` 和 UE 原生 `OnRep_Owner` 共用；Owner 尚未到达时不再解引用空指针。
- 更新项目导航、架构审计、多人网络计划和代码规范，使文档与当前职责一致。
- 将原本使用 GBK 且含乱码注释的 `ShootGameCharacter.h/.cpp` 规范化为 UTF-8；逻辑差异仍仅限本次实验代码清理。

## 遇到的问题

- `ShootGameCharacter.h/.cpp` 原文件混用 GBK 注释字节，补丁工具因非法 UTF-8 拒绝修改。
- 第一次完整验证在 DedicatedNetwork 阶段崩溃：`OnRep_CurrentWeapon` 停用上一把武器时，客户端武器的 `WeaponOwner` 尚未由 `BeginPlay` 初始化。
- 初次空指针保护后，第二次完整验证在 EmulatedNetwork 阶段触发 `SparseDelegate` 断言：延迟丢包条件下武器先执行 `BeginPlay`，但 `GetOwner()` 仍为空。

## 处理方式

- 先按原 GBK 编码读取两个 Character 文件并无 BOM 写回 UTF-8；检查 Git 差异确认编码步骤只恢复了四行乱码中文，再继续应用代码补丁。
- 将 `WeaponOwner` 显式初始化为 `nullptr`，激活和停用通知前检查接口是否可用。
- 没有只用空判断掩盖 Owner 晚到问题，而是新增 `InitializeWeaponOwner` 并从 `BeginPlay`、`OnRep_Owner` 重复安全调用；Owner 到达后会补齐销毁委托、接口、Pawn 和 Mesh 附着。
- 第三次完整验证在普通网络和延迟丢包条件下均通过。

## 遗留项

- `IMC_Default` 和 `BP_FirstPersonCharacter` 仍保存 `IA_NetCounterTest`、`IA_NetCounterLocalTest`、`IA_OwnerShipTest` 引用；需要在编辑器中移除映射和属性引用后再删除三个 Input Action 资产。
- 根目录 `AShootGamePlayerController`、`AShootGameCameraManager`、`AShootGameGameMode` 及其兼容重定向尚未处理。
- `AShootGameCharacter` 是否改为 Shooter 命名或将能力拍平到 `AShooterCharacter`，仍需结合 NPC 和动画蓝图类型引用单独讨论。
