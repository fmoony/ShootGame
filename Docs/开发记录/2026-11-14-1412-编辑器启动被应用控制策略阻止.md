# 编辑器启动被应用控制策略阻止

- 日期：2026-11-14
- 计划提交说明：`文档：记录源码编辑器启动的应用控制阻塞`
- 变更类型：只读诊断 / 文档

## 目的

定位双击 UE58 Worktree 的 ShootGame.uproject 后，输出停在 UBT 启动处的原因。
本轮不迁移、不修改游戏实现、不重编、不改变全机安全策略。

## 本提交完成内容

- 核对引擎注册、文件关联、版本、Build ID、进程与已有日志。
- 读取 Application 与 CodeIntegrity 日志，关联编辑器和 UBT 的阻止事件。
- 保存原始事件、受影响文件签名及哈希，保留当前未提交修改。
- 没有重新触发已确认会被系统阻止的构建或编辑器启动。

## 根因与时间线

本机 Smart App Control 处于启用状态，VerifiedAndReputablePolicyState 为 1。
事件明确指向 VerifiedAndReputableDesktop 策略，而非只根据异常码推测。
策略 GUID 为 `{0283ac0f-fff1-49ae-ada1-8a933130cad6}`。

- 12:37:37：CodeIntegrity 3099 记录该策略刷新并激活。
- 14:10:05、14:10:37：3077 与 3033 记录 UnrealEditor.exe 被阻止。
- 14:11:17～18：同一策略阻止 dotnet.exe 加载 UBT 的 EpicGames.Core.dll。
- 14:11:18：Application 1026 记录未处理的 System.IO.FileLoadException。
- 14:11:18～21：Application Error 与 WER 记录 dotnet.exe 异常退出。

托管异常为应用程序控制策略已阻止文件，HRESULT 为 0x800711C7。
WER 中的 KERNELBASE.dll 与 0xe0434352 是异常呈现，不是已定位的损坏模块。
UBT 的生成成功只表示托管工具编译成功，不代表项目文件生成或编辑器启动成功。
其依赖加载在自身日志初始化前失败，故目标 VersionSelector 日志未生成。

同一策略已直接阻止编辑器 EXE，因此单独执行 EXE 也不能当作已解决的启动方式。
没有证据将本次问题归因于动画资产、项目 C++、引擎关联或 Build ID。
策略激活时间不能证明是哪个用户操作或哪次系统更新导致，不作进一步推断。

## 排除项与范围

- EngineAssociation 的 GUID 注册到现有 UE_5.8_Source，版本为 5.8.4。
- 项目与引擎 Build ID 均为 db931d31-8703-4c38-b2b7-93dc445fd12b。
- UnrealEditor.exe 的 SHA-256 与此前已验收基准完全一致，文件时间仍为 11 月 6 日。
- Editor EXE 与被阻止的 Core DLL 均无 Authenticode 签名，且没有 Zone.Identifier 流。
- 因此没有依据要求重新编译整个引擎、修改引擎关联或对下载文件解锁。
- 用户原有 uproject 行尾与 Fire.cpp 文本修改均保留，不为诊断顺手修改。
- 仅观察到旧 MSBuild 复用节点；没有发现仍在工作的 UBT 主进程或 UE 编辑器。

## 后续处理方案

先在 Windows 安全中心的应用和浏览器控制中核对智能应用控制状态。
这属于全机安全策略，不能作为普通工程配置修复自动修改。
若专用开发机选择调整该功能，应由用户明确决定，再验证编辑器与项目文件生成。
若保持其启用，则需考虑受信任代码签名或适合源码开发的受控环境。

[Microsoft Smart App Control FAQ](https://support.microsoft.com/en-gb/windows/security/threat-malware-protection/smart-app-control-frequently-asked-questions)
说明当前没有针对单个应用的放行方式。
不要将 Defender 扫描排除、PowerShell 执行策略或自签名自动视为 SAC 可信签名。
当前系统能否关闭后重新开启，应以实际 Windows 版本和安全中心提示为准。
不套用旧文档中所有版本都必须重装的结论。

[Microsoft 官方原理](https://learn.microsoft.com/en-us/windows/apps/develop/smart-app-control/overview)
与[事件说明](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/app-control-for-business/operations/event-id-explanations)
用于核对策略名、签名要求与 3077 强制阻止事件。

- 事件 XML 已给出策略名称、GUID 与文件哈希，无需为列表权限改变系统状态。
- 只维护一份工作区进度文档，汇入此记录后删除。
