# 将武器静态Binding改为事件驱动

- 日期：2026-08-29
- 计划提交说明：`动画：将武器静态 Binding 改为事件驱动`
- 变更类型：生产代码 / 测试

## 目的

执行《武器装备表现事件收束与动画切换解耦执行计划》E4：第三人称 AnimInstance 不再每帧扫描 Weapon / Mesh / Owner / AttachParent / AttachSocket / Socket 签名和五状态机，改为订阅 Character 的 `OnWeaponPresentationChanged`，在表现完成事件到达时一次性重建静态 Binding；AnimClass 替换后的新实例主动回放 Equipment 当前状态。

## 本提交完成内容

- `Source/ShootGame/Characters/Animation/ShooterThirdPersonAnimInstance.h/.cpp` 重写：
  - 删除 `EIKBindingState` / `EIKBindingFailureReason`、公共依赖签名结构、五状态机、逐帧签名比较、WaitingForAttach / Pending 计时器和调试状态 UPROPERTY。
  - `NativeInitializeAnimation` 订阅 Character `OnWeaponPresentationChanged`，随后从 `Equipment.CurrentWeaponActor` 主动回放一次。
  - `HandleWeaponPresentationChanged`：非空 Current 缓存弱引用并 `RebuildWeaponStaticBindings`；空 Current 清空全部静态 Binding 与 IK 开关。
  - `RebuildWeaponStaticBindings`：事件时一次性判定 Aim / LeftHand 各自能力；永久缺失 Socket 只关闭对应 IK；Transform 瞬时非法只置一个 `bStaticBindingRebuildPending`。
  - `NativeUpdateAnimation` 保留移动、Aim、Tag 动态采集与 Weapon 身份廉价校验；静态签名逐帧轮询全部移除。
- 重写 `Source/ShootGame/Tests/Animation/ShooterIKBindingTestHarness.h` 与 `ShooterIKBindingAutomationTests.cpp`：
  - 8 个事件驱动验证：空事件清空、Rifle 事件重建、缺失 Muzzle 只关 Aim、Pistol 无握把只关 LeftHand、Pending 单次重试、Detach 不轮询、初始化回放、帧级输入分离。
  - 无 `.uasset` 改动；AnimBP 继续消费同名公开属性 `HandToMuzzle` / `LeftHandGripInRightHandSpace` / `HandGripInLeftHandSpace` / `bAimIKEnabled` / `bLeftHandIKEnabled`。

## 遇到的问题

- 首次重写时 TP AnimInstance 未声明 `NativeInitializeAnimation` / `NativeUninitializeAnimation` override，C++ 实现定义触发 C2509。
- 旧测试壳依赖签名注入；新生产 Rebuild 依赖 AnimInstance 的 Owning Character 缓存，直接 NewObject 的测试壳必须先走 `NativeInitializeAnimation`。

## 处理方式

- 在派生类头文件显式声明两个生命周期 override。
- 测试壳新增 `CallNativeInitializeAnimationForTest`，场景创建时初始化 Owning Character 缓存与事件订阅。

- 真实 PIE / 网络会话中 AnimInstance 重建与旧 Binding 消费由 E5 全回归和人工视觉验收覆盖。
- ABP_TP_Rifle 的 `CalibratedWeaponGripInRightHandSpace` 校准链决策仍独立挂账，不在本计划内。
