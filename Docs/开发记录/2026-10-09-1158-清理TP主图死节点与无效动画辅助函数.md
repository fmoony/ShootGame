## 目的

阶段一已把玩家第三人称固定到 `ABP_TP_Player`，四枪切换不再重建动画实例。
本轮先做引用审计，再只清理“已证实没有任何消费者”的 TP 动画内容，

## 本提交完成内容

### 资产：`ABP_TP_Player` 删除 5 个死节点

删除对象与判定依据：

- AnimGraph 的 `Get CalibratedWeaponGripInRightHandSpace`：
  `get_pin_details` 读回 `links: []`，输出引脚没有任何消费者。
- EventGraph 的 `Set CalibratedWeaponGripInRightHandSpace`、`Compose Transforms`、
  `Make Transform`、`Get HandGripInLeftHandSpace`：
  四者构成一条只服务上述孤立 Getter 的每帧链，
  链路下游在删除前已无任何读取点。
- 该构造在源图 `ABP_TP_Rifle` 中同样是孤立节点，属阶段一复制主图时一并带入的遗留物；
  本轮不动 `ABP_TP_Rifle`，NPC 动画路径保持原样。

删除后读回：AnimGraph 26→25，EventGraph 17→13，其余 22 张图节点数不变。
变量读取点只减少 `Get/Set CalibratedWeaponGripInRightHandSpace` 两项，无新增；
`BeginReloadPresentationRecovery`、`Get Owning Actor`、`Make Rotator`、
`NOT Boolean`、`float <= float` 等活跃调用全部保留。

### C++：删除无效的动画辅助函数

`UShooterThirdPersonAnimInstance::GetHandWorldTransform` 声明与定义一并删除。
审计证据：`UFUNCTION(BlueprintPure)`，C++、测试、`Scripts`、`Plugins`
以及 `Content` 全部 `.uasset` 的字符串扫描均为 0 命中。
该函数是脚本化 socket 计算时代的 BlueprintPure 辅助，
现由 `RebuildWeaponStaticBindings` 在 C++ 内部直接完成。

### 明确保留、本轮不删除的项

- `FShooterWeaponConfigRow::ThirdPersonAnimInstanceClass`、
  `AShooterWeapon::ThirdPersonAnimInstanceClass` 与
  `GetThirdPersonAnimInstanceClass()`：运行时确无消费者，
  但 `DT_WeaponData` 四行仍存有该列取值；删除 C++ 字段必须重存 DataTable，
  否则会留下指向旧 TP 资产的死引用。当前工具链没有 DataTable 编辑或保存能力，
  因此按“不得强行删除”保留，理由记入遗留项。
- `ABP_TP_Rifle`：`BP_ShooterNPC.CharacterMesh0.AnimClass` 实测仍指向
  `ABP_TP_Rifle_C`，且 `AShooterNPC::OnWeaponActivated` 为空实现，
  NPC 不走武器动画类切换，该资产必须保留。
- `ABP_TP_Pistol`、`ABP_TP_AWP`、`ABP_TP_GrenadeLauncher`：仍被
  `DT_WeaponData` 的上述列引用，保留。
- `ABP_TP_Player` 的三个 Blueprint 局部变量
  （`Character`、`MovementComponent`、`CalibratedWeaponGripInRightHandSpace`）
  与 `Sequence`、`Get` 两个节点：变量已是“只写不读”，
  但当前 MCP 没有删除 Blueprint 变量的 action，本轮按用户确认的范围
  只删 5 个节点，不制造“有写无变量”的混合状态。
- `ShooterTPPlayerMigrationCommandlet`：一次性迁移工具，
  已带 `-Apply` 显式门控且会覆写 DataTable 与角色默认值；
  不在本轮“旧动画架构”范围内，保留待用户决定。

## 当前稳定 TP 资源的唯一应用链

```text
FShooterWeaponConfigRow（三个硬资源 + 枪口距离）
→ AShooterWeapon::ApplyWeaponRow 启动快照
→ AShooterCharacter::ApplyWeaponAnimClasses
→ UShooterThirdPersonAnimInstance::ApplyWeaponAnimationResources
→ ThirdPersonHoldSequence / ThirdPersonAimOffset / ThirdPersonReloadSequence
  / MinimumRemoteAimTargetDistanceFromMuzzle
→ ABP_TP_Player 四个资源引脚
```

`ApplyWeaponAnimClasses` 只负责 FP 类应用与 TP 固定类的修复，
TP 资源更新是同一函数的第二个动作；`HasCompleteWeaponPresentation` 用
`PlayerThirdPersonAnimInstanceClass` 与 `HasWeaponAnimationResources` 双重确认，
不再存在第二条按武器选择 TP 类的路径。
