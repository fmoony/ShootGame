## 本提交完成内容

### 测试：断线清理阶段适配本地预测换弹

`GA_Reload` 改为 `LocalPredicted` 后，服务器**不能**再直接为远端 Pawn 激活它：
引擎会把 `TryActivateAbility` 转成 `ClientTryActivateAbility`（返回 true 但服务器本地不激活），
原有「服务器直接激活换弹作为断线前置条件」的做法因此失效。

- 协调器新增 `ClientTriggerDisconnectReload`（Client Reliable）：
  服务器只负责请拥有者客户端按生产输入路径换弹，然后等待权威实例出现（有限重试）。
- 客户端侧新增 `TrySubmitDisconnectReloadInput`：有限窗口内重按。
  依据实测：弱网下本机可能仍持有迟到的 `State.Equipping`
  （GA_Equip 尚未预测，仍是复制标签），该次换弹输入会按设计被本地拒绝或缓冲；
  3 秒窗口内的重按等价于玩家在动作结束后再按一次。
- `Scripts/Tests/RunAbilityCleanup.ps1` 与 `RunAll.ps1` 保持原样：
  断线流程仍由服务器发起，客户端只通过新的 Client RPC 参与，
  因此不需要给客户端追加 `-ShootGameDisconnectTest`；会话时长用
  `RunAll.ps1 -SessionDurationSeconds 60` 显式给出即可。

## 遇到的问题

- 断线清理首轮失败：`Disconnect reload precondition failed; Activated=true Active=false Tag=false`
  —— 服务器直接激活被引擎转成客户端激活，服务器本地没有实例；且客户端首按被迟到的
  `State.Equipping` 拦住后超窗丢弃。
- 曾尝试给客户端追加 `-ShootGameDisconnectTest` 让客户端自己调度断线换弹：脚本加入中文注释后
  在 Windows PowerShell 5.1 下失效（无 BOM 被按 ANSI 解析，续行符被吞），
  且该改法本身也没有解决客户端侧门闩条件不足的问题。

## 处理方式

- 断线清理改为「服务器请求 + 客户端按生产输入路径发起 + 服务器有限等待权威实例」，
  客户端在 3 秒窗口内重按；实测两次子会话均通过，且不需要修改任何测试脚本。
- 放弃脚本改动：`RunAbilityCleanup.ps1` 与 `RunAll.ps1` 与 HEAD 完全一致，
  会话时长通过命令行参数给出。

## 遗留项

- `GA_Equip` 仍为 ServerOnly：`State.Equipping` 仍是复制状态，
  迟到的装备标签可能让一次开火或换弹点击落入缓冲并在超窗后被丢弃（本次已实测到）。
  这属于已登记的预测边界，若要彻底消除需要把装备事务也改为本地预测（不在本轮范围）。
- 拥有者预测换弹被服务器 Reject 时会出现一次不可撤销的本地换弹表现（已接受）。
- 既有不稳定阶段 `Remote invariant invalid` 与 `Timed out waiting for network state` 未修复。
