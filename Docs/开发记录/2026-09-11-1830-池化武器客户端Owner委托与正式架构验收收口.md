# 池化武器客户端 Owner 委托与正式架构验收收口

- 日期：2026-09-11
- 计划提交说明：`修复：收口池化武器客户端Owner委托并完成正式验收`
- 变更类型：生产代码 / 测试 / 文档

## 目的

验收大阶段 B 的池化武器实现，并补齐验收中发现的客户端生命周期缺口：
服务器归还对象池时会解除旧 Owner 的 `OnDestroyed` 委托，但客户端只通过 `OnRep_Owner`
重新绑定新 Owner，旧实现没有在 Owner 从 A 切到空或 B 前解除 A 的委托。
当同一 WeaponActor 已复用给 B 而 A 延迟销毁时，旧委托可能错误触发已复用武器的销毁逻辑。

## 本提交完成内容

- `AShooterWeapon` 新增 `CachedWeaponOwnerActor` 与统一的 `ClearWeaponOwner()`：
  每次 Owner 初始化前先解除旧 Actor 的销毁委托并清空领域缓存，再绑定当前 Owner；
  `OnReleasedToPool` 与 `EndPlay` 复用同一清理入口。
- 新增自动化测试
  `ShootGame.Weapon.Lifecycle.ClientOwnerRebindClearsPreviousDelegate`，模拟客户端依次收到
  `Owner=A → nullptr → B`，随后广播 A 的销毁事件，验证武器仍归 B 且不会进入销毁。
- 更新武器与 Inventory 正式架构计划、Demo 最终路线和 P1 前置状态：
  记录单表 `DT_WeaponData + WeaponRowName` 为当前事实，正式架构验收通过，P1 等待用户批准。
- 未新增、删除、移动或重命名 `Source/`、`Plugins/` 文件，无需刷新 Visual Studio 项目文件；
  未修改任何 `.uasset`。

## 遇到的问题

首次构建失败：测试曾尝试对 `FActorDestroyedSignature` 调用 `IsBoundToObject`，
但该类型是稀疏动态多播委托，不提供此查询接口。

## 处理方式

删除对稀疏委托内部绑定状态的测试侵入，改为行为验证：在武器复用给 B 后广播旧 Owner A 的
`OnDestroyed`，直接断言武器未销毁且 Owner 与缓存仍为 B。修正后构建、定向测试与全量回归均通过。
