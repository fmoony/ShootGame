# 全仓合并冗余折行

- 日期：2026-09-12
- 计划提交说明：`格式：合并 Source 下可并入更少行的冗余折行`
- 变更类型：纯格式整理

## 目的

新规范允许“最后一个参数”越过 120 列，并要求能一行就一行、能两行就两行；
参数列表达到三行及以上时，每个参数单独一行。
反向检查发现历史代码存在大量“每参数一行”式冗余折行，因此按检查结果做一次
只合并、不重排其他内容的纯格式提交。

## 本提交完成内容

- 依据 `CheckTextLayout.ps1` 的反向检测，合并 `Source/` 下 90 个
  h / cpp / cs 文件中可安全并入更少行的折行；
- 共删除 4,832 行、新增 1,831 行，主要为 UE_LOG、函数声明与调用、
  Ability 事务与自动化测试的垂直拆分合并；
- 对需要三行及以上的参数列表恢复“每参数一行”排布，包括
  `CanActivateAbility` / `ActivateAbility` 等 Ability 声明与定义、
  `ShooterNetworkTestCoordinator` 的大型 Printf 与测试断言；
- 合并只发生在同一语句的显式续行（`(`、`,`、运算符、`&&/||`、成员链等）之间；
  注释、预处理、宏与 `UPROPERTY` 声明不参与合并；
- 不改变任何表达式、参数顺序、字符串内容或运行逻辑；
- 不修改 Markdown、PowerShell 和 `Plugins/McpAutomationBridge`。

  80 Passed / 33 Warnings / 0 Failed / 0 NotRun；
- `-Scope All` 全仓统计降至 4,651 处；`Source/` 剩余 7 条冗余换行记录
  均为本次未修改的历史行，不参与提交门禁。

## 遇到的问题

- 首次对插件文件应用合并后，增量门禁因插件历史的 4 空格缩进失败；
- 批量写入曾给文件尾部多补一个空行，被 `git diff --check` 检出；
- 手工恢复 `ShooterNetworkTestCoordinator.cpp` 大型参数列表时误替换了
  相邻 `if` 块，导致一次编译出现括号不匹配。

## 处理方式

- 撤回插件文件合并，保留其历史状态；本提交只清理使用 Tab 缩进的
  `Source/` 代码，插件后续需与缩进改造一起单独处理；
- 对 105 个受影响文件统一移除尾部多余空行后，`git diff --check` 通过；
- 将该文件回退到 HEAD，再按新规则从 HEAD 直接重排一次，
  避免手工替换错误；重排后重新构建与自动化回归均通过。

## 遗留项

- `Plugins/McpAutomationBridge` 仍有 94 处可合并的冗余折行与历史空格缩进，
  需要一次插件专项格式提交；
- 全仓存量仍有超宽、注释超限与缩进问题，按“不追溯”原则逐步收敛。
