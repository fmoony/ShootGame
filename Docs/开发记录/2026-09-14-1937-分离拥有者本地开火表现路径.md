# 分离拥有者本地开火表现路径

- 日期：2026-09-14
- 计划提交说明：`射击：分离拥有者本地开火表现路径并归档P1实施方案文档`
- 变更类型：生产代码 / 测试 / 文档

## 目的

P1-A 的目标是在不改变任何 Gameplay 行为的前提下，
先建立“拥有者本地第一人称开火表现”这条可单测、可观测的路径。

上游计划 P1-B 才会把 GA_Fire 切成 `LocalPredicted`。
本提交只做分离：把纯表现入口从权威开火事务里抽出来，
让 P1-B 能把本地表现挂到预测路径上，而不再依赖服务器往返。

## 本提交完成内容

### 生产代码

- `Weapons/Interfaces/ShooterWeaponHolder.h`
  新增纯虚 `PlayOwnerLocalFiringFeedback(UAnimMontage*, float)`。
  该入口只播第一人称 Montage 与本地 Recoil，绝不触发网络 RPC，
  也不修改任何 Gameplay 状态。

## 遇到的问题

1. 新测试首次编译失败：
   `NewObject<UNiagaraSystem>()` 报 `error C2027: 使用了未定义类型 UNiagaraSystem`。
   `ShooterWeapon.h` 只前向声明了该类型。
2. 首次自动化运行报 `No automation tests matched`，
   而同一提交更早一次运行却正常识别到新测试。
3. 两次新测试均为 Fail：
   - `character is both player controlled and locally controlled` 为 false
   - `owner feedback counter matches the three calls` 期望 3 实际 0
4. `CheckTextLayout.ps1 -Scope Staged` 报 8 处“可合并成更少行”的冗余换行，
   全部位于新增测试文件的断言与参数续行。

## 处理方式

1. 在测试文件补 `#include "NiagaraSystem.h"`。
   Niagara 已是 `ShootGame.Build.cs` 的 PrivateDependency，
   `ShooterWeapon.cpp` 用的是同一 include 形式。
2. 定位为环境问题：用户当时打开着 Unreal Editor（PID 7192），
   它持有 `Binaries/Win64/UnrealEditor-ShootGame.dll`。
   UBT 无法重链主模块，只能产出 Live Coding patch DLL
   （`UnrealEditor-ShootGame-0002/-0003.dll`），
   独立 `UnrealEditor-Cmd` 进程加载到的模块因此不确定。
   经用户授权关闭 Editor（关闭时触发了崩溃上报进程，
   清理后句柄释放），删除残留 patch DLL 并重新完整链接，
   主模块 DLL 时间戳更新后运行稳定。
3. 加临时 `PREDICTION_SETUP` 诊断日志后定位到根因：

```text
Controller=PlayerController_0 NetMode=0 LocalRole=3 IsLocalController=true
Pawn=ShooterWeaponPresentationTestCharacter_0 CharController=PlayerController_0
IsPlayerControlled=false IsLocallyControlled=true WorldNetMode=0
```

   即 `Possess` 已成功、`IsLocallyControlled()` 已为真，
   只有 `IsPlayerControlled()` 为假。
   引擎源码核对（`Pawn.cpp:265-268`）：

```cpp
bool APawn::IsPlayerControlled() const
{
	return GetPlayerState() && !GetPlayerState()->IsABot();
}
```

   UE 5.6 该函数依赖 `PlayerState` 非空。
   最小测试世界没有 GameMode，`AController::InitPlayerState()`
   不会生成 PlayerState，因此恒为假。
   修复：在测试夹具中显式给 PlayerController 补一个 `APlayerState`
   （`AController::PlayerState` 是公开字段，顺序放在 `Possess` 之前）。
   诊断日志与临时 include 已移除。

   生产代码不需要改动：真实游戏里本地玩家的 `AShooterPlayerState` 存在，
   判定为真；NPC 没有 PlayerState，判定为假，正是需要的边界。
4. 按门禁提示把这 8 处换行合并为单行（合并后宽度 106 到 120 列，均在 120 以内），
   随后重新编译并重跑同一过滤器的 18 项测试，结果保持一致。
