# 开发记录：收紧网络射击不变量证据

## 改动类型

生产代码门控修复、网络测试证据收紧、自动化测试修正。

## 背景

网络射击测试此前存在三类不可接受的证据缺口：客户端本地预测没有检查已知弹药、
换弹中开火测试会把无效武器引用当作预测增量 0、远端确认表现允许
“对手没有产生权威射击”时跳过通过。全自动测试还可能在本地节拍尚未形成前
提前松开输入。

## 本次改动

- `GA_Fire` 本地预测表现门控增加 `CanConsumeAmmo()`；服务器拒绝统一记录测试观测计数。
- `AShooterWeapon` 增加按武器的表现通道计数、反馈/确认顺序号和最小反馈间隔观测；
  测试专用时间复位不修改权威 `TimeOfLastShot`。
- `AShooterCharacter` 增加拥有者第一人称 Montage/Recoil 与远端第三人称 Montage 的实际提交计数。
- 网络协调器的单发、全自动、换弹拒绝和远端确认报告均绑定阶段起点
  WeaponActor；引用失效报告为不可测量而不是伪造 0。
- 单发要求 Owner Feedback、Montage、Muzzle、Sound、Recoil、Server Confirmation、
  Authority Shot、Projectile、Ammo 各恰好一次，并验证表现先于确认。
- 全自动要求本地至少两次节拍反馈、最小间隔不低于 `RefireRate`，松开后
  Timer 清理，并要求 Authority Shot / Projectile / Ammo 消耗一一对应。
- 换弹中开火同时覆盖“尚未看到 Tag”和“已看到 `State.Reloading`”两种时序；
  要求服务器发生实际 Reject、无权威结果、无本地残留状态。
- 远端确认要求同一窗口内的权威增量与第三人称 Montage/Muzzle/Sound 增量对应；
  不再以 inconclusive 作为通过条件。既有 Listen/Emulated 脚本显式跳过
  远端窗口时仍保持未要求语义。
- 修正本地表现自动化用例，使独立冷却测试使用不同武器类；声音计数按提交路径
  观测，兼容 `-NoSound` 测试环境。
- 新增 `KnownBlockers` Automation，用生产门控直接验证 Ammo、Reloading、
  Equipping、Dead、隐藏、非当前武器及确认 grace 清除边界。
- 修复半自动立即释放早于服务器确认时的回退缺口：初始表现被本机已知状态挡下后，
  只延后客户端本地 Ability 收口；Confirm 补播一次后结束，Reject 仍由 GAS
  统一清理。
- 删除网络测试对“客户端开火瞬间必须仍看到迟到 Reloading Tag”的竞态要求；
  实际 Tag 状态保留为观测，两个时序分支都必须满足一次反馈、一次确认与最终收敛。
- 修正死亡取消换弹场景的测试竞态：服务器验证部分伤害后立即进入致死取消，
  不再等待客户端伤害复制而错过 Reload 提交窗口；客户端伤害观察仍由最终条件
  独立验证。

## 遗留项

- Listen/Emulated 的远端确认仍由既有脚本按参数跳过；这不是 Remote invariant
  的正向证据，应在最终报告中明确标记为未要求/未执行。
- 自动化只能证明 Montage/Muzzle/Sound/Recoil 的提交顺序与次数，不能代替真人
  对画面、声音与后坐力手感的主观验收。
