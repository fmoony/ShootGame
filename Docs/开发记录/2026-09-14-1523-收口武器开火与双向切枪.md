# 收口武器开火与双向切枪

- 日期：2026-09-14
- 计划提交说明：`玩法：收口武器开火与双向切枪`
- 变更类型：生产代码 / 测试 / 文档 / 资产 / 配置

## 目的

收口当前工作树中已经完成的武器相关改动：取消每次开火携带整行配置快照，
让玩家可以通过鼠标滚轮双向循环切枪，修复 FirstPerson Capture 的打包编译器崩溃，
并保存本轮配套的地图、武器表、HUD 与输入资产。提交时排除本地产物目录。

## 本提交完成内容

- `AShooterWeapon` 删除 `ConfigSnapshot`、`FireBehaviorInstance` 与行为解析入口；
  `ApplyWeaponRow` 在启动绑定时把 `ProjectileClass` 镜像到 WeaponActor，开火直接调用
  `FireProjectile`，不再运行时查表或复制整行配置。
- `FShooterWeaponFireContext` 只保留本次攻击所需的 `ProjectileClass`；现有 FireBehavior
  定义与数据表列标记为休眠，测试保留其独立生成弹丸的定义守卫。
- `IA_SwapWeapon` 改为 Axis1D；`IMC_Weapons` 增加滚轮上、下映射，滚轮上通过
  `InputModifierNegate` 产生负方向，同时保留 Shift 与手柄原有输入。
- `AShooterCharacter` 按输入符号提交 `Input.Equip.Next` 或
  `Input.Equip.Previous`；`AShooterPlayerState` 为同一个 Equip Ability 类幂等授予
  两个带动态输入标签的 Spec。
- `UShooterGameplayAbility_Equip` 从当前 Spec 解析方向；Inventory 新增双向相邻槽位查询，
  支持升序、降序与首尾回绕。ASC 输入匹配改为精确标签，避免父标签误激活方向 Spec。
- 自动化补充输入资产契约、双向槽位和回绕覆盖；网络协调器同步 Equip Spec 数量与新查询接口。
- `ShooterFirstPersonCapture.cpp` 将 `FCaptureState` 移出命令 Lambda，规避 MSVC 在打包目标中
  实例化局部结构与 `MakeShared` 时触发的 C1001 内部编译器错误。
- 保存当前 `UI_ShooterBulletCounter`、`DT_WeaponData`、`IA_SwapWeapon` 与
  `IMC_Weapons` 资产版本；编辑器和游戏默认地图改为 `Lvl_Test`，服务器默认地图保持
  `Lvl_Shooter`。
- 更新 Inventory/武器数据架构说明与 AnimClassMapping 分析文档版式；统一本轮文本 CRLF。
- `.gitignore` 新增仓库根目录 `/Package/`；既有 `/.zcode/` 排除规则保持生效。

## 遇到的问题

- 首次单独调用网络脚本沿用其旧默认地图 `/Game/FirstPerson/Lvl_FirstPerson`，服务器因地图
  不存在而正常退出；改用正式地图后，10 秒窗口不足以产生完整成功标记。
- 编辑器最初占用输入资产，命令行保存 `IA_SwapWeapon` 时遇到 Windows 文件锁。
- 文本门禁发现一个 Markdown 文件为 LF、一个源码声明存在冗余断行，以及 INI 末尾空行。

## 处理方式

- 关闭 Unreal Editor 后重新保存并回读输入资产，确认 Axis1D、滚轮键和 Negate Modifier
  均已落盘。
- 网络验证显式使用 `/Game/Shooter/Maps/Lvl_Shooter`，并按全量脚本的 45 秒基线执行；
  随后的七阶段回归使用 `RunAll.ps1` 当前有效地图配置并全部通过。
- 按项目规范统一 CRLF、移除多余文件尾空行并收敛冗余断行。
