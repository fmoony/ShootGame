## 目的

执行《Shooter 核心玩法架构解耦重构执行计划》R8：删除 Character 上零调用或已失去用途的 Aim / Equipment 兼容入口，把 `IShooterWeaponHolder` 缩到 `AShooterWeapon` 运行时真正回调的最小边界，并按 Input / Lifecycle / GAS Avatar / Mesh Attachment / Health / Death 重新整理 Character 公开接口。同时更新最终路线规划中的所有权描述，并纳入用户在本阶段手工完成的动画资产同步。

## 遇到的问题

- `EquipmentComponent::EquipWeapon` 是普通 C++ 方法而非 UFUNCTION，不能用 `FindFunctionByName` 断言存在；修正为断言 Character 的 `CommitActiveWeapon` 已删除，并保留“装备提交唯一入口在 EquipmentComponent”的注释。
- 网络测试新增的 Aim helper 定义在 `ShooterNetworkTest` 命名空间内、调用点在类成员函数内，首次编译因未限定命名空间失败；已改为 `ShooterNetworkTest::` 限定调用。
- 本阶段运行中发现编辑器已手工保存了三个动画/角色资产；经 MCP 与自动化日志复核为计划内资产同步，纳入同一提交。

## 处理方式

- 只删除 C++ 源码与测试能证明无引用（或仅测试引用）的兼容入口；仍被旧 AnimBP 节点引用的 BP 函数继续保留。
- `IShooterWeaponHolder` 不整体删除：`AShooterWeapon` 仍通过接口回调 Character / NPC 的运行时表现，Fire Ability 仍用其做 NPC 回退。
