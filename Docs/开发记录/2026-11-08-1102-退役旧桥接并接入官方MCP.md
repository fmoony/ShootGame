## 遇到的问题

- 常规构建计划重编 IrisCore、NetCore 并重写引擎模块清单，被保护门禁阻止。
- 首次构建命令的版本参数被 PowerShell 拆分，未进入编译。
- 本机官方初始化响应的 serverInfo 名称与版本为空，和在线文档存在差异。
- find_nodes 的 title 在实际 schema 中必填，不能因 Python 有默认值而省略。
- 工程刷新和打开动画编辑器附带更新了 VS 组件清单与预览配置。

## 处理方式

- 修正命令参数，使用 -UsePrecompiled 和 -NoEngineChanges 复用已有引擎。
- 未放开引擎保护，未修改引擎源码、DLL、PDB 或 Build ID。
- 通过 PID、回环监听和官方 DLL 加载日志确认服务来源，并记录身份字段限制。
- 按实际 schema 补齐空过滤参数，没有过滤错误或修改引擎以迎合探测。
- 已撤销本轮自动生成的 VS 组件与预览配置差异，不覆盖用户修改。

## 遗留项

- Codex 新会话需从受信任的正式 Worktree 加载项目配置，实际发现状态另行确认。
- 严格依赖非空 serverInfo 的客户端兼容性尚未验证。
- Blender 的旧可执行与示例路径仍待独立适配，动画重放未运行。
- 原 main 的下蹲与滑铲属于第二版隔离动画原型，本轮不整合或接入生产。
- 常规共享引擎目标的重编计划需后续单独核对，本轮只验收复用引擎模式。
