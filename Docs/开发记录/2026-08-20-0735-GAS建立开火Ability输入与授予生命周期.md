# GAS 建立开火 Ability 输入与授予生命周期

- 日期：2026-08-20
- 计划提交说明：`GAS：建立开火 Ability 输入与授予生命周期`
- 变更类型：生产代码 / 测试 / 构建

## 目的

执行 `Docs/执行计划/GA_Fire_ServerOnly执行计划.md` 的子阶段 4A：先建立 ASC 输入基础设施、GameplayTag 契约和玩家/NPC 的 GA_Fire 授予生命周期，但暂不切换实际开火路径，保证该提交不改变现有开火行为。

## 本提交完成内容

- 新增 `UShooterAbilitySystemComponent`：按 Input Tag 查找 Ability Spec、按下时尝试激活、松开时通过引擎可靠 Server RPC 转发给服务器，避免 Character 直接遍历 AbilitySpecContainer。
- 新增 `UShooterGameplayAbility`：只提供安全 Avatar 获取入口；CDO 场景下安全返回 nullptr，不触发引擎 ensure。
- 新增 `UShooterGameplayAbility_Fire` 4A 壳体：`InstancedPerActor`、`ServerOnly`、资产标签 `Input.Fire`、`ActivationBlockedTags=State.Dead`、`ActivationOwnedTags=State.Firing`；激活后立即 EndAbility，不调用武器。
- 新增 `ShooterGameplayTags`：冻结 `Input.Fire`、`State.Dead`、`State.Firing` 三个 Native GameplayTag。
- `AShooterPlayerState` / `AShooterNPC` 改用 `UShooterAbilitySystemComponent`；服务器在 PostInitializeComponents / BeginPlay 中幂等授予 GA_Fire，重复调用不新增 Spec。
- 重生路径不重新授予：`InitializeAbilityActorInfo` 只切换 Avatar，沿用 PlayerState ASC 中的原 Spec Handle。
- Feature Tests 新增 `ShootGame.Ability.Fire.Grant.Player`、`Grant.NPC`、`Grant.RespawnNoDuplicate`（静态授予边界）、`ActorInfo`（CDO 安全入口）。
- 网络测试协调器新增服务器/客户端观测：玩家 ASC 有且只有一个 Fire Spec、重复 Grant 不增长、NPC 独立持有一个 Spec、重生后 Spec Handle 不变、拥有者客户端收到 Spec、远端不收到完整 Spec。成功/超时标记增加 `FireGrant` 字段。
- `ShootGame.Build.cs` 增加 `ShootGame/AbilitySystem/Abilities` include 路径。

## 遇到的问题

- 首次编译失败：测试 helper 中误用未限定作用域的 `TestEqual` / `TestTrue`，RunTest 方法中误用不存在的 `Test` 变量；已在 helper 中改为 `Test.xxx`，RunTest 中改为 `this->xxx`。
- UE 5.6 已弃用 `UGameplayAbility::AbilityTags` 与 `FGameplayAbilitySpec::DynamicAbilityTags` 直接访问，编译产生 C4996；改为构造函数内 `SetAssetTags` 与 `GetAssetTags()` / `GetDynamicSpecSourceTags()`。
- `ActivationBlockedTags` / `ActivationOwnedTags` 是 protected 成员，测试不能直接读取；在 GA_Fire 上增加只读测试观察接口。
- Automation `ActorInfo` 首轮失败：`UGameplayAbility::GetAvatarActorFromActorInfo()` 在 CDO 上会触发 ensure；安全入口先判断 `IsInstantiated()`，CDO 返回 nullptr。

## 处理方式

- 依据 UE 5.6 引擎源码（`GameplayAbility.h` / `AbilitySystemComponent_Abilities.cpp`）确认 ServerOnly 客户端激活会走 `ServerTryActivateAbility`，松开使用已有 `ServerSetInputReleased` 可靠 RPC。
- 逐项按编译错误与 Automation 日志修正，重新执行 Build 与 Automation 至全绿。
- 网络授予与重生不重复授予的事实行为由现有网络测试协调器在 Dedicated/Listen 会话中验证，避免在无真实网络连接的 EditorContext 中伪造 Actor 生命周期。

- 旧 `ServerStartFire` / `ServerStopFire` 仍然存在且是当前唯一开火入口；4D 删除。
- 未运行 Full Regression，最终阶段收尾时执行。
