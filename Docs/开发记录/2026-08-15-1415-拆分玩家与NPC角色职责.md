# 拆分玩家与 NPC 角色职责

- 日期：2026-08-15
- 计划提交说明：`重构：拆分玩家与 NPC 角色职责`
- 变更类型：生产代码 + 资产

## 目的

执行 [GAS 接入前架构整理执行方案](GAS接入前架构整理执行方案.md) 阶段 2：消除 `AShooterCharacter` 与 `AShooterNPC` 共享带玩家第一人称职责的错误基类 `AShootGameCharacter`，使玩家与 NPC 都直接继承 `ACharacter`，为后续分别接入 GAS 的不同 Owner/Avatar 生命周期做准备。

## 本提交完成内容

- `AShooterCharacter` 改为直接继承 `ACharacter`，迁入原基类的全部玩家内容：第一人称 Mesh（手臂）、第一人称摄像机、第一/第三人称 Mesh 可见性配置、Enhanced Input 绑定、移动/视角/跳跃输入处理、胶囊体与 CharacterMovement 配置。
- `AShooterNPC` 改为直接继承 `ACharacter`，不再创建玩家第一人称摄像机和第一人称手臂：
  - 武器挂接改为只挂接第三人称武器 Mesh；
  - 瞄准起点改用 `GetPawnViewLocation()`（Pawn 视点），无目标时使用自身朝向（由 AI Controller 控制）。
- `ShooterStateTreeUtility` 视线检测起点从 NPC 第一人称摄像机改为 `GetPawnViewLocation()`。
- 资产 `BP_FirstPersonCharacter` 父类由 `ShootGameCharacter` 迁移为 `ShooterCharacter`（编辑器 Reparent 操作，`.uasset` 已重保存）。
- 删除旧基类 `ShootGameCharacter.h/.cpp`。

## 验证结果

- 执行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Tests\BuildEditor.ps1`，编译链接成功。
- 执行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Tests\RunAll.ps1 -Port 17794`，七阶段（Build / Automation / Standalone / DedicatedNetwork / ListenNetwork / EmulatedNetwork / DisconnectCleanup）全部 Passed。
- 实际结果文件：`Saved/Automation/Runs/20260815_141218/Summary.json`，顶层 `status: Passed`、`error: null`。
- Standalone 与双客户端网络测试正常加载玩家与 NPC 资产，证明玩家第一人称职责保留、NPC 拆分无失效父类、无找不到旧 C++ 类的日志。

## 遇到的问题

- 首次编译失败两处：`ShooterStateTreeUtility.cpp` 仍引用 NPC 的第一人称摄像机；`ShooterCharacter.cpp` 缺少 `ShootGame.h` 的 include（`LogShootGame` 未声明）。
- 编辑器重启后只读蓝图 MCP 会话过期，报 `Invalid or expired session ID`，客户端不自动重连。

## 处理方式

- 将 `ShooterStateTreeUtility.cpp` 视线起点改为 `GetPawnViewLocation()`；给 `ShooterCharacter.cpp` 补充 `#include "ShootGame.h"`，重新编译通过。
- MCP 会话过期由用户在 Reasonix 侧重载 unreal-engine 连接后恢复，编辑器侧无需操作。

## 遗留项

- `AShooterNPC` 的 `FirstPersonWeaponSocket` 成员保留但已不再使用（NPC 无第一人称 Mesh），属无害冗余，可在后续清理阶段移除。
- `DefaultEngine.ini` 中 `TP_FirstPersonCharacter` → `ShootGameCharacter` 类重定向现在指向已删除的类，按方案留待阶段 4 统一收束。
