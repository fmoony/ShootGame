## 目的

P1 Local Predicted 基础射击反馈已经完成并提交（`757545f`），当前工作区需要一份下一阶段的
执行依据，同时把已经完成的 P1 计划从「执行计划」归档到「已完成计划」，避免路线规划、
架构文档与文档入口继续指向一个已经结束的阶段。

下一阶段要解决的不是新框架，而是现有 Fire / Reload 因「一次性 TryActivate」产生的三个问题：

```text
输入丢失：按下 → TryActivateAbility 失败 → 这次输入永久消失
绕过硬门控：为保住唯一一次输入，客户端分支先于 Super::CanActivateAbility 返回
动作边界耦合：换弹 / 装备状态判断散落在 Ability 自己身上
```

## 本提交完成内容

### 新增执行计划

`Docs/执行计划/输入缓冲与Reload本地预测执行计划.md`（新增）：

- 冻结分层职责：ASC 只负责输入意图与短窗口缓冲，GAS Tag 负责动作互斥，
  Ability 负责生命周期与双端分流，服务器独占 Ammo / Reload 事务 / Projectile / Hit。
- 冻结 Input Buffer 第一版语义：单条 Press Edge 条目、绝对过期时间不续期、
  集中配置（`InputBufferWindowSeconds` = 0.15s、`TransientInputBlockedTags`、
  `MaxHeldRetryPerPress`、`HeldRetryIntervalSeconds`）。
- 冻结失败分类：只用「失败容器 ∩ 本机 OwnedTags」判定，因此半自动节拍未 Ready、
  武器无效、`State.Dead`、自定义客户端否决都不可缓存；阻塞来自该 Ability 自己的
  `ActivationOwnedTags` 时也不缓存（例如换弹中再按换弹）。
- 冻结半自动 / 全自动语义：半自动保留「一次按下沿」，全自动保留「按住持续」，
  Held 状态直接读 `FGameplayAbilitySpec::InputPressed`，不新增第二份布尔。
- 冻结 GA_Fire 的 `CanActivateAbility` 顺序（本地确定性条件先于 `Super` 的 Tag 门控）
  与需要保留的预测语义。
- 冻结 GA_Reload 改为 `LocalPredicted` 的双端生命周期、客户端资格不读弹药真值、
  `bServerRespectsRemoteAbilityCancellation = false`、Reject / Cancel 收敛路径。
- 给出 12 项验证矩阵、测试组织、修改文件范围、回退规则与按不变量汇报的格式。

### 修订网络契约

`Docs/架构/网络射击AI自主验证契约.md`：

- 明确「不变量以标题含义为准」：标题是判定标准，正文清单只是该含义在当前阶段的实例，
  不是定义边界；清单逐项通过不等于不变量成立，未覆盖的维度必须补证据或列为缺失证据。
- 五条不变量改为「含义 / 当前阶段的实例（非穷尽）/ 反例（出现即 FAIL）」三段结构。
- Invariant 1 的含义扩展到本地动作边界：Owner 的本地 Shot Attempt 与本地换弹窗口都要在
  服务器确认前成立，并明确「服务器已产生结果而 Owner 一直没有动作与表现」是 FAIL。
- Invariant 2 改为「服从 / 不越权 / 收敛」三个必须同时成立的维度，
  并同步当前语义：不再有「确认回退只补播一次」；本地已知阻塞通过 GAS Tag 门控阻止激活，
  而不是事后否决已成立的本地表现；不得用可能过期的复制状态二次否决本地有效动作。
- Invariant 3 的权威结果清单加入「换弹弹药转移」，并明确客户端本地预测不得提交任何权威事务。
- Invariant 4 补充含义：不得依赖 Owner 预测入口，也不得产生额外远端表现或结果。
- Invariant 5 补充「本地动作边界与表现也恰好一次」以及「换弹事务不得重复提交」。
- 新增第 7 节「按标题含义确认改动与计划」：给出固定的四条确认结构
  （触及维度 / 未改变维度 / 需要的新增证据 / 范围外维度与理由），并说明计划内部的子不变量
  （如 Input Buffer、Reload Prediction）必须能映射回五条契约不变量。
- 第 3、4、6 节同步：修改前必须先做含义覆盖确认；证据规则补充输入意图与换弹预测的取证要求；

- 归档时同步修正两条相对链接；并用文本检索确认两份文档内没有其它相对链接需要调整。
- 失败分类因此改为只依赖引擎追加的**具体阻塞标签**（
  `GameplayAbility.cpp:339` 的 `AppendMatchingTags`）与本机 OwnedTags 的交集，
  不读取任何通用失败标签；该结论已写入计划第 2.3 与 5.3 节。
