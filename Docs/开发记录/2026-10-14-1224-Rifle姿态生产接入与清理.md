- 日期：2026-10-14
- 计划提交说明：`动画：接入 Rifle 肩部衔接与头颈姿态并清理原型`

## 目的

采用用户验收的 ShoulderSeam 方案，消除进入 LowReady 时肩部的小位移。
保留已有 Local 胸腔相对收枪系统与 K 网络动画预览的实际 Gameplay 边界。

  保留面部仰角，ArmedAim 状态不接入该节点。

## 验证结果

- Runtime 头颈节点与验收节点同相位对照：7,200 帧，位置差 0 cm，旋转差约 0.0000034°。
  这是只替换节点的瞬态图算法对照；真实生产图另由下述 K 与 Camera 测试验证。
- 五项 RifleReady 生产回归全部 Success：Standalone、Listen、Dedicated、Emulated、Off。
  覆盖真实 K、中途反向、弹药与 Shot 不变、Fire、Reload、非 Rifle 与无武器门控。
  有原有 GAS / NavMesh 环境警告，错误数为 0。
- 真实生产 AnimInstance 的四角度 FP / TP 取证 Success，168 次截图中 56 次为生产版本。
  使用真实角色、原 FP Camera 与 K 输入；覆盖 0°、-30°、-60°、+60°及正反播放。
- 进入 LowReady 后约 0.16 秒、upperarm 相对 spine_05 的最大位移：
  TP 旧 35% 配旧端点约 3.369 cm →生产约 0.013 cm。
  FP 旧组合约 9.210 cm →生产约 0.607 cm，仍有残余运动。
- 稳定 LowReady 的面部 Yaw 与 Roll 接近 0°，不同 Pitch 下仍保留原面部仰角。
  Camera View Pitch 保持输入角度；抽查 FP 截图未见新中心遮挡，不能代替全面主观验收。
- 两套保留 Blender 脚本实际重跑成功，关键帧烘焙及 FBX 导出正常。
- 移除原型类后 Editor 与独立 Game Target 编译成功；未执行完整打包 / Cook。
- 最终资产依赖、保护基线、include、文本版式与 git diff 检查结果见验证摘要。

## 遇到的问题

临时迁移 / 对照代码出现 UE 签名、TObjectPtr 遍历和未暴露 PlayRate 引脚问题。
最后一项曾使对照 Commandlet 因空指针退出；一次旧 DLL 不包含新采集过滤器。
UE Python 不暴露 Blueprint ParentClass，也没有 AssetData.get_soft_object_path。
删除测试地图后一个外部 Actor 包未自动清理。

## 处理方式

核对本地 API 并修正临时代码；同相位比较改为验收图仅替换 Runtime 节点。
修正后重新编译并执行，生产资产未受损；最终移除这些一次性代码。
Python 改用实际暴露接口，生产父类另通过只读 MCP 核对。
外部 Actor 经 Registry 确认原地图已删除且无引用，使用 UE ObjectTools 空包清理接口移除。
不人工删除 World Partition 的外部文件。

## 遗留项

FP 肩部仍存在约 0.61 cm 的残余运动；本轮沿用已验收算法，不扩大为净空算法修复。
完整 Cook、跨机器及长期 Gameplay 视觉回归未执行。
历史报告保留原文，已删除的实验图和 Saved 证据路径不再可访问。
