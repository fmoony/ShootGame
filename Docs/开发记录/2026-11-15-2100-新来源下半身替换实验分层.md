# 新来源下半身替换实验分层

- 日期：2026-11-15
- 计划提交说明：`资产：用新来源原地动作替换实验下半身分层输入`
- 变更类型：资产 / 实验代码 / 工具 / 文档

## 目的

以刚导入的完整父层烘焙来源替换实验下半身，观察原始动作分层表现。
保留现有上半身与所有旧资源，用实际运行骨骼验证输入及分层关系。

## 本提交完成内容

- Blender 从 ParentBaked 派生五段原地输入及前左镜像的前右动作。
- LayerPlayback 保留六份 blend、FBX 与姿态对照数据。
- SourceLayer 新增六段生产 Skeleton 动画及六样本 BlendSpace。
- 实验默认读取新下半身，-StanceLegacyLower 保留旧输入对照。
- 按新动作实际行进量匹配 Pawn 速度，保持输入方向，不修改足部骨骼。
- 增加实际双腿各阶段采样、独立输入匹配与分层数据分析。
- Run.ps1 默认 Verify 新输入，-LegacyLower 验证或预览旧输入。
- 更新当前现状文档，新增本轮报告、原始数据和窗口验收记录。

## 验证结果

UE Editor 构建通过，使用 -UsePrecompiled -NoEngineChanges。
导入前后生产骨架参考姿态及重定向设置一致。
370 帧 × 89 骨骼的 RAW／压缩重载通过，最大位置误差约 0.002438 cm。
五段非镜像非 root 局部轨道最大位置差约 0.000627 cm。

Ground 最终覆盖 40 场景、7,511 帧。
直接来源实际输入核对 359 帧、3,231 骨骼帧通过。
View 覆盖 108 场景、2,160 帧。
稳定下半身 16,220 组骨骼帧在 raw、layer、实际 Body 之间无变换差。
上半身相对相机的几何保持，FP 复制最终 TP 通过。
实际 Actor 速度重建核对最大误差约 0.05355 cm/s。

142 个既有保护文件保持不变，原始 Source、完整 SourceBaked 与旧步态保留。
脚掌接触未通过，最差参考接触点仍约 -17.162 cm。
速度匹配使整体脚滑 P95 从 155.592 降至 48.585 cm/s，仍明显劣于旧步态。
因此只判定替换与分层输入验证通过，不判定接地或自然度通过。

Python、PowerShell、include 与文本门禁结果见本轮 Checks.json。
实际 Git 暂存区保持空白，没有创建提交。
未新增、删除或移动 C++ 文件，无须刷新 VS 工程。
可见编辑器恢复实验地图并启动 PIE 供试走。

## 遇到的问题

分层再烘焙时使用单位全局尺度，导致生产重定向后骨长异常放大。
Probe 检测到约 1661 cm 误差并中止保存。
沿用旧约 50.35 cm/s 移速时，与新动作原始步幅不匹配。
旧 View 未采双腿，仅共有 pelvis，不能作为前后完整腿部姿态差证明。
CodeGraph 命令不可用，按范围读取现有夹具与官方资源接口。
官网定向 5.8 页面未能访问，当前公开说明展示 5.9。

## 处理方式

保留原 Armature 与骨骼矩阵尺度，CandidateV3 通过两种重定向预检。
按完整源 root 每循环净行进量和当前混合权重匹配 Actor 速度。
用实际 Body 数据重建速度，不以实现内部返回值代替运行证据。
新腿部输入由独立 UE 动画求值直接核对，不强行补造旧采集通道。
本地 UE 5.8 API 签名与真实求值分别验证，官网只用于概念依据。

## 遗留项

部分混合方向穿地、双脚接触间隙和残余滑步尚未解决。
原始前左及镜像也存在接触间隙，不只涉及方向插值。
需要补齐来源方向、核对脚相位，必要时继续在 Blender 制作。
生产 AnimBP、AO／AimIK 顺序复刻和正式角色接入仍未完成。
网络、坡面、碰撞、Cook、换弹与贴墙未在本轮回归。
