# 收敛 Health 读取与兼容镜像

- 日期：2026-08-26
- 计划提交说明：`生命：收敛 Health 读取与兼容镜像`
- 变更类型：C++ 生产代码 + 自动化测试

## 目的

执行《Shooter 核心玩法架构解耦重构执行计划》R7：登记 Character / NPC 的 `CurrentHP` / `MaxHP` / `IsDead` 全部调用方，在 Ability 已统一使用 ASC `State.Dead` 的基础上，把 UI 与网络测试的生命值读取逐步改到 `UShooterAttributeSet`，同时保留 `bIsDead` 作为廉价复制表现镜像。不新增 HealthComponent。

## 调用方登记结果

- Character 内部：`BeginPlay` / `PossessedBy` / `HandleHealthAttributeChanged` / `OnRep_CurrentHP` / `OnRep_IsDead` / `TakeDamage` / `Die` / `Respawn`；其中 `HandleHealthAttributeChanged` 是 ASC → 镜像的唯一桥接写入点。
- NPC 内部：`BeginPlay` / `HandleHealthAttributeChanged` / `TakeDamage` / `Die`；同样是 ASC → 镜像的唯一桥接写入点。
- UI：`AShooterPlayerController::OnPawnDamaged` 绑定 Character 的 `OnDamaged` 转发事件，但初始绑定路径仍直接读 Character 镜像。
- 表现/交互：`ShooterAimPresentationComponent`、`ShooterFirstPersonAnimInstance`、`ShooterAnimInstanceBase`、`ShooterPickup` 只读 `IsDead()` 镜像，符合“bIsDead 保留为表现镜像”。
- 测试：`ShooterNetworkTestCoordinator` 有大量 `GetCurrentHP()` / `GetMaxHP()` 读取；`ShooterWeaponAutomationTests` 验证镜像复制契约；`ShooterAbilityFireCancellationAutomationTests` 验证 NPC CDO 非死亡。

## 本提交完成内容

- `AShooterCharacter` 增加三个读穿透入口：
  - `GetHealthAttributeValue()`：ASC `Health` 权威值，ASC 不可用时回退 `CurrentHP`。
  - `GetMaxHealthAttributeValue()`：ASC `MaxHealth` 权威值，ASC 不可用时回退 `MaxHP`。
  - `GetHealthRatio()`：ASC 权威比例，供 HUD 和测试使用。
- `AShooterPlayerController` 初始 HUD 刷新改调 `GetHealthRatio()`，不再直接组合 Character 镜像字段。
- `ShooterNetworkTestCoordinator`：
  - 伤害计算与客户端报告路径的 `GetCurrentHP()` / `GetMaxHP()` 改调上述读穿透入口。
  - 保留两处“ASC 属性值 vs CurrentHP 镜像”一致性断言，继续守护镜像同步契约。
  - NPC 死亡断言继续同时校验 ASC 属性归零与 `CurrentHP` 镜像归零。
- 新增 `ShootGame.Architecture.Baseline.HealthSurface`：
  - 断言 `UShooterAttributeSet::Health` / `MaxHealth` 是复制属性。
  - 断言 Character `CurrentHP` / `bIsDead` 是 BlueprintReadOnly 复制镜像，`MaxHP` 只是非复制服务器配置。
  - 断言 Character / NPC 没有 `SetCurrentHP` / `SetMaxHP` 公开写入口。
  - 验证无 ASC 时三个读穿透入口回退到兼容镜像。
- 未删除 `CurrentHP` / `MaxHP` 字段；按计划该项留到镜像无 Gameplay 写入后再单独决策。

## 遇到的问题

- 网络测试文件中的生命值读取分散在伤害应用、客户端上报和一致性断言三类位置；一次性全部替换会破坏“镜像同步”测试价值。本次按用途区分：伤害/上报路径改读 ASC，一致性断言继续读镜像。

## 处理方式

- 读穿透入口放在 Character 上作为迁移期兼容；它们本身直接读 AttributeSet，不写任何 Health 值。
- 保持 `HandleHealthAttributeChanged` 为唯一镜像写入桥接，没有新增第二套可写 Health。

## 遗留项

- `CurrentHP` / `MaxHP` 镜像删除仍为单独决策；需等所有剩余镜像读取方（含蓝图与回归测试）收敛后单独提交。
- NPC 的 `CurrentHP` 镜像继续由服务器 ASC 桥接维护，未改复制模式。
- 后续 R8 清理 Character 兼容接口时再评估 `GetCurrentHP` / `GetMaxHP` 旧 Getter 的退出时机。
