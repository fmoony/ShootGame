## 目的

玩家第三人称动画类固定在 `AShooterCharacter::PlayerThirdPersonAnimInstanceClass`，
NPC 直接用自身 Mesh 的默认动画类，`DT_WeaponData` 的 TP AnimClass 列已无任何消费者。
本提交删除这条配置链的字段、成员、镜像与旧断言，并重存 DataTable 让废弃列真正消失。

## 序列化与实施顺序依据

实施顺序为“先删 C++ 字段、再重存 DataTable”，依据本机 UE 5.6 引擎源码：

- `CoreUObject/Private/UObject/Class.cpp:1961-1966`：未被消费的属性标签按
  `UnderlyingArchive.Seek(StartOfProperty + Tag.Size)` 跳过，跳过长度来自标签自身，
  因此后续属性仍从正确偏移继续解析。
- `Class.cpp:1875-1891`：未知属性只在 `SerializeContext->bTrackUnknownProperties`
  为真时才写入 `FUnknownPropertyTree` 并参与回写；
  `UObjectThreadContext.cpp:66` 把该标志默认初始化为 false，
  `:171` 只在 Instance Data Object 装载路径临时置真。
  常规编辑器与 Commandlet 装载都走 false 分支，因此重存时不会保留已删除的列。
- 不需要 Core Redirect：结构体与表的身份未变，只是少了一个属性，不存在重命名或迁移映射。

DataTable 重载成功由两处独立证据覆盖：Commandlet 的 `-Verify` 在全新进程中从磁盘重新加载，
以及自动化测试经 `ShooterWeaponTable::ResolveWeaponTable()` 重新解析同一资产。
