# Rifle 动画派生副本与端点取证

- 日期：2026-10-10
- 计划提交说明：`动画：派生Rifle四份规范动画副本并建立端点取证`
- 变更类型：资产 / 生产代码（Editor 工具）

## 目的

《Rifle 新动画与 WeaponAction 状态机预审查》阶段一要求把四段外部导入动画整理成
Shooter 正式资产根下的规范副本，确认裁切、首尾帧、时长与握姿，并在动状态机之前
判定姿态端点是否达标。用户已授权阶段 A、B；阶段 A 不达标时不得推进阶段 B 接线。

## 遇到的问题

- `Animation/AnimData/BoneTrack.h` 在本机 5.6 不存在；`FBoneAnimationTrack` 实际声明在
  `Animation/AnimData/IAnimationDataModel.h`，首次构建因此 C1083 失败。
- `IAnimationDataModel::GetNumberOfFrames()` 返回 `int32`（等于最后一个零基帧），
  不是 `FFrameNumber`；误取 `.Value` 导致 C2737 与格式串静态断言失败。
  `SetNumberOfFrames(N)` 的参数是"帧数 = 保留的最后一个零基帧"，不是"保留帧数 + 1"。
- `FindBoneTrackByName` / `GetBoneAnimationTracks` 自 5.2 起废弃，
  构建产生大量 C4996；已改用 `GetBoneTrackNames` + `GetBoneTrackTransforms`。
- `FPackageName::GetAssetPackageExtension()` 返回 `FString` 而非 `const TCHAR*`，
  用 `const TCHAR* const` 接收时 C2440 失败。
- `CheckTextLayout.ps1 -Scope Staged` 对新增代码报三类版式问题：
  单行逗号落在 120 列之后、可合并的两行调用、以及三行以上参数列表。
  该类规则按"变更行"判定，历史文件未变更因此不会暴露同样写法。
- 本机 PowerShell 执行策略禁止运行 `.ps1`，`Scripts/Tests/BuildEditor.ps1` 与
  `CheckTextLayout.ps1` 直接调用均被拒绝。
- 本机可用内存仅约 1.9GB，UBT 把并行动作数限制为 1，构建明显变慢。
- 派生后出现 4 条 `EnsureDependenciesAreLoaded: InterchangeAssetImportData_0` 警告：
  副本继承了来源的 Interchange/FBX 导入记录。
- 预审查正文称"四段 RateScale=1"，与其自带的 `rifle_samples.json`
  不符：`GrabRifleAndPutBack` 与 `PutBackRifleBehindShoulder` 实际为 1.2。

## 处理方式

- 头文件路径与取帧语义改为按本机 5.6 头文件核对后的写法，重建通过；
  帧数预期固化为 257 / 45 / 119（键数 258 / 46 / 120）。
- 废弃 API 换成非废弃等价接口，构建恢复 0 warning 的自定义代码路径。
- 扩展名改用 `const FString` 接收后重建通过。
- 按 `CheckTextLayout.ps1` 的判定把可合并的两行调用并为单行（该脚本对 ≤140 且
  末参数起点在 120 列前的单行判定通过），把轨道名预先取为局部字符串以让逗号前移，
  最终 `-Scope Staged` 通过（Files=4 Warnings=0）。
- 脚本改用 `powershell -NoProfile -ExecutionPolicy Bypass -File <脚本>` 运行。
- 构建直接调用 `Build.bat ShootGameEditor Win64 Development -Project=...`，
  附加 `-WaitMutex -FromMsBuild -NoUBA`。
- 用报告自带的原始采样 JSON 复核 RateScale，以实测值（1.2）为准；
  派生副本继承来源 RateScale，属预期行为，不做改写。
- Interchange 警告已记录，未做处理：原始导入资产保留，无需清理导入记录。

## 遗留项

阶段 A 的姿态端点未达标，按用户门控**未推进阶段 B 的完整接线**。以下差距已量化
（组件空间手部距离 / 主要上身链路最大局部角差）：

| 衔接 | 右手 | 左手 | 最大角差 |
| --- | --- | --- | --- |
| ArmedAim ↔ `MM_Rifle_AimToLowReady` 首帧 | 39.196cm | 44.296cm | 48.0° |
| `MM_Rifle_AimToLowReady` 末帧 ↔ LowReady | 1.054cm | 6.768cm | 23.5° |
| LowReady ↔ `MM_Rifle_Holster` 首帧 | 17.223cm | 9.541cm | 36.5° |
| `MM_Rifle_Draw` 末帧 ↔ LowReady | 17.223cm | 9.541cm | 36.5° |

需要人工在 UE 动画编辑器内完成、本工具链无法可靠代劳的修改：

1. `MM_Rifle_AimToLowReady` 首帧：把 `clavicle_r/l`、`upperarm_r/l`、`lowerarm_r/l`、
   `hand_r/l` 与 `spine_01..05` 对齐到 ArmedAim 的实际输出姿态
   （`MF_Rifle_Idle_ADS` + `AO_Rifle`）；建议把第 0 帧设为对齐姿态、第 2–3 帧回到原姿态，
   避免单帧突变。对齐目标随视角俯仰变化，需带枪目视确认。
2. `MM_Rifle_AimToLowReady` 末帧：仅左手偏差 6.768cm，右手已达标；对齐到
   `MM_Rifle_LowReady` 首帧的左手。
3. `MM_Rifle_Holster` 首帧：对齐到 `MM_Rifle_LowReady` 首帧；修改后**必须重跑派生**
   重新生成 `MM_Rifle_Draw`，否则镜像关系失效。
4. `MM_Rifle_Holster` 末帧右手仍有 14.12cm/s，收尾未静止；可延后收尾或由 Stowed 混合吸收。

其它已量化、待决策的风险：

- 加速失真：`MM_Rifle_Holster` 逐帧最大局部角步进 13.474°（RateScale 1.2 下约 16.2°/帧）；
  压到 0.85s 需总倍率约 3.92，峰值约 52.8°/帧。`MM_Rifle_AimToLowReady` 逐帧 7.7°，
  压到 0.30s 需 2.778 倍，峰值约 21.4°/帧。候选时长偏短，需要用户按观感取舍。
- 时长口径：`GetPlayLength()` 返回未除 RateScale 的原始长度。副本
  `MM_Rifle_Holster` / `MM_Rifle_Draw` 的实际播放时长为 3.333333 / 1.2 = 2.777778s，
  接入 Sequence Player 时须按此计算倍率。
- 头颈位移：`MM_Rifle_AimToLowReady` 20.299cm、`MM_Rifle_Holster` 12.364cm、
  `MM_Rifle_Draw` 8.246cm（`MM_Rifle_LowReady` 仅 0.628cm）；需在对应状态局部排除颈/头，
  以免影响第一人称视点。
- 武器附着点 `HandGrip_R` 行程：`MM_Rifle_LowReady` 1.224cm、
  `MM_Rifle_AimToLowReady` 28.052cm、`MM_Rifle_Holster` 91.394cm、`MM_Rifle_Draw` 112.831cm。
- 未做带真实 Rifle 的皮肤与握把穿模检查；握把约束没有按真实 `LeftHandGrip` 校准。
- 未接入 `ABP_TP_Player`，未启用 TP Arms Slot 的 `AlwaysUpdateSourcePose`；
  这两项属于阶段 B，等待端点达标与用户确认。
- 未追踪的原始导入资产（`RifleIdle`、`RifleAimToDown`、`GrabRifleAndPutBack`、
  `PutBackRifleBehindShoulder`、`PistolAim`）与预审查报告仍保持未跟踪，未纳入本提交。
