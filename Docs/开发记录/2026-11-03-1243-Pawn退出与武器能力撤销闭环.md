# Pawn 退出与武器能力撤销闭环

- 日期：2026-11-03
- 计划提交说明：`修复：收束 Pawn 退出与武器能力撤销生命周期`
- 变更类型：生产代码 / 测试 / 文档
- 当前状态：实现与定向验证完成，本记录随对应改动一同提交。

## 目的

持久 PlayerState ASC 与可替换 Pawn 的主体分工已经存在。
本轮补齐退出协调和授予归属，不引入新组件，也不改装备表现职责。

原先 Pawn 直接销毁时，解除控制先清空 PlayerState。
Character.EndPlay 与 Inventory 随后反查宿主失败，武器虽归池，旧动作、输入与 Fire Spec 仍残留。
正常死亡提前执行了清理，因此不能用正常死亡通过替代真实销毁覆盖。

## 本提交完成内容

- Character 的 `CleanupPawnGameplay` 收束死亡、解除控制和 EndPlay 的清理顺序。
  先使旧输入失效、取消动作，再清 Inventory / Equipment，最后按需解除 ActorInfo。
- UnPossessed 在 Super 清空控制关系之前清理；死亡保留 Avatar，供属性桥接与死亡流程使用。
- 保存建立关联时的 ASC 弱引用，客户端 PlayerState / Controller 失效时也能使用原上下文。
  新 Pawn 初始化前通知旧 Avatar 拆卸，清理时核对 Avatar，保护新 Pawn 的动作和输入。
- Inventory 不保存逐武器 Grant Map，Clear 接收调用方明确提供的原 PlayerState。
  Character 复用 Bound ASC 的 OwnerActor 传入，普通 Remove 仍使用当前宿主。
  Remove / Clear 在广播前固定本次宿主，避免回调改变控制关系后撤销到其他 PlayerState。
- 撤销沿用 PlayerState 已有的按 Weapon.SourceObject 查询实现，在武器归池前完成。
  未增加 PlayerState 的撤销接口或额外授予状态；Reload / Equip 的持久 Spec 保留。
- 新增并维护九个生命周期回归用例：原六场景、Reload / Equip 迟到旧 Pawn、显式退出宿主。
  原始六场景来自本会话前一阶段的取证，随本次修复共同保留。
- 更新当前 Inventory 架构说明，写明原宿主上下文与 Pawn 退出边界。
- 未修改 WeaponActor、Equipment、AnimInstance、资产或复制字段；没有新增源码文件。

### 实现依据

Epic UE 5.6 Lyra 文档区分持久 ASC 和 Pawn 相关状态，并强调退出时撤销 Pawn 相关状态：

<https://dev.epicgames.com/documentation/en-us/unreal-engine/abilities-in-lyra-in-unreal-engine?application_version=5.6>

本地 UE 5.6.1 的 Pawn::UnPossessed 清空 PlayerState，ASC 的 Avatar 销毁回调只清属性。
因此本项目在现有类中补退出协议，没有复制 Lyra 的组件体系。
当前 Inventory 在一次控制关系中对应单个宿主，退出时直接传递原上下文，无需逐武器凭据集合。

## 遇到的问题

- 第一版额外维护逐武器 Grant Map 与按 Handle 撤销接口。
  用户评审指出维护成本后，确认当前单宿主模型不需要该额外能力，要求简化。
  本记录按最终方案整理；简化前报告继续保留在 Saved 中。
- 上一轮隐藏编辑器进程仍在，普通 MainWindowHandle 为 0，用户看到的关闭状态不足以证明进程退出。
- 首轮定向 14 用例中，12 通过、2 失败，失败只发生于新增迟到旧 Pawn 用例的观测对象检查。
  测试助手追加武器行并重建池时销毁了已回池的旧观测武器。
- 既有测试夹具有无骨骼与 World 清理警告；警告未隐藏或折算为无警告通过。

## 处理方式

- 按评审意见移除 Grant 结构、集合、维护函数和新增 PlayerState 接口。
  保留退出顺序、绑定 ASC 弱引用与 Avatar 保护；复用原宿主上下文和现有 SourceObject 查询。
  原宿主任意变更用例改为显式退出上下文用例，不将额外场景支持当成生产需求。
- 在本轮用户会话确认后，只向已核对的 ShootGame 隐藏主窗口发送正常关闭消息并等待进程退出。
  没有强制结束交互编辑器，也没有操作 VS。
- 迟到用例改用既有 RuntimeConfig，从真实池中重新 Acquire 相同武器实体。
  保持原观测对象可用，同时验证新 Spec 与新 Avatar 不被旧清理误伤。
- 调整后重新编译并运行上述 112 个相关用例；全部通过，再完成 Dedicated 回归。
