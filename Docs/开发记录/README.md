# 开发记录规范

本目录保存提交级开发记录。目标是让后续开发者和 Agent 不只看到代码结果，还能知道每个提交的目的、验证证据、排错过程和未完成边界。

## 强制规则

- 每个新提交对应一份独立 Markdown 记录，并与对应改动进入同一个提交。
- 必须先完成记录，再暂存和提交；禁止提交后另补记录。
- 文件名使用 `YYYY-MM-DD-HHMM-简短主题.md`，主题优先中文，不使用含义模糊的 `update`、`fix`。
- 一份记录只对应一个提交。生产代码、测试和文档若拆成多个提交，就分别建立记录。
- 使用“计划提交说明”关联提交；不要求预填提交哈希，也不得仅为补哈希修改历史。
- 已有历史提交不追溯补写，本规范自引入它的提交开始生效。

## 必填内容

```markdown
# <简短主题>

- 日期：YYYY-MM-DD
- 计划提交说明：`类型：中文说明`
- 变更类型：生产代码 / 测试 / 文档 / 资产 / 构建

## 目的

为什么需要这个提交；它解决哪个具体问题或完成哪个闭环。

## 本提交完成内容

- 写实际落地的改动，不写尚未实现的计划。
- 标出关键文件、类、蓝图或脚本。

## 验证结果

- 写实际执行的命令、测试或人工检查及结果。
- 未运行完整验证时说明原因和当前验证边界。

## 遇到的问题

- 记录失败现象、错误信息、环境问题或错误尝试。
- 没有问题时必须写“无”。

## 处理方式

- 说明如何定位和处理上述问题。
- 没有问题时必须写“无”。

## 遗留项

- 写未覆盖场景、已知风险和后续工作。
- 没有遗留项时必须写“无”。
```

## 提交前检查

```powershell
git diff --check
git diff --cached --check
git diff --cached --name-only
```

检查时必须确认：

- 暂存区包含本提交专属记录。
- 记录的“本提交完成内容”与暂存文件一致。
- 记录不存在 `<简短主题>`、`YYYY-MM-DD` 等模板占位符。
- 用户已有的无关修改没有被暂存。
