# 武器启动快照与 WeaponId 预热池

- 日期：2026-09-11
- 计划提交说明：`武器：建立启动配置快照与 WeaponId 预热池`
- 变更类型：生产代码 / 测试 / 文档

## 目的

按《武器启动预配置与实体池简化重构方案》S1 阶段要求，建立 World 级武器运行时子系统：
在 World 开始时一次性读取 `DT_WeaponData` 形成不可变 RuntimeConfig 快照，并按每个
WeaponId 的 `InitialPoolSize` 预创建配置完成的武器池；耗尽时只从冻结快照弹性 Spawn。
本提交不接入生产 Pickup，旧 `UShooterActorPoolSubsystem` 授予路径保持不变。

## 本提交完成内容

- 新增 `Weapons/ShooterWeaponRuntimeSubsystem.h/.cpp`（`UShooterWeaponRuntimeSubsystem`）：
  - `OnWorldBeginPlay` 一次性导入：加载表、校验 RowStruct 与全部行、按行值复制为
    `FShooterWeaponRuntimeBucket.RuntimeConfig` 快照；已初始化时幂等返回，运行时不重读表。
  - 服务器按 `InitialPoolSize` 预创建复制型 WeaponActor；客户端只建快照、不自主创建。
  - `AcquireWeapon(WeaponId, Owner, Instigator)` 池命中复用 / 耗尽弹性 Spawn，成功直接
    返回 `AShooterWeapon*`；未知 WeaponId、非权威端、Spawn 失败返回 nullptr。
  - `ReleaseWeapon` 归还复位（隐藏 / 关碰撞 / 关 Tick / Detach / 清 Owner），扩容 Actor
    留在原 Bucket 复用；重复归还 fail closed。
  - 失败策略落地：表缺失或结构错误 → 初始化失败；单行非法（含 abstract 类与
    `InitialPoolSize<=0`）→ 不建 Bucket 并输出一次 Error；预热失败 → 撤销该 Bucket。
  - `SetWeaponTableOverride` 供测试注入瞬态表（须在 World BeginPlay 前调用）。
- `FShooterWeaponConfigRow` 新增 `InitialPoolSize`（默认 2，ClampMin=1）；既有
  DT_WeaponData 行以 tagged property 加载自动获得默认值，无需重写资产。
- `AShooterWeapon` 新增永久 `WeaponId` 复制字段（全端）与创建时一次性
  `InitializeWeaponIdentity`（从启动快照应用静态配置）；客户端 `OnRep_WeaponId` 从本地
  快照恢复静态表现。新增新池租用回调 `OnAcquiredFromWeaponPool / OnReleasedToWeaponPool`，
  与旧 `IShooterPoolableActor` 路径并存至 S4 收口。
- 新增测试 `Tests/Pool/ShooterWeaponRuntimeSubsystemAutomationTests.cpp`（4 例）与
  `Tests/Pool/ShooterWeaponRuntimeTestTypes.h`：快照与预热、非法行/坏表失败边界、
  Acquire/Release 与复用、耗尽弹性 Spawn 与扩容留存。
- 更新方案文档状态为已批准实施并记录 S0 审计结论（WeaponId、地图规模、资产迁移先例、
  GameMode 断线断言联动点）。

## 遇到的问题

- 首次运行测试时子系统未初始化（Acquire 全部 unknown WeaponId）：UE5.6 的
  `AWorldSettings::NotifyBeginPlay` 只派发 Actor BeginPlay，不调用 `UWorld::BeginPlay`
  （子系统 `OnWorldBeginPlay` 所在）。已核对本地引擎源码（WorldSettings.cpp:351、
  World.cpp:5903）并确认生产路径由 `UEngine::LoadMap → World->BeginPlay()` 保证时序；
  测试世界改为直接调用 `World->BeginPlay()`。
- 测试武器 UCLASS 不能定义在 .cpp 命名空间内（UHT 不支持），按项目既有模式抽到独立
  头文件 `ShooterWeaponRuntimeTestTypes.h`。
- 首版行校验遗漏 abstract 检查：`AShooterWeapon::StaticClass()` 通过了
  `IsRowValidForGrant` 的 IsChildOf 判定，预热 Spawn 才失败。已在
  `IsRuntimeRowValid` 增加 `CLASS_Abstract` 拒绝，使非法行在校验期即不建 Bucket。

## 处理方式

- 测试辅助 `BeginRuntimeWorldPlay` 直接调用 `UWorld::BeginPlay()` 并注释说明该差异；
- 预期 Error 日志通过 `AddExpectedError` 声明，避免 Automation 误判。
