## 实现依据

[Epic 动画镜像](https://dev.epicgames.com/documentation/unreal-engine/mirroring-animation-in-unreal-engine)
说明左右映射、镜像轴与参考姿态修正。
本地 UE 5.8.4 核对 AnimationRuntime.cpp 的 MirrorPose 与 BoneContainer 接口。
官方常见方案是 Mirror Data Table 与运行时 AnimGraph；本实验离线调用同一算法烘焙。
不新增 Runtime 节点或改变正式 AnimBP。

[Epic FBX 动画导入](https://dev.epicgames.com/documentation/unreal-engine/fbx-animation-pipeline-in-unreal-engine)
支持动画单独导入并指定既有 Skeleton。
本轮使用现有 Manny 骨架的导入副本，不改写正式 Skeleton 或来源 FBX。

## 遇到的问题

- CodeGraph 命令不可用，按约定读取限定范围内的实验代码。
- 首个 FBX 检查脚本使用了旧的 32 位节点头，实际文件为 FBX 7700 的 64 位格式。
- 文件全局时段不能代表动画真实时长；idle 实际导入为 202 个关键帧、约 6.7 秒。
- 来源没有骨盆平移动画，直接使用站立骨盆位置会导致脚部悬空。
- 旧夹具固定采样 idle，且采集期间没有连续推进动画时间，不足以验证新资源的完整动作。
- 首轮连续采集发现混合脚尖穿地约 1.346 cm，原接地断言正确失败。
- 新来源低头时出现 FP 手臂截面；尝试补面与前景位置调整均未可靠改善。
- 交互预览自动发起的 Turnkey VerifySdk 退出 1，但游戏仍正常启动并接收输入。
- 最终全量中既有 Listen 换弹 Notify 出现间歇失败；独立复跑通过，根因未确定。
- 该夹具约 0.2 秒后取消换弹，3.1 秒后检查计数；未证明失败仅由时间窗口造成。
- 新增源码与脚本存在四处版式问题。
- 每次编译后的首个 UE 启动模块装载明显缓慢，首轮资源生成等待约 17 分钟。
