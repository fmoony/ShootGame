# 武器弹药本地预测与 Rejected 退还

- 日期：2026-09-19
- 计划提交说明：`功能：武器弹药最小本地预测与 Rejected 退还`
- 变更类型：生产代码

## 目的

`MagazineAmmo` 是服务器权威的复制字段，拥有者客户端此前完全不参与弹药判定，于是有三个真实问题：

1. 本地已经预测了最后一发，客户端仍会按旧的 replicated `MagazineAmmo` 继续播放开火表现；
2. 全自动连发时本地表现不受任何"可预测弹药"上限约束；
3. 服务器弹药复制回来时，本地会把它当成"又有子弹了"，与刚刚预测消费掉的那一发不一致。

本次在**不改变**权威模型的前提下加一层最小本地预测：

- `MagazineAmmo` / `ReserveAmmo` 继续是唯一权威，仍属于具体 Weapon 实例；
- 服务器继续独占真实扣弹与 Projectile / Damage；
- GA_Fire 继续 LocalPredicted；ASC 继续不感知 Ammo；
- 不维护第二份完整的 `LocalMagazineAmmo` 镜像，只维护一个"已预测但尚未被吸收"的计数。

## 本提交完成内容

### AShooterWeapon：权威快照 − 待吸收预测

- 新增非复制成员 `int32 PendingPredictedShots`：语义是"Owner 客户端已预测消费、尚未被新的服务器
  Ammo 状态吸收的弹药数量"。
- 新增接口：`IsAmmoPredictionContext()`、`GetPredictedMagazineAmmo()`、`CanConsumePredictedAmmo()`、
  `TryConsumePredictedAmmo()`、`RefundPredictedAmmo()`、`ResetAmmoPrediction()`、
  `GetPendingPredictedShots()`。`TryConsumePredictedAmmo` 只增加 Pending，
  **绝不写** `MagazineAmmo` / `ReserveAmmo`；权威端与非拥有者视图不维护 Pending，直接放行。
- `IsAmmoPredictionContext() = !HasAuthority() && HasOwnerLocalPlayerView()`：
  Listen Host 与 Standalone 的弹药在本地直接写入 `MagazineAmmo`，自身复制不触发 OnRep，
  一旦维护 Pending 就永远没有下降复制可以吸收它，因此它们被排除在预测之外。
- `OnRep_MagazineAmmo` 改为带旧值形态 `OnRep_MagazineAmmo(int32 OldMagazineAmmo)`：
  - 下降：按**整段差值**吸收（一次复制可能跳过多个中间值，例如 10 → 7），clamp 到 ≥ 0；
  - 上升：视为权威端建立新基线（换弹提交 / 池取用恢复 / 未来补弹），Pending 清零。
- `ResetAmmoPrediction()` 挂在 `ClearWeaponOwner()`（一处覆盖 Owner 变化 / 归还池 / teardown）。
- 新增开发构建 marker：`AMMO_PREDICT_CONSUME / ABSORB / REBASELINE / REFUND / RESET`。

### GA_Fire：本地 Shot Attempt 先扣预算，Reject 时退还

- 新增私有 helper `CommitOwnerShotAttempt(Weapon, Marker)`：先 `TryConsumePredictedAmmo()`，
  失败则本次本地 Shot Attempt 不成立（不播表现、不推进 `LocalFireCooldown`）；
  成功则记入 `PredictedShotsThisActivation`、推进节拍、再提交表现。
- 两处 Shot Attempt 统一走该 helper：`StartOwnerPredictedFeedback`（Semi 与 FullAuto 首拍共用）
  与 `HandlePredictedFeedbackTick`（FullAuto 每一拍）。
- 本地预算只门控本地表现与节拍：**不**参与 `CanActivateAbility`、**不**阻止 Press edge 或
  `TryActivateAbility`，**不**因预算为 0 结束 Ability 或停止 FullAuto timer。
- `EndAbility` 在释放武器缓存之前，按 `ActivationInfo.ActivationMode == Rejected` 调用
  `RefundPredictedAmmo(PredictedShotsThisActivation)`；`Cancelled` 一律不退还
  （切枪 / 换弹 / 死亡取消时服务器可能已经扣过本次 burst 的部分弹药，退还会反向过冲）。
- 权威流程未改动：`Fire()` 仍独占 `CanConsumeAmmo()/ConsumeAmmo()` 与
  Projectile / Montage / Multicast / Noise。

### 明确不做

Ammo 搬入 GAS AttributeSet、第二份完整 Ammo 镜像、PredictionKey Ledger / Shot ID / 新 RPC、
ServerReject 状态机、把 FullAuto 拆成每发一次 Ability、把 Ammo / Weapon 业务塞进 ASC。

## 遇到的问题

- 首次版式检查报 3 处：`UE_LOG` 参数跨三行、两处可合并的换行、以及一条 `UE_LOG` 首行
  comma-separated item 超过 120 列。已按检查器规则改成"格式串与参数各自成行 / 合并可合并行 /
  精简 ABSORB 标记字段"。
- 构建产出 `-0001` 变体：原因是用户已有一个 UnrealEditor 会话持有基线 DLL。
  未关闭该会话（规范禁止自动操作编辑器），改用 manifest 一致性与新 marker 内容确认运行新鲜度。

## 处理方式

- 版式问题按检查器规则逐条修正后复跑通过。
- `-0001` 变体不做额外处理（不删除 `Binaries` / `Intermediate`，也不重启用户编辑器）；
  运行新鲜度由 `AMMO_PREDICT_*` 标记的存在性证明。

  因此本地预测消费不会立即反映在 UI 上；接入点在 `PushAmmoToOwnerHud` 与另外三处 HUD 读取。
- `ShouldAttemptWhileInputActive`（Held 自动重试的弹药保守门控）未实现：
  当前 Held 重试仍会按 RTT 频率发起注定被拒的请求（既有已接受的代价）。
- `ResetAmmoPrediction` 只挂在 `ClearWeaponOwner`，未额外挂到死亡 / 单纯 Unequip /
  行配置重应用等节点；后者在纯预测模型里不是必需。
- `ApplyWeaponRow` 导致 MagazineSize 变小时会产生一次"下降"，会被当成确认消费吸收：
  当前只在测试注入路径可达（协调器 `SetReloadTestAmmo`），生产路径未触发。
- 工作区另有与本提交无关的用户改动（`UI_ShooterBulletCounter.uasset` 与
