# 收紧列表元素换行门禁

- 日期：2026-09-13
- 计划提交说明：`规范：收紧列表元素换行门禁`
- 变更类型：构建 / 测试 / 文档

## 目的

修正 120～140 列尾参数豁免过松的问题。原规则允许独立列表元素只在第 120 列前露出开头，
导致 `ShootGame.Build.cs` 中的 `StateTreeModule` 几乎完全落在常用可视区域之外。

## 本提交完成内容

- 将 `ShootGame.Build.cs` 的公开模块依赖列表改为每个模块单独一行；
- 收紧代码规范：以逗号结束的独立参数或列表元素不得跨越 120 列；
- 明确三行及以上逐项分行规则同时适用于参数、数组元素与集合元素；
- 更新 `CheckTextLayout.ps1`，对第 120 列之后出现的代码逗号直接判定失败；
- 补充集合初始化器识别，使反向门禁能够拒绝三行及以上仍在同行放置多个元素的布局。

## 验证结果

- PowerShell Parser：`CheckTextLayout.ps1` 语法通过；
- 定向宽度验证：旧 `StateTreeModule` 行宽 136，按新规则判定 Fail；
- 定向反向门禁验证：三行分组布局产生 1 个逐项分行违规，最终逐项布局产生 0 个；
- `CheckTextLayout.ps1 -Scope WorkingTree`：Passed，检查 6 个文件，0 警告；
- `CheckTextLayout.ps1 -Scope Staged`：Passed，检查 4 个文件，0 警告；
- `CheckSourceIncludePaths.ps1`：Passed，检查 126 个源码文件与 51 个头文件；
- `git diff --cached --check`：Passed；
- 未运行编译与完整回归：本提交只调整构建列表版式、规范文本及其静态门禁，
  不改变依赖集合或 Gameplay 行为。

## 遇到的问题

- 旧门禁只检查最后一个参数的起始位置，没有检查独立元素的结束位置。
- 反向门禁只识别圆括号参数组，会在集合初始化器的右花括号处停止扫描。

## 处理方式

- 将代码逗号作为完整元素的可验证结束边界，并要求该边界位于 120 列内。
- 将函数调用中的集合初始化器纳入多行参数组扫描，并复用三行以上逐项分行判定。
