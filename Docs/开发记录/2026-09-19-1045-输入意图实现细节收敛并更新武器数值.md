## 目的

上一提交（`c69567b`）把「按住可恢复」收敛为「Spec.InputPressed 是唯一持续意图来源」之后，
实现上仍留有三处只被单一调用点使用的间接层，装备侧的输入语义同步仍按形参判定，
测试钩子名与生产函数名也不一致。本提交只做实现细节收敛，不改变 Gameplay 语义；
同时纳入一处独立的武器数值（DataTable）改动与两处动画代码的折行整理。

## 本提交完成内容

### 1. ASC 延迟意图入口合并（行为不变）

- `RequestBufferedInputProcessing()` 并入 `HandleTransientBlockedTagChanged()`：
  阻塞解除时一次登记 + 调度到下一 Tick，同帧多次标签变化（含已排程）只调度一次；
  `INPUT_BUFFER_TAG_CLEARED` 标记只在实际排程时输出（原来在每次 Tag 归零时都会输出）。
- `ProcessBufferedInputs()` 更名 `ProcessDeferredInputIntents()`
  （定义、`SetTimerForNextTick` 回调、测试钩子调用同步）。
- `ConsumeBufferedInput()` / `RemoveBufferedInput()` 内联进唯一调用点，
  并删除其声明与定义；消费顺序（`IsActive()` 判定 → `TryActivateAbility` →
  已松开则补标准释放 → `INPUT_BUFFER_CONSUMED`）逐条保持不变。
- 注释按新形状重写；`HandleAbilityFailed` 的 C++17 if 初始化语句改为两条语句（等价）。

### 2. 装备侧输入语义同步一律取权威

- 触发点（装备逻辑转移 + 武器配置晚到）与状态完全不变。

### 3. 测试钩子更名

### 4. 文档

## 遇到的问题

1. `ShooterAbilitySystemComponent.cpp` 提交前有一行 `}` 后跟 184 个尾随空格（显示宽度 185），
   会被 `git diff --check` 与版式检查直接拦下。
2. 在此之前的一次自动化曾实际加载到旧模块：编辑器会话长时间持有
   `UnrealEditor-ShootGame.dll`，UBT 只能输出编号模块（`-0001`…`-0006`），
   而 `UnrealEditor.modules` 被写回基础文件名，于是命令行运行静默加载了变更前的二进制
   （报告只有 128 项、输入缓冲为旧的 9 项套件）。

## 处理方式

- 清除尾随空格后重跑 `git diff --check` 与版式检查，均通过。
- 用「按内容核对报告」的方式判定每次运行是否为新代码：本轮所有运行都核对为 130 项、
  含 4 个 `HeldRepeat*` 用例、无 `Sustained*` 旧用例；旧模块那次结果已作废并重跑。
- 编辑器退出后基础 DLL 恢复正常命名，`UnrealEditor.modules` 也回到指向基础 DLL 的天然状态，
  命令行运行不再需要任何手工干预。
