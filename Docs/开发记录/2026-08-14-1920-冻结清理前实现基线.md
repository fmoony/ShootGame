## 遇到的问题

1. 首次完整验证在 Listen Server 阶段缺少成功标记。延长测试时间后确认其余网络状态均已满足，但远端玩家为 `Kills=0`、`Deaths=1`、`Score=0`，因此 `matchState=false`。
2. 修复 Listen 时序后，一次 Dedicated 验证出现 `Projectile aim differs from server control rotation; dot=-0.289`；同一路径此前为 `1.000`，说明随机散布参与了方向断言，导致测试不稳定。
3. Git 曾将四个武器 `.h/.cpp` 文件显示为已修改，但它们与 `HEAD` 内容一致，没有实际文本差异。

## 处理方式

1. 调整测试协调器的 Listen 专用击杀步骤：对手 Pawn 不可用或未确认产生击杀时不再提前结束，等待后续轮询重试。
2. 仅在自动化测试持有的武器实例上将 `AimVariance` 临时设为零，随后分别通过 Dedicated 专项与最终全量验证；正式资产配置保持不变。
3. 增加计分字段超时诊断，使类似问题能够直接从服务器日志判断。内容一致的武器源码不纳入提交差异。
