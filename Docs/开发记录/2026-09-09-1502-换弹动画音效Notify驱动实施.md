# 换弹动画音效 Notify 驱动实施

- 日期：2026-09-09
- 计划提交说明：`音频：接入换弹动画Notify驱动的武器本地音效`
- 变更类型：生产代码 / 测试 / 资产 / 文档

## 目的

为换弹动画接入武器音效（弹匣退出 / 弹匣插入 / 拉枪机上膛），由序列内 AnimNotify 在各端本地触发，与各机同步播放的换弹动画同源同时，不新增任何网络通道。换弹动画本身已由 `State.Reloading` Tag 复制驱动（各端 AnimInstance 各自播放 Sequence），AnimNotify 为本地评估事件，因此各端声音与画面天然同步、无需 RPC。

## 本提交完成内容

- 新建 `Source/ShootGame/Weapons/ShooterAnimNotify_WeaponSound.h/.cpp`：`UShooterAnimNotify_WeaponSound`（编辑器显示名 WeaponSound，英文枚举 MagazineOut/MagazineIn/Cocking 直接显示）；`Notify()` 三重守卫——仅第三人称 Mesh 出声（防 FP/TP 双 Mesh 双份声音）、仅 `bIsReloading` 期间接受（防取消后迟到 Notify）、经 `GetCurrentWeaponActor()` 路由到当前武器。
- 修改 `Source/ShootGame/Weapons/ShooterWeapon.h/.cpp`：新增三个音效属性 `ReloadMagazineOutSound / ReloadMagazineInSound / ReloadCockingSound` 与 `PlayReloadSoundStage()`——Dedicated 服务器早退，`SpawnSoundAttached` 挂第三人称武器 Mesh 的 `MuzzleSocketName`（骨骼位置），附时序日志 `Reload sound stage %d triggered (Sound=%s)`。
- 修改 `Source/ShootGame/Tests/ShooterWeaponAutomationTests.cpp`：`ShootGame.Weapon.Configuration` 新增断言——Rifle/Pistol 蓝图三音效非空；`MM_Rifle_Reload` / `MM_Pistol_Reload` 各含三阶段 WeaponSound Notify（直接读 `UAnimSequence::Notifies`，补 MCP 无法读取序列 Notify 的验证缺口）。
- 编辑器配置（人工）：两个换弹序列各放 3 个 WeaponSound Notify；`BP_ShooterWeapon_Rifle` / `BP_ShooterWeapon_Pistol` 填入 `Content/Weapons/_PublicAudio/` 三个音效资产（换弹所用三个音效随本提交入库）。

## 验证结果

- 外部 UBT 编译通过；`RunAll.ps1 -Port 17794` 全量回归两次（配置后与英文化后各一次），七阶段（Build/Automation/Standalone/DedicatedNetwork/ListenNetwork/EmulatedNetwork/DisconnectCleanup）全部 Passed，81 个测试 0 失败，无 `AUTOMATION_TEST_FAILURE`，断线清理 Orphans=0，无残留进程。
- Emulated 弱网阶段实证双端同步：一次真实 Rifle 换弹中两个客户端在 3ms 内各自触发同阶段音效日志（各自动画驱动 Notify，无 RPC）。
- 用户 PIE 人工验收通过：本地三阶段各响一次、位置跟随武器、无双重声；远端旁观声画对齐；取消不出声。

## 遇到的问题

- 编译时编辑器占用 DLL，UBT 生成热重载补丁编号模块（`UnrealEditor-ShootGame-0003.dll`）；新增 UCLASS 依赖用户完全重启编辑器后才会出现在 Notify 选择器，已提示用户重启后配置。
- 网络协调器的换弹阶段使用无动画类的 C++ 测试武器（`SetAnimInstanceClass(nullptr)` 清空 TP AnimBP），会话内换弹默认不走动画、不触发 Notify，无法直接作为音效链路的网络证明。
- 实施中途曾按用户意见调整方案：评估"Notify 直接传音效资产 + 武器覆盖表"替代 Stage 枚举，用户最终决定保留 Stage 枚举与武器侧配置，仅要求编辑器可见文本英文化（枚举中文 DisplayName 移除、日志改英文，注释保持中文）。

## 处理方式

- 热重载问题：明确要求用户重启编辑器加载新类后再做序列配置。
- 网络证明缺口：将时序日志移至函数入口（含未配置音效情况）；实测弱网阶段恰有一次真实 Rifle 换弹（随后被取消阶段打断），两客户端 3ms 内各自记录阶段 0 日志，作为双端同步实证；完整三阶段听感由用户 PIE 验收覆盖。
- 英文化调整：枚举去掉中文 `UMETA(DisplayName)` 直接显示英文成员名，日志消息改英文；枚举成员名与类路径未变，用户已配置的序列 Notify 与武器蓝图不受影响，改后重跑全量回归通过。

## 遗留项

- 本地玩家自身换弹音为空间化 3D（与 FireSound 同策略）；第一人称加强/2D 化需改 `PlayReloadSoundStage` 单处。
- 音量/衰减调优在音效资产侧进行，未处理。
- 若将来多武器共用换弹序列且需按武器差异化音效，再评估武器侧覆盖表方案。
- `_PublicAudio` 资产目录未迁移整理。
- 工作区中与本功能无关的用户已有资产改动（`ABP_FP_Pistol`、`ABP_TP_Pistol`、`ABP_TP_Rifle`、`BP_ShooterWeapon_AWP`、`BP_ShooterWeapon_GrenadeLauncher` 及 AWP/榴弹开火音效资产调整）未纳入本提交，待用户后续整理。
