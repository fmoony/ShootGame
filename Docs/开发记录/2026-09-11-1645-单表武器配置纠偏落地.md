# 单表武器配置纠偏落地

- 日期：2026-09-11
- 计划提交说明：`武器：收敛为 DT_WeaponData 单表武器配置并撤销 Definition 层`
- 变更类型：生产代码 / 测试 / 资产 / 文档

## 目的

执行 [单表武器配置纠偏小计划](../执行计划/单表武器配置纠偏小计划.md)（C0～C3）。

纠偏前武器配置存在三份来源：`DT_WeaponData` 行（只保存预览网格 + Definition 软引用）、
`WD_*` WeaponDefinition 资产（ActorClass / Ammo / Fire / Presentation / FireBehavior）、
以及真正生效的 `BP_ShooterWeapon_*` CDO。本提交把武器模板收敛为单表：

```text
DT_WeaponData（唯一武器模板库）
→ Pickup / NPC 只选择一行
→ 该行决定 WeaponActorClass、玩法参数与表现资源
```

并撤销不符合当前 Demo 规模的 `UShooterWeaponDefinition + FPrimaryAssetId` 配置层。
Actor Pool、WeaponActor 生命周期状态机与既有网络闭环保持不变。

  `APlayerController::AddControllerPitchInput` 直接叠加到控制旋转 Pitch
  （`RotationInput.Pitch += Val`，`ProcessViewRotation` 再累加到 `ViewRotation`）；
  UE 约定 Pitch 正值抬头、负值下压。四把武器现值均为负（-0.05 / -0.1 / -0.1 / -0.3），
  属既有生产基线，本次只统一语义与约束（新行字段 `ClampMin=-100`），不修改数值。

### C2 切换生产消费路径

  `WeaponRowName`（`FName`）。随之删除 `FShooterWeaponInstanceEntry::NetSerialize`、
  `WithNetSerializer` 特化与 `SetDeltaSerializationEnabled(false)`，恢复默认 Struct Delta。

- `AShooterWeapon::SetBoundInstanceId` → `SetInstanceBinding(InstanceId, RowName)`；
  新增全端复制属性 `WeaponRowName` + `OnRep_WeaponRowName`。绑定时 `ApplyWeaponRow`

  弹药经济、开火节奏、时序、Socket、视角参数），并按行的 `FireBehaviorClass` 实例化行为。
- `ResolveFireBehavior` 改为返回按行创建的行为实例；`FShooterWeaponFireContext` 用

- 删除 `GetMagazineCapacity()`，换弹事务与 GA_Reload 预检统一读 `GetMagazineSize()`

- `AShooterNPC` 新增 `WeaponRowName`：行名有效时由行决定 `WeaponActorClass` 与全部配置；

## 遇到的问题

1. **资产写入被文件锁阻塞**：迁移工具首次运行在 `UPackage::SavePackage` 的
   `MoveFile` 阶段报 Error Code 32 并导致 `UnrealEditor-Cmd` 进程崩溃（
   `Content/Shooter/Data/DT_WeaponData.uasset` 无法被重命名或覆盖）。
2. **`[CoreRedirects] +StructRedirects` 未生效**：按 UE 官方 Core Redirects 文档在
   `DefaultEngine.ini` 加入 `FWeaponTableRow → FShooterWeaponConfigRow` 重定向后，
   `DT_WeaponData` 加载时仍报 `Missing RowStruct while loading DataTable`，
   RowStruct 解析为空。
3. **一次性工具测试完全不被 Automation 发现**：`Found 0/No automation tests matched`，
   但同一 DLL 中其他项目测试可被发现。
4. **新增测试名与既有测试名前缀冲突**：新增
   `ShootGame.Weapon.Configuration.ProductionRowsResolvable` 后，父路径测试
   `ShootGame.Weapon.Configuration` 从发现列表中消失。
5. **清空蓝图 CDO 后三个按 CDO 读取武器配置的断言失败**：
   `ShootGame.Ability.Fire.FullAutoRelease`（读 `bFullAuto` / `RefireRate`）、
   `ShootGame.Equipment.Presentation.AnimClassMapping`（读 FP/TP AnimClass）、
   `ShootGame.Weapon.Configuration`（读弹药 / 网格 / 表现资源）；
   `ShooterFirstPersonCapture.cpp` 也依赖 BP 网格与 AnimClass。
6. **`USkeletalMesh` 没有 `DoesSocketExist`**：首版行校验测试直接调用该函数导致编译失败。

## 处理方式

1. 先用 Restart Manager（`rstrtmgr.dll`）确认锁的持有者：编辑器运行期间是 `UnrealEditor`，
   编辑器退出后一度仍由 `devenv`/残留句柄短暂持有。按项目规范没有自动关闭或操纵 VS 与编辑器，
   而是请用户关闭 Unreal Editor；锁释放后重跑迁移工具，写盘成功。
2. 迁移工具改为不依赖核心重定向：显式执行 `EmptyTable()`（先按当前 RowStruct 释放旧行）→
   赋新 `RowStruct` → `AddRow` 重建四行 → 保存，并在工具内逐行回读。由于工具会完整重建行数据，
   重定向缺失不会造成数据丢失；随后删除该无效配置，避免留下误导性的死配置。
3. 根因是编辑器占用 DLL 期间的增量构建留下了多个 chunk DLL
   （`UnrealEditor-ShootGame-0001/-0002/-0006/-0010.dll`）与陈旧根 DLL 混用；
   编辑器退出后重新链接得到单一模块 DLL，测试发现恢复。
4. UE Automation 的名称前缀冲突：把新增测试改名为同级
   `ShootGame.Weapon.ProductionRowsResolvable` 后，两个测试都恢复被发现。
5. 把三处断言与 Capture harness 改为读取武器模板行（`ShooterWeaponTable` /
   `FShooterWeaponConfigRow`）：`AnimClassMapping` 改用行内 AnimClass，
   `FullAutoRelease` 读 Rifle 行的 `bFullAuto`/`RefireRate`，
   `Weapon.Configuration` 全面改为按行校验（含四把武器），
   Capture harness 直接使用生产行名授予。
6. 改用 `USkeletalMesh::FindSocket(Name) != nullptr`，与运行时
   `USkeletalMeshComponent::DoesSocketExist` 语义一致。
