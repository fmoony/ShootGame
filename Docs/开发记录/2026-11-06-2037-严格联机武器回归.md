# 严格联机武器回归

- 日期：2026-11-06
- 计划提交说明：测试：按玩家和武器实例验收严格联机
- 变更类型：测试 / 文档

## 目的

旧联机夹具在 Listen 模式下将首个模拟代理误作固定对手。
修复身份映射，并验证切枪、开火、换弹和重生后重新占有。

## 本提交完成内容

- RunNetworkSession.ps1 提供严格入口，并拒绝跳过 CurrentWeapon 或远端 Montage 的参数。
- ShooterNetworkTestCoordinator 与严格用例核对 PlayerId、Pawn、武器实例和序号。
- 每位玩家执行三轮真实动作，其中一轮在重生后执行。各端核对权威结果、拥有端即时反馈及旁观端开火表现。
- 自动化测试文档补充 Listen 和 Dedicated 运行方式。

## 验证结果

- ShootGameEditor Win64 Development 构建通过。引擎、项目和 MCP 模块清单的 Build ID 一致。
- Listen 单客户端、Listen 双客户端、编辑器 Dedicated 双客户端均通过普通网络和 PktLag=100。
- 三人延迟场补跑通过。服务器记录远端 Equip、Fire、Reload 各六次 RPC 接受。
- 全量自动化完成 201 项，失败和跳过均为零，其中 64 项带警告。

## 遇到的问题

- 切枪复制可能早于拥有端装备阻塞 Tag 清除。三人延迟场的串行重生等待可能耗尽 60 秒门禁。
- 批量命令中日志参数的引号阻止 GAS Verbose 生效。

## 处理方式

- 输入等待实际开火条件成立。每次死亡获全员确认后，重生计时与下一名玩家的轮次重叠。
- 单独补跑三人延迟场并记录引擎层 RPC 接受日志。

## 遗留项

- 本提交证据来自编辑器运行时。正式 Cook、独立客户端和 Server 由后续验收覆盖。
- 严格网络矩阵覆盖正向动作。拒绝回滚、跨机器联机和实际视听输出需单独验证。
