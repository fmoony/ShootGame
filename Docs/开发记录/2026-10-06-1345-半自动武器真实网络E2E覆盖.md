# 半自动武器真实网络 E2E 覆盖

- 日期：2026-10-06
- 计划提交说明：`测试：补齐半自动武器的真实网络单发与按住不发证据`
- 变更类型：测试

## 目的

上一个提交（`重构：将开火语义收敛为一次 GA_Fire Activation 一发 Shot`）
已经证明"一次 Activation 恰好一发"，但网络夹具的被试武器固定为
正式 `Rifle`（全自动），半自动 `OnInputTriggered` 策略分支只有
Ability 层 Automation 覆盖。夹具运行时因此显式声明过缺口：

```text
AMMO_PREDICTION_EVIDENCE_GAP Case=SemiAutoSingleShot Reason=WeaponIsFullAuto
```

本提交用**真实半自动武器行**补上这条端到端证据，并新增
"按住不放不得重复开火"这条半自动专属不变量。

## 本提交完成内容

- `Tests/Weapon/ShooterWeaponRowCompletenessAutomationTests.cpp`：
  新增输入策略数据层守卫——正式武器行必须同时存在全自动与半自动武器，
  并输出半自动行清单（`WEAPON_SEMI_AUTO_ROWS`）。
  守卫失败时半自动 E2E 会失去验证对象，因此必须在数据层先失败。
- `Tests/Network/ShooterAmmoPredictionNetworkTests.cpp` 与
  `ShooterNetworkTestCoordinator.h/.cpp`：
  - 夹具按运行时武器表**动态挑选**第一个半自动行（按行名排序保证确定性），
    用与 Rifle 相同的授予 / 装备路径把被试角色切到该武器，
    并把夹具钉住的武器指针改到它上面；
  - 拥有端观测新增"当前武器身份 + 是否全自动"，
    使每个用例都能自证跑在什么武器上；
  - 新增用例 `SemiAutoWeaponSingleShot`（一次按下沿 → 一次 Activation
    → 一发 Shot → 一次拥有端表现）与 `SemiAutoHold`
    （按住 ≥3 个射速周期，权威发数必须恰好 1）；
  - 用例总数 `Cases=12`。

## 验证结果

### 数据层守卫

```text
pwsh -File Scripts/Tests/RunAutomation.ps1 -TestFilter ShootGame.Weapon.ProductionRowsResolvable
[Summary] Passed=1 Warnings=0 Failed=0 NotRun=0
WEAPON_SEMI_AUTO_ROWS Rows=Pistol,AWP,GrenadeLauncher FullAutoRows=1 SemiAutoRows=3
```

### 网络 E2E（Dedicated，2 远端客户端，会话 20261006_135027）

夹具动态挑中 `AWP`（行名排序后第一个 `bFullAuto == false` 的正式行），
换枪后用拥有端自己的观测确认武器身份：
```text
AMMO_PREDICTION_SEMI_AUTO_PICK Row=AWP
AMMO_PREDICTION_SEMI_AUTO_SWITCH Step=11 Row=AWP FullAuto=0 Size=10 RefireRate=2.000
  Mag=10 Reserve=10 Hold=6.00
AMMO_PREDICTION_SEMI_AUTO_READY Row=AWP OwnerWeapon=BP_ShooterWeapon_AWP_C_1
  OwnerFullAuto=0 OwnerMag=10 OwnerReserve=10
```

两个新用例（原日志为单行，这里为版式折行）：

```text
CONVERGED Case=SemiAutoWeaponSingleShot Row=AWP OwnerFullAuto=0 Shots=1 Accepted=1
  Rejects=0 ClientAct=1 Keys=1 Verdicts=1 Predicted=1 Backfill=0 Pending=0
  MagDelta=-1 Records=0 LastKey=101 Committed=1
CONVERGED Case=SemiAutoHold Row=AWP OwnerFullAuto=0 HoldSeconds=6.00 RefireRate=2.000
  Shots=1 Accepted=1 Rejects=0 ClientAct=1 Keys=1 Verdicts=1 Predicted=1 Backfill=0
  Pending=0 MagDelta=-1 Released=1 Records=0 LastKey=102 Committed=1
AMMO_PREDICTION_OBSERVER_SUCCESS Predicted=0 Backfill=0 Verdicts=0
AUTOMATION_TEST_AMMO_PREDICTION_DONE Cases=12 Converged=12 Mismatches=0
```

要点：

- `SemiAutoWeaponSingleShot`：一次按下沿 → 拥有端 1 次 Activation / 1 个唯一 Key
  → 服务器 1 次被接受 Activation / 1 发权威 Shot / 0 次拒绝
  → 拥有端 1 次表现、0 次补播；`Pending` 回到起点，`Records=0`。
  这正是"一次 GA_Fire Activation 恰好一发"在半自动真实武器上的端到端形状。
- `SemiAutoHold`：按住 6.00 秒（= 3 × 该行 RefireRate 2.0s，期间本可打 3 发）
  **权威发数恰好 1**，且 `Released=1` 证明窗口真的结束过——
  因此"没有连发"不是因为第二发还没轮到，而是半自动策略本身不重复开火。
- 两个用例都由拥有端观测自证 `Row=AWP`、`OwnerFullAuto=0`，
  不可能与全自动用例的结论混淆。

### 网络 E2E（Emulated，两端 `-PktLag=100`，会话 20261006_135503）

同一夹具在 100ms 单向延迟下同样全用例收敛
（`Cases=12 Converged=12 Mismatches=0`）。两个半自动用例的取值与无延迟会话完全一致：

```text
CONVERGED Case=SemiAutoWeaponSingleShot Row=AWP OwnerFullAuto=0 Shots=1 Accepted=1
  Rejects=0 ClientAct=1 Keys=1 Verdicts=1 Predicted=1 Backfill=0 Pending=0
  MagDelta=-1 Records=0 LastKey=101 Committed=1
CONVERGED Case=SemiAutoHold Row=AWP OwnerFullAuto=0 HoldSeconds=6.00 RefireRate=2.000
  Shots=1 Accepted=1 Rejects=0 ClientAct=1 Keys=1 Verdicts=1 Predicted=1 Backfill=0
  Pending=0 MagDelta=-1 Released=1 Records=0 LastKey=102 Committed=1
AUTOMATION_TEST_AMMO_PREDICTION_DONE Cases=12 Converged=12 Mismatches=0
```

弱网下 `Pending` 仍收敛到起点、`Records=0`、`Rejects=0`，
说明半自动的"每次按下沿一次动作边界"在延迟下不会被重放成多发。

## 遇到的问题

无。半自动武器行的存在性由数据层守卫保证；夹具按表动态挑选，
并通过完整授予 / 装备路径换枪，首次运行即收敛。

## 处理方式

无。

## 遗留项

1. 半自动证据目前覆盖"一次按下沿 ⇒ 一发"与"按住 ⇒ 恰好一发"；
   未覆盖"两次独立按下 ⇒ 两发"（第二发需要等待 AWP 的 2.0s 本地节拍，
   本轮没有为此增加步骤）。
2. 换枪只切换被试武器，Rifle 仍在背包中；
   "半自动武器单独装备时"的 HUD / 表现不在本轮范围。
3. `AWP` 的 RefireRate 为 2.0s，因此本轮半自动证据与高射速无关；
   高射速（600 / 900 RPM）仍由全自动 Rifle 行覆盖。
