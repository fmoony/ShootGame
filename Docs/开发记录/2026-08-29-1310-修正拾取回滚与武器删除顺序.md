# 修正拾取回滚与武器删除顺序

- 日期：2026-08-29
- 计划提交说明：`背包：修正拾取回滚与武器删除顺序`
- 变更类型：生产代码 / 测试 / 构建

## 目的

执行《武器装备表现事件收束与动画切换解耦执行计划》E1：修复两个生命周期缺陷——Pickup 在 Add 成功但首次 Equip 失败时留下已加入 Inventory 的武器；Inventory Remove / Clear 先销毁 WeaponActor 再通知 Equipment，导致当前装备 Deactivate 时对象已经失效。

## 本提交完成内容

- `Source/ShootGame/Weapons/ShooterPickup.cpp`：
  - Equip 失败分支调用 `RemoveWeaponInstance(GrantedInstanceId)` 完整回滚本轮新增 Instance 与 WeaponActor，再恢复 Pickup 可拾取；回滚失败输出 Warning。
- `Source/ShootGame/Inventory/ShooterInventoryComponent.cpp`：
  - `RemoveWeaponInstance`：先移除逻辑 Entry → 广播 `OnWeaponInstanceRemovedFromInventory` → 再 Unregister + Destroy。
  - `ClearInventory`：冻结待销毁 WeaponActor 列表 → 清空逻辑 Entries → 广播 `OnInventoryCleared` → 再统一 Unregister + Destroy；空 Inventory 重复 Clear 幂等返回。
  - 未新增 `OnWeaponRegistered`（计划 8.1）。
- `Source/ShootGame/ShootGame.Build.cs`：新增 `ShootGame/Tests/Equipment` include path，供测试共享新测试类型头文件。
- 新增 `Source/ShootGame/Tests/Inventory/ShooterInventoryLifecycleAutomationTests.cpp`：
  - `Pickup.EquipFailureRollback`、`Remove.CurrentWeaponOrder`、`Remove.NonCurrentKeepsCurrent`、`Clear.WeaponDestroyOrder` 四个生命周期验证。

## 遇到的问题

- 测试武器重写 `DeactivateWeapon()` 记录调用顺序失败：基类方法不是 virtual，`TObjectPtr<AShooterWeapon>` 调用时静态绑定到基类实现，子类标志不会置位。
- `ShooterPickup.cpp` 原无 `LogShootGame` 声明，新增 Warning 日志时编译失败。
- 新测试文件放在 `Tests/Inventory`，引用 `Tests/Equipment` 下的测试类型头时因 include path 缺失编译失败。

## 处理方式

- 顺序证据改为断言 `IsHidden()`（DeactivateWeapon 的后置条件）在 `IsActorBeingDestroyed()` 前成立，不依赖 virtual 分派。
- 为 `ShooterPickup.cpp` 增加 `#include "ShootGame.h"`。
- 在 `ShootGame.Build.cs` 增加 `ShootGame/Tests/Equipment` include path。

## 遗留项

- Owner Client 的 FastArray Remove/Clear 回调与服务器路径的等价性由后续 Dedicated / Listen 网络会话验证。
- 测试世界未调用 EndPlay，日志存在 CleanupWorld Warning，属测试环境噪音。
