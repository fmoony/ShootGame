# 迁移 AnimBP 数据源到 C++ 快照

- 日期：2026-08-26
- 计划提交说明：`动画资产：迁移 AnimBP 数据源到 C++ 快照`
- 变更类型：动画 C++ + AnimBP 资产 + 测试

## 目的

执行《Shooter 核心玩法架构解耦重构执行计划》R6.3 的功能部分：让 TP AnimBP 的 AimOffset、状态机移动输入和 Transition 规则改为消费 C++ AnimInstance 快照，不再依赖蓝图 EventGraph 每帧手工计算。按用户决定，本提交先完成数据源切换和全量验证；旧 EventGraph 计算节点暂时保留，后续再清理。

## 本提交完成内容

- `UShooterAnimInstanceBase`：
  - 新增 `Velocity`（BlueprintReadOnly），与 `LocomotionGroundSpeed`、`bIsInAir` 一起由 `RefreshCommonAnimationData` 每帧采集并随 `ClearCommonAnimationData` 清空。
- `UShooterThirdPersonAnimInstance`：
  - 新增 `AimPitchN`：来源与旧图完全一致，调用 `AShooterCharacter::GetAimPitchN()`。
  - 新增 `MoveDirection`：`UKismetAnimationLibrary::CalculateDirection(Velocity, Character->GetActorRotation())`；`bOrientRotationToMovement` 为 false 时夹取到 ±45°，与旧 Select/Clamp 图等价。
  - 新增 `bShouldMove`：`LocomotionGroundSpeed > 0.01f`，与旧 `ShouldMove` 图阈值一致。
  - 无 Character 分支同步清空上述三个值。
- 手工资产改动（编辑器内完成）：
  - `ABP_TP_Rifle` / `ABP_TP_Pistol` AnimGraph：AO_Rifle/AO_Pistol 的 `Y` 改连继承属性 `Get AimPitchN`。
  - 两个 TP 状态机 `FPP_Run`：Blendspace 改连 `Get MoveDirection` 与 `Get LocomotionGroundSpeed`。
  - Transition 规则改连 `Get bShouldMove` 与 `Get bIsInAir`。
  - `ABP_TP_Rifle` 删除断链的 `Get CurrentWeapon`；两个 TP 资产删除会与新基类属性冲突的 `Set Velocity`。
- 测试更新：`ShootGame.Animation.InstanceHierarchy` 增加 `Velocity` 共享属性断言，以及 `AimPitchN` / `MoveDirection` / `bShouldMove` 属于 ThirdPerson、不泄漏进基类的断言。
- 未修改 FP AnimBP 的 ControlRig、姿势或其余旧变量。

## 遇到的问题

- 新基类属性 `Velocity` 与 TP AnimBP 旧变量同名；旧 `Set Velocity` 节点在新 DLL 下会报“BlueprintReadOnly 不可写”。按迁移清单手工删除 `Set Velocity`，其余只读 Get 节点与新属性同名时由编辑器正确指向继承属性。
- 用户选择暂时保留大部分旧 EventGraph 计算节点；这些节点仍会执行并写旧蓝图变量，但 AnimGraph 与状态机已不再消费这些旧变量，因此不影响当前结果。旧节点清理另行安排。
