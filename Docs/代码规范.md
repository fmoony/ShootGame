# ShootGame 代码规范

以现有 `Source/ShootGame/` 代码为准，新代码遵循下列约定。

## 命名

- UE 标准前缀：`A`（Actor）、`U`（UObject）、`F`（Struct）、`E`（Enum）、`I`（Interface）、`T`（模板）。
- 类名、方法名、成员变量一律 PascalCase：`AShooterWeapon`、`StartFiring()`、`CurrentBullets`。
- 布尔变量用 `b` 前缀：`bFullAuto`、`bIsFiring`、`bReplicates`。
- Getter 用 `Get` 前缀：`GetBulletCount()`、`GetFirstPersonMesh()`。
- 指针成员优先 `TObjectPtr<T>`（UE 5 风格，参考 `ShooterWeapon.h` 的 `PawnOwner`）。
- 成员变量在声明处初始化默认值（`int32 MagazineSize = 10;`），不在构造函数里重复赋值。

## 文件结构

- 头文件用 `#pragma once`，`#include "X.generated.h"` 必须放在最后。
- include 顺序：自身头文件 → `CoreMinimal.h` → 引擎头文件 → 项目内头文件。
- 头文件里前向声明（`class X;`）优先于 include，减少依赖。
- `UCLASS(abstract)` 用于不直接实例化的基类（如 `AShooterCharacter`、`AShooterWeapon`）。

## 版式与换行

### C++、C# 与 PowerShell

- 显示宽度口径：Tab 按 4 列，中文与全角字符按 2 列。
- 120 列是常规边界，140 列是绝对上限；120 不是要求填满的目标。
- 普通代码行不超过 120 列时不换行。
- 不需要换行时保持一行，不为凑垂直结构拆分本可放下的调用或声明。
- 超过 120 列但不超过 140 列时，仅当 120 列处已经位于“最后一个参数”内才允许：
  从 120 列处逐层向外检查每个括号组，该位置必须落在该层最后一个参数内；
  最外层尾参数中最深的尾巴（如 `k(A,B,C(a,b))` 的 `b`）至少有一部分仍在 120 列以内，
  完全看不见就必须换行。
- `if`、`return` 等表达式按“最后一个操作数”判断；整个表达式没有可分边界时视为一个尾单元。
- 超过 140 列必须换行。
- 注释（`//` 与 `/**/`）超过 120 列即换行，按标点断句，不享受 120～140 列的尾巴豁免。
- 字符串字面量 140 列以内不拆；超过 140 列在语义边界拆成相邻字面量。
- `http://`、`https://`、`/Game/...`、`/Engine/...`、`/Script/...` 是不可拆单元：
  整行基本就是一个 URL 或资产路径时不参与宽度检查；嵌在参数里且整行超过 140 列时，
  把该 URL / 路径整体移到下一行，不截断。
- 行首缩进使用 Tab，Tab 宽度为 4；续行固定增加一级缩进，不使用大量空格与左括号对齐。
- 参数列表优先一行；一行放不下时优先两行（参数整体打包到续行）；
  需要三行或更多时，每个参数单独一行，右括号跟随最后一个参数。
- 禁止为凑宽度把未超过两行的参数列表拆成每参数一行。
- 长条件在 `&&`、`||` 之后换行，运算符保留在上一行末尾。
- 三元表达式换行时，`?` 和 `:` 放在续行开头。
- `UPROPERTY`、`UFUNCTION` 等反射宏超限时拆分宏参数，不保留超长声明。

### Markdown

- 普通文本上限为 100 个显示列；围栏代码块执行对应语言规则，默认上限为 120 列。
- 一个完整语义句占一行；超限时在分句边界改写，不在术语、行内代码、链接或路径中间截断。
- 列表续行缩进两个空格；标题、列表、代码块和相邻段落之间保留空行。
- 明显过宽的表格改为分节列表；URL 所在行允许超过上限。

### 增量门禁

- 历史代码不做全仓机械重排；新建或修改的行必须满足本节规则。
- 提交前暂存本次目标文件，再运行
  `Scripts/Development/CheckTextLayout.ps1 -Scope Staged` 和 `git diff --check`。
- 检查器对 120～140 列之间无法自动判定参数边界的行只输出黄色警告，由提交者人工确认。
- 检查器会反向标记“能合并成更少行却多折”的冗余换行：
  涉及的每一行都是本次修改行时计为失败，否则只输出黄色警告；
  PowerShell 的 `param` 块按语言惯例不参与反向检查。
- 纯格式调整必须独立提交，不与 Gameplay 行为、资产或配置变更混合。
- `.clang-format` 只负责缩进、大括号与空格，不负责断行（`ColumnLimit: 0`）；
  断行按本节规则执行，`.editorconfig` 统一编辑器基础设置，增量检查脚本是提交门禁。

依据：Epic C++ Coding Standard 要求 Unreal 代码使用 4 字符 Tab 缩进和 Allman 大括号，
并建议大范围空白修正独立提交；UE 的格式化配置同样关闭列宽自动折行，
断行按可读性由提交者决定，项目在此基础上补充 120/140 与最后参数豁免规则。

## 注释与文档

- 新代码注释优先中文；英文注释仅允许保留在未改动的模板代码中。
- UPROPERTY、UFUNCTION、类成员用 `/** ... */` 块注释说明用途。
- 修改文件时，被修改的注释同步改为中文，避免中英混杂。

## 日志

- 正式代码使用 `LogShootGame`（在 `ShootGame.h` 定义）。
- 正式逻辑不得使用 `LogTemp`；统一使用 `LogShootGame`，便于自动化日志筛选。
- 日志消息用 `TEXT("...")` 包裹，运行时信息用 `*GetNameSafe()` 取名字符串。

## 网络代码

结合 [多人网络改造计划](已完成计划/多人网络改造计划.md) 的原则：

- 持续状态用 `UPROPERTY(ReplicatedUsing = OnRep_X)` + `GetLifetimeReplicatedProps` 注册；短暂事件用 RPC。
- 服务器权威逻辑入口加 `HasAuthority()` 检查；客户端只提交输入意图，不直接改状态。
- 复制变量在 `OnRep` 中做表现更新，且 OnRep 与服务器修改共用同一个幂等更新函数（参考 `AShooterCharacter::ApplyCurrentWeapon`）。
- 第一人称摄像机、第一人称手臂、本地 HUD 只允许本地 Controller 访问，网络属性对第三方客户端保持 OwnerOnly 或不可见。

## 自定义网络序列化

通用规则：

1. 默认优先使用 UE 原生反射复制与原生网络容器（`UPROPERTY(Replicated)`、`FFastArraySerializer` 等）。
2. 只有存在明确实际理由时才使用自定义 `NetSerialize`，例如：
   - 字段不是 UHT 反射类型，无法声明为 `UPROPERTY`；
   - 需要压缩协议或自定义位布局；
   - 存在明确的特殊兼容需求。
3. 自定义 `NetSerialize` 必须在对应领域架构文档说明：
   - 为什么需要；
   - 哪些字段属于手动网络协议；
   - 删除该定制需要满足什么条件。
4. 手写 `NetSerialize` 时：
   - 新增网络字段必须同步更新 Serializer；
   - 必须有自动化 / 网络测试覆盖；
   - 不允许仅依赖代码审查发现遗漏。
5. 自定义网络序列化应尽量局限在网络边界，不应为了使用默认复制而无意义地扭曲上层 Gameplay 数据模型。
6. 对 FastArray：
   - `MarkItemDirty` / `MarkArrayDirty` 规则仍必须遵循；
   - 自定义 Item `NetSerialize` 不等于重新实现 FastArray；
   - 修改 Struct Delta 开关时必须记录原因。

Inventory 的具体约束见 [Inventory 与武器数据架构](架构/Inventory与武器数据架构.md)；代码规范只保留通用规则，不复制具体实现说明。

## 提交前开发记录

- 每个新提交必须先完成一份 [开发记录](开发记录/README.md)，再执行 `git add` 和 `git commit`。
- 开发记录必须说明计划提交说明、改动目的、实际改动、验证结果、遇到的问题、处理方式和遗留项。
- “遇到的问题”不得省略；没有问题时明确写“无”。验证失败、环境故障、错误尝试和中途修正都应如实记录。
- 开发记录与对应代码、蓝图、脚本或文档必须进入同一个提交，不能在提交后另开“补记录”提交。
- 提交前使用 `git diff --cached --name-only` 确认记录文件已经暂存；记录缺失时禁止提交。
- 提交前运行 `Scripts/Development/CheckTextLayout.ps1 -Scope Staged`，新增或修改行不合规时禁止提交。
- 记录只约束规范生效后的新提交，不补写、不 amend、不 rebase 已有提交。
