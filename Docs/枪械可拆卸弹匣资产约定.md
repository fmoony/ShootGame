## 1. 目标与边界

每把枪应具备可独立控制的弹匣骨骼、有效蒙皮、统一挂点和独立弹匣网格。
隐藏或移动弹匣时，枪体不应跟随变形；独立弹匣装回挂点后应与原位置重合。
仅存在名为 Magazine 的骨骼或挂点，不足以证明这些条件成立。

本轮不接入实际换弹动画、AnimNotify、运行时弹匣组件或新增 RPC。
弹药转移仍由服务器的 Reload 事务执行，动画和弹匣资产不取得 Gameplay 权威。
现有 FP/TP 整枪配置、枪体参考姿态、枪口与左手握把变换保持原有语义。

## 3. 统一资产接口

### 骨骼与权重

- Rifle、Pistol、AWP 使用 `Magazine`；GrenadeLauncher 保留 `Clip_Bone`。
- 弹匣区域应能作为刚性部件独立移动，枪身顶点不得受到弹匣骨骼影响。
- 检查实际骨骼层级、顶点权重和三角面边界，不以骨骼名称代替检查。
- 覆盖整枪所有可用 LOD，避免远距离弹匣恢复原位或枪体被隐藏。
- 不修改已有枪体骨骼的参考变换，不重命名已有有效弹匣骨骼。

### 统一挂点

每个整枪 SkeletalMesh 设置 Mesh Socket `MagazineSocket`，父级为对应弹匣骨骼。
挂点相对骨骼采用零位移、零旋转、单位缩放，作为独立弹匣的装回参考帧。
挂点保存在 Mesh 上，避免共享 Skeleton 时把专用挂点扩散到其他网格。
最终需要确认不存在同名挂点歧义，且保存重载后仍解析到预期骨骼。

### 独立弹匣网格

独立资产采用 `SM_<Name>_Magazine`，保存于以下目录。

```text
/Game/Weapons/<Name>/Meshes
```

`<Name>` 为对应 WeaponId：Rifle、Pistol、AWP 或 GrenadeLauncher。
网格顶点使用对应弹匣骨骼的参考局部空间，pivot 与该骨骼对齐。
相对变换为 Identity 时，网格应准确装回 `MagazineSocket`。
保留弹匣原材质、UV、法线和尺寸；不要将整枪缩放或旋转补偿烘焙到弹匣上。

整枪默认仍包含弹匣；独立网格供后续动画在原弹匣隐藏后使用。
未来同时显示原弹匣和独立网格会产生重复几何，接入方必须管理二者切换。
隐藏弹匣骨骼后，不应直接依赖该骨骼上的挂点显示替代件；需核验实际缩放行为。

## 4. 官方依据与本地 UE 5.6 核对

官方 `SkeletonModifier` 支持添加骨骼，新增骨骼变换位于父骨骼局部空间。
修改需要调用 `commit_skeleton_to_skeletal_mesh()` 提交到网格。
[官方 SkeletonModifier 5.6 API](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/SkeletonModifier?application_version=5.6)

官方 `SkinWeightModifier` 支持按顶点读写骨骼权重；提交权重会执行归一化。
提交会使资产变脏，保存资产是后续独立步骤。
[官方 SkinWeightModifier 5.6 API](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/SkinWeightModifier?application_version=5.6)

官方 Socket 文档区分 Skeleton Socket 与专属 Mesh Socket，并定义骨骼相对变换。
本项目据此选择 Mesh Socket；`MagazineSocket` 名称是项目约定，并非 UE 强制规则。
[官方 Skeletal Mesh Sockets 5.6 文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/skeletal-mesh-sockets-in-unreal-engine?application_version=5.6)

本轮核对的本地安装版本位于 `E:/Unreal_Engine/UE_5.6`。
相关实现位于引擎 `MeshModelingToolset` 插件的 `SkeletalMeshModifiers` 模块。

- `SkeletonModifier.h/.cpp`：骨骼提交使用 LOD0 的 MeshDescription。
- `SkinWeightModifier.h:186`：`LODIndex` 固定为 0；公开入口没有 LOD 参数。
- `SkinWeightModifier.cpp`：提交调用 `CommitMeshDescription` 和 `PostEditChange`。
- `SkeletalMesh.h:2551`：编辑器接口 `AddSocket(InSocket, false)` 添加 Mesh Socket。

官方权重 API 概述没有承诺覆盖所有 LOD；本地实现明确限定 LOD0。
因此一次 Modifier 提交不能证明多 LOD 武器全部完成，尤其需要核验榴弹发射器。
官方 Python 示例中的简写调用不代替实际签名；写权重需提供 vertex_id、weights。
拓扑分离、独立网格提取与骨骼编辑是不同操作，单独提交骨骼不能拆开焊接边界。

当前项目运行时只有 FP/TP 两个整枪组件，没有独立弹匣组件或对应配置列。
本轮统一资产接口与当前项目之间的差异，仅在资产可控制能力，不扩大运行时职责。
后续实现应继续读取当前 WeaponActor，避免另建弹药或换弹状态真相。

## 7. 后续动画接入要求

弹匣拆卸、手持、丢弃与装回只属于表现，不得提交 Ammo 或结束权威 Reload。
动画仍消费现有换弹状态；新增 Notify 需要防守取消后的迟到事件。
FP/TP 使用各自表现组件与可见性约定，声音保持现有单次播放规则。
Owner 本地预测与 Remote 服务器确认的来源边界保持不变。

未来必须在以下路径恢复原弹匣，并清理独立表现件与临时附着。

- Reload 正常结束、取消或预测被拒绝。
- 切枪、武器失活、死亡、Avatar 更换或 Owner 变化。
- 武器归还池、再次租用及表现组件销毁。
- 动画中断、缺失 Notify 或残余混合帧到达。

复位应幂等，不能依赖最后一个动画 Notify 必然执行。
保存到资产的骨骼、权重和挂点也不代表运行时已经具备上述复位逻辑。

独立 StaticMesh 当前不开碰撞和物理模拟；将来需要落地物理弹匣时再配置碰撞。

## 8. 离线准备与复查入口

脚本：`Scripts/Development/PrepareWeaponMagazines.py`。
以下命令从项目根目录执行，只读重载并输出报告，不修改资产包。

```powershell
& 'E:/Unreal_Engine/UE_5.6/Engine/Binaries/Win64/UnrealEditor-Cmd.exe' `
    'D:/Unreal_Projects/ShootGame/ShootGame.uproject' `
    -run=pythonscript `
    -script='D:/Unreal_Projects/ShootGame/Scripts/Development/PrepareWeaponMagazines.py' `
    -MagazineMode=verify -unattended -nop4 -nosound `
    -AllowCommandletRendering -RenderOffscreen -onethread -norhithread `
    -DDC-ForceMemoryCache -DisablePlugins=McpAutomationBridge `
    '-EnablePlugins=PythonScriptPlugin,GeometryScripting,SkeletalMeshModelingTools' `
    -abslog='D:/Unreal_Projects/ShootGame/Saved/Logs/MagazineVerifySingleThread.log'
```

必须使用真实 RHI。NullRHI 下渲染权重未初始化，不能作为权重验证依据。
UE 5.6 的 RenderData 转换器存在初始化竞态，必须使用 `-onethread` 或
`-norenderthread` 禁用渲染线程；脚本会提前拒绝缺少该参数的运行。
本轮采用 `-onethread -norhithread` 通过全部重载检查，无引擎源码修改。

`preview` 是默认模式，在独立进程内准备和验证，不保存包。
`apply` 对全部目标验证通过后才逐包保存，失败时报告保留已保存的精确列表。
二者仅供处理修改前基线；当前资产已经准备完成，应使用 `verify`。
已有目标骨骼、挂点或独立网格时拒绝覆盖，重复 apply 不会替换已有成果。
`verify` 不依赖本地 apply 报告也能检查结构；存在报告时额外对照原基线。

外部进程保存不会刷新当前已打开 Editor 的内存资产。
在编辑器查看前应重新加载受影响资产，避免将旧内存版本再次保存覆盖。
