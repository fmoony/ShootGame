# 第三人称瞄准表现同步实施计划

## 1. 计划定位

本计划承接 [第三人称动画分层实施计划](../已完成计划/第三人称动画分层实施计划.md)，落实
[动画分层与射击表现扩展规划](动画分层与射击表现扩展规划.md) 的“阶段 B：建立第三人称瞄准表现链路”。

实施开始前先完成动画分层收尾，并移除本轮专用的 AnimBP 自动迁移工具。随后才增加表现瞄准数据，避免把一次性资产工具演变为长期运行时代码。

本阶段只改善其他玩家看到的角色、手臂、武器和枪口朝向。服务器命中、散布、弹丸、伤害和 GAS 开火权威保持不变。

## 2. 最终目标与非目标

### 2.1 最终目标

- 观察者看到的第三人称朝向尽量对应服务器认可的“预散布瞄准目标”。
- 地面移动、空中状态和开火 Montage 继续使用已经验收的上下半身分层结构。
- 水平朝向、垂直朝向和武器枪口具有可测量的数据来源，不再只靠肉眼猜测。
- 观察端对网络离散更新进行平滑，弱网下允许短暂滞后，但不能左右反向、瞬间翻转或长期停留在旧方向。
- 第一人称继续使用本地摄像机和 Control Rotation，不被远端表现数据覆盖。
- 表现瞄准数据不参与命中，不包含本次射击随机散布。

### 2.2 明确非目标

- 不实现客户端预测命中、预测弹丸或服务器倒带。
- 不让客户端上传世界命中点作为服务器真相。
- 不用独立旋转 Weapon Actor 或 Weapon Mesh 掩盖动画姿势问题。
- 不在没有左右 AimOffset 样本时强行把 `AimYaw` 接入空的 X 轴。
- 不在本阶段顺便实现 Reload / Equip 动画、动态散布或 Recoil。
- 不建立新的通用资产迁移框架。

## 3. 当前项目基线

### 3.1 当前表现链路

当前远端第三人称主要依赖：

```text
拥有者 Control Rotation
→ 服务器 APawn 生成 RemoteViewPitch16
→ 模拟代理 GetBaseAimRotation().Pitch
→ AShooterCharacter::ApplyRemoteAimPitch
→ 按名称反射查找 AnimBP.PitchN
→ PitchN = GetBaseAimRotation().Vector().Z
→ AimOffset.Y
```

现状特点：

- 只有 Pitch，没有独立的表现目标或相对 AimYaw。
- `ApplyRemoteAimPitch` 通过字符串 `PitchN` 和反射写 AnimInstance，类型契约脆弱。
- `PostNetReceive` 只在收到网络更新时写入，AnimBP 本身没有统一的平滑和失效处理。
- Character 目前只显式复制 `CurrentWeapon`、生命和死亡状态，没有第三人称表现瞄准字段。
- `BP_ShooterCharacter` 中已经存在远端瞄准调试函数，可作为下一阶段调试入口，但正式逻辑不得依赖调试蓝图。

### 3.2 当前权威射击链路

```text
输入
→ GA_Fire（ServerOnly）
→ AShooterWeapon::Fire（仅 Authority）
→ AShooterCharacter::GetWeaponTargetLocation
→ 服务器从 Pawn View Location 沿 Control Rotation 做 Trace
→ AShooterWeapon::CalculateProjectileSpawnTransform
→ 施加散布并生成服务器弹丸
```

因此当前正确边界是：服务器开火时重新计算目标，弹丸和伤害由服务器决定。下一阶段可以复用同一套“预散布目标计算规则”，但不能让一个较早复制的表现目标直接决定本次弹丸。

### 3.3 当前动画资源限制

只读资产审计确认：

- `AO_Rifle` 只有中心、向上、向下样本。
- `AO_Pistol` 同样只有中心、向上、向下样本。
- 两个 AimOffset 的 X 轴目前没有左右 Yaw 样本。
- 两个 AimOffset 都使用 Mesh Space Additive，并以各自的 ADS Idle 作为参考姿势。

因此首轮水平瞄准不能依赖 2D AimOffset。默认策略是：

```text
大角度水平朝向 → 角色身体 / Actor Yaw 承担
垂直朝向       → 现有 AimOffset Pitch 承担
剩余小角度误差 → 达到触发门槛后才评估程序化上半身校正
```

如果未来希望角色身体不立即跟随准星、支持 Turn In Place 或大范围独立腰部扭转，需要先补充可信的左右 Additive 样本或单独设计程序化方案，不在本阶段假定资源已经具备。

## 4. 外部依据与本地 UE 5.6 核对

Epic 官方资料给出的边界是：

- `GetBaseAimRotation` 返回 Pawn 的瞄准旋转；有 Controller 时通常来自玩家视角，否则回退到 Pawn 旋转与远端视角数据：[APawn::GetBaseAimRotation](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/APawn/GetBaseAimRotation)。
- 持续状态适合使用复制属性和 RepNotify，并可以使用 `COND_SkipOwner` 避免把远端表现数据回送给拥有者：[Replicate Actor Properties](https://dev.epicgames.com/documentation/en-us/unreal-engine/replicate-actor-properties-in-unreal-engine?application_version=5.6)。
- 高频、非关键事件不应使用每 Tick 的 Reliable RPC；RPC 需要服从 Actor 所有权和连接规则：[Remote Procedure Calls](https://dev.epicgames.com/documentation/en-us/unreal-engine/remote-procedure-calls-in-unreal-engine?application_version=5.6)。
- 复制字段应尽量少，并优先使用量化类型降低带宽：[Performance and Bandwidth Tips](https://dev.epicgames.com/documentation/en-us/unreal-engine/performance-and-bandwidth-tips-for-unreal-engine?application_version=5.6)。
- AnimBP 可以通过 Property Access 或线程安全更新从宿主读取稳定数据，避免外部按名称写入蓝图内部变量：[Property Access](https://dev.epicgames.com/documentation/en-us/unreal-engine/property-access-in-unreal-engine?application_version=5.6)。
- AimOffset 是 Mesh Space Additive 姿势的混合工具，大范围水平瞄准还需要考虑角色身体旋转与移动混合：[Aim Offset](https://dev.epicgames.com/documentation/en-us/unreal-engine/aim-offset-in-unreal-engine?application_version=5.6)。

本地 UE 5.6 源码进一步确认：

- 旧的 `uint8 RemoteViewPitch` 在 UE 5.6 已弃用；当前实际使用 `RemoteViewPitch16`，将 360 度压缩到 16 位。
- `APawn::PreReplication` 在服务器根据 Controller Control Rotation 更新 `RemoteViewPitch16`。
- `RemoteViewPitch16` 使用 `COND_SkipOwner` 复制。
- 模拟代理没有 Controller 时，`GetBaseAimRotation` 会解压 `RemoteViewPitch16` 作为 Pitch。

这说明当前问题的主因不是“Pitch 只有 8 位精度”，而是缺少完整表现目标、水平表达、观察端平滑和稳定的 AnimBP 数据契约。

## 5. 目标职责边界

```text
拥有者客户端
└─ 本地 Control Rotation / 摄像机
   └─ 只负责即时第一人称视角和输入

服务器
├─ 使用已同步的 Control Rotation 计算预散布瞄准目标
├─ 开火时重新计算权威目标并生成弹丸
└─ 以受限频率发布 PresentationAimTarget

观察客户端
├─ 接收 PresentationAimTarget
├─ 本地平滑
├─ 转换为角色局部 AimYaw / AimPitch
└─ 驱动身体朝向、AimOffset 和必要的局部姿势校正
```

`PresentationAimTarget` 是表现快照，不是命中缓存。服务器开火时必须调用当前时刻的权威目标计算，不能直接使用可能已经过时的复制值。

## 6. 分阶段实施路径

### B0：完成 Pistol 验收并移除一次性迁移工具

#### 前置门槛

- `ABP_TP_Rifle` 和 `ABP_TP_Pistol` 都处于目标分层结构。
- 两者均完成修改后 Audit、二次幂等 Apply、完整自动化和双客户端视觉验收。
- 最终 Branch Filter、Depth、Mesh Space Rotation、AimOffset 资源和 Montage Slot 已写入开发记录。

任何一项未满足时，先完成分层计划，不得提前拆除工具。

#### 移除范围

在确认 `ShootGameEditor` 模块只服务本次迁移后：

- 移除 `Source/ShootGameEditor/` 中的 AnimLayerRestructure Commandlet 和专用模块代码。
- 从 `ShootGameEditor.Target.cs` 删除 `ShootGameEditor` 额外模块，仅保留正常项目 Editor Target 所需模块。
- 移除只为本轮迁移服务的 `Scripts/DevTools` 命令说明和一次性探针；如果某个只读脚本仍有明确长期调用者，必须先证明用途再保留。
- `Content/Test/AnimLayer/TP_Rifle_TestCopy.uasset` 必须通过 Unreal Editor 资产系统删除，不能直接删除二进制文件。
- `Saved/Automation/DevTools` 属于运行产物，不进入 Git；是否本地清理由用户决定。
- 不删除项目原有 `Plugins/`，也不影响 `McpAutomationBridge`。

如果这些工具从未进入 Git，不为了“留下历史”而额外提交数千行一次性代码；在分层开发记录中保存最终拓扑、验证结果、哈希和使用过的命令即可。如果工具已经进入 Git，则使用独立中文清理提交移除，历史自然保留。

#### 工程同步与验证

移除模块和 Target 引用属于项目结构变化：

1. 重新生成 Visual Studio 项目文件。
2. 如果 Visual Studio 正在运行，必须提示用户点击“全部重新加载”；用户未完成前不得从 VS 构建。
3. 命令行 UBT 可以独立继续执行。
4. 完成 Editor Build 和 `Scripts/Tests/RunAll.ps1` 七阶段回归。
5. 确认正式 Rifle/Pistol AnimBP 不依赖该 Editor 模块，打开、编译和运行均正常。

### B1：冻结可测量基线与数据语义

本步骤不改变网络权威，只建立统一术语和调试证据。

#### 操作

1. 在 Listen 与 Dedicated 双客户端环境验证：玩家原地只转动视角时，服务器 Control Rotation 是否持续更新。
2. 审计 `BP_ShooterCharacter` 的角色 Yaw 配置、CharacterMovement 旋转设置和 Locomotion 的方向计算，确认身体是否已经跟随控制器水平朝向。
3. 统一四类调试数据：
   - 拥有者本地摄像机方向。
   - 服务器预散布瞄准方向或目标。
   - 观察端收到并平滑后的表现目标。
   - 第三人称真实枪口 Forward。
4. 输出枪口方向与表现目标方向的夹角，不只画颜色线。
5. 固定中距离、近墙、移动、跳跃和弱网测试位置，形成修改前基线。

#### 判定

- 如果服务器 Control Rotation 在原地转视角时已经及时更新，后续不增加客户端 Aim RPC。
- 如果服务器数据确实无法达到所需频率，才讨论受限频率的 Unreliable、量化视角旋转 RPC；仍禁止上传世界命中点，也禁止每 Tick Reliable RPC。

### B2：建立服务器表现目标

#### 默认方案

在 `AShooterCharacter` 中建立服务器产生的表现目标，概念名称为 `PresentationAimTarget`：

- 服务器从 Pawn View Location 沿当前 Control Rotation 做无散布 Visibility Trace。
- 命中时保存 Impact Point，未命中时保存最大瞄准距离终点。
- 使用适合世界坐标的量化向量表达，首选 `FVector_NetQuantize`；最终类型在实现前用地图范围验证。
- 只复制给非拥有者，拥有者继续使用本地即时视角。
- 复制值通过 RepNotify 更新观察端目标，不通过 Multicast 或每 Tick Reliable RPC 广播。

#### 更新节奏

第一轮以约 10～15 Hz 的服务器采样作为调试起点，并同时使用角度/距离变化门槛减少无意义更新。具体频率必须通过网络模拟和带宽统计决定，不写成永久常量。

稳态采样不主动每次 `ForceNetUpdate`。如果开火瞬间表现仍明显落后，再评估只在服务器确认开火时推动一次最新表现值，但不能影响开火权威事务。

#### 避免第二套真相

把“从服务器视点计算预散布目标”整理为一个无副作用的公共计算入口：

- 表现同步按受限频率调用，得到可复制快照。
- 每次实际开火再次调用，得到本次权威目标。
- 两者使用同一规则，但不是同一个缓存值。
- 散布只在权威开火目标之后应用。

### B3：观察端平滑与 AnimBP 稳定契约

#### 数据消费

观察端收到目标后保留“最新网络目标”和“当前平滑目标”两个值：

- RepNotify 只更新目标值，不直接瞬移骨骼。
- 每帧表现更新负责向目标插值。
- 武器切换、死亡、复活、传送和首次初始化时直接重置，避免从旧 Pawn 或旧武器继续插值。
- 长时间没有有效目标时回退到角色 Forward + 当前远端 Pitch，而不是保持任意历史点。

#### 局部角度

由当前角色表现基准计算：

```text
世界方向 = Normalized(PresentationAimTarget - AimPivot)
局部方向 = Character / Mesh Transform 的逆变换方向
AimYaw   = 局部方向的水平角
AimPitch = 局部方向的垂直角
```

角度必须正确处理 `-180° / +180°` 环绕，并在插值前做最短路径归一化。

#### 替换反射写入

AnimBP 改为通过明确的 Character Getter 或 Property Access 读取平滑后的表现角度。完成 Rifle/Pistol 切换后删除：

- `AShooterCharacter::ApplyRemoteAimPitch`。
- `PostNetReceive` 和 `OnRep_CurrentWeapon` 中只为反射写 `PitchN` 服务的调用。
- `FindFProperty(..., "PitchN")` 这类字符串耦合。

首轮可以继续保留 AnimBP 内的 `PitchN` 变量作为 AimOffset 输入，但它的来源必须变成明确类型的数据契约。

### B4：水平朝向与现有 Pitch AimOffset

#### 首选路线

1. 先让角色身体 Yaw 与服务器表现方向一致。
2. Locomotion 继续根据角色局部速度表达前后左右移动。
3. 现有 Rifle/Pistol AimOffset 只负责垂直 Pitch。
4. 计算并记录相对 AimYaw，但现有 AimOffset X 仍保持 0。
5. 大角度水平变化通过身体转向完成，不让脊柱无限扭转。

如果当前角色已经跟随 Control Rotation Yaw，本步骤应尽量复用现状，只修复观察端数据和插值，不重复创建第二个身体旋转系统。

#### 暂缓的 2D AimOffset

只有获得 Rifle/Pistol 左、中、右且基础姿势一致的 Mesh Space Additive 样本后，才允许把小范围相对 AimYaw 接入 AimOffset X。届时还必须定义：

- 上半身允许的最大相对 Yaw。
- 超出范围时身体转向的门槛和速度。
- 移动、空中和 Turn In Place 的优先级。

### B5：按误差门槛决定是否增加程序化校正

先完成 B2～B4 并重新测量，不预设一定需要 IK 或 Control Rig。

如果静止中距离下，第三人称枪口与服务器表现目标仍持续存在肉眼明显的大角度偏差，才建立小范围程序化校正实验：

- 校正位于 AimOffset / Arms Slot 之后、最终输出之前。
- 只修改受控的上半身骨骼链，不独立旋转 Weapon Actor。
- 大角度仍交给身体 Yaw；程序化校正只处理有限残差。
- Rifle 先作为样本，Pistol 独立验收，不共享手工补偿角。
- 校正失败或姿势变形时，可以无损关闭并回到 B4 基线。

是否使用 Look At、Control Rig、IK Rig 或自定义 Skeletal Control，必须根据当时可用骨骼、手部插槽和性能测量另行决策，本计划不提前冻结具体节点。

### B6：网络与视觉验收

#### 自动验证

- 局部 AimYaw / AimPitch 计算覆盖四象限和 `±180°` 环绕。
- 服务器表现目标只能由 Authority 更新。
- 拥有者不会被复制表现目标覆盖。
- 死亡、复活、切枪和断线后不会保留旧目标或旧平滑状态。
- 权威开火仍从服务器当前 Control Rotation 重新 Trace。
- `PresentationAimTarget` 不被 `CalculateProjectileSpawnTransform` 当作缓存真相使用。
- 工程中不再存在 `FindFProperty(..., "PitchN")` 的运行时写入。
- Editor Build、现有 Automation 和 `RunAll.ps1` 七阶段回归全部通过。

#### 双客户端视觉矩阵

| 环境 | 动作 | 观察重点 |
| --- | --- | --- |
| Listen | 静止水平/上下瞄准 | 身体、肩部和枪口连续 |
| Dedicated | 静止转动视角 | 服务器与观察端方向能稳定收敛 |
| Dedicated | 前后左右移动/扫射 | 腿部 Locomotion 正常，身体水平朝向合理 |
| Dedicated | Jump Start/Apex/Fall/Land | 分层结构不回归，Pitch 不跳变 |
| Dedicated | Rifle/Pistol 开火 | 枪口表现与预散布目标同向，权威弹丸不变 |
| 弱网 | 连续快速转向 | 允许平滑滞后，不允许左右反转或长期冻结 |
| 近墙 | 准星指向遮挡 | 表现目标使用服务器 Trace，近距离视差可解释 |
| 中距离 | 固定目标 | 记录枪口到目标夹角和收敛时间 |

第一轮验收预算以“静止中距离持续误差不超过约 5°，弱网快速转向后约 0.3 秒内收敛”为调试目标，不作为未经实测的永久产品参数。若资源限制导致无法达到，必须记录误差来源，再决定是否进入 B5。

## 7. Agent 与用户协作方式

### Agent 自主负责

- 使用 CodeGraph、只读 Unreal MCP 和官方资料审计现状。
- 实现每个独立网络闭环，并补充自动化测试。
- 命令行 Build、Focused Test、Full Regression 和日志分析。
- 为每次提交提前完成中文开发记录。
- 只在 B0 条件满足后移除一次性工具。

### 必须交给用户

- Pistol 分层的最终双客户端视觉验收。
- 移除模块并重新生成项目文件后，在已打开的 Visual Studio 中点击“全部重新加载”；未完成时不得从 VS 构建。
- Rifle/Pistol 的姿势自然度、枪口是否肉眼同向以及弱网观感验收。
- 是否接受新增或制作左右 AimOffset 动画资源。
- 是否在 B4 后继续投入 B5 程序化校正。

## 8. 推荐提交拆分

每次提交前必须按 [开发记录规范](../开发记录/README.md) 写明改动、验证、问题和遗留项。

1. **完成 Pistol 分层与阶段 A 验收**：Pistol 资产、最终配置和人工验收记录；不混入 AimTarget。
2. **移除一次性动画迁移工具**：仅在工具已经进入 Git 时作为独立清理提交；未进入 Git 时只清理工作区并在阶段 A 记录中留痕。
3. **建立瞄准表现基线与测试工具**：只包含可测量调试信息和纯计算测试，不新增网络字段。
