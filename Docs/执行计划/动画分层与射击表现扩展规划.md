# 动画分层与射击表现扩展规划

## 规划定位

本规划用于在当前服务器权威射击闭环之上，集中改善第三人称瞄准、武器动作、射击不稳定性和开火反馈。

《Shooter 完整 Demo 最终路线规划》在本阶段暂缓执行，但不被替代。完成本规划并确认表现链路稳定后，再回到最终 Demo 路线继续推进。

本文件只描述实现目标、系统边界和大致路线。具体类型、接口、蓝图节点、参数和提交拆分，应在进入对应阶段前根据当时工程状态另行确定。

## 实现目标

### 1. 保留并完善第三人称动画分层

- 将移动、跳跃和落地作为下半身与全身基础姿势。
- 将持枪待机、瞄准、开火、换弹和切枪作为腰部以上的战斗表现。
- 避免跳跃动画自身的躯干倾斜与 AimOffset 重复叠加，导致远端看到异常的 AimYaw、肩部扭转或枪口偏移。
- Rifle 和 Pistol 可以保留不同的姿势资源，但应遵循相同的变量来源、分层顺序和权威边界。
- 第一人称动画继续独立处理，不让远端第三人称逻辑读取本地摄像机或第一人称 Mesh。

目标动画结构概念如下：

```text
移动 / 跳跃 / 落地基础姿势
            │
            ├────────────── 下半身与根骨骼
            │
武器姿势 + 瞄准 + 武器动作
            │
            └────────────── 腰部以上
                         │
                      最终姿势
```

空中状态需要有独立的混合策略：保留跳跃所需的重心和腿部动作，同时限制基础跳跃动画对上半身持枪方向的干扰。最终效果以第三人称枪口方向和身体姿势为准，而不是只观察某个 AimYaw 数值是否变化。

### 2. 提升第三人称瞄准表现同步

其他玩家看到的角色身体、手臂和武器方向，应尽量对应开火者的服务器预散布瞄准方向，而不是只依赖一个俯仰值。

大致链路为：

```text
玩家瞄准输入
→ 服务器得到预散布瞄准方向或目标
→ 向观察者同步表现所需的瞄准信息
→ 观察端进行平滑
→ 转换为角色局部 AimYaw / AimPitch
→ 驱动上半身 AimOffset
→ 必要时继续校正手臂和武器姿势
```

默认由服务器根据已同步的视角旋转重新计算表现瞄准目标，不直接接受客户端提交的世界命中点。这样可以让第三人称表现与服务器认可的射击基线保持一致，也避免增加第二套瞄准真相。

表现瞄准目标只用于动画和调试：

- 不参与命中裁决。
- 不直接决定弹丸方向。
- 不替代开火时的服务器射线检测。
- 不包含本次射击产生的随机散布。

观察端需要平滑处理同步结果，并限制上半身可表达的水平和垂直范围。当目标超出合理扭转范围时，应由角色身体朝向和上半身瞄准共同完成，而不是让脊柱无限旋转。

AimOffset 是第一层校正。如果中近距离仍能明显看到枪口与目标分离，再增加手臂或武器骨骼校正。武器仍应附着在手部插槽上，不通过独立旋转武器 Actor 来掩盖动画姿势问题。

如果未来出现中心准星和视角旋转无法表达的 Free Aim、VR 武器或独立枪口瞄准，再评估同步受服务器校验的“瞄准意图方向”，而不是上传客户端世界命中结果。

### 3. 补充 Reload / Equip 动画表现

在现有 GAS Reload / Equip 事务基础上补充第一、第三人称动画，但动画不取得权威逻辑控制权。

总体原则为：

- GAS 能力和服务器计时决定动作是否允许、何时提交以及何时取消。
- 动画系统根据已确认的武器动作状态播放对应表现。
- Reload 动画不能通过 Montage 完成或 AnimNotify 直接写入弹药。
- Equip 动画不能通过 Montage 完成或 AnimNotify 直接修改逻辑武器。
- AnimNotify 只负责弹匣显隐、声音和其他可丢失的纯表现。
- 死亡、取消、互斥能力和武器失活时，动画表现必须能够安全结束并恢复到正常持枪状态。

资源策略采用由小到大的验证方式：

1. 先以 Rifle 的现有 Reload / Equip 动作为原型。
2. 验证现有身体动画经第一人称 Copy Pose 后是否可接受。
3. 如果第一人称视角不合格，再制作第一人称专用动作或局部修正。
4. Rifle 链路稳定后，再将相同规则推广到 Pistol。

Reload / Equip 播放期间仍保留下半身移动能力。上半身的动作、瞄准和持枪姿势需要明确优先级，避免 AimOffset 与换弹动作同时争夺手臂骨骼。表现时长应与服务器配置保持协调，但不能反过来让动画资源长度成为权威事务时钟。

### 4. 将射击偏移升级为角度散布

现有目标点位置偏移应替换为真正的方向锥体散布，使散布参数表达稳定的角度含义，不再随着目标距离改变实际效果。

服务器射击方向大致分为：

```text
服务器预散布瞄准目标
→ 从枪口指向目标的基础方向
→ 应用本次角度散布
→ 得到权威弹丸方向
→ 生成弹丸并处理命中
```

第一步只建立静态角度散布，确认参数含义和弹丸方向正确。稳定后再加入：

- 连续射击逐发扩散。
- 最大扩散限制。
- 停火后的恢复延迟和恢复速度。
- 移动状态修正。
- 空中状态修正。
- 不同武器类型的独立配置。

动态散布状态由服务器维护。移动和空中信息也从服务器认可的角色状态读取。初期不要求向客户端复制完整散布数值，也不在本阶段立即实现动态准星预测。

NPC 的瞄准技术误差与武器机械散布需要保留为两个概念：前者描述 NPC 的瞄准能力，后者描述具体武器。接入统一武器散布时应避免无意中对 NPC 重复应用两次同类随机偏移。

### 5. 增强射击表现和手感

在瞄准方向和散布逻辑稳定后，再逐步加入：

- 第一人称摄像机后坐力。
- 第一人称手臂或武器的视觉后坐。
- 第三人称开火动作。
- 第一、第三人称枪口闪光。
- 开火声音和必要的环境反馈。
- 后坐力恢复和连续射击节奏。

需要逐步分离“权威射击结果”和“射击表现”：

- 服务器负责耗弹、射速、散布、弹丸、伤害和噪声结果。
- 拥有者负责第一人称摄像机和武器手感。
- 观察者只播放服务器确认过的第三人称表现。

本阶段可以先使用服务器确认后的表现。未来重新推进客户端预测时，再让拥有者即时播放可回滚的本地反馈，并使用明确的射击标识避免预测表现与服务器确认重复。

## 推荐推进顺序

### 阶段 A：建立动画分层基线

- 具体执行步骤见 [第三人称动画分层实施计划](../已完成计划/第三人称动画分层实施计划.md)。
- 整理第三人称 AnimGraph 的基础姿势、上半身瞄准和武器动作关系。
- 分别验证站立、移动、跳跃、下落和落地时的 Rifle / Pistol 姿势。
- 优先解决跳跃基础动画与 AimYaw、AimPitch 重复混合的问题。

### 阶段 B：建立第三人称瞄准表现链路

- 具体执行步骤见 [第三人称瞄准表现同步实施计划](第三人称瞄准表现同步实施计划.md)。
- 在正式接入瞄准同步前，完成 Pistol 分层验收并移除只服务本次 AnimBP 迁移的一次性 Editor 工具。
- 引入水平和垂直瞄准信息。
- 同步服务器认可的表现瞄准目标或方向。
- 在观察端平滑，并验证身体、手臂、武器和枪口的对应关系。
- 必要时在 AimOffset 之后增加局部姿势校正。

### 阶段 C：接入 Reload / Equip 动画

- 先完成 Rifle 第三人称动作，再验证第一人称表现。
- 将动作播放接入现有 GAS 生命周期和取消路径。
- 明确瞄准、换弹、切枪和移动之间的动画优先级。
- Rifle 稳定后推广到 Pistol。

### 阶段 D：替换静态射击偏移

- 使用真正的角度散布替换位置偏移。
- 验证服务器生成的每颗弹丸都位于配置锥体范围内。
- 保持第三人称瞄准指向预散布目标，不让人物姿势随机追随每颗弹丸。

### 阶段 E：增加动态扩散与恢复

- 加入连续射击、恢复、移动和空中修正。
- 分别调整 Rifle 与 Pistol 的参数和节奏。
- 检查切枪、停止开火、死亡和复活后的散布状态是否正确清理。

### 阶段 F：增加 Recoil 与枪口反馈

- 先完成拥有者第一人称反馈。
- 再完成观察者第三人称反馈。
- 最后统一声音、枪口闪光、开火动作和后坐力节奏。

## 验收方向

本规划完成后，应达到以下体验目标：

- 远端玩家站立、移动和跳跃时，下半身动作正常，上半身仍能稳定持枪瞄准。
- 跳跃动画不会无意义地带动 AimYaw 或让枪口突然横向偏移。
- 其他玩家看到的枪口方向与服务器预散布瞄准方向基本一致。
- 近距离因身体结构限制产生的偏差可解释，中距离不再出现明显的左右相反或大角度错位。
- Reload / Equip 在第一、第三人称都具有可辨识表现，取消、死亡和切枪竞态不会遗留错误姿势。
- 弹丸散布具有稳定的角度语义，并能体现连续射击、移动和空中的不稳定性。
- 动画缺失、Montage 中断或枪口特效丢失不会改变弹药、武器、伤害和得分结果。
- Listen Server、远程客户端和 Dedicated Server 下的权威结果保持一致。

## 已确认的默认决策

1. 表现 AimTarget 默认由服务器根据已同步的视角信息重新计算，不接受客户端世界命中点作为权威输入。
2. Reload / Equip 先以 Rifle 为原型，允许先验证现有第三人称身体动画和第一人称 Copy Pose，效果不足时再补第一人称专用资源。
3. 本阶段不立即加入动态准星 UI 和开火预测；先稳定服务器散布、动画表现与调试链路。

## 暂不纳入本规划

- 背包系统的新一轮扩展。
- 客户端预测弹丸和预测弹药。
- 服务器倒带与历史命中检测。
- 通用武器附件、词条和复杂数据驱动系统。
- 为了动画表现改写服务器权威 Reload / Equip 事务。
- 为每种武器一次性制作完整的高品质第一人称动画资源。

这些内容继续由《Shooter 完整 Demo 最终路线规划》或后续独立计划承接。
