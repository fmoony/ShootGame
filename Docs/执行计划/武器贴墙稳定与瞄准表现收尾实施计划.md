# 武器贴墙稳定与瞄准表现收尾实施计划

> 状态：暂缓。阶段 0～4 已完成当前 IK 基线并通过人工视觉验收；大范围快速甩枪的远端同步速度仍不满意，留待后续专用瞄准表现同步阶段处理，本计划尚未进入阶段 5 总收尾。当前优先执行核心玩法架构解耦重构。

## 1. 背景与已确认事实

- Rifle 第三人称左手已经能够基本贴合握把；当前校准结果先作为可回退基线，不再继续移动武器 Socket。
- 故障发生在其他玩家观察到的第三人称角色；临时绕过第一人称 `ABP_FP_Weapon` 的 Hit Location 后现象不变，第一人称 Control Rig 已被排除。
- 服务器的 `PresentationAimTarget` 从 Pawn 视点 Trace 得到，但远端第三人称 AnimInstance 会重新计算 `ThirdPerson Muzzle → SmoothedPresentationAimTarget`。
- 贴墙时命中点可能非常靠近第三人称枪口，甚至因相机与枪口起点不同而落到枪口侧后方；很小的目标变化会被放大成很大的方向变化，再由右手 Aim IK 和左手 IK 共同表现为双臂与武器抖动。
- `FAnimNode_ShooterAimIK` 当前把最多 30 度的残差集中施加给 `hand_r`；左手 IK 则求解整条左臂，快速转向时两侧手臂的处理不对称。
- `PresentationAimTarget` 当前由服务器以 10 Hz 采样，变化门槛为 50 cm / 3 度，观察端指数平滑速率为 8/s；快速转向会叠加采样、复制和平滑延迟。

## 2. 目标与边界

### 2.1 目标

- 远端第三人称角色贴墙静止、沿墙移动和快速进出障碍范围时不再抖动。
- 将权威命中目标与第三人称安全姿势方向保持职责分离。
- 让远端第三人称瞄准更快跟随拥有者真实视角，同时保持弱网下稳定。
- 在同步输入稳定后，改善快速视角移动时的右手腕、左肘和双臂组合姿势。
- 保持 Rifle 当前左手握持基线，Pistol 不错误启用 Rifle 左手 IK。

### 2.2 非目标

- 不修改服务器权威开火、命中、Spread、Projectile、伤害和 GAS 事务。
- 不复制骨骼姿势，不使用逐帧 Reliable RPC。
- 不修改已经由隔离实验排除的第一人称 `ABP_FP_Weapon` 与第一人称 Control Rig。
- 不创建一次性蓝图资产修改 Commandlet；蓝图和 Control Rig 的视觉节点由人工按精确说明修改。
- 不在本计划中接入 Pistol 左手 IK。

## 3. 实施顺序

```text
阶段 0：保存 Rifle 左手握持基线（已通过）
→ 阶段 1：修复第三人称近点/后方目标奇异方向
→ 阶段 2：验证并细化第三人称安全姿势方向
→ 阶段 3：改造第三人称快速瞄准同步
→ 阶段 4：细化手臂姿势与 IK
→ 阶段 5：清理、回归与归档
```

必须先稳定上游数据，再调整下游骨骼。禁止用动画调参补偿过期网络目标，也禁止用网络平滑掩盖本地 Control Rig 的近距离奇异姿势。

## 4. 分阶段执行

### 阶段 0：Rifle 左手握持基线

状态：人工视觉验收通过。

Location X=-29.886 Y=7.307 Z=-1.157

### 阶段 1：第三人称近点/后方目标安全门

状态：诊断完成，不作为最终方案。硬回退消除了疯狂抖动，但会让枪口方向与相机射线平行，近点汇聚不准确。

只修改第三人称 AnimInstance 的表现方向选择：

```text
远端目标安全（离 Muzzle 足够远且位于基础视线前方）
→ Muzzle → SmoothedPresentationAimTarget

远端目标不安全（离 Muzzle 过近或位于基础视线后方）
→ GetBaseAimRotation().Vector()
```

首轮最小安全距离为 150 cm，作为 AnimInstance 可配置表现参数。该安全门不修改相机 Trace、服务器命中目标、Spread、Projectile 或伤害。

人工验收矩阵：

| 场景 | 观察内容 |
| --- | --- |
| 远端角色正对墙面静止 | 枪和双臂是否停止高频抖动 |
| 观察端看远端角色沿墙移动 | 是否仍在碰撞边界抽搐 |
| 远端角色快速靠近与离开墙面 | 是否出现方向翻转或明显切换 |
| 远距离瞄准 | 枪口是否仍能汇聚到表现目标，而非永久退化为粗略 Pitch |

阶段门：

- 抖动消失：确认 Muzzle→近点/后方点是根因，进入阶段 2 做阈值与过渡细化。
- 抖动仍存在：不再碰第一人称；分别关闭第三人称 Shooter Aim IK 与 Left Hand IK，定位是右手方向源还是左臂求解放大。

本阶段由 Agent 完成 C++、纯计算测试和编译；人工只负责双客户端第三人称视觉验收。

### 阶段 2：第三人称安全姿势方向细化

状态：已通过。疯狂抖动消失，近点汇聚精度恢复到可接受范围；权威 Trace 与 Capsule 均未修改。

使用连续的安全虚拟目标替换阶段 1 的硬方向回退：

```text
ForwardDepth = Dot(PresentationTarget - PawnViewLocation, BaseAimDirection)
SafeDepth = Max(ForwardDepth, MinimumSafeDepth)
SafeTarget = PresentationTarget + BaseAimDirection * (SafeDepth - ForwardDepth)
PoseDirection = Normalize(SafeTarget - Muzzle)
```

该投影保留近点相对基础视线的横向偏移，因此仍能向相机射线汇聚；投影量在安全平面边界连续，不需要额外硬切换或先堆插值。权威 Trace 和 Pawn Capsule 命中规则保持不变。完成条件是第三人称静止贴墙、沿墙和快速进出均无抖动，近点不再突然退化为平行方向，远距离瞄准精度不回退，准星与服务器开火结果不变。

### 阶段 3：第三人称快速瞄准同步

状态：已通过。编译、Focused Automation、Dedicated / Listen 联机与人工快速转向视觉验收均通过。

本地现状：服务器原先以 10Hz 自行 Trace，按 50cm / 3 度门槛写入属性，再由观察端以 8/s 平滑；拥有者没有主动提交自己的即时表现目标。

外部依据：UE 5.6 官方将高频、临时和动画表现类通信列为 Unreliable RPC 的适用场景；Server RPC 必须由拥有该复制 Actor 的客户端调用；`COND_SkipOwner` 适合让服务器属性只转发给非拥有者。参考：[Remote Procedure Calls](https://dev.epicgames.com/documentation/en-us/unreal-engine/remote-procedure-calls-in-unreal-engine?application_version=5.6)、[Actor Owner and Owning Connection](https://dev.epicgames.com/documentation/en-us/unreal-engine/actor-owner-and-owning-connection-in-unreal-engine?application_version=5.6)、[Replicate Actor Properties](https://dev.epicgames.com/documentation/en-us/unreal-engine/replicate-actor-properties-in-unreal-engine?application_version=5.6)。

本阶段差异：改为拥有者 20Hz 受限提交、服务器仅校验并转写现有表现属性；权威开火仍由服务器现场 Trace，不信任该表现 RPC。

现有服务器 10 Hz 采样路线替换为表现专用链路：

```text
拥有者本地即时 Aim Target
→ 受限频率 Unreliable Server RPC
→ 服务器有限值、距离和频率校验
→ PresentationAimTarget
→ COND_SkipOwner 属性复制
→ 观察端短窗口平滑
```

首轮候选值：

```text
发送频率：20 Hz
角度门槛：约 1 度
距离门槛：约 20 cm
保活更新：0.2 秒
```

首轮不做角速度外推。只有在 20 Hz 输入和自适应收敛完成后仍有量化证据表明延迟不可接受，才新增受限外推阶段。

完成条件：拥有者不消费服务器回传值；丢包不影响权威开火；Listen Server、Dedicated Server 和普通观察客户端都能稳定看到快速转向；停止转动后不来回修正。

自动验证记录（2026-08-25）：

- `ShootGame.Aim`：12/12 通过，包含发送门槛、保活、目标距离边界、16 位序号回绕和近点连续投影。
- Dedicated：服务器 + 2 个远端客户端通过 `AimRotation=true Presentation=true Smoothing=true`。
- Listen：监听主机 + 1 个远端客户端通过同一标记。
- 修正了网络协调器的既有阶段门竞态：AimRotation 必须等到至少两名参与者且武器全部就绪，避免首名客户端在第二名尚未加载时提前完成扫描。

### 阶段 4：手臂姿势与 IK 细化

子阶段 4A 结果：左手末端握把 Transform 保持不变，将 Joint Target 改为输入动画肩—肘—腕弯曲平面的逐帧投影。Editor Build 与 `ShootGame.Aim.LeftHand*` 5/5 通过，但人工快速左右甩动仍观察到手肘外翻和翻转，因此视觉验收未通过。根因是逐帧来源本身会随输入姿势漂移，投影跨越共线区后仍可能换边。

子阶段 4B 结果：首次有效持枪姿势的弯肘方向缓存为角色组件空间基准；每帧投影到当前目标肩腕平面，并用上一帧 Pole 选择同一半球。自动阶段门通过，但人工快速转向时仍观察到左臂类似面筋的跳变，视觉验收未通过。半球锁只阻止约 180 度换边，无法限制投影接近奇异区时仍处于同一半球内的大角度单帧旋转。

子阶段 4C 结果：自动阶段门通过，但人工仍观察到明显左臂跳动，同时枪支快速瞄准同步仍有拖尾。Pole 角速度限制没有解决上游目标和右手姿势大幅变化，反而会让肘部继续追赶已经移动的握把，因此撤回 4C 限速，不把失败调参留在正式路径中。

当前子阶段 4D：保持 20 Hz、Unreliable、服务器校验的表现目标输入预算不变，将观察端指数平滑由 `8/s` 提升为 `20/s`，减少额外表现拖尾；将 Shooter Aim IK 的默认最大右手校正由 30 度降至 12 度，使 AimOffset / 上半身基础动画承担主体姿势，`hand_r` 只修正小角度枪口残差，左手 IK 只闭合到随右手移动的武器握把。Rifle AnimBP 可能序列化旧节点默认值，人工视觉验收前必须检查 `Shooter Aim IK → Max Correction Angle` 实际值为 12。

4D 人工验收顺序：先关闭 Left Hand IK，确认枪支快速跟随速度和右手姿势不再出现大幅折腕；再开启 Left Hand IK，确认左手贴合且快速横扫不再承担整段瞄准角变化。若关闭 Left Hand IK 时右手/枪仍跳，问题属于 AimOffset、Shooter Aim IK 或网络表现目标，禁止继续调整左肘 Pole。

4D 自动阶段门：Editor Build 通过；`ShootGame.Aim*` 13/13 通过且无警告。当前等待重启后的 Rifle 节点实际值检查与两组人工视觉验收。

4D 人工结果：基本通过。降低右手残差负担后，Rifle 左手握持和常规视角移动的整体表现已达到当前可接受基线；大范围快速甩枪时仍可观察到远端动画落后，但该问题归入表现目标采样、转发与观察端追赶策略，不再由左手 IK 继续补偿。

若 4C 仍出现跳变，不再继续叠加平滑；下一步先记录肩到目标手掌距离与上下臂总长度的比值，确认是否在满伸展边界两侧反复切换，再决定是否限制右手 Aim IK 残差或加入软伸展区。

先执行隔离矩阵：

| Shooter Aim IK | Left Hand IK | 目的 |
| --- | --- | --- |
| 关 | 关 | 原始动画基线 |
| 开 | 关 | 只检查右手枪口残差 |
| 关 | 开 | 只检查左臂求解 |
| 开 | 开 | 检查最终组合 |

实施方向：

- 上半身 Aim Offset / 分层姿势吸收主要俯仰和转向。
- Shooter Aim IK 只处理小角度枪口残差，不让大误差全部集中在 `hand_r`。
- 根据隔离证据降低当前 30 度残差上限，候选区间为 8～12 度。
- 为左肘建立稳定、可解释的 Pole Target；不在未验证时写死角色轴。
- 节点顺序保持 `分层动画 → Shooter Aim IK → Left Hand IK`。

完成条件：原地快速转向、移动、跳跃、Fire、Reload、Equip 中无持续脱手、翻肘、腕部大角度折叠和明显一帧追逐。
