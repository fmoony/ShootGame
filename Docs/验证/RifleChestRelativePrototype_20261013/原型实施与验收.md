# Rifle 胸腔相对收枪：原型实施与验收

日期：2026-10-13；UE 5.6.1；生产基线 `f1d6a22`。
首发提示词原样保存在同目录，SHA256 与附件一致。

**推荐保留 LocalBoundary 作为下一轮候选；本轮不取消 Down30 / Down60。**
Local 确实让单一 CorrectedGrip 的肩臂动作继承当前胸腔旋转。
真实 FP 的指定负俯仰 LowReady 帧消除了画面中心的枪械遮挡。
增加一次 0.12 秒反向边界混合后，循环后抬枪首步明显减小。
仍需用户验收 0° 动作节奏、肩肘自然度和完整连续 FP 表现。

## 1. 运行原型与空间依据

### 资产及操作

新资产统一位于：

```text
/Game/Experiments/RifleTransition/ChestRelative_20261013/
```

- `ABP_RifleChest_Down`：ExistingDown 的新副本。
- `ABP_RifleChest_Mesh`：旧 Progressive 的新副本，内部 Mesh Space=True。
- `ABP_RifleChest_Local`：只把两个内部 LBB 的旋转混合改为 Local Space。
- `ABP_RifleChest_LocalBoundary`：Local 加反向出口 0.12 秒状态混合。
- `L_RifleChestRelative`：可连续播放的独立 TP 对照地图。

打开新地图，选中 `RifleChest_Preview_UseDetailsButtons`，使用实时视口或 Simulate。
默认 Candidate=2，即 Local，IK 关闭；可对准关卡中的 TP Camera 观察。

1. `Cycle Candidate`：0 Down、1 Mesh、2 Local、3 LocalBoundary。
2. `Toggle Rifle Test Goal`：收枪 / 抬枪；过渡中再次点击沿原累计时间反向。
3. `Cycle Rifle Test Pitch`：0、+30、+60、-30、-60，不重建播放器。
4. `Toggle Existing IK`：切换既有 AimIK / LeftHandIK。
5. `Chest Status`：显示最近完成求值的状态、时间、方向和内部 Alpha，约落后一帧。

切换候选会重建实例，请先回 ArmedAim；连续播放中用目标和 Pitch 按钮。
直接编辑 Actor 属性可能触发 Construction，不能用这种重建证明中途反向连续。
旧 Rifle Layer 按钮在新 Actor 中隐藏；NaturalPitchStrength 不被本轮图消费。
TP 预览 Actor 没有真实 FP 净空上下文；本轮 FP 证据全部来自真实角色。

### 复用和改动范围

保留旧原型、旧地图、生产状态机、原播放器、Mask 和已验证的零 Alpha 更新机制。
没有重新实现 Alpha 或时钟；内部 Alpha 仍为原播放器实际 `t/T`。
保持 Base=实时 ArmedAimPose、Blend=CorrectedGrip / 原 MM_Rifle_LowReady。
Reload 分支、外层 LBB、Arms Slot、原有 IK 及其权重更新均未改。
只读引用生产 `RifleReloadWeightedUpperBody`；spine、neck、head 权重仍为 0。

LocalBoundary 只调整新副本的一条边：LowReady→AimTransition，0→0.12 秒。
ArmedAim 入场仍为 0；进入 LowReady 和返回 ArmedAim 仍为原 0.12 秒。
没有给 Alpha 加新曲线，没有重置时钟、冻结动作或改源动画关键帧。
没有实现空间补偿 C、D2/D3、Control Rig 或新 IK。

### 胸腔坐标与实际验证

参考为同帧最终 `spine_05` Component Space Transform。
记录双手、Rifle 实际第 0 根骨骼 Root、Muzzle 相对于该 Chest 的 Transform。
位置单位 cm；Raw Chest 坐标轴来自骨骼，不假定其 +Z 就是人体向上。
角度诊断的统一向上轴由实测 0° ArmedAim 的 Chest 反变换 Component +Z 得到。
枪口方向由实际 Muzzle Socket +X 取得。

```text
Relative = Component.GetRelativeTransform(Chest)
RecoveredComponent = Relative * Chest
RecoveredWorld = Component * MeshWorld
```

每帧用原始 BoneSpaceTransforms 和实际父骨骼 CS 做独立 FK 读回。
同时核对 Muzzle 的 Socket CS→Weapon World，以及 Chest 相对→CS→World。
115,680 帧最大位置误差在输出精度下为 0，最大旋转误差约 0.000005663°。
另以右臂四段原始 Local Pose 重建 Chest 相对手位，位置差小于 0.000010 cm。
因此本轮没有凭公式猜测乘法方向，也没有把枪械焊死在胸口。
相同 LowReady 相位跨 Pitch 一致；不同循环时刻仍保留原动画的运动。

## 2. TP 实际求值与边界原因

### 覆盖和结果

208 个案例，固定 60 Hz，共 115,680 帧；统一 Hold 相位为 1.0 秒。
固定 -60、-30、0、+30、+60；完整收放、一个完整 LowReady 循环及三组中途反向。
收枪、LowReady、抬枪各自覆盖负俯仰折返及 0→+30→+60→0。
先关 IK，再恢复既有 IK；所有候选使用同一源资源、Skeleton 和输入。

初始三候选的状态、累计时间、PlayRate、Hold 和 LowReady 相位完全一致。
Boundary 的反向源 LowReady 在交叉混合期间继续更新，属于新混合的正常行为。
活动播放器时钟仍与 Local 一致；全部案例时钟异常为 0，Alpha 误差约 2.99×10⁻⁸。
中途反向没有重置，实际 25% / 50% / 75% 请求点按 60 Hz 离散。

同一 LowReady 相位，五个固定 Pitch 的最大枪械 Chest 相对差如下。

| 候选（IK 关闭） | 位置差 cm | 旋转差 ° | Chest 随 AO |
|---|---:|---:|---|
| Down | 0 | 0 | LowReady 不保留实时 AO |
| Mesh | 36.756 | 51.706 | 保留 |
| Local | 0 | 0 | 保留 |
| LocalBoundary | 0 | 0 | 保留 |

Down 的相对差为 0 不能独立证明它跟随人体：其 LowReady 胸腔也不随输入 Pitch 改变。
Mesh 保留背部，但肩臂选择固定组件旋转，因而对保留的胸腔产生反向相对旋转。
Local 保留相同 AO 父级，复制收枪肩臂局部旋转，枪械才随 Chest 一起俯仰。
候选 Chest 与同帧 ArmedAim Base 的旋转差在微小浮点误差范围内。

负俯仰收枪仍有小的相对方向包络超额：Local -60° 约 0.081°、-30° 约 1.055°。
Mesh -30° 同口径约 3.715°；Local 并非数学上每个指标都严格单调。
相对位置、距离及方向曲线须结合动作意图看，不再以绝对高度幅度单独判失败。

### 循环后反向首步

下表为相同完整循环相位的 frame 799→800，IK 关闭，右手 CS 位移。

| Pitch | Down cm | Mesh cm | Local cm | LocalBoundary cm |
|---|---:|---:|---:|---:|
| -60° | 0.764 | 4.164 | 3.270 | 0.168 |
| -30° | 0.758 | 3.925 | 3.365 | 0.173 |
| 0° | 1.301 | 3.627 | 3.483 | 0.179 |
| +30° | 1.301 | 3.441 | 3.689 | 0.190 |
| +60° | 1.301 | 3.340 | 3.837 | 0.198 |

源 CorrectedGrip 末端与当前 LowReady 循环姿态并不相同。
以 0° Local 的末端→循环后姿态为例，Local 角差及单骨替换对手位的影响为：

| 骨骼 | Local 角差 ° | 单骨替换手位变化 cm |
|---|---:|---:|
| clavicle_r | 1.979 | 1.099 |
| upperarm_r | 3.708 | 1.985 |
| lowerarm_r | 3.027 | 1.439 |
| hand_r | 5.294 | 约 0 |

这些替换是诊断，不可直接相加；腕部旋转解释枪向差，基本不解释腕点位置差。
零时长反向入口把当前循环姿态立即换成收枪末端附近，放大了这种源姿态差。
Local 可以解决继承空间，却不能自动解决两个源动作的端点差。

0.12 秒混合改善首步，动作时间和响应没有冻结。
但随后 0.12 秒内最大手位单步仍为约 1.31～2.42 cm，不能只用首步评分。
是否存在不自然减速或抬枪迟滞，需要用户连续播放观察。

### 原有 IK 与人体姿态

Local 的肩臂与低位方向在 TP 截图中跟随弯曲或抬起的胸腔。
未观察到所检视截图中的明显骨骼失控；不据静态图宣布所有肩肘腕都自然。
关闭 IK 的握点距离保留源 LowReady 的误差；恢复 LeftHandIK 后稳定低位靠近实际握点。
现有 AimIK 仍会改变过渡期间右手 / 枪向，不能把最终姿态只归功于 Local Blend。
没有调整其算法、目标或权重；若继续迭代，应先在实验数据源评估收枪期释放时序。
ArmedAim 和 LowReady 两端应保留原语义，不先建设新 IK。

已采集 300 张 TP 图，覆盖四候选、五 Pitch、15 个状态时间点。
同组状态、播放器时间与方向一致；截图的短暂 LowReady 抬枪不是完整循环边界。
完整循环边界由上述 60 Hz 序列验证，不能拿截图 frame 200 代替 frame 800。

## 4. 复测与最终回答

正常保存并退出本项目编辑器后使用启动脚本，标签必须未使用。

```powershell
Scripts/Tests/RunRifleChestPrototype.ps1 -Mode Measure -Label NewMeasure
Scripts/Tests/RunRifleChestPrototype.ps1 -Mode Measure -Boundary -Label NewBoundary
Scripts/Tests/RunRifleChestPrototype.ps1 -Mode TP -Label NewTP
Scripts/Tests/RunRifleChestPrototype.ps1 -Mode FP -Candidate Local -Label NewLocalFP
```

FP Candidate 可选 Down、Mesh、Local、LocalBoundary；每次使用独立真实角色世界。
Prepare 只保存新目录；Map 只允许初次创建，存在时拒绝覆盖。
原始数据和可交互曲线 / TP / FP 图库位于 Saved/RifleChestRelativePrototype_20261013。
正常灯光、持续鼠标俯仰、完整 K 收放与肩肘自然度仍需用户实际连续验收。
自动化窗口的离散截图不能替代该项，独立 TP 地图也不能代替真实 FP Gameplay。

1. Mesh Space 确实限制肩臂继承 Chest 旋转；实际相对差支持此前空间判断。
2. Local 保留动作局部轨迹，稳定低位跨 Pitch 同相位的相对姿态一致。
3. 单一 CorrectedGrip 已在 -60°～+60° 完成全部自动化动作；自然度尚待连续验收。
4. LowReady 可以随实时 AO 胸腔移动和旋转，不要求固定组件位置。
5. Local 本身未消除反向端点差；0.12 秒边界混合明显改善，仍需看后续速度分布。
6. 暂不需要额外胸腔空间补偿；已有局部混合与一次状态交叉混合足以继续验证。
7. 指定负俯仰中心遮挡消失，高俯仰右缘大块身体入镜改善；不保证全视角全帧。
8. 值得继续研究替代 Down，以 LocalBoundary 为候选；本轮不正式取消回退选片。

本轮纠正了验收目标，旧历史报告保留原貌，不把新结论回填到旧文件。
工具仅为 Editor / Uncooked 原型，不是可烹饪的生产实现。

外部依据：[Epic UE5.6 Blend Nodes](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprint-blend-nodes-in-unreal-engine?application_version=5.6)。
