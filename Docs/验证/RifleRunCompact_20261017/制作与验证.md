# Rifle Run 贴身与抬枪修正隔离验证

日期：2026-10-17；UE 5.6.1、Blender 4.5.8 LTS。
用户要求解决新跑姿抬枪时左臂歪曲、枪托扫入 FP 中央，并缩减横移、随双肩前后摆动。
本轮完成隔离资产和定向验证，等待用户视觉验收；未接入生产、未提交。

## 现象与依据

旧 F5 使用相对原 LowReady 的大幅 Local Additive，过渡中叠加到仍在变化的肩臂姿态。
既有左手 IK 持续启用，最终握持关系稳定；因此问题不能归类为左手脱离握点。
现有 IK 根据进入节点前的肘点确定弯曲平面，抬枪时输入姿态会影响最终左臂形状。

- 旧 F5 实际日志出现约 33 cm 以上源手误差、约 20 cm 肘点修正和 Pole 点积为负。
- 固定 60 Hz 的抬枪图像可见旧版左臂短暂靠近脸部、弯曲方向突变。
- 新版不修改 IK 算法，而是修正其输入动画、过渡基础姿态及叠加幅度。
- 本轮没有改 ClearanceProxy、摄像机、Socket、Skeleton 或 Gameplay。

官方 Apply Additive 定义为向当前基础姿态叠加差值，不保证中间姿态满足双手约束。
本项目实际图与 UE5.6 节点用法一致；没有改为新的运行架构或增加 AnimNode。

[UE5.6 Blend Nodes](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprint-blend-nodes-in-unreal-engine?application_version=5.6)

## 实际修改

```text
    ABP_RifleRunCompact

```

- Base 保留原 LowReady 的 258 点、8.566667 秒动态持姿，协调双臂到更贴身的手部目标。
- 过渡副本保持 26 点、0.833333 秒、RateScale 2.6；首帧逐项保留原始值。
- 过渡以五次平滑权重协调右手路径和双臂，到末端匹配新 Base 第 0 帧。
- 末端肩臂 Local Quaternion 最大差约 0.00164°，不是全身所有骨骼的匹配结论。
- 过渡的 spine、root、pelvis、腿、头颈和手指沿用原始轨道，不改原有胸腔 AO。
- 跑动 Additive 改为相对新 Base 第 0 帧，只承载周期运动，不再承载大的持枪姿态差。
- 从原 Rifle Run 保留胸腔左右转动节奏，峰值约 ±6°，沿 spine_01–05 小幅分配。
- 双肩随胸腔一前一后；双手目标随胸腔转动，减少枪相对胸腔独立横移。
- 右手横向、前后、竖直残余运动分别缩放为原素材的 10%、15%、15%。
- 双臂在 Blender 离线协调并烘焙，保留双手关系；导出不依赖 Constraint。
- 跑动仍为 54 点、1.766667 秒，三轮周期匹配原下身，保持 SprintStride 同步。

ABP 副本保留三态、真实时间比例、正反播放、头颈修正、AO、Mask、IK 和原 Reload / Fire。
只更换对应基础序列、过渡配置与 Additive 序列，不增加运行时 C++ 类或节点。

IK 日志按周期或阈值输出，不把已输出样本最大值描述为所有帧的误差峰值。
日志按 Listen 段、拥有端实例和引擎帧号关联；排除同日志内 Dedicated / Emulated 的其他实例。
肘平面相邻转角来自最终 TP 肩、肘、手骨骼；固定 60 Hz 两版各有 20 个抬枪姿态样本。
两版起始步态相位不完全相同，不能当作严格同相位 A/B 的穷尽证明。

普通运行中新版 0°、-60°、+60° 胸腔跨度分别约 11.46°、11.35°、11.59°。
三角度相机旋转跨度均为 0°，固定步长数值残差小于 0.0001°。
新版相机 Z 总跨度约 8.92、8.66、8.95 cm，含下身步态运动，不等于相机位置完全静止。
最终双手相对位置最大偏差小于 0.00056 cm，不等于网格表面握点零误差。

全部动画 UE 读回最大 Local 位置误差约 0.000527 cm、旋转误差约 0.001321°。
没有产生异常缩放；过渡首帧保持，原资源播放倍率与时间方向保持。

## 操作与保护

Play 后向前拾 Rifle，W + Shift 跑步，松 Shift 抬枪。
F4 是新贴身版、F5 是旧 Rifle Run、F6 是 Sway、F7 是原版；HUD 显示实际方案。
先选方案再 F8 脱离看 TP，也可在新角色实例详情面板使用四个方案按钮。
切换 AnimClass 会重新初始化，应在同一方案内通过 Shift 评价自然过渡。

696 个既有基线文件中，仅原实验地图发生预期改变；旧 F5 与生产资源、源码、配置保持哈希。
已恢复两份临时 C++，正式 Editor 重编译通过，耗时约 24 秒。
恢复后只读核对新 AnimBP、三项过渡引用、角色和 GameMode / HUD 关联，查询包均未脏。
没有新增地图、改生产资源、提交或推送。

## 问题与处理

- 首次制作检查把原有腿、手指和 spine 差异也纳入衔接门限，导致校验拒绝。
  改为检查本轮调整的肩臂链；保留原轨道，不通过改无关骨骼掩盖失败。
- 旧实验角色保存失败，Windows 报 sharing violation 32；磁盘文件仍与基线相同。
  Restart Manager 确认是 VS PID 19748 持有文件；未操作、关闭或重载 VS。
- 新 AnimBP 当时已保存。核对部分结果后续接，改为复制角色、HUD、GameMode，避开旧文件。
- 截图耗时让普通运行短过渡只取得三帧。按本地 UE5.6 固定步长参数补充 60 Hz 取证。
- 临时截图工具有已有弃用 API 警告；工具已移除。测试有既有 GAS / NavMesh 警告。
