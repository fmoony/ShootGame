# 左前与右后混合挤脚、下沉的只读分析

日期：2026-11-17；UE 5.8.4；codex/ue-5.8。
用户已验收前、后、左、右、前右、后左，本次只分析左前与右后。
不修改动画、BlendSpace、AnimGraph、Skeleton、代码或编辑器内容。

## 结论与问题分类

主要问题是两组来源在当前同相位下的腿部动作不兼容。
关键帧的左右脚前后排列相反，等权局部姿态混合使脚步对冲。
局部旋转插值又使腿链的水平展开缩小、向下伸展增大。
因此出现双脚挤到一起，以及踝、脚尖低于两段来源的结果。

这是当前两条邻向组合的资源兼容性与姿态插值问题。
不等同于四段原始动画自身不合格，更不能据此统一它们的运动特征。
没有发现重新引用旧资源、重复右后样本或错误方向权重的证据。
旧版 Root 净行进与循环回跳不是本次主要原因。
骨盆在所查下沉帧没有出现额外下压，不能归因于来源骨盆高度不同。

## 挤脚：左右脚前后排列对冲

脚的位置并非只由移动方向标签决定。
同一周期进度，两段素材可能采用不同的摆腿排列。
以下取当前离线鞋面相交候选最明显的实际运行帧。
间距为 foot_l／foot_r 踝点的三维距离，不是鞋面距离。

| 混合方向 | 周期进度 | 来源一踝间距/cm | 来源二/cm | 实际混合/cm |
| --- | ---: | ---: | ---: | ---: |
| 右后 | 0.1333 | 后 66.25 | 右 69.17 | 1.70 |
| 左前 | 0.7333 | 前 84.35 | 左 86.64 | 3.70 |

以各姿态髋部横轴及地面法线定义身体前后参考：
右后帧的来源双踝前后有符号距离约为 -63.67／+68.88 cm。
左前帧约为 -82.55／+86.54 cm。
符号相反说明左脚相对右脚的前后排列对冲。
这些排列各自在原动作中可以自然，但不能直接假设等权混合也自然。

来源前行和后退在部分相位的横向踝点次序本来就会交叉。
由于当时仍有较大的前后距离，不等于鞋子互穿。
混合缩掉前后距离后，才把原本分开的两只鞋挤到一起。
实际蒙皮估算在这些帧同时产生左右鞋表面相交候选。
不能只用横向踝点次序为负就判定原动作错误。

## 下沉：额外位移在腿链中逐级产生

原生 BlendSpace 混合的是骨骼局部变换，随后按层级得到最终脚的位置。
它没有把来源鞋底在世界空间直接做平均，也不约束脚底高度。
因此两段来源的脚均在地面上方，不保证混合后的脚仍在地面上方。

### 左前，周期进度约 0.3667，右腿

| 骨骼 | 来源组件位置平均 Z/cm | 实际混合 Z/cm | 差值/cm |
| --- | ---: | ---: | ---: |
| Root | -30.08 | -30.08 | 约 0 |
| pelvis | 65.59 | 65.72 | +0.13 |
| thigh_r／髋 | 63.04 | 63.17 | +0.13 |
| calf_r／膝 | 36.26 | 30.62 | -5.64 |
| foot_r／踝 | 12.85 | 0.74 | -12.12 |
| ball_r／脚尖 | 3.65 | -14.96 | -18.61 |

右大腿局部旋转在两段来源间相差约 83.84°。
髋到踝的水平伸展由来源约 44.16／35.08 cm 缩为 14.42 cm。
混合腿链更朝下，垂直落差增大，脚部继续累积额外下沉。
此帧膝关节内角在来源约 98.93／95.34°，混合约 96.98°。
这说明并非单纯把膝盖错误拉直，而是整条腿的方向与弯曲平面变化。

没有建议把它作为新的混合算法，也没有据此修改任何关键帧。
下沉最明显帧与挤脚最明显帧不同，它们是同一兼容性问题的不同表现。

## 为什么主要是这两个方向

前与右的腿部屈伸变化较接近，后与左也较接近。
前与左、后与右则存在不同的屈伸与前后摆腿组合。
全周期双腿膝角曲线的平均相关性如下：

| 来源组合 | 不移相位的相关性 |
| --- | ---: |
| 前＋右 | 0.79 |
| 后＋左 | 0.91 |
| 前＋左 | -0.17 |
| 后＋右 | -0.04 |

这里只用相关性区分动作时序，不把它作为自然度合格线。
用户对其余六个方向的视觉验收结果保持有效。

不能据此直接认定两段整体错开了半个周期。
前＋左、后＋右的踝部高度曲线在当前相位仍有正相关，约 0.63／0.59。
在离线统计中平移半周期后，膝角相关性虽提高，踝高相关性却变成负值。
对应约为 -0.62／-0.63。
因此一个固定的半周期偏移不能同时证明屈膝与抬脚时序都正确。
本轮没有执行移相位播放，也没有制作对应动画。

## 引擎行为与验证边界

本地 UBlendSpace::GetAnimationPose 调用 FAnimationRuntime::BlendPosesTogether。
该实现按来源权重累积 CompactPose 的骨骼变换，并归一旋转。
位置求平均与层级旋转求值后的脚部位置不是同一件事。
本次观察符合该机制，没有证据指向坐标导入错误或新的 IK 干预。

本地范围：
Engine/Source/Runtime/Engine/Private/Animation/BlendSpace.cpp。
Engine/Source/Runtime/Engine/Private/Animation/AnimationRuntime.cpp。

Epic 同步文档区分长度同步和基于标记的动画同步。
同周期长度或相同归一时间不能单独证明脚步事件相同。
这不是建议立刻添加标记；当前多项动作特征仍需分别验证。
[官方同步说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-sync-groups-in-unreal-engine)。

本次没有重新渲染或采集新的 UE 姿态，没有改变编辑器状态。
没有实施资源修复、全局相位偏移或运行时补偿。
后续若验证修复，必须单独保护已验收的六个方向。
不能因为某种相位变换改善两条邻边，就默认另外两条邻边仍正确。
