# Rifle K 动画网络预览

日期：2026-10-13。用户授权最小 C++ 通信接口与既有蓝图 K 结合，方便移除。
会话已确认保存且不编辑；不提交 / 推送，不改素材、Mask、FP Proxy 或 Gameplay 规则。

## 不变量含义覆盖确认

### Invariant 1 Owner Immediate Feedback

- 触及：K 姿态入口分流，网络 K 暂用服务器确认目标，有往返延迟。
- 不应改变：Shot Intent、Owner Fire 立即反馈、Authority Result 仍分离。
- 新证据：真实 K 无射击、无 Ammo 消耗；Fire 保留原入口并可打断预览。
- 范围外：Fire 四种 Accepted / Rejected 组合；未改 Fire 预测，姿态同步不证明其完整通过。

### Invariant 2 Local Prediction Obeys Weapon Rules

- 触及：本地与服务器均核对 Rifle 及原有动作边界。
- 不应改变：半自动 / 全自动、Ammo 预算、预测窗口、Hit / Damage 不由新组件处理。
- 新证据：不合法 K 无切换，中断后目标清理；新 RPC 仅改预览 bool。
- 范围外：完整射速、预测 Reject 与延迟补枪矩阵，新组件不调用这些路径。

### Invariant 3 Server Is Final Authority

- 触及：服务器裁定预览目标，拥有连接才可提交组件 Server RPC。
- 不应改变：权威射击、Ammo、Projectile、Hit、Damage 的校验与提交职责。
- 新证据：Owner / Observer 目标收敛，稳定对象 K 案例的 Shot / Ammo 增量为 0。
- 范围外：所有非法 Shot Intent 的 Reject / Cleanup，未改权威射击实现。

### Invariant 4 Remote Is Confirmed Only

- 触及：远端消费服务器复制目标，不消费拥有端本地入口。
- 不应改变：Remote Fire 沿用原服务器确认表现，不增加 Multicast 或可靠逐发反馈。
- 新证据：SimulatedProxy 播放复制目标；非拥有者不能用 K 接口操控别人的目标。
- 范围外：逐发 Muzzle / Sound / Recoil 去重，新组件没有这些入口。

### Invariant 5 Exactly One Authority Result

- 触及：增加预览 RPC，必须证明其无额外权威游戏结果。
- 不应改变：一份 Shot Commit、一次 Ammo 消耗、一次 Reload 提交的规则。
- 新证据：稳定对象的 K 增量对照；保留 Fire / Reload 打断回归。
- 范围外：完整多人射击四反馈计数，不用姿态测试冒充全部绿色。

## 最小实现

一个可移除的原生 ActorComponent：可靠 Server Toggle / Cancel，复制一个 bool。
既有 BP_ShooterCharacter 的蓝图 K 仍调用 ToggleDebugRifleLowReady，网络模式委托新组件。
Standalone 或开关关闭时沿用原本地入口；专用服务器存目标，不求值低位姿态。
不复制逐帧动画时间，不新建 Gameplay 状态，不挂接 Ability、弹药或伤害提交。
属性复制可合并短暂目标；本轮验证最终目标与动作方向，不承诺每个快速脉冲可见。

## 本轮结果

Build 通过。真实 PIE 使用正式 Lvl_Shooter、BP_ShooterCharacter 和 ABP_TP_Player。
K 经 PlayerController InputKey 进入既有角色蓝图，不直接改测试实例的姿态 bool。
Listen 使用真实服务器及一条客户端连接；Dedicated 使用专用服务器及两条客户端连接。
Emulated 在各 PIE NetDriver 设置 PktLag=80 毫秒、PktLoss=2%，采用 Listen 拓扑。
测试中的 NPC 移除、角色冻结及 Rifle 装备仅作用于临时 PIE 世界，不保存资产。

| 场景 | 结果 | 实际覆盖 |
|---|---|---|
| Listen | PASS | 客户端触发、主机触发、远端观察、中途反向 |
| Dedicated | PASS | 两个客户端，服务器存目标，Owner / Observer 播放 |
| Emulated | PASS | 80 毫秒延迟、2% 丢包、反向及目标收敛 |
| Off | PASS | 开关 0 时仅拥有端切换，服务器目标保持 false |
| 既有 Standalone PIE | PASS | 原有 K、俯仰、反向及动作打断回归 |

网络三场景确认 Fire / Reload 清理预览目标，并回到 ArmedAim。
Fire 回归要求固定权威武器实际 Shot Count 增加，不用零样本宣称开火成功。
Reload 回归实际进入原 WeaponAction 的 Reload 状态；没有新增换弹提交逻辑。
每个纯 K 检查点均确认该固定权威武器 Shot Count / Ammo 增量为 0。
非拥有者通过同一蓝图入口尝试切换，服务器目标保持不变。

CSV 每帧读取真实 RifleReady 状态、播放器时间、速率、组件目标、动画目标及网络角色。
最终 Emulated 的四次新入场差为 82.86～83.34 毫秒，反向速率变化差为 83.24 毫秒。
这描述同进程采样的表现阶段差，不是 RPC 往返时延或跨机器时钟测量。
无延迟场景的微秒差来自同一帧遍历，不能视为微秒级同步精度。
各端 CSV 均有实际负速率过渡样本；原片段长度 0.833333 秒及各端累计时间机制保留。
未发送动画时钟，后加入玩家只能从复制目标进入动作，不保证追赶其他端的当前相位。
未执行晚加入专项测试，不把上述机制分析作为晚加入验收。

## 实现依据与本地核对

Epic 文档说明 ActorComponent 可复制属性和执行 RPC，其所属 Actor 也必须复制。
本组件使用原角色的复制及拥有连接，无额外网络 Actor。
依据：[Actor Component Replication](https://dev.epicgames.com/documentation/unreal-engine/replicating-actor-components-in-unreal-engine?application_version=5.6)。
Server RPC 的路由依赖拥有关系；不采用由任意观察端触发的 Multicast。
依据：[Actor Owner and Owning Connection](https://dev.epicgames.com/documentation/unreal-engine/actor-owner-and-owning-connection-in-unreal-engine?application_version=5.6)、[Remote Procedure Calls](https://dev.epicgames.com/documentation/unreal-engine/remote-procedure-calls-in-unreal-engine?application_version=5.6)。
本机 UE5.6 ActorComponent.cpp 已核对 GetFunctionCallspace / CallRemoteFunction 委托所属 Actor。
实际使用 SetIsReplicatedByDefault、DOREPLIFETIME 和可靠 Server RPC，UHT / UBT 编译通过。
原项目 K 只消费本地目标；本轮差异仅为网络委托与远端 TP 的预览可用性。
FP 仍由本地角色沿用 CopyPose 与现有净空处理，不让远端访问本地 FP 或摄像机。

## 按网络契约固定格式报告

以下 PASS 只覆盖本轮 K 网络预览的变更范围，不表示五条射击不变量已完整复验。

### Invariant 1 Owner Immediate Feedback

- 结果：K 改动范围 PASS；完整 Fire 反馈范围未评估。
- 含义覆盖：Shot Intent / Owner Presentation / Authority Result 沿用原分离边界。
- Predicted / Unpredicted：K 不预测目标；Fire 原有预测逻辑未改，四组合未测。
- Owner immediate feedback：网络 K 等服务器确认；Fire 实际可触发，立即反馈计数未测。
- Confirmed replay：未新增 Fire 回补入口；本轮未量化原 Fire 的四项 replay 计数。
- Accepted 但未本地表现：未构造该射击案例；K 确认延迟允许存在且最终收敛。
- 证据：稳定武器纯 K 的 Shot / Ammo 增量 0，实际 Fire 能打断预览。
- 测试：NetworkPreview.Listen / Dedicated / Emulated / Off、既有 RifleReady.PIE。

### Invariant 2 Local Prediction Obeys Weapon Rules

- 结果：K 改动范围 PASS；完整射速、预测限制与 Reject 清理范围未评估。
- 含义覆盖：仅消费 Rifle 及既有动作限制，不创建预测射击或新装备语义。
- Semi-auto / Full-auto：未复验完整射速矩阵；网络回归仅实际触发当前 Rifle Fire。
- 本地已知限制：沿用原 Firing / Reloading / Equipping / Dead / Montage 检查。
- 不越权：组件只改姿态 bool，不写 Ammo、Projectile、Hit、Damage 或 GAS Tag。
- 收敛：Fire / Reload 清理姿态目标；未测全部 Reject、死亡、换枪及断连时序。
- 测试：NetworkPreview.Listen / Dedicated / Emulated。

### Invariant 3 Server Is Final Authority

- 结果：K 改动范围 PASS；完整非法 Shot Intent 与 Accept 数量契约未评估。
- 含义覆盖：Server RPC 裁定预览目标；权威游戏结果仍由原代码产生。
- Accept：真实拥有连接提交 K，服务器与可渲染观察端最终目标一致。
- Reject：非拥有者的既有入口无效；未构造伪造网络包或所有动作门控组合。
- Cleanup：实际 Fire / Reload 后服务器目标 false，动画回到 ArmedAim。
- Accepted Activation == exactly one Authority Shot：纯 K 无 Shot；Fire 仅验证实际提交。
- Owner confirmed cosmetic backfill：没有新增入口；未量化原有回补计数。
- 测试：NetworkPreview.Listen / Dedicated / Emulated / Off。

### Invariant 4 Remote Is Confirmed Only

- 结果：K 改动范围 PASS；Remote Fire 四项表现计数未评估。
- 含义覆盖：远端 TP 从服务器复制目标取值，不从 Owner 本地 bool 取值。
- 证据：Dedicated 的 SimulatedProxy 实际收枪及反向；关闭开关后远端保持 ArmedAim。
- 没有新增 Multicast、Muzzle、Sound、Recoil 或远端游戏结果入口。
- 测试：NetworkPreview.Listen / Dedicated / Emulated / Off、角色 CSV。

### Invariant 5 Exactly One Authority Result

- 结果：纯 K 无额外结果 PASS；完整 Fire / Reload exactly-once 范围未评估。
- 含义覆盖：姿态目标不产生权威射击、伤害或换弹事务。
- Authority Commit 数：纯 K 固定武器增量 0；Fire 回归实际增量大于 0。
- Ammo 消耗：纯 K 固定武器增量 0；没有用换枪后的实例计数代替稳定对象。
- 换弹事务提交次数：原 Reload 实际运行；本轮未做 exactly-once 定量断言。
- Projectile 数：未测；新组件不生成 Projectile。
- 是否存在重复：K 未产生额外 Shot / Ammo；Fire 四表现及逐发重复未专项复验。
- 测试：NetworkPreview.Listen / Dedicated / Emulated / Off。

### Owner Fire Presentation 四路径及其余边界

PredictedAccepted、PredictedRejected、UnpredictedAccepted、UnpredictedRejected 未完整取证。
FullAuto / PktLag 的 delayed Owner replay 未专项复验。
本轮没有修改这些实现，按变更范围采用 K 定向验证及既有 Fire / Reload 打断回归。
Build / Listen / Dedicated / Emulated / Standalone 均完成；视觉自然度仍需人工观察。

## 用户检查与撤销

1. 在正式 Lvl_Shooter 设置 2 Players、Play As Listen Server，两个窗口各自装备 Rifle。
2. 客户端按 K，同时在主机观察该角色；检查收枪、抬枪、中途再按 K、动态低头与抬头。
3. 交换操作者，从主机按 K，在客户端观察；确认 FP 仅显示本地角色的原表现链。
4. LowReady 时触发原 Fire / Reload，确认动作仍执行，结束后回到 ArmedAim。
5. 需要 Dedicated 时选 Play As Client、2 Players；近景遮挡和手臂自然度由用户视觉验收。

快速关闭：各进程执行 `ShootGame.RifleReady.NetPreview 0`；恢复用 1。
彻底移除：删除新增组件 h / cpp，撤销 Character 的 include / CreateDefaultSubobject。
再撤销 AnimInstance 的 include、网络委托、网络目标读取与 bWasNetworkRiflePreview。
蓝图 K、原动画状态机、素材及 Local 肩臂节点不用删除；Editor 网络测试可一并移除。
新增 / 删除源码后按项目规范只刷新一次 VS 工程文件，随后重新编译。
