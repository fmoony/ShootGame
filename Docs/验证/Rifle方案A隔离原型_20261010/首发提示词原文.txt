# ShootGame — 方案 A：Rifle 原生状态机过渡隔离原型与运行时验证

## 一、任务性质与目标

本轮从只读审查转为**有限授权的隔离原型实施**。

目标是在 UE5.6.1 中，采用原生 State Machine Transition Blend，验证 Rifle 三个动画状态之间的自然过渡、反向播放、动态俯仰以及中断恢复。

目标状态：

```text
ArmedAim
    ↕
AimTransition
    ↕
LowReady
```

只研究同一把 Rifle 的持枪姿态切换。

本轮**允许创建、修改并保存隔离测试资产**，允许进行必要的隔离测试与诊断。

不得修改、保存或覆盖正式生产 AnimBP、原有动画资产、Gameplay 代码及稳定动画系统。

**不实施 Drawing、Holstering、Stowed，不修改 GAS，不改变任何开火资格。**

本轮是功能性实验，不是完整换枪系统交付。

## 五、方案 A：实现原生状态机

测试状态：

1. `ArmedAim`
2. `AimTransition`
3. `LowReady`

### ArmedAim

完整复用现有 ArmedAimPose。

继续支持：

- Rifle Hold Sequence
- AO_Rifle
- 动态 AimPitchN
- 原有上半身分层

不得将 ArmedAim 替换为固定 Sequence 或 Mixamo 姿态。

### LowReady

使用：

`MM_Rifle_LowReady`

要求：

- 正常循环。
- 能维持非瞄准低位持枪姿态。
- 不自动触发 Gameplay 状态修改。

### AimTransition

使用：

`MM_Rifle_AimToLowReady`

这段 Sequence 的方向约定：

- t=0：接近 ArmedAim 的抬枪端。
- t=L：接近 LowReady 的降低端。

ArmedAim → LowReady：

- 正向播放。
- 从 t=0 开始。
- 到达 LowReady 端后进入 LowReady。

LowReady → ArmedAim：

- 反向播放。
- 从 t=L 开始。
- 到达 ArmedAim 端后进入 ArmedAim。

要求：

1. 使用同一个 Sequence Player。
2. 明确设置正反向进入时的播放起点。
3. 中途改变方向时保留已有 Accumulated Time。
4. 不允许每帧重置累计时间。
5. 反向出口不能直接依赖只适合正向播放的自动结束规则。
6. 状态已经失活后重新进入，应根据入口来源正确初始化时间。
7. 原生 Transition Blend 负责状态之间的交叉混合。

**必须区分状态机 Transition 反向与 Sequence Player 时间反向。**

### 过渡混合

首选 UE 原生 Standard Blend。

初始试验参数：

- ArmedAim ↔ AimTransition：0.10s
- AimTransition ↔ LowReady：0.10s
- Blend 曲线：HermiteCubic

这些只是试验初值，不是最终手感参数。

可在隔离环境中比较 0.08s、0.12s、0.15s。

不要用过长混合掩盖素材问题，也不要为了缩短动画而强行提高播放倍率。

```text
RifleTestGoal:
    ArmedAim
    LowReady
```

仅驱动测试动画状态机。

不增加 GameplayTag、不复制状态、不改正式输入映射。

要求支持：

- LowReady 请求 ArmedAim。
- AimTransition 正向播放期间请求 ArmedAim。
- AimTransition 逆向播放期间请求 LowReady。

目标变化应尽可能在同一 AimTransition Player 内完成速率反转，保留当前累计时间。

不得为每次输入重新创建一个动作实例或无条件从头播放。

如果 UE 状态机相关性或初始化机制导致无法保持进度，请先定位并处理测试图的节点时间管理，而不是引入方案 C。

## 七、优先验证的四项内容

### 1. 原生过渡的实际观感

测试：

- ArmedAim → LowReady
- LowReady → ArmedAim
- 25%、50%、75% 进度反向
- 刚进入 AimTransition 就反向
- 靠近两端点时连续切换

记录：

- 实际 Sequence 累计时间。
- 当前播放方向。
- Transition Alpha。
- 当前状态及状态权重。
- 是否发生姿态突跳或动作重播。

### 2. 动态俯仰

至少测试：

- 0°
- +30°
- +60°
- -30°
- -60°

分别在不同俯仰下开始过渡。

额外测试：

- 抬枪期间继续向上看。
- 降枪期间继续向下看。
- 中途反向后恢复当前 AimPitch 对应的 ArmedAim。
- 快速连续改变俯仰方向。

不要把 AO 单独样本当作真实 ArmedAimPose 输出。

### 3. Layered Bone Blend 边界

保留生产图相同的：

- Spine_01 Branch Filter
- BlendDepth=1
- Mesh Space Rotation Blend=True
- WeaponUpperBodyWeight=1（有有效装备时）

检查：

- pelvis 最终来自哪条分支。
- spine_01 的 Mesh Space Rotation 过渡是否连续。
- clavicle / upperarm / hand 的组件空间轨迹。
- Mixamo 的 pelvis 姿态是否在分层边界产生补偿旋转。

重点记录：

**普通 Transition Blend 是否导致可见的躯干或肩部快速偏转。**

优先观察效果。

若有明显问题，再进行节点级姿态取证，不必一开始就开发庞大的全骨骼导出框架。

### 4. Arms Slot 满覆盖后的恢复

当前生产 Slot：

`Always Update Source Pose=False`

在隔离副本中比较：

A. False（当前配置）。

B. True（实验配置）。

使用现有 Fire Montage 制造 Arms Slot 覆盖，只测试动画表现，不触发真实射击 Gameplay。

记录：

- WeaponAction 是否持续 Update。
- Sequence Player 时间是否继续推进。
- 状态机是否重新初始化。
- Fire Montage 结束后是否恢复正确姿态。
- 是否出现 AimTransition 从头重播。

**不要因为 True 看起来更合理就直接修改生产 Slot。**

必须先给出实验结论。

## 九、视觉验收

需要在隔离环境内实际播放并检查：

- ArmedAim 是否保持原有握枪姿态。
- LowReady 是否合理持枪。
- 抬枪与降枪是否存在突然的肩部旋转。
- 中途反向是否自然。
- 是否出现短暂参考姿态。
- 相机是否产生明显晃动。
- FP CopyPose 是否继承正确的 TP 姿态。
- 左手是否被 IK 强行拖拽。
- Rifle 是否出现明显枪口跳动。

允许调用已有 IK 诊断，不修改生产 IK 节点。

如果只能验证节点、日志或骨骼坐标，不能声称已经完成人眼观感验收。

无法可靠自动判断的视觉问题应提供可复现的编辑器操作步骤，交由用户确认。
