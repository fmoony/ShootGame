### 三态实现

```text
ArmedAim --LowerRequested--> AimTransition --AtLowEndpoint--> LowReady
ArmedAim <--AtAimEndpoint--- AimTransition <--RaiseRequested-- LowReady
```

测试副本的 WeaponAction 只有这三态，移除了副本中的 Reload 及其过渡。
生产 Reload、ReloadRecovery、Fire、Slot、IK 和上游 ArmedAim 图均未修改。

ArmedAim 完整沿用原图的动态 Hold → AO → ArmedAimPose 缓存。
LowReady 使用 `MM_Rifle_LowReady`，循环播放。
AimTransition 使用单个非循环 `MM_Rifle_AimToLowReady` Player，长度 0.833333 秒。
动画 RateScale 保持 1，没有通过提速缩短动作。

Goal 只有 ArmedAim 和 LowReady；PlayRate 为 -1 或 +1。
进入动作态时，目标 LowReady 使用 StartPosition=0，目标 ArmedAim 使用 StartPosition=L。
StartPosition 是动态输入，但只在 Player Initialize 时决定累计时间。
中途变更 Goal 只改变速率，不调用 SetAccumulatedTime，也不重新创建 Player。
AimTransition 的 AlwaysResetOnEntry=True，仅处理状态退出后再次进入。

四条过渡均为 Standard Blend、HermiteCubic、0.10 秒。
两个出口显式同时检查方向目标及对应累计时间端点，不依赖正向自动结束规则。
状态机相关性、首次更新和原生过渡栈沿用生产副本的设置。

### 正常过渡与反向

最终在 60 Hz 下实际运行 7,666 帧。
57 项检查全部通过，其中包含对 Slot False 恢复问题的预期复现。
“检查通过”表示观察成立，不表示发现的素材问题或视觉表现合格。
最终 Commandlet 为 0 错误、45 警告；初始化时存在 Mesh 未绑定前的 Socket 查询警告。
这与 Blueprint 编译的 0 警告是不同检查，不能合并称为运行零警告。

五个俯仰角都完成 ArmedAim → AimTransition → LowReady → AimTransition → ArmedAim。
正向进入首帧累计时间 0.016667 秒，反向进入首帧 0.816667 秒。
这是从 0 或 L 初始化后推进一帧的结果。

约 25%、50%、75%，以及刚进入和接近终点的双向反转均已运行。
以下为反转前一帧与反转首帧的实际时间，未重新播放动作。

| 正向播放后反转 | 反转前 | 反转首帧 | 首帧速率 |
| --- | --- | --- | --- |

| 25 帧，50% | 0.416667 | 0.400000 | -1 |

WeaponAction 持续更新，动作时间推进，覆盖期间可反转，未发现此 Fire 导致重播。

为了验证源图被完全覆盖的分支，另创建了不保存的动态 Montage。
它使用既有非加法 Rifle Hold，仅作源图活性诊断，不修改 Fire 或 Hold 资产。
这项补充测试不能冒充“现有 Fire 非加法满覆盖”的结果。

| 非加法 SourceWeight=0，55 帧 | False | True |
| --- | --- | --- |
| WeaponAction 更新 | 停止 | 继续 |
| 动作累计时间 | 停在 0.416667 | 持续推进，可反转 |

## C. 方案 A 评价

1. 原生 Standard Transition 能稳定完成三态过渡，技术路径成立。
2. 同一 Player 的时间反向可靠；中途反向与状态过渡方向是两个独立机制。
3. 素材/握持几何问题无法仅靠混合时长解决，延长时长只减缓姿态跨度。
4. 是否编辑 Mixamo，需先看真实动作，再在新的实验副本上校准肩臂、手部与两端姿态。
5. 不建议现在直接推进正式阶段 B；先完成视觉验收和最小素材校准。

不需要因此引入方案 C、Pose Snapshot、内部 Cached Pose Blend 或重构 Gameplay。
非加法满覆盖的源图更新策略应在正式接入前独立评审，不能忽略已复现的 False 重播。
LowReady 的瞄准 IK 权重语义也需要明确，但本轮不修改稳定 IK 或其正式参数。
