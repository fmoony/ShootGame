# Rifle 真实 K 收枪：组件级遮挡取证

日期：2026-10-11。基线：`f1d6a22`。本轮只建立 Editor 取证工具并运行独立 Standalone。
未修改 ClearanceProxy 算法、生产动画、蓝图、相机、Socket、IK 或 Gameplay。

## 1. 真实 FP 架构与取证范围

使用 `/Game/Shooter/Maps/Lvl_Shooter` 中真实本地 `BP_ShooterCharacter`，通过
`PlayerController::InputKey` 发送 K 按下与松开，不直接调用切换函数或赋值动画目标。
Rifle 经正式 RuntimeSubsystem、Inventory、Equipment 装备链取得。
角色固定在 `(-534,1506,98.21)`，本独立世界移除 NPC，禁用人工移动与视角输入。

实际 FP AnimClass 为 `ABP_FP_Player_C`，TP 为原生产动画实例。
FP 图为 CopyPoseFromMesh → Arms Slot → Output，原生 ClearanceProxy 在图输出后执行。
相机仍附着 FP Mesh 的 head，使用 Pawn Control Rotation；FP FOV=90、Scale=1、NearClip=1 cm。
原生 Clearance CVar 保持 8 cm，未覆写 FP 动画类或构图下沉量。

实时组件记录确认：

| 组件 | 附着对象 | Owner 可见性 | 本轮实际渲染证据 |
|---|---|---|---|
| FP Character | TP Character Mesh | OnlyOwnerSee | 手臂、身体表面出现 |
| TP Character | 角色 Capsule | OwnerNoSee | 排除后主要消失地面人体阴影 |
| FP Rifle | FP Character / HandGrip_R | OnlyOwnerSee | 枪械表面出现 |
| TP Rifle | TP Character / HandGrip_R | OwnerNoSee | 未确认直接近景表面遮挡 |
| FP/TP Magazine Proxy | 武器 Root | 对应 Owner 标志 | 均隐藏，未参与本次遮挡 |
| 相机代理、Frustum、Capsule | 对应父组件 | 均隐藏 | 未参与本次遮挡 |

每个采样姿态暂停世界，保持骨骼求值结果和相机，再通过当前玩家的
`HiddenPrimitiveComponents` 生成六张实际游戏视口截图：Normal、NoFPBody、NoFPWeapon、
NoTP、NoCharacterWeapon、NormalRepeat。只排除渲染，不调用 SetHiddenInGame，
不关闭骨骼 Tick、不改变武器附着或相机父级。每组结束恢复视图列表和暂停状态。

该接口的官方说明为玩家相机单独排除组件；安装版 UE5.6 PlayerController.cpp
将它们汇入 HiddenComponentsOut。本实验采用该现有机制，不创建 SceneCapture 替代真实视口。
外部依据：[Epic APlayerController API](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/APlayerController?application_version=5.6)。

以及可逐组对照的 `组件取证图库.html`。首轮同样有 54 组，保存于 KComponents_20261011。

第二轮 54 组 / 324 张截图 / 7128 行骨骼记录全部通过冻结一致性检查。
组内相机位置、旋转、动画状态、资源、播放器时间、速率和骨骼坐标漂移均为零。

没有 FIRST_PERSON_POSE_FAILURE；进程完成后正常退出。

## 3. 根因排序与边界

第一，负俯仰的主要中心遮挡来自 FP Rifle，伴有 FP 前臂、手掌表面。
仅排除 FP Character 后大面积枪械仍在；仅排除 FP Rifle 后该表面消失。
问题也存在稳定 LowReady，不能归因于过渡混合独有异常。
-60° LowReady 的 FP/TP hand_r 与 upperarm_r 坐标相同，hand_r 相机前向深度
44.446 cm；FP pelvis 比 TP 后退 12 cm、head 位置不变，符合现有 Proxy 已执行的特征。
现有前向深度约束满足时，枪械仍可在视锥中心挡住画面。

第二，大幅抬头的边缘遮挡确认来自 FP Character，不是 FP Rifle。
+75° 收枪 0.267 s 的手臂相关表面仅在 NoFPBody 中消失。
FP upperarm_r 前向深度 32.181 cm，TP 为 -12.784 cm；FP hand_r 为 30.929 cm，
TP 为 -27.276 cm。Proxy 已明显改变姿态，但最终身体表面仍入镜。
这支持现有净空结果未覆盖该可见表面的判断，不支持“Proxy 完全没执行”。
不能仅凭右侧外观把具体蒙皮归因锁定为 clavicle_r。

第三，相机运动须作为独立事实保留，不能继续描述成世界位置完全稳定。
角色 Actor 位置在采样间不动，控制俯仰保持固定，但 head 附着相机随最终姿态移动。
相对同角度初始 ArmedAim 的最大采样位置变化：-30° 25.705 cm、-50° 33.290 cm、
-60° 34.983 cm、-70° 37.646 cm、+75° 28.772 cm。
这是实际相机缓存的测量结果，不是画面晃动的主观评分，也不是本轮相机修改建议。
同组组件排除相机完全相同，因此该运动不削弱前两项遮挡来源的确认。

本轮没有实施 A/B/C 修复。后续应先分开对待 FP 武器净空与 FP 身体边缘表面，
不要用移动肩部统一处理枪械遮挡，也不要修改 TP 收枪关键帧或直接隐藏整条手臂。

## 4. 工具、复现与下一步

新增文件仅为 Editor 取证实现、启动脚本、Pillow 分析脚本及本验证目录。
641 个受保护 Source/ShootGame、Content、Config 文件的 SHA256 与任务前基线全部一致。
三次构建成功；源码 include 检查通过。新增源文件后只刷新一次 VS 工程，未操作 VS。
未保存任何正式资产、未 commit、未 push。

构建后在项目根目录执行，Label 必须是未使用名称：

```powershell
Scripts/Tests/RunRifleFPOcclusionCapture.ps1 -Label KReview_New
python Scripts/Tests/AnalyzeRifleFPOcclusion.py `
    Saved/Automation/RifleFPOcclusion/KReview_New
```

运行工具要求显式启动参数、Game 世界、Standalone。不会在编辑器资产世界或网络世界执行。
只运行 Rifle K 正反动作，不发 Fire/Reload；没有新增 RPC、Gameplay 状态或运行时公开接口。
分析脚本依赖 Pillow，本机为 12.3.0；结果在 Saved，长期摘要见测量摘要.json。

取证进程禁用 MotionBlur、AA、自动曝光、Lumen GI/Reflection，便于稳定像素差分。
使用真实 FP 渲染与生产动画，但这种灯光配置不能代替用户正常 Gameplay 视觉验收。
本轮离散采样无法证明采样间没有更严重帧，也未测移动、开火、换弹或多人观察端。

下一轮优先建议复用 +75° / 0.267 s 和 -60° LowReady 两个冻结帧，
只给实验 FP 实例增加 Proxy 输入/输出与净空标量的只读快照，再决定局部 FP 修正。
先核对高角度蒙皮表面及低角度武器投影，保持 TP、ArmedAim、Reload、Fire 基线。
现阶段工具不能测出 Proxy 内部每一步，本轮不据缺失数据实施算法调整。
正常灯光、完整动作连续播放、转动视角时的主观影响仍需用户亲自观察。
