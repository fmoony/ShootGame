# Rifle 单动画肩臂分层原型：实施与实测

日期：2026-10-13；UE 5.6.1；生产基线 `f1d6a22`。
首发提示词以附件原始字节保存在同目录，不做改写。

**最终推荐：保留 A。**
单一 CorrectedGrip + 渐进 Mask 能正常运行，也改善入场断层。
但枪口高度轨迹、循环后抬枪边界及恢复 IK 后的表现未达到现有 Down 基准。
因此保留 Down30 / Down60 运行时选片；本轮未替换生产方案。

## 1. 运行原型

### 资产与操作

所有新增资产位于：

```text
/Game/Experiments/RifleTransition/LowReadyLayering_20261013/
```

- `ABP_RifleLayer_ExistingDown`：复制生产图，保留原分区选片。
- `ABP_RifleLayer_FullAlpha`：单一 CorrectedGrip，内部肩臂 Mask 恒为 1。
- `ABP_RifleLayer_Progressive`：单一 CorrectedGrip，内部 Alpha 为真实播放器 `t/T`。
- `L_RifleLowReadyLayering`：可连续播放的 TP 独立预览关卡。

打开关卡，选中 `RifleLayering_Preview_UseDetailsButtons`，启用视口实时或使用 Simulate。
视口对准角色；可用关卡中的 `Experiment_TP_Camera` 观察固定斜前方视角。

1. 默认 Version=2，即 Progressive；IK 默认关闭。
2. `Toggle Rifle Test Goal`：收枪 / 抬枪，中途再次点击会沿原累计时间反向。
3. `Cycle Rifle Test Pitch`：循环 0、+30、+60、-30、-60，不重建实例。
4. `Toggle IK`：只开关既有 AimIK / LeftHandIK。
5. `Cycle Version`：依次切换 0 Existing Down、1 FullAlpha、2 Progressive。
   切换版本会重建实例，请先返回 ArmedAim 再比较。

运行中用按钮改变意图；直接编辑 Actor 属性可能触发 Construction、重建动画实例。
继承夹具还显示 NaturalPitchStrength，但本轮生产图副本不消费它，无需调整。
详情中的 `Layer Status` 显示最近求值的版本、状态、时间、方向和内部 Alpha，约落后一帧。
`GetLayerStatus` 是同一信息的 Blueprint Pure 读取函数。
本关卡没有 K 键 Gameplay 绑定；它只承担 TP 原型连续观察。
用户连续播放视觉验收尚未完成，不能据此宣称已通过 Gameplay 验收。

### 实际图与时间驱动

三个副本保留原 WeaponAction、嵌套 RifleReady 三态、状态出口和 Blend 时间。
原 Reload 分支、Arms Slot、外层 LBB、ShooterAimIK / LeftHandIK 均保留。
没有向收枪分支加入 Reload 的三处 spine ModifyBone。

候选 AimTransition 为 ArmedAimPose Base + CorrectedGrip Blend。
LowReady 为 ArmedAimPose Base + 原 MM_Rifle_LowReady Blend，Alpha=1。
只读引用生产 Skeleton 中的 `RifleReloadWeightedUpperBody`；Mesh Space Rotation=True。
spine、neck、head 权重为 0；肩臂使用原 Mask 权重，没有新建或修改 Mask。

Editor 隔离节点继承原生 `FAnimNode_LayeredBoneBlend`，仍调用原生姿态求值。
Update 阶段用相关权重 1 保证 Blend 输入登记原生 TickRecord。
Evaluate 阶段读取已经推进的原 SequencePlayer 累计时间，计算并应用真实 `t/T`。
没有独立过渡时钟、播放器重置、伪造完成条件或正式状态机改动。
新增节点与数据源只存在于 ShootGameEditor，不是已交付的可烹饪 Runtime 实现。

实际零 Alpha 对照：连续 30 帧请求收枪，姿态 Alpha 始终固定为 0。
原生零相关性让播放器停在 0；隔离更新机制使它推进至 0.500000179 秒。
正常渐进版 Alpha 与 `t/T` 最大差值为 2.99×10⁻⁸。

## 2. 实测结果

### 口径与证据等级

以下为实际 UE AnimGraph 求值，不是上轮数学模型。
114 个独立案例，50,640 帧，固定 60 Hz；每帧记录 20 个骨骼 / Socket 变换。
三版本的 Hold 相位统一为 1.0 秒，使用动态 PlayRate=0 冻结 Hold。
过渡和 LowReady 时钟仍由原生播放器推进，没有手动设置其累计时间。
各版本状态时间、过渡时间和 LowReady 相位对应一致。

坐标为 TP Mesh Component Space，位置单位 cm。
枪口方向由真实 Rifle Muzzle Socket 的 +X 轴取得，仰角为 atan2(Z,水平长度)。
左手误差为角色 HandGrip_L 与 Rifle LeftHandGrip 的位置距离。
Rifle 刚性附着于角色 HandGrip_R；本轮未改变右手 Socket 或武器相对变换。

额外上抬 = 窗口最大枪口仰角 − 首尾较大仰角，负数取 0。
高度超额用相同首尾包络口径，窗口为 frame 59～139。
窗口包含 ArmedAim 入场前、完整过渡及相同 LowReady 早期相位。
角度包络不能反映全部折返和手部运动，因此同时检查高度、握点和边界。
约 0.022°～0.023° 的残值包含 LowReady 原始循环运动。

| 指标（IK 关闭） | Existing Down | FullAlpha | Progressive |
|---|---:|---:|---:|
| -30° 额外上抬 / ° | 0.02345 | 33.28795 | 0.02208 |
| -60° 额外上抬 / ° | 0.02345 | 33.28795 | 0.02208 |
| -30° 高度超额 / cm | 0.00676 | 53.65785 | 4.46144 |
| -60° 高度超额 / cm | 0.12592 | 56.96640 | 0.11825 |
| 0° 入场右手位移 / cm | 1.31589 | 1.31598 | 0.02490 |
| -60° 入场右手位移 / cm | 0.01953 | 27.41081 | 0.56059 |
| 0° 进入 LowReady 位移 / cm | 0.05254 | 0.14883 | 0.14883 |
| 0° 循环后抬枪首步 / cm | 1.30095 | 3.74167 | 3.62659 |
| -60° 循环后抬枪首步 / cm | 0.76397 | 3.74167 | 4.16440 |

入场为 frame 59→60；进入 LowReady 为 110→111。
循环后抬枪为 799→800，三版本均使用同一 LowReady 相位。
这不是“播放器重置”证据：重入状态的初始化属于原生产规则，时间对照一致。
这里比较的是相同规则下，LowReady 当前姿态与收枪末端姿态的实际视觉边界。

### 正反播放、循环和动态视角

全部案例的活动 AimTransition 时钟均符合 `Clamp(prev + rate/60,0,T)`，异常数为 0。
中途反向不重新初始化播放器；25% / 50% / 75% 请求点按 60 Hz 离散取样。
代表案例实际反向首步分别为：

- 0.216666669 → 0.200000003 秒。
- 0.416666806 → 0.400000125 秒。
- 0.633333385 → 0.616666734 秒。

每个 Full 案例均完成一个 LowReady 循环回绕，然后正常抬枪返回 ArmedAim。
候选 spine / neck / head 组件旋转与同帧 ArmedAim Base 的最大误差约 0.000003°。
臂段长度最大变化约 0.000107 cm，没有数值上的骨骼伸缩异常。
这些结果证明分层和时钟机制成立，不能单独证明手臂自然度。

DynamicDown 实测 0→-30→-60→-30→0；DynamicUp 实测 0→+30→+60。
候选始终使用 CorrectedGrip；Alpha 不受 Pitch 变化影响，背部与头颈实时更新。
LowDynamic 还连续改变稳定 LowReady Pitch，并完成原 LowReady 循环。
固定及动态 LowReady 枪口方向保持原循环变化，不随 AO 躯干一起大幅旋转。
但枪口位置会随 AO 父级变化：旋转混合与平移继承不是同一件事。
动态最大值包含状态边界，详见证据摘要与曲线，不把它们全归因于 Pitch 跳动。
LowDynamic 的稳定段枪口仰角范围三版本均约 2.19°，来自同一 LowReady 循环。
同段高度范围：Existing 约 2.61 cm，两个候选约 8.08 cm，包含实时 AO 的平移影响。

### 恢复原有 IK

AimIK 与 LeftHandIK 使用原算法和权重更新；未改节点配置、目标或曲线。

| 指标（IK 开启） | Existing Down | FullAlpha | Progressive |
|---|---:|---:|---:|
| -30° 额外上抬 / ° | 0.02345 | 0.02208 | 0.02208 |
| -60° 额外上抬 / ° | 0.02345 | 0.02208 | 0.02208 |
| 0° 额外上抬 / ° | 0.18081 | 0.18081 | 1.19880 |
| +60° 额外上抬 / ° | 0 | 0 | 2.28516 |
| -30° 高度超额 / cm | 0 | 12.31589 | 1.13156 |

IK 关闭时，候选 LowReady 左手握点最大距离约 8.51 cm，基准约 7.14 cm。
原 LeftHandIK 恢复后，三版本稳定 LowReady 握点距离均在 CSV 精度下接近 0。
过渡仍有握点误差：-60° 全序列峰值约 12.29 cm，三版本相同的 ArmedAim 也贡献峰值。
因此不能用“LowReady 握点归零”证明整个动作手臂自然。

右手位移不因现有 AimIK 改变；该节点主要调整右手旋转，因而改变枪口方向。
LeftHandIK 处理左臂，不能解释恢复 IK 后的右手枪口额外上抬。
当前证据定位到原有 AimIK 与渐进肩臂旋转的组合；本轮没有为通过实验修改 IK。

## 3. 最终推荐

1. 单一 CorrectedGrip + Reload 风格 Mask 在隔离图中可以运行，分层机制成立。
2. 渐进 Alpha 明显改善 FullAlpha 的入场断层；零 Alpha 播放器更新已实际验证。
3. 0° 入场更柔和，但节奏改变、循环后抬枪边界增大，原 IK 下多余上抬增加。
   不能认定整体动作质量不低于原方案，明显程度仍需用户连续观察。
4. LowReady 枪械方向保持稳定循环；保留 AO 不等于保留完全相同的空间位置。
5. 动态 Pitch 的时钟与头颈旋转连续，但位置轨迹、握持和边界仍有质量问题。
6. 若继续追求替代，需先处理空间轨迹与 LowReady / 过渡端点的一致性。
   当前结果不证明建设 D2/D3 或新 IK 的收益足够，本轮未实施这些系统。
7. 目前不值得取消 Down30 / Down60 运行时选片。
