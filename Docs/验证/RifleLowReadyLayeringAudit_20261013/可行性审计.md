# Rifle LowReady 复用 Reload 分层：可行性审计

日期：2026-10-13；UE 5.6.1。基线为当前 `f1d6a22` 及上轮未提交取证文件。
首发提示词原样保存在同目录，SHA256 与附件一致，不因报告精简而改写。

**主判断 D：目前不能取消 Down30 / Down60；优先按 B 做一次隔离验证。**
单一 CorrectedGrip + ArmedAim Base + 肩臂 Mask 有机会减少素材，
但必须处理入场混合权重，不能直接照搬 Reload 的满权重覆盖。
目前不推荐先建设 D2/D3 求解系统。保留全部现有素材与三态结构。

本轮仅读取生产与实验图、导出权重、读取动画并做数学分析。
没有修改 AnimGraph、Skeleton、Mask、动画或任何现有运行时代码。
没有运行候选动画图、FP 修复实验、Blender 编辑或重复工具链往返测试。

## 1. Reload 为什么能够使用现有分层混合？

### 当前生产图与实验图区分

重新读取生产 `ABP_TP_Player`：34 张图，主 AnimGraph 为 25 节点。
生产 FP `ABP_FP_Player` 为 2 张图，主图 CopyPose → Arms Slot → Output。
只读原始快照保存在 `Saved/RifleLowReadyLayeringAudit_20261013/`。
同目录报告的[证据摘要](证据摘要.json)保留节点配置、连接与量化结果。

```text
动态 Hold → AO Player → Save ArmedAimPose
                         ↓
WeaponAction：ArmedAim（嵌套 RifleReady） ↔ Reload
                         ↓
Arms Slot
                         ↓
外层 LBB：Locomotion 为 Base，Arms Slot 为 Blend
                         ↓
LocalToComponent → ShooterAimIK → LeftHandIK → ComponentToLocal → Output
```

外层为 BranchFilter：spine_01、Depth=1，上半身全部后代覆盖；
Mesh Space Rotation=True，Mesh Space Scale=False，Curve=Override。
root/pelvis/腿保留 Locomotion，但输入全父链仍参与目标组件旋转累计。

生产 RifleReady：ArmedAim 使用缓存，AimTransition 直接输出动态 SequencePlayer，
LowReady 直接输出原 MM_Rifle_LowReady。没有 Natural Pitch LBB。
当前选择规则有 0.0001° 容忍：-50° 仍用 Down30，低于约 -50.0001° 才用 Down60。
-30° 用 Down30；更高角度用 CorrectedGrip。活动过渡锁片，改变 Pitch 不重选素材。

当前保留的两套实验图均为 27 张图：

| 实验图 | 实际数据源 | AimTransition / LowReady 内部关系 |
|---|---|---|
| ABP_RifleSegmented_LowToReady | Editor SegmentedAnimInstance | 动作为 Base，AO 缓存为 Blend |
| ABP_RifleBlender_GripCorrected_Test | Editor TransitionTest | 同上，固定 CorrectedGrip |

第一套图的播放器静态引用仍显示 CorrectedGrip，Editor 数据源在稳定状态入场时
用 SetSequence 选择分段素材，不能只看节点名称判定实际资源。
两套实验图都引用 SK_RiflePitchMask_Test 内的 RifleLowReadyNaturalPitch；
它们与本轮候选“AO 为 Base、肩臂动作为 Blend”的输入方向不同。
旧独立 Preview Actor 的 TP 测量不能替代真实 ShooterCharacter FP 验证。

### Reload 的真实连接

```text
ArmedAimPose ─────────────────────────────────────────→ LBB Base

ThirdPersonReloadSequence → SequencePlayer（不循环）
  → LocalToComponent
  → ModifyBone spine_01 → spine_02 → spine_03
  → ComponentToLocal ────────────────────────────────→ LBB Blend

LBB（RifleReloadWeightedUpperBody，Alpha=1） → Reload Result
```

Rifle 的序列为 MM_Rifle_Reload，67 个采样键、2.2 秒、非 Additive。
三处 ModifyBone **仍接线并执行**，不是遗留断开的节点。
它们共用 `MakeRotator.Roll = AimPitchDegrees / -3`，
RotationMode=Additive，RotationSpace=ComponentSpace，Alpha=1；Translation/Scale 忽略。
累计的源分支旋转会影响后代手臂的组件旋转，即使这些 spine 在后续 Mask 中权重为 0。

内层 LBB：BlendMask、MeshSpaceRotation=True、RootSpaceRotation=False、
MeshSpaceScale=False、CurveBlendOption=Override、BlendWeights=1、LODThreshold=-1。
Reload 分支实时消费 ArmedAimPose；AO 的 Y 来自 sin(Pitch)，未冻结为入场姿态。

直接读取当前生产 Skeleton 的 BlendProfile 并导出[完整权重](ReloadMask权重.t3d)。
没有借历史计划中的待办值代替现状。未列入 Mask 的骨骼默认权重为 0，非递归继承。

| 骨骼或集合 | Reload 权重 |
|---|---:|
| root、pelvis、spine_01～05 | 0 |
| neck_01、neck_02、head | 0 |
| clavicle_l/r、upperarm_l/r、lowerarm_l/r、hand_l/r | 1 |
| 明确列出的双手手指、手腕、weapon_l/r、手臂 twist/corrective | 1 |
| clavicle_out_l/r、clavicle_scap_l/r | 1 |
| clavicle_pec_l/r、spine_04_latissimus_l/r | 0.35 |
| 未列出骨骼 | 0 |

Profile 有 96 条非零记录，当前 SKM_Manny_Simple 的 89 骨姿态中只有 54 根命中。
四根 0.35 辅助骨均不在该 Simple Mesh 的 89 骨集合内。
所以不能把它们解释成当前 Simple Mesh 主脊柱或锁骨之间的实际渐进缓冲。

Natural Pitch 实验 Mask 则为 spine_02/03/04/05 = 0.05/0.10/0.15/0.20，
neck_01/neck_02/head = 0.45/0.65/0.80，其他骨骼 0。

没有证明单独 Mask 适用于收枪。Reload 允许枪械继续随视角运动，
而 LowReady 希望枪械稳定收回，两者目标不同。

## 2. 单一收枪动画能否复用 ArmedAim 的背部弯曲？

### 骨骼与 AO 的空间贡献

当前 Simple Mesh 实际父链为：

```text
root → pelvis → spine_01 → spine_02 → spine_03 → spine_04 → spine_05
                                                     ├→ neck_01 → neck_02 → head
                                                ├→ clavicle_l → upperarm_l → lowerarm_l → hand_l
                                                └→ clavicle_r → upperarm_r → lowerarm_r → hand_r
```

Hold 为 MF_Rifle_Idle_ADS，8 秒、241 键、非 Additive；AO 三个端点为 CU、CC、CD_Fixed，
Y=+1/0/-1，X=0，均为 Mesh Space Rotation Additive，参考 Hold 第 0 帧。
当前 ArmedAim 缓存使用动态 Hold + AO，不能用某个静态 AO 端点代替。

本轮读取 UE 源姿态，按 Mesh Space Additive 公式重建 Hold=1 秒的 P0 缓存。
0°/-30°/-60° 与工具输入中已捕获的真实缓存 Local Pose 最大旋转差约 0.0000104°。
FK 与 UE 导出的组件姿态最大位置差约 0.00000482 cm。
这支持计算约定正确；+30°/+60° 是该约定下的重建，未新增运行时图采样。

### D1：直接 LBB，为什么可能入场断层？

以 B=ArmedAim、T=收枪姿态，w 为骨骼权重；单位缩放下主要关系为：

```text
Q_i_out = normalize(FastLerp(Q_i_B, Q_i_T, w_i))     # Mesh Space rotation
q_i_out = inverse(Q_parent_out) × Q_i_out
t_i_out = lerp(t_i_B, t_i_T, w_i)                  # Local translation
p_i_out = p_parent_out + rotate(Q_parent_out, t_i_out)
```

spine 权重 0 可以保留完整 AO；手臂权重 1 时，其组件旋转选择收枪源动画，
clavicle 的 Local Rotation 反向补偿保留的父级旋转。它不会自动把固定收枪方向再旋转
一次 AO 角度；但肩锚点和 Local Translation 的 FK 位置仍受父链影响。
因此“保留脊柱”既不保证手臂继承其全部朝向，也不保证枪械位置固定。

按当前 Reload 权重、CorrectedGrip、真实 Socket 相对变换，数学重建无 IK 的候选。
下表比较满权重候选首帧与同角度 ArmedAim；**不是运行过的候选图结果**。

| Pitch | 首帧 hand_r 位置差 cm | 首帧 hand_r 角差 ° |
|---|---:|---:|
| -60° | 28.65 | 76.27 |
| -30° | 17.11 | 43.62 |
| 0° | 0.00061 | 0.00154 |
| +30° | 15.43 | 45.43 |
| +60° | 26.39 | 79.50 |

候选过渡源第一帧枪口为 +11.645°，末帧约 -24.982°，与 Pitch 无关。
把进入前的 ArmedAim 也计入起终点包络，-30°/-60° 的立即满权重方案会多抬约 36.63°。
若只从候选首帧开始统计，反而会错误得到“没有上抬超调”。
生产 AimIK 可改变早期手腕角度，却不能消除这组右手位置差。

数学上把节点强度改成累计时间比例 t/length，-60°/-30°/0°/+30° 没有该方向超调，
+60° 的超调约 0.33°。这说明**渐进权重值得验证**，不能说它已优于 Down60。
该计算固定 Hold 相位、Pitch、下半身，未包含状态边界混合、两项 IK 或 FP Proxy。
0° 中间节奏也会随该权重改变，须与现有 CorrectedGrip 对照。

用原 LowReady 的 0.5 秒姿态做同样合成，五角度枪口组件方向都约 -23.954°。
这支持共用稳定方向的可能性；枪口位置仍随父链变化，不是严格固定空间目标。
候选过渡末帧到该 LowReady 时刻的右手差约 2.97 cm / 5.21°，
包含源素材和所取 LowReady 相位差，不能直接当作新方案独有断层。
仍需验证现有 0.12 秒状态混合和完整 LowReady 循环。

### D2：局部相对增量

UE5.6 的 Local Additive 定义为：

```text
delta_q_i(t) = q_target_i(t) × inverse(q_reference_i)
q_out_i = delta_q_i(t) × q_current_ArmedAim_i
delta_t_i = t_target_i - t_reference_i
```

不是任意把左右乘顺序交换。可用独立 Additive 副本或原生 Make Dynamic Additive +
Apply Additive 表达；本轮没有改任何素材或节点。
Local Transform 旋转增量在父坐标关系中应用，组件空间结果仍有当前父链的累计作用。
参考帧必须同 Skeleton、空间、Retarget 条件；要完整恢复来源，还需处理位移和缩放。

把 CorrectedGrip 首帧作为参考，只对上述肩臂 Mask 应用 Local 增量的数学端点：

| 输入 Pitch | 候选末端枪口方向 ° |
|---|---:|
| -60° | -31.22 |
| -30° | -37.11 |
| 0° | -21.35 |
| +30° | +11.28 |
| +60° | +32.91 |

首帧增量为零有利于入场，但末端不再共用稳定 LowReady，+60° 仍明显朝上。
它也未继承源动画中被 Mask 排除的脊柱运动。该定义不足以独立满足目标 B，
不能因为使用“相对姿态”就认定组件空间轨迹正确。

### D3 / D4：何时才值得进一步做？

D3 需要先明确目标：枪械相对 Mesh、胸部还是相机稳定，这些空间不是同一目标。
给定目标手部 Transform，Local 目标必须由最终父组件 Transform 反求，
右臂还要满足 `abs(L1-L2) ≤ 肩腕距离 ≤ L1+L2`，不能只旋转手腕解决位置。

以 ArmedAim 的右肩起点不动、旧平视 LowReady 手位为固定组件空间目标，
右臂两段约 27.77 / 27.25 cm；五角度目标距离约 32.86～52.79 cm，位置上均可达。
+60° 已接近 55.02 cm 最大伸展。它只证明端点几何可达，
不证明中段肘向、腕部旋转、身体碰撞或左手握持自然。
现有 AimIK 不解右手位置；新增右臂目标必须与它及 LeftHandIK 明确协调，
目前没有证据要求先引入新 IK 或 Control Rig。

D4 可以先只用动作累计时间渐进节点 Alpha；必要时再给 spine_04/05 或肩带部分权重。
后一种会牺牲“脊柱完全来自 AO”的目标，且可能把组件旋转差集中到颈或锁骨。
当前 Reload Mask 的主 spine 权重全为 0，不能声称已验证过该渐进脊柱配置。

## 3. 三种实现方案比较

表中“实测”=已有实测证据，“理论”=理论可行、未实测，
“冲突”=已发现明显冲突（本轮候选为数学反例），“不足”=证据不足。
单一 Mask 列包含渐进 Alpha 变体；不把满权重首帧风险隐去。

| 评价维度 | 当前 Down 方案 | 单一动画 + Mask | 单一动画 + 相对补偿 |
|---|---|---|---|
| 负俯仰枪械轨迹 | 实测：折返明显减少 | 满权重冲突；渐进理论 | D2 冲突；D3 不足 |
| 头颈脊柱自然度 | 实测：生产不保留 AO | 理论：可保留完整 AO | 理论，依具体定义 |
| 双臂握持关系 | 素材实测；全程验收不足 | 数学有偏差；IK 未实测 | D3 可达；协调不足 |
| LowReady 稳定性 | 实测：共用原 LowReady | 方向理论；位置仍变化 | D2 冲突；D3 理论 |
| 正反播放连续性 | 实测：原单 Player 连续 | 理论：保留时钟可反向 | 理论，新增约束需验证 |
| 动态改变 Pitch | 实测：活动过渡锁片 | 理论：AO 连续更新 | 理论，目标空间需明确 |
| FP 视野风险 | 实测：身体与武器遮挡 | 不足：可能改变遮挡位置 | 不足：需真实 FP 验证 |
| 实现复杂度 | 实测：三片与选片逻辑 | 理论：两处 LBB 与权重 | 理论：D2 中等、D3 更高 |
| 维护成本 | 实测：三片工具已建立 | 理论：减素材、增调权重 | 理论：减素材、增求解维护 |

旧真实图、IK 关闭的制作对照，在 -30° 下额外上抬由 21.031° 降至 0.025°，
-60° 由 20.666° 降至 0.025°；额外高度分别由约 39 cm 降至 0.007 / 0.132 cm。
这些有实际图采样，不与本轮固定相位数学模型的“零超调”作直接质量排名。
现有生产 K 的正反机制有实测；本轮没有重跑这些已具充分证据的用例。

FP 当前链仍为 TP Final → CopyPose → Arms Slot → ClearanceProxy → FP Final。
保留 spine/neck/head 的 AO 有望减少固定 Pitch 下动作带来的 head 变化，
但身体肩锚点、枪械位置、相机 Eye 和 Proxy 深度计算都会改变。
旧取证已确认 -60° LowReady 中心有 FP Rifle，+75° 有 FP 身体表面；
前向深度安全不是视锥无遮挡。候选未经真实 FP 运行，不能宣称修复或不会退化。

## 4. 最终技术判断

**主推荐 D；下一轮优先方向 B，现有 Down30/Down60 继续作为 A 回退。**

- 有机会废弃负俯仰专用动画，但当前证据只支持开展实验，不支持替换或删除。
- CorrectedGrip 仍是最有价值的单一过渡输入；本轮不需要重做它。
- 初始实验可只读引用现有 Reload Mask，未必需要新增 Mask。
  若要调整脊柱/辅助骨权重，应另建实验容器中的 LowReady 专用 Mask，保护原 Mask。
- 可复用缓存、LBB、旋转空间和权重范围；不要直接搬入 Reload 的三处实时 Roll 修正。
  它们服务“枪械随视角换弹”，可能使稳定 LowReady 又跟随视角抬高或降低。
- 主 spine 是否必须混入动作目前证据不足；首个实验先设 0，失败后再定位具体原因。
- 不推荐先做 C。D2 的简单局部增量有端点冲突，D3 只是备选、没有证明其必要。
- 保持 ArmedAim ↔ AimTransition ↔ LowReady、同 Player 累计时间及中途反向结构。
  不引入 Gameplay、网络或新的姿态语义。

## 5. 下一轮唯一最小验证方案

在新隔离目录复制生产 ABP_TP_Player，保留其外层、三态、两个原 IK 与 Slot。
将三个过渡资源字段都引用 CorrectedGrip，让既有选片函数仍返回同一资源，
无需先改生产 C++。在 AimTransition 和 LowReady 增加 LBB：
ArmedAimPose 为 Base，原播放器为 Blend，初始只读引用 Reload Mask。
前者按同一个播放器的累计时间渐进 Alpha，后者保持 Alpha=1。

必须检查权重为零时播放器是否停更：本地 UE5.6 LBB 仅更新相关权重的 Blend 输入。
不可形成“Alpha 等待 Player 时间、Player 又因 Alpha=0 不更新”的闭环。
若现有夹具不足，仅在 Editor 实验数据源提供必要的时间/强度控制，
或验证一个大于相关性阈值的最小权重；不修改 Runtime 类。

对照 0°/-30°/-60°/+60°，统一 60 Hz、Hold 相位、LowReady 采样相位、角色位置。
每角度做完整收枪、完整抬枪和 25%/50%/75% 中途反向；再做一次动作中连续变 Pitch。
先关闭原 IK 测基础轨迹，再打开原 IK 测生产完整链，两个结果单独记录。
保留当前 Down 基准，逐帧导出入口手位、枪口包络、肩腕轨迹、握点误差、
首末端差、累计时间、反向速率和骨长；验证全段，不只看单一首帧。

负俯仰要在相同条件下不劣于 Down 方案的上抬/高度包络，
0° 不能出现明显节奏或肩臂退化；LowReady 必须覆盖动态循环与 Pitch 改变。
复用真实 ShooterCharacter 的组件排除取证检查 FP 表面与武器，
