# 自动化测试

当前总控包含七个阶段：编译、Unreal Automation、独立端冒烟、专用服务器双客户端、监听服务器、延迟丢包模拟和主动断线清理。各子脚本彼此独立，定位问题时可以只执行失败的入口。

## 一键完整验证

日常验证默认只运行总控入口：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Tests\RunAll.ps1
```

它会自动执行完整七阶段矩阵。任一阶段失败都会立即停止后续步骤、返回非零退出码，并保留已经产生的日志和报告。

本次运行的机器可读汇总保存在：

```text
Saved/Automation/Runs/<时间戳>/Summary.json
```

汇总包含每个阶段的通过状态、耗时和失败原因。我后续可以直接运行这个入口并根据报告继续定位，不需要你手动打开 PIE 或逐条执行命令。

## 脚本入口

所有命令均在项目根目录执行。

### 1. 编译编辑器目标

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Tests\BuildEditor.ps1
```

脚本编译 `ShootGameEditor Win64 Development`，工具不存在或编译失败时返回非零退出码。需要使用其他引擎位置时传入 `-EngineRoot`。

### 2. 运行 Unreal Automation 测试

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Tests\RunAutomation.ps1 -TestFilter System.AssetRegistry.SerializeTagMap
```

这里的引擎内置测试仅用于确认运行器和报告解析可用。项目测试统一使用 `ShootGame` 作为测试名前缀：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Tests\RunAutomation.ps1 -TestFilter ShootGame
```

脚本默认使用 `NullRHI` 无渲染运行，并读取 JSON 报告。出现失败测试或没有执行到任何测试时都会返回非零退出码。需要渲染上下文的测试可追加 `-WithRendering`。

报告保存在：

```text
Saved/Automation/Reports/<时间戳>/
```

### 3. 运行独立端冒烟测试

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Tests\RunStandaloneSmoke.ps1
```

脚本以无渲染独立游戏模式加载 Shooter 地图，等待 World 进入 Play，继续运行一段时间，并把崩溃、`EXCEPTION_ACCESS_VIOLATION`、`Accessed None` 等标记视为失败。日志保存在 `Saved/Automation/Standalone/`。

### 4. 运行服务器与双客户端会话

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Tests\RunNetworkSession.ps1
```

脚本会依次完成：

1. 启动 Dedicated 或 Listen 模式的 `UnrealEditor-Cmd.exe`，等待网络驱动开始监听。
2. 启动两个客户端，分别等待服务器欢迎日志。
3. 保持会话一段时间，检查所有进程是否仍然存活。
4. 无论成功或失败，只回收本次脚本启动的进程。

为了避免多个编辑器进程争用 MCP 传输端口，网络测试角色默认带有 `-DisablePlugins=McpAutomationBridge`。这不会修改项目中的插件启用状态。

所有无头入口还会传入 `-DDC-ForceMemoryCache`，避免本机 Zen/DDC 写入状态导致启动失败。首次运行可能因内存缓存预热而较慢。

日志保存在：

```text
Saved/Automation/Network/<时间戳>/
```

可以修改客户端数量、端口和观察时间：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Tests\RunNetworkSession.ps1 `
    -ClientCount 2 `
    -Port 17777 `
    -SessionDurationSeconds 30
```

监听服务器示例：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Tests\RunNetworkSession.ps1 `
    -ServerMode Listen `
    -ClientCount 1 `
    -Port 17778
```

网络模拟通过 `-ServerExtraArgs` 与 `-ClientExtraArgs` 传递，例如 `-PktLag=100`、`-PktLoss=2`。主动断线用例通过 `-DisconnectClientIndex` 和 `-DisconnectAfterSeconds` 指定由脚本终止的客户端。

## 项目行为验证标记

直接运行 `RunNetworkSession.ps1` 且不传成功标记时，只检查服务器启动、客户端连接和会话存活。`RunAll.ps1` 默认启用项目内的测试协调器，执行以下端到端流程：

1. 服务器为每个客户端角色授予步枪和手枪，并记录权威基线。
2. 客户端等待 `CurrentWeapon` 复制，发起切枪 Server RPC，并确认武器切换。
3. 客户端通过现有入口发起开火，服务器验证方向、扣减弹药和弹丸生成。
4. 拥有者确认精确弹药，观察者确认不能读取精确弹药。
5. 客户端观察远端俯仰与第三人称开火 Montage。
6. 服务器依次施加部分伤害和致死伤害，客户端确认生命、死亡、PlayerState 与 GameState。
7. 每个客户端输出独立成功标记；任一失败标记或标记数量不足都会使阶段失败。

当前还有 `ShootGame.Weapon.Configuration` 快速项目测试，会自动加载步枪和手枪蓝图，检查武器 Actor 已开启复制、弹匣容量有效且开火间隔大于零。

网络脚本支持让权威服务器输出成功和失败日志标记，再由脚本判断：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Scripts\Tests\RunNetworkSession.ps1 `
    -SuccessMarker AUTOMATION_TEST_SUCCESS `
    -FailureMarker AUTOMATION_TEST_FAILURE `
    -SessionDurationSeconds 60
```

使用标记后，只有在超时前找到成功标记且没有找到失败标记，测试才通过。这样可以逐步把“人工观察两个窗口”替换成可重复的自动验收。

## 推荐执行顺序

每完成一个小型网络闭环，按以下顺序验证：

1. 运行 `BuildEditor.ps1`，先排除编译和链接问题。
2. 运行 `RunAutomation.ps1 -TestFilter ShootGame`，验证不依赖真实连接的规则。
3. 运行 `RunNetworkSession.ps1`，验证真实服务器与客户端连接。
4. 对暂时不能自动判断的动画、音效和枪口特效，再进行 PIE 人工观察。

当前端到端测试已覆盖武器复制、切枪、拥有者弹药、服务器瞄准与开火、弹丸、生命/死亡、PlayerState、GameState、远端俯仰和第三人称 Montage，并在 Dedicated、Listen、100ms/2% 丢包及主动断线场景复验。Niagara、声音和 HUD 的最终画面仍需带渲染 PIE 人工观察；同一 Pickup 争抢和复杂同帧竞态尚未自动化。
