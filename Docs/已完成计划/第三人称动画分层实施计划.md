# 第三人称动画分层实施计划

## 1. 计划目的

本计划只落实 [动画分层与射击表现扩展规划](../执行计划/动画分层与射击表现扩展规划.md) 的“阶段 A：建立动画分层基线”。

本阶段要解决的是第三人称姿势组合关系：移动、跳跃和落地继续提供角色基础运动，上半身持枪、瞄准和武器动作在明确的骨骼范围内覆盖基础姿势，避免两套姿势无边界叠加。

完成后应获得一个稳定的动画骨架，供后续第三人称 AimTarget、AimYaw、Reload、Equip 和射击表现继续接入。本阶段不提前实现这些后续功能。

## 2. 本阶段边界

### 2.1 纳入范围

- 审计 `ABP_TP_Rifle` 和 `ABP_TP_Pistol` 的现有 AnimGraph、AimOffset、跳跃资源和骨骼过滤配置。
- 将 `Arms` Slot 放入上半身分支，使未来开火、换弹和切枪 Montage 不覆盖腿部移动。
- 明确 `Locomotion`、武器待机姿势、AimOffset、Slot 和 `Layered Blend Per Bone` 的顺序。
- 以 `spine_01` 为首选分界验证腰部以上覆盖。
- 验证 Mesh Space 旋转混合与 AimOffset 的 Mesh Space Additive 配置。
- 分别验证 Rifle、Pistol 的站立、移动、跳跃、下落和落地表现。
- 定位跳跃过程中出现的视觉 AimYaw、肩部扭转或枪口横向漂移来自哪一层。

### 2.2 不纳入范围

- 不新增或复制 `PresentationAimTarget`。
- 不接入真正的第三人称 AimYaw；AimOffset 的 X 输入本阶段继续保持 0。
- 不创建 Reload / Equip Montage。
- 不修改 GAS Reload / Equip 的事务时钟和提交逻辑。
- 不修改散布、弹丸、伤害、后坐力和枪口特效。
- 不在本阶段删除 `ApplyRemoteAimPitch` 或重构为新的 C++ AnimInstance。
- 不为了修正姿势直接旋转武器 Actor 或武器 Mesh。
- 不修改第一人称 AnimBP 和 Control Rig。

将这些内容分开，是为了先证明“动画如何混合”正确，再改变“瞄准数据从哪里来”。否则同一次验证失败时，无法区分是网络数据错误还是姿势组合错误。

## 3. 已确认的当前基线

### 3.1 C++ 表现入口

- `AShooterCharacter::OnWeaponActivated` 根据当前武器切换第一、第三人称 AnimInstance Class。
- `AShooterCharacter::PostNetReceive` 和 `OnRep_CurrentWeapon` 会调用 `ApplyRemoteAimPitch`。
- `ApplyRemoteAimPitch` 只对模拟代理生效，通过属性名查找 `PitchN`，写入 `GetBaseAimRotation().Vector().Z`。
- 本地玩家的 AnimBP EventGraph 则从 Controller 读取 Control Rotation 并计算 `PitchN`。
- 开火 Montage 由服务器 Multicast，在第三人称 Mesh 上播放；本地拥有者还会在第一人称 Mesh 上播放。因此移动 `Arms` Slot 后必须回归当前开火动画。

本阶段保留这条数据链，不同时更改 Pitch 的来源。

### 3.2 `ABP_TP_Rifle` 当前 AnimGraph

当前蓝图直接继承 `UAnimInstance`，AnimGraph 共 7 个节点：

```text
LocomotioStateMachine ─────────────→ Layered Blend Per Bone.Base Pose

MF_Rifle_Idle_ADS
        → AO_Rifle（X = 0，Y = PitchN）
        → Layered Blend Per Bone.Blend Pose 0

Layered Blend Per Bone
        → Arms Slot
        → Output Pose
```

### 3.3 `ABP_TP_Pistol` 当前 AnimGraph

结构与 Rifle 相同，区别是上半身资源为：

- `MF_Pistol_Idle_ADS`
- `AO_Pistol`

其 AimOffset 同样是 X 固定为 0、Y 使用 `PitchN`，最终 `Arms` Slot 同样位于骨骼分层之后。

### 3.4 当前资源

Rifle 已有独立的 Jump Start、Start Loop、Apex、Fall Loop、Fall Land 和 Recovery Additive 资源。

Pistol 当前可确认的跳跃资源较少，主要包括 Jump Start、Fall Loop 和 Recovery Additive。Pistol 不能假定与 Rifle 使用完全相同的跳跃状态和过渡，应单独验收。

当前 AimOffset 资产为：

- `/Game/Characters/Mannequins/Anims/Rifle/AIM/AO_Rifle`
- `/Game/Characters/Mannequins/Anims/Pistol/Aim/AO_Pistol`

现有只读审计已经确认：

- 两个 AimOffset 都使用 `[-1, 1]` 的轴范围，当前只有 Y 轴 Pitch 样本，X 轴没有 Yaw 样本。
- `AO_Rifle` 使用 `MF_Rifle_Idle_ADS` 作为基础参考姿势，`AO_Pistol` 使用 `MF_Pistol_Idle_ADS` 作为基础参考姿势。
- 两个 AimOffset 都使用 Mesh Space Additive，因此现有 `PitchN = ForwardVector.Z` 的归一化输入语义与资产范围匹配。
- 当前 Rifle、Pistol AnimGraph 都符合第 3.2、3.3 节描述的旧结构。
- 当前 `Layered Blend Per Bone` 使用 `spine_01`、Depth 0，未开启 Mesh Space Rotation Blend；本计划提出的 Depth 1 与 Mesh Space Rotation Blend 仍属于待验证目标配置。

现有跳跃 AnimSequence 审计曾尝试通过 `IAnimationDataModel` 按固定骨骼名读取原始 Track，但所有目标骨骼都返回“无轨道”。该结果不能证明跳跃资源没有驱动 root、pelvis 或 spine，也不能作为分层决策证据。后续必须先枚举资产真实 Track，或改为按时间采样动画求值后的 Component Space Pose；在工具修复前，此项只能通过编辑器预览和运行时调试辅助判断。

### 3.5 外部 Agent 已建立的工具基线

当前工作区已出现一个待审的 `ShootGameEditor` Editor 模块和 `AnimLayerRestructureCommandlet`，用于执行以下工作：

- 只读导出 AnimGraph 节点、Pin、连线、AimOffset、Montage 和动画序列信息。
- 识别当前 AnimGraph 是否符合本计划记录的旧结构。
- 准备将 `Arms` Slot 移入上半身分支，并编译、保存目标 AnimBP。
- 为目标 AnimGraph 写入中文节点注释。

这个方向符合项目长期自动化目标，但当前只能把只读 Audit 结果视为有效证据，不能直接批准写资产路径。现有实现仍需解决幂等、精确拓扑校验、Schema 连线、失败回滚、保存结果判断、资产白名单和序列采样有效性问题。

当前 Git 状态没有显示 Rifle 或 Pistol `.uasset` 被修改，因此本计划仍以“资产尚未正式应用目标结构”为起点。

## 4. 外部依据与 UE 5.6 核对

Epic 的 Aim Offset 文档明确说明：Aim Offset 使用 Mesh Space Additive 姿势叠加到基础姿势，并特别提醒水平瞄准与行走、奔跑混合时容易出现问题，应限制水平极值或让角色身体承担部分水平转向：

- [Aim Offset in Unreal Engine](https://dev.epicgames.com/documentation/unreal-engine/aim-offset-in-unreal-engine?application_version=5.6)

Epic 的分层动画示例将 Montage Slot 放在需要覆盖的上半身分支中，再通过 `Layered Blend Per Bone` 从 `spine_01` 混入基础移动姿势，并建议使用 Mesh Space Rotation Blend：

- [Using Layered Animations in Unreal Engine](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-layered-animations-in-unreal-engine?application_version=5.6)
- [Animation Blueprint Blend Nodes](https://dev.epicgames.com/documentation/unreal-engine/animation-blueprint-blend-nodes-in-unreal-engine?application_version=5.6)

本地安装的 UE 5.6 源码进一步确认：

- `Layered Blend Per Bone` 支持 Branch Filter 和 Blend Mask 两种骨骼范围表达。
- `LayerSetup` 在 Branch Filter 模式下定义各层覆盖范围。
- Mesh Space Rotation Blend 决定骨骼旋转在 Mesh Space 还是 Local Space 中混合。
- 节点可以设置 LOD Threshold，但低 LOD 禁用后的过渡需要单独验证。

因此本阶段首选最小的 Branch Filter 方案，不提前创建共享 Skeleton Blend Mask；只有 Branch Filter 无法获得可接受过渡时，才升级为 Blend Mask。

## 5. 目标 AnimGraph

Rifle 和 Pistol 都调整为以下结构：

```text
Locomotion State Machine
        │
        └──────────────────────────────→ Layered Blend Per Bone.Base Pose

Weapon Idle ADS
        → AimOffset（本阶段仍只有 Pitch）
        → Arms Slot
        → Layered Blend Per Bone.Blend Pose 0

Layered Blend Per Bone
        → Output Pose
```

关键区别是把 `Arms` Slot 从最终输出之前移动到上半身分支内部。

目标含义为：

- 根骨骼、骨盆、腿部和整体位移来自 Locomotion。
- 上半身从持枪待机姿势开始，再叠加 AimOffset。
- 开火以及未来 Reload / Equip Montage 只进入上半身分支。
- 最后一次骨骼混合决定上半身覆盖范围，Montage 不再有机会绕过这个范围覆盖全身。

### 5.1 首选骨骼混合配置

第一轮验证使用以下起点：

- Blend Mode：Branch Filter。
- Branch Bone：`spine_01`。
- Blend Depth：1。
- Blend Weight：1.0。
- Mesh Space Rotation Blend：开启。
- Mesh Space Scale Blend：保持关闭，除非资源审计证明存在缩放动画需求。
- Root Motion Based On Root Bone：保持当前值，不在本阶段主动改变。
- Curve Blend Option：先保持当前值；如 Montage 曲线产生冲突，再单独讨论。

这些值是验证起点，不是未经测试的永久参数。Rifle 验证通过后才能将同一配置应用到 Pistol。

### 5.2 空中状态策略

第一轮不根据 `bIsInAir` 降低上半身 Blend Weight，仍保持 1.0。这样能先判断严格分层是否消除了跳跃资源对持枪上半身的干扰。

如果一开始就把空中权重降为 0.5 或 0.8，跳跃姿势和 AimOffset 会重新混合，反而难以确认误差来自哪一层。只有严格分层稳定后，才允许为了自然感少量恢复空中躯干动作。

需要注意：`spine_01` 的父骨骼仍会继承 root / pelvis 的旋转。若跳跃资源在骨盆或根骨骼上带有明显旋转，单纯的腰部以上分层不一定能完全消除枪口漂移。此时必须先定位父骨骼影响，不能继续随机调整 AimOffset 或武器 Rotation。

## 6. 具体实施步骤

### 6.0 Agent 与人工协作方式

本计划不再默认要求人工逐个完成蓝图连线。满足安全门后，Agent 可以通过 Editor-only Commandlet 自动审计、修改、编译和保存单个目标 AnimBP；人工只承担工具无法可靠替代的编辑器状态协作和视觉验收。

#### Agent 自主负责

- 审计项目代码、AnimGraph、AimOffset、Montage、Skeleton 和资产引用。
- 加固并验证 Editor-only 自动化工具。
- 每次只处理一个明确白名单资产。
- 修改前后导出结构化审计结果并比较目标拓扑。
- 编译目标蓝图、检查保存结果、执行项目 Build 和现有自动化。
- 记录每次提交的改动、验证、问题和遗留项。

#### 必须由用户协作或确认

- 新增模块、Target 或插件后，若 Visual Studio 已打开，在从 VS 构建前点击“全部重新加载”；未完成时任务不得继续从 VS 构建。
- 执行会写入 `.uasset` 的 Commandlet 前，关闭 Unreal Editor，或明确确认目标资产没有在 GUI 编辑器中加载且不存在未保存修改。
- 对跳跃、肩部、持枪姿势、枪口漂移和 Montage 自然度完成双客户端视觉验收。
- 对超出本计划边界的资源重制、骨架调整或架构扩张单独拍板。

只读 Audit 可以在编辑器运行时执行；`Apply`、`Comment` 和其他写资产模式不得与 GUI 编辑器同时操作同一资产。

### 6.1 自动写资产前置安全门

在任何 `Apply` 或 `Comment` 前，自动化工具必须同时满足以下要求：

1. **目标白名单**：只允许本计划明确列出的 `ABP_TP_Rifle` 或 `ABP_TP_Pistol`，默认拒绝其他资产。
2. **三态识别**：能准确区分“旧基线结构”“已是目标结构”“未知结构”。旧结构允许迁移；目标结构无修改返回成功；未知结构拒绝执行。
3. **精确拓扑检查**：不仅检查某两个 Pin 已连接，还要检查连接数量、方向、目标节点及 Pin 类型都完全符合预期。
4. **Schema 安全连接**：通过图 Schema 校验建立连接，只断开明确的目标连接，不使用无约束的 `BreakAllPinLinks` 修改未知拓扑。
5. **结构修改通知**：按 Blueprint 编辑器要求标记结构变更，再执行编译。
6. **失败回滚**：编译、目标结构复核或保存任一步失败时，恢复原始连线和配置，不在内存中留下已标脏的半成品。
7. **保存结果校验**：保存 API 的真实结果必须参与退出码和日志判定；不能在保存失败时输出成功。
8. **写后复核**：保存后重新加载或重新审计资产，确认节点顺序、Branch Filter、Depth 和 Mesh Space 配置与目标完全一致。
9. **注释条件**：只有资产已经处于目标结构时才能写入结构说明，禁止给旧结构或未知结构写误导性注释。
10. **可重复执行**：对已经完成的资产重复运行时不得再次改写，也不得因“不符合旧结构”而报告失败。

安全门未全部满足时，只允许继续运行只读 Audit，不得尝试写入 Rifle 或 Pistol 资产。

### 步骤 A0：收口工作区并冻结视觉基线

#### 操作

1. 在修改 `.uasset` 前处理或明确排除当前未提交的 Editor 模块、开发工具、VS 同步与规划文档改动。
2. 记录 `ABP_TP_Rifle`、`ABP_TP_Pistol` 当前 Git 状态；两者开始实施前应无未知修改。
3. 如果 `ShootGameEditor` 是新模块，先完成项目文件刷新；Visual Studio 已打开时等待用户点击“全部重新加载”，之后才允许从 VS 构建。
4. 写资产前关闭 Unreal Editor，并再次检查目标资产没有未保存修改。
5. 使用两玩家 PIE，固定观察客户端位置和视角。
6. 分别装备 Rifle、Pistol，录制或截图以下状态：
   - 原地水平瞄准。
   - 原地向上、向下瞄准。
   - 前后左右移动。
   - 保持准星不动执行 Jump Start、上升、最高点、下落和落地。
7. 保留现有摄像机方向、第三人称枪口方向调试线；记录每种颜色对应的数据源。

#### 产物

- 一份基线记录，写明 Rifle、Pistol 分别在哪个空中阶段出现横向漂移、俯仰漂移、肩部翻转或腿部覆盖。
- 明确“变量数值变化”和“视觉姿势变化”不是同一问题。

#### 完成门槛

- 能稳定复现至少一次用户目前观察到的跳跃瞄准异常。
- 没有复现时不开始调整节点，先确定测试条件差异。

### 步骤 A1：只读审计资源配置

#### 操作

1. 优先通过只读 Commandlet 导出 `AO_Rifle`：
   - X/Y 轴名称和范围。
   - 实际使用的样本位置。
   - Preview Base Pose。
   - 每个样本的 Additive Anim Type、Base Pose Type 和 Base Pose Animation。
2. 对 `AO_Pistol` 做同样的自动审计，并将结果与第 3.4 节已知基线比较。
3. 修复动画序列审计：先列出真实 Track；如果原始 Track 不足以表达最终姿势，则按时间采样 Component Space Pose。只有能输出可信数据时，才自动比较以下骨骼在关键帧的旋转：
   - `root`
   - `pelvis`
   - `spine_01`
   - `spine_02`
   - `spine_03`
   - `clavicle_r`
   - `hand_r`
4. 自动导出两个 AnimBP 当前 `Layered Blend Per Bone` 的完整配置：
   - Blend Mode。
   - Branch Filter 或 Blend Mask。
   - Blend Depth。
   - Mesh Space Rotation / Scale。
   - Curve Blend。
   - Root Motion 相关选项。
5. 自动检查当前武器配置引用的 Firing Montage 及其 Slot 名称和 Skeleton，确认移动 `Arms` Slot 后仍能接收该 Montage。
6. 只有 Python 或 Commandlet 无法读取的资产字段才交由人工在 Unreal Editor 中查看，不把“人工打开资产”作为默认第一步。

#### 判定

- 如果 AimOffset 样本不是 Mesh Space Additive，先停止改 AnimGraph，建立单独的资源修复步骤。
- 如果 AimOffset 的预览基础姿势与 AnimGraph 输入的 Weapon Idle ADS 不一致，先记录差异，不能把后续扭曲直接归因于分层节点。
- 如果跳跃的明显横向旋转发生在 root / pelvis，记录为“父骨骼驱动”；如果只发生在 spine 以上，记录为“上半身姿势污染”。

### 步骤 A2：只调整 `ABP_TP_Rifle`

#### 自动修改流程

1. 确认第 6.1 节安全门全部通过，并将 `/Game/Shooter/Animation/ThirdPerson/ABP_TP_Rifle` 作为本轮唯一写入白名单。
2. 运行只读 Audit，保存修改前拓扑和配置指纹；如果不是已知旧结构，则停止并报告。
3. 通过 Commandlet 保留 Locomotion State Machine、`MF_Rifle_Idle_ADS`、`AO_Rifle` 和现有变量连线，断开当前：

   ```text
   Layered Blend Per Bone → Arms Slot → Output Pose
   ```

4. 自动改为：

   ```text
   MF_Rifle_Idle_ADS
   → AO_Rifle
   → Arms Slot
   → Layered Blend Per Bone.Blend Pose 0

   Locomotion State Machine
   → Layered Blend Per Bone.Base Pose

   Layered Blend Per Bone
   → Output Pose
   ```

5. `AO_Rifle.X` 本阶段继续保持 0；`AO_Rifle.Y` 继续连接现有 `PitchN`，不改变数值语义。
6. 将 `Layered Blend Per Bone` 设置为第 5.1 节的首选配置。
7. 不修改 EventGraph、State Machine 内部状态、跳跃资源和武器 Socket。
8. 在保存前验证目标拓扑；编译蓝图且无 Error 后只保存 `ABP_TP_Rifle`，并检查保存返回值。
9. 保存后重新运行 Audit；只有写后结果完全匹配目标结构才判定成功。
10. 对同一资产再次运行自动修改，验证其以“已是目标结构”无修改成功退出。

如果安全工具尚未完成，本步骤退回人工连线，但仍必须使用修改前后 Audit 作为证据，且不得让未经加固的 Commandlet 写资产。

#### 为什么先只改 Rifle

Rifle 的跳跃资源更完整，能分别观察起跳、上升、最高点、下落和落地。先建立一个明确样本，可以避免 Rifle 与 Pistol 同时变化后无法判断配置是否应该共享。

### 步骤 A3：验证 Rifle 分层

#### 编辑器预览

1. 在 AnimBP 预览中确认水平、向上和向下 AimOffset 正常。
2. 确认没有 Montage 时，`Arms` Slot 只是透传上半身姿势。
3. 预览每个跳跃 AnimSequence，确认资源自身是否包含 root / pelvis / spine 横向旋转。

#### 双客户端 PIE 矩阵

观察者始终查看另一名玩家的第三人称角色，依次验证：

| 状态 | 瞄准输入 | 观察内容 |
| --- | --- | --- |
| Idle | 水平、向上、向下 | 肩部、手臂、枪口连续 |
| Walk / Run | 前后左右 | 腿部方向正确，上半身不被步态覆盖 |
| Jump Start | 固定水平 | 起跳瞬间枪口不横向跳变 |
| Rising / Apex | 固定水平 | 枪口不因跳跃资源产生反向 AimYaw |
| Falling | 固定水平 | 下落循环不扭转肩部和武器 |
| Landing | 固定水平 | 落地恢复不覆盖持枪上半身 |
| Jump | 固定向上、向下 | Pitch 连续，不发生符号翻转 |
| Fire while moving | 水平 | 当前开火 Montage 不覆盖腿部或停止 Locomotion |

#### 完成门槛

- 地面移动和空中状态的腿部动画继续工作。
- 上半身持枪姿势不进入参考 Pose 或 T Pose。
- 跳跃过程中不出现肉眼可见的枪口左右反转、肩部翻面或突然大角度横跳。
- 当前开火 Montage 仍能播放，并且只影响预期的上半身范围。
- 第一人称表现没有变化。

如果仍有轻微连续漂移，先记录关键帧和骨骼来源，不立即以手工 Rotation 抵消。

### 步骤 A4：按来源处理 Rifle 残留问题

#### 情况 1：关闭 AimOffset 后问题消失

说明问题主要来自 AimOffset 样本、基础姿势或输入范围：

1. 核对 AimOffset 样本的 Mesh Space Additive 配置。
2. 核对 Preview Base Pose 与 `MF_Rifle_Idle_ADS` 是否一致。
3. 核对 `PitchN` 的实际范围是否与 AimOffset Y 轴范围一致。
4. 修复资源配置后重新执行 A3，不修改武器 Transform。

#### 情况 2：AimOffset 为 0 时跳跃仍带动枪口

说明问题来自 Locomotion 父骨骼或骨骼过滤：

1. 对比 root、pelvis、spine 的空中关键帧。
2. 确认 Mesh Space Rotation Blend 已开启。
3. 只在副本测试中尝试调整 Branch Bone / Blend Depth，找到最小有效范围后再应用正式资产。
4. 如果旋转来自 root / pelvis，承认上半身 Branch Filter 无法消除父骨骼全部影响；将精确的组件空间上半身校正留到后续 AimTarget 阶段，不能在当前阶段给每把武器写死补偿角。

#### 情况 3：移动 `Arms` Slot 后开火动画消失

1. 检查 Montage 使用的 Slot 是否确实为 `Arms`。
2. 检查 Montage Skeleton 与第三人称 Mesh Skeleton 是否兼容。
3. 检查 Montage 是全身、上半身还是 Additive 资源。
4. 只修复 Slot / Montage 资产契约，不把 Slot 放回最终输出之后。

#### 情况 4：严格上半身覆盖使跳跃过于僵硬

只有枪口方向已经稳定后才处理自然感：

1. 先尝试更平滑的 Branch Depth 或 Blend Mask。
2. 再评估空中上半身权重，但必须保证方向误差不会重新出现。
3. 每次只改一个参数并重跑 A3 矩阵。

### 步骤 A5：将已验证结构应用到 `ABP_TP_Pistol`

#### 操作

1. 只有 Rifle 已完成自动审计、写后复核和人工视觉验收后，才把唯一写入白名单切换为 `ABP_TP_Pistol`。
2. 以 Rifle 已验收的节点顺序为参考，通过已通过安全门的 Commandlet 单独修改 `ABP_TP_Pistol`。
3. 继续使用 Pistol 自己的 `MF_Pistol_Idle_ADS` 和 `AO_Pistol`。
4. 不复制 Rifle 的 AimOffset 资产、跳跃资源或武器校准值。
5. `AO_Pistol.X` 继续保持 0，Y 继续使用原 `PitchN`。
6. 先应用 Rifle 已验证的骨骼过滤配置，再根据 Pistol 资源单独验收。
7. 完成修改前 Audit、编译、保存结果检查、写后 Audit 和第二次幂等执行验证。

#### 验证

完整重复 A3 的双客户端矩阵，重点检查：

- Pistol 双手姿势是否因上半身覆盖发生肩部挤压。
- 较少的跳跃资源是否导致状态切换时姿势突变。
- 手枪枪管较短时，跳跃横向漂移是否更容易被观察到。
- 开火 Montage 和第一人称手臂是否保持原行为。

Pistol 未通过时不得因为 Rifle 已通过而结束本阶段。

### 步骤 A6：清理和建立后续契约

#### 操作

1. 先验证两个 AnimGraph 都处于目标结构，再通过安全工具或人工为其增加简短中文注释，标明：
   - Locomotion Base。
   - Upper Body Aim / Weapon Action。
   - Final Per-Bone Blend。
2. 记录最终 Branch Filter、Blend Depth 和 Mesh Space 配置。
3. 记录 AimOffset 轴范围与当前 `PitchN` 映射。
4. 记录跳跃仍存在但必须由后续 AimTarget / IK 阶段解决的父骨骼误差。
5. 不在本步骤顺便重命名大量变量、状态机或资源。

#### 为后续阶段留下的接口约束

- 后续 AimYaw 接入 `AimOffset.X`，但不能改变本阶段已验收的骨骼分层顺序。
- 后续 Reload / Equip Montage 进入上半身 `Arms` Slot，不允许回到最终输出之后。
- 后续手臂 IK 或组件空间校正位于 AimOffset / Montage 之后、最终输出之前，并必须受角色状态控制。
- 后续 C++ AnimInstance 可以替换变量来源，但应保持 AnimGraph 输入语义稳定。

## 7. 自动化与人工验收

### 7.1 自动化可覆盖部分

- Editor-only 工具的目标白名单、旧结构/目标结构/未知结构三态判定和幂等执行。
- 两个 AnimBP 修改前后的节点、Pin、连线及 `Layered Blend Per Bone` 配置对比。
- Blueprint 编译、保存返回值和保存后重新加载审计。
- Editor 编译和项目 Build 通过。
- 两个 AnimBP 与 AimOffset 资产可加载。
- Rifle / Pistol 武器仍引用有效的第一、第三人称 AnimInstance Class。
- 现有 GAS、Inventory、开火、伤害、死亡和复活自动化没有回归。
- Listen / Dedicated 网络会话脚本继续通过。

### 7.2 必须人工观察部分

自动化无法可靠判断姿势是否自然或枪口是否发生肉眼可见漂移，以下内容必须使用带渲染双客户端验收：

- 腰部上下是否真正分离。
- 跳跃时肩、手臂和枪口是否稳定。
- Montage 是否只覆盖上半身。
- Rifle 与 Pistol 是否都保持合理持枪姿势。
- 第一人称是否出现意外回归。

人工验收不负责替代可自动验证的拓扑、编译、保存和引用检查；Agent 必须先给出这些机器证据，再请求用户观察视觉结果。

### 7.3 推荐验证顺序

```text
Blueprint Compile
→ 项目 Build
→ 自动化测试
→ Standalone 冒烟
→ Listen 双客户端人工动画矩阵
→ Dedicated 双客户端权威回归
```

## 8. 提交拆分

每次提交前都必须按 [开发记录规范](../开发记录/README.md) 记录改动、验证、问题和遗留项，提交说明使用中文。

建议拆分为：

1. **规划提交**：本实施计划、父规划和 `AGENTS.md` 导航。
2. **Editor 工具加固提交**：只包含 Editor-only 模块、经过整理的统一审计/执行入口、工具验证和开发记录；不包含 `.uasset` 修改。一次性失败探针不得原样进入正式提交。
3. **Rifle 分层提交**：只包含 `ABP_TP_Rifle`、必要的资源配置修复、机器审计证据、人工验收记录和开发记录。
4. **Pistol 分层提交**：只包含 `ABP_TP_Pistol`、必要的资源配置修复、机器审计证据、人工验收记录和开发记录。
5. **分层收尾提交**：只在确实需要补充自动化契约、注释或验收记录时创建。

禁止把 AimTarget 网络同步、Reload / Equip Montage、散布和 Recoil 混入上述提交。

## 9. 阶段完成定义

满足以下条件后，才能结束本计划并进入第三人称瞄准表现同步阶段：

- Rifle 和 Pistol 都使用同一套清晰的“Locomotion Base + Upper Body Branch + Final Per-Bone Blend”结构。
- Editor-only 写资产工具满足第 6.1 节安全门，并能对已完成资产幂等执行。
- `Arms` Slot 位于上半身分支内。
- 站立、移动、跳跃、下落和落地时腿部 Locomotion 正常。
- 跳跃不再造成明显的枪口左右反转、肩部翻转或上半身瞬间错位。
- 当前开火 Montage 和第一人称动画未回归。
- 无法由分层本身消除的 root / pelvis 继承误差已经有证据和记录，不使用武器硬编码旋转掩盖。
- 自动化回归通过，双客户端人工动画矩阵完成。
- 开发记录写明最终配置、遇到的问题和后续 AimTarget 阶段需要承接的事项。
