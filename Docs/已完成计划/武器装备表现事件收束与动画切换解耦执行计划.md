# 武器装备表现事件收束与动画切换解耦执行计划

> 状态：已完成（2026-08-29）。E0～E5 已实施并验证，本文件归档到 Docs/已完成计划。

## 1. 计划定位

当前项目已经完成 Inventory、Equipment、AimPresentation 和薄 AnimInstance 基类的第一轮架构解耦，但“当前装备已改变”和“本机武器表现已完成”仍混在同一条调用链中：

```text
Equipment 提交 CurrentWeaponActor
→ ApplyCurrentWeapon
→ Character.AttachWeaponMeshes
→ Weapon.ActivateWeapon
→ Character.OnWeaponActivated
→ HUD 更新 + 第一/第三人称 SetAnimInstanceClass
→ Equipment.OnEquippedWeaponChanged
```

这条链路可以工作，但存在以下问题：

- Equipment 的逻辑提交、Weapon 的显隐、Character 的附着、HUD 和 AnimClass 切换没有明确的完成边界。
- `ApplyCurrentWeapon()` 会被服务器装备、`BeginPlay`、多个 RepNotify 和 Weapon Ready 回调重复触发。
- 第三人称 AnimInstance 每帧重新判断 Weapon、Owner、Mesh、AttachParent、AttachSocket、Socket 和 Binding Signature，承担了本应由生命周期事件处理的静态检查。
- Inventory 删除武器时可能先销毁 WeaponActor，再通知 Equipment 清理当前装备，使 Deactivate / Unequip 的对象已经失效。
- Pickup 在 Inventory Add 成功、Equipment Equip 失败时会留下已加入 Inventory 的武器，同时恢复 Pickup 可拾取，事务结果不一致。
- 动画蓝图切换由 Equipment 间接触发，却实际散落在 Weapon 回调和 Character 中，难以判断一次切换何时真正完成。

本计划目标是：

> 保持 `UShooterEquipmentComponent::CurrentWeaponActor` 为当前逻辑装备的唯一事实来源，在本机建立一个可重复调用、可验证完成的 Weapon Presentation 应用入口，并让 AnimInstance 只在表现完成时重建静态 Binding。

## 2. 已确认决策

### 2.1 唯一事实来源

| 状态 | 唯一事实来源 | 说明 |
| --- | --- | --- |
| 角色拥有哪些武器、槽位、弹药 | `UShooterInventoryComponent` | Inventory FastArray 继续只描述拥有关系和实例状态 |
| 当前逻辑装备 | `UShooterEquipmentComponent::CurrentWeaponActor` | 服务器提交并复制给所有相关客户端 |
| 当前装备稳定身份 | `UShooterEquipmentComponent::ActiveWeaponInstanceId` | 与 CurrentWeaponActor 属于同一事务；当前保持 OwnerOnly |
| 本机表现是否已应用 | Character 私有幂等缓存 | 只服务本地附着、显隐、AnimClass 和动画 Binding 收敛，不是玩法事实 |
| Aim / LeftHand IK 动态输入 | `UShooterAimPresentationComponent`、移动状态、GameplayTag | 保持现有动态采集与 AnimNode 求解职责 |

### 2.2 禁止把 PresentedWeapon 变成事实真相

本计划不提供公开的 `PresentedWeapon` 状态。若实现需要记录上一次已应用对象，只允许在 Character 内使用：

```text
private TWeakObjectPtr<AShooterWeapon> LastAppliedPresentationWeapon
```

它必须满足以下约束：

- 不复制、不保存，不进入 Inventory FastArray。
- 不提供给 Ability、Inventory、Equipment、UI 或 Gameplay 查询。
- 不决定能否开火、换弹、切枪、伤害或命中。
- 不反向写入 `CurrentWeaponActor` 或 `ActiveWeaponInstanceId`。
- 只用于跳过已经满足后置条件的重复本地表现调用，以及生成本地表现变化事件的 Previous 参数。
- 与 `Equipment.CurrentWeaponActor` 不一致时，永远以 Equipment 为准重新应用或清空表现。
- 弱引用失效时只清空本地缓存，不产生新的装备事务。

为避免语义误用，代码命名优先使用 `LastAppliedPresentationWeapon`，不使用看起来像公开状态所有者的 `PresentedWeapon`。

### 2.3 本轮不新增

- 不新增 Revision、复杂状态机或 Result enum。
- 不新增独立 WeaponPresentationComponent。
- 不新增动画网络复制属性或 RPC。
- 不让 Inventory 注册事件驱动远端装备表现。
- 不修改 `FAnimNode_ShooterAimIK` 和 LeftHandIK AnimNode 的求解职责。
- 不复制 Lyra 的 EquipmentInstance / Definition / Fragment 完整体系。
- 不在本轮统一 NPC 与玩家的全部装备架构。
- 不在 Unequip 时直接把 AnimClass 设为 `nullptr`；无武器默认动画策略另行规划。

## 3. 当前真实调用链

以下结论来自当前项目 CodeGraph、源码和只读资产检查。

### 3.1 Pickup 与 Inventory Add

```text
ShooterPickup
→ Inventory.TryAddWeapon
→ 创建 FastArray Instance
→ 服务器 Spawn AShooterWeapon
→ 设置 Owner / BoundInstanceId
→ 隐藏 WeaponActor
→ Inventory.RegisterWeaponActor
→ Equipment.EquipWeapon
```

当前异常边界：如果 `TryAddWeapon` 成功但 `EquipWeapon` 失败，Pickup 只恢复可拾取状态，刚加入的 Inventory Instance 和 WeaponActor 会继续保留，占用槽位且未装备。

### 3.2 服务器装备提交

```text
Equipment.EquipWeapon(InstanceId)
→ 从 Inventory 找到 WeaponActor
→ 校验 Authority / Owner / InstanceId / Actor
→ Deactivate PreviousWeapon
→ 同时提交 ActiveWeaponInstanceId + CurrentWeaponActor
→ ApplyCurrentWeapon
→ Reset AimPresentation
→ ForceNetUpdate
```

### 3.3 客户端复制与补偿入口

```text
CurrentWeaponActor OnRep
→ ApplyCurrentWeapon(PreviousWeapon)

ActiveWeaponInstanceId OnRep
→ 当前也会再次 ApplyCurrentWeapon(nullptr)

Equipment BeginPlay
→ ApplyCurrentWeapon(nullptr)

Weapon BeginPlay / OnRep_Owner / OnRep_BoundInstanceId
→ Equipment.HandleWeaponActorReady
→ 当前武器命中时再次 ApplyCurrentWeapon(nullptr)
```

`CurrentWeaponActor` 对所有相关客户端复制；`ActiveWeaponInstanceId`、Inventory FastArray 和 Weapon `BoundInstanceId` 只复制给 Owner。因此远端模拟代理只能依赖：

```text
Equipment.CurrentWeaponActor + Weapon.Owner
```

远端表现不能依赖 Inventory 注册事件、Active InstanceId 或 BoundInstanceId。

### 3.4 当前动画蓝图切换

```text
Equipment.ApplyCurrentWeapon
→ Character.AttachWeaponMeshes
→ Weapon.ActivateWeapon
→ WeaponOwner.OnWeaponActivated
→ Character.OnWeaponActivated
   ├─ 更新 Bullet Counter
   ├─ FirstPersonMesh.SetAnimInstanceClass(Weapon.FPAnimClass)
   └─ ThirdPersonMesh.SetAnimInstanceClass(Weapon.TPAnimClass)
```

因此：

- Equipment 决定什么时候切换。
- Weapon Blueprint 配置第一、第三人称分别切换到哪个 AnimClass。
- Character 实际调用 `SetAnimInstanceClass()`。
- 第一、第三人称 AnimInstance 被替换后，各自重新进入初始化生命周期。

当前 `Character.OnWeaponDeactivated()` 为空；Clear / Unequip 会隐藏武器，但不会明确恢复默认 AnimClass。

### 3.5 当前删除与死亡链路

当前 Inventory Remove / Clear 的顺序是先移除或销毁 WeaponActor，再广播 Inventory 清理事件；Equipment 收到事件后才 `ClearEquippedWeapon()`。当前装备 Actor 可能已经无效，无法可靠执行 Deactivate。

死亡路径调用 Inventory Clear，并由 Inventory 事件让 Equipment 收敛为空；客户端还会通过死亡复制状态执行本地死亡表现。无武器时保留上一 AnimClass 是当前既有行为，本轮先保持，不把“默认无武器姿势”混入事件收束。

## 4. 外部依据与本地 UE5.6 核对

### 4.1 Inventory 与 Equipment 的职责区别

Epic 的 Lyra 文档把 Inventory 描述为持有的物品集合，把 Equipment 描述为当前拿出、穿戴或使用的对象。ShootGame 只采用职责边界，不复制 Lyra 完整对象模型。

- [Lyra Inventory and Equipment](https://dev.epicgames.com/documentation/en-us/unreal-engine/lyra-inventory-and-equipment-in-unreal-engine)

与当前项目差异：Lyra 通常在装备时创建 Equipment 表现实例；ShootGame 当前让 Inventory 中每把武器长期对应一个 WeaponActor。本计划保留当前 Actor 生命周期，只收束事件和表现边界。

### 4.2 RepNotify 不保证跨属性顺序

Epic 官方说明，不同复制属性的 OnRep 回调之间没有确定顺序。由此不能假定 `CurrentWeaponActor`、`ActiveWeaponInstanceId`、Weapon Owner 和 BoundInstanceId 按固定次序到达。

- [Replicated Object Execution Order](https://dev.epicgames.com/documentation/unreal-engine/replicated-object-execution-order-in-unreal-engine?lang=en-US)
- [Replicate Actor Properties](https://dev.epicgames.com/documentation/en-us/unreal-engine/replicate-actor-properties-in-unreal-engine)

采用范围：逻辑变化事件只由 `CurrentWeaponActor` 的真实转移产生；表现应用保持幂等，并允许 Weapon Owner 稍后到达时补做。不能用“一次事件必定成功”代替必要的到达顺序收敛。

### 4.3 AnimInstance 生命周期

Epic API Reference 把 `NativeInitializeAnimation()` 和 `NativeUninitializeAnimation()` 定义为 AnimInstance 的初始化与反初始化入口；普通 `NativeUpdateAnimation()` 适合采集数据。

- [UAnimInstance](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/UAnimInstance)
- [UAnimInstance::InitializeAnimation](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UAnimInstance/InitializeAnimation?lang=en-US)

本地 UE5.6 源码核对：

- `USkeletalMeshComponent::SetAnimInstanceClass()` 只在新 Class 不同，或之前不是 Animation Blueprint 模式时清理并重新初始化 AnimInstance。
- 对同一个非空 Class 重复调用通常不会重建 AnimInstance。
- 传入 `nullptr` 会清空 AnimClass 和 AnimInstance。

采用范围：上游仍要阻止无意义的重复 Activate / HUD / Delegate 副作用；不能因为同 Class 的 `SetAnimInstanceClass()` 当前较安全，就把整个表现入口视为天然幂等。

## 5. 目标事件模型

事件分成两层，禁止混用。

### 5.1 逻辑装备变化事件

由 Equipment 发布：

```text
OnEquippedWeaponChanged(PreviousWeapon, CurrentWeapon)
```

语义：

- 表示本机镜像中的 `CurrentWeaponActor` 已发生真实逻辑转移。
- `CurrentWeapon == nullptr` 表示 Unequip。
- 服务器在成功提交时发布；客户端在 `OnRep_CurrentWeaponActor` 中发布。
- 同一个 CurrentWeapon 的 Ready 补偿、BeginPlay 补偿和 ActiveInstanceId 到达不得重复发布。
- 该事件可以供 UI、日志、调试或其他只读观察者使用，但不能替代 `CurrentWeaponActor` 本身。

现有 `OnEquippedWeaponChanged(InstanceId, Weapon)` 当前没有已确认的生产订阅者。实施前仍需通过 C++、只读 MCP 和资产字符串扫描复核；确认无订阅后，优先直接改为 Previous / Current 语义，不并存两套相似 Delegate。

### 5.2 本机表现完成事件

由 Character 发布原生本地事件：

```text
OnWeaponPresentationChanged(PreviousAppliedWeapon, CurrentAppliedWeapon)
```

语义：

- 只表示当前机器上的武器附着、显隐、AnimClass 等必要表现已经达到预期后置条件。
- 不复制，不触发服务器事务。
- `CurrentAppliedWeapon == nullptr` 表示本机装备表现已清空。
- Previous 参数来自私有 `LastAppliedPresentationWeapon`，只用于事件上下文。
- AnimInstance 使用该事件重建或清空静态 Binding。
- Gameplay 代码不得监听它决定武器、弹药、Ability 或命中。

### 5.3 为什么两层事件不能合并

逻辑装备已提交，不代表当前客户端此刻已经拿到 Weapon Owner、完成 Attach 或成功初始化目标 AnimClass。若只保留一个事件，会迫使订阅者猜测事件发生在提交前、应用中还是应用后。

目标顺序是：

```text
Equipment CurrentWeaponActor 转移
→ 发布逻辑变化
→ 尝试 EnsureWeaponPresentation(CurrentWeaponActor)
→ 到达条件不足则等待既有 Weapon Ready 回调补做
→ 后置条件全部满足
→ 发布本机表现完成事件
```

## 6. Character Weapon Presentation 收敛入口

### 6.1 最小入口

在 `AShooterCharacter` 中建立一个可重复调用的本地表现入口，命名建议：

```text
bool EnsureWeaponPresentation(AShooterWeapon* ExpectedWeapon)
```

返回值只表示本次调用结束时表现是否满足后置条件，不新增 Result enum。

输入来源只能是：

```text
Equipment.GetCurrentWeaponActor()
```

Equipment 调用时可以直接传入当前值；Character 内仍要校验传入值与 Equipment 当前值一致。若不一致，以 Equipment 当前值为准，不接受调用方建立第二套当前武器状态。

### 6.2 非空武器完成条件

至少满足：

- Weapon 有效且未进入 Destroy。
- Weapon Owner 是当前 Character。
- 第一人称武器 Mesh 已附着到第一人称角色 Mesh 和预期 Socket。
- 第三人称武器 Mesh 已附着到第三人称角色 Mesh 和预期 Socket。
- Weapon Actor 当前可见/已激活。
- 第一人称角色 Mesh 的 AnimClass 等于 Weapon 配置的 FP AnimClass。
- 第三人称角色 Mesh 的 AnimClass 等于 Weapon 配置的 TP AnimClass。

Muzzle / Grip Socket 是否存在属于动画能力和 IK Binding 条件，不作为通用 Weapon Presentation 成功的硬门；缺失时由对应动画功能禁用并给出诊断。

### 6.3 空武器完成条件

- 上一次本地已应用武器已 Deactivate 或已经失效。
- `LastAppliedPresentationWeapon` 被清空。
- 发布一次 `(Previous, nullptr)` 表现事件。
- 不把第一、第三人称 AnimClass 设为 `nullptr`，保持当前死亡和无武器表现行为。
- AnimInstance 收到事件后清空 Weapon 专属 Binding 和 IK 开关。

如果未来需要明确的 Unarmed 动画，应为 Character 配置显式默认 FP / TP AnimClass，并作为独立计划处理，不能用 `nullptr` 隐式代替。

### 6.4 幂等规则

如果 `LastAppliedPresentationWeapon == ExpectedWeapon` 且全部后置条件成立：

- 直接返回成功。
- 不重复 Attach、Activate、更新 HUD、设置 AnimClass 或广播事件。

如果对象相同但任一后置条件不成立：

- 重新应用缺失的表现步骤。
- 成功后不把它当成新的逻辑装备变化。
- 只有从“未完成”转为“完成”时才允许发布表现完成事件。

如果对象不同：

- 旧表现先 Deactivate。
- 应用新表现。
- 成功后更新私有弱引用并发布一次 Previous / Current。

### 6.5 现有接口复用

优先复用：

- `AttachWeaponMeshes()`：继续负责两个武器 Mesh 的附着。
- `ActivateWeapon()` / `DeactivateWeapon()`：继续负责武器显隐和停火。
- `OnWeaponActivated()`：迁移期继续承接 HUD 与 AnimClass 应用，避免同时破坏 NPC 的 Holder 接口。
- Weapon 上现有 FP / TP AnimClass Getter。

本轮先让 `EnsureWeaponPresentation()` 成为明确完成点，不强制同时删除 `IShooterWeaponHolder`。如果后续发现 Character 的 `OnWeaponActivated()` 只剩内部转发，再单独清理。

## 7. Equipment 收束规则

### 7.1 逻辑提交

`EquipWeapon()` 继续只允许服务器提交：

```text
校验 Inventory 与 Weapon
→ 提交 CurrentWeaponActor + ActiveWeaponInstanceId
→ 发布逻辑装备变化
→ 尝试 EnsureWeaponPresentation
→ 重置 AimPresentation
→ ForceNetUpdate
```

PreviousWeapon 只在提交前保存，用于 Deactivate 和逻辑变化事件；不得写入长期第二状态。

### 7.2 客户端 CurrentWeaponActor OnRep

```text
OnRep_CurrentWeaponActor(PreviousWeapon)
→ 发布逻辑装备变化（仅 Previous != Current）
→ EnsureWeaponPresentation(CurrentWeaponActor)
→ Reset AimPresentation
```

### 7.3 ActiveWeaponInstanceId OnRep

Owner 的 UI 或身份显示可以消费该值，但它不再触发 `ApplyCurrentWeapon()`。原因：

- 观察端没有该字段。
- AnimClass、Attach 和 Visibility 只需要 CurrentWeaponActor。
- 不同 OnRep 顺序不确定，重复调用会模糊逻辑变化事件语义。

### 7.4 BeginPlay 与 Weapon Ready

保留两个表现收敛入口：

- Equipment `BeginPlay()`：用当前 `CurrentWeaponActor` 做一次状态回放。
- `HandleWeaponActorReady(Weapon)`：仅当 `Weapon == CurrentWeaponActor` 时补做表现应用。

这两个入口：

- 不发布新的逻辑装备变化。
- 只调用幂等 `EnsureWeaponPresentation()`。
- 用于处理 CurrentWeaponActor、Weapon Owner 和 Actor 创建映射的到达顺序差异。

## 8. Inventory 与 Pickup 生命周期修正

### 8.1 暂不新增 OnWeaponRegistered

`OnWeaponRegistered(InstanceId, Weapon)` 的语义可以成立，但本轮没有必要消费者：

- Equipment 已有 `HandleWeaponActorReady()`。
- 远端没有 Inventory FastArray 和 BoundInstanceId，不能依赖注册事件完成表现。
- Register 可能由服务器 Spawn、Weapon BeginPlay、Owner RepNotify 和 BoundInstanceId RepNotify 多次进入。

因此本轮不新增该 Delegate。未来若出现明确消费者，只能在 `BoundWeaponActors` 首次真实插入成功时发布，并明确它是本地注册完成事件，不是装备事件。

### 8.2 Pickup Equip 失败回滚

如果 Pickup 本轮创建的新 Inventory Instance 已成功，但紧随其后的首次 Equip 失败：

```text
RemoveWeaponInstance(NewInstanceId)
→ 回滚本轮新增实例与 WeaponActor
→ Pickup 恢复可拾取
```

不允许同时留下 Inventory 武器和仍可拾取的 Pickup。该回滚只针对本次 Pickup 新增的实例，不影响角色已有武器。

### 8.3 RemoveWeaponInstance 顺序

目标顺序：

```text
确认待删除 Instance
→ 从逻辑 Inventory Entries 移除
→ 广播 OnWeaponInstanceRemovedFromInventory(InstanceId)
→ Equipment 若命中当前装备，先 Clear / Deactivate / 清表现
→ Inventory Unregister WeaponActor
→ Destroy WeaponActor
```

重点：Equipment 必须在 Actor Destroy 前获得清理机会。

### 8.4 ClearInventory 顺序

目标顺序：

```text
冻结待销毁 WeaponActor 列表
→ 清空 Inventory 逻辑 Entries
→ 广播 OnInventoryCleared
→ Equipment Clear / Deactivate / 清表现
→ Unregister 并 Destroy 全部 WeaponActor
```

必须保证重复 Clear 安全，并覆盖死亡、EndPlay、重生和手动清空。

## 9. AnimInstance 事件驱动静态 Binding

### 9.1 生命周期订阅

`UShooterThirdPersonAnimInstance`：

- 在 `NativeInitializeAnimation()` 获取 Owning Character 并订阅 `OnWeaponPresentationChanged`。
- 初始化后立即从 `Equipment.CurrentWeaponActor` 回放一次当前状态，避免 AnimClass 切换发生在事件之前或订阅晚于表现事件。
- 在 `NativeUninitializeAnimation()` 解除订阅并清空 UObject 弱引用和静态 Binding。
- 对第一人称 AnimInstance 只建立其实际需要的最小同类机制，不因为第三人称需要而上提无关字段到基类。

### 9.2 表现事件到达时重建一次

非空 CurrentWeapon：

- 缓存当前 Weapon 弱引用。
- 读取已完成 Attach 的 Character Mesh、Weapon Mesh 和 Socket 配置。
- 重建 `HandToMuzzle`、`WeaponGripInRightHandSpace`、`HandGripInLeftHandSpace` 等静态 Binding。
- 分别判定 AimIK / LeftHandIK 所需 Socket 是否存在。
- 缺少某项能力时只关闭对应 IK，并输出一次有范围的诊断。

空 CurrentWeapon：

- 清空 Weapon 引用和全部静态 Binding。
- 禁用 Weapon 专属 AimIK / LeftHandIK。
- 不让旧 Weapon 的 Transform 在后续 Tick 继续被消费。

### 9.3 Tick 中可以删除的内容

- Character / Mesh / Weapon / Owner 的重复签名拼装与比较。
- AttachParent / AttachSocket 的逐帧轮询。
- SkeletalMesh Asset 和 Weapon Mesh Asset 的逐帧签名检查。
- 对永久缺失 Socket 的逐帧重试。
- `WaitingForAttach / Pending / Unsupported / Ready` 等由静态生命周期问题产生的五状态机和重复计时器。
- 只为判断“是否换枪”存在的每帧 CurrentWeapon 对比。

### 9.4 Tick 中必须保留的内容

- GroundSpeed、Direction、bIsInAir 等移动输入。
- AimPitch、AimDirection、PresentationAimTarget 与观察端动态平滑结果。
- GameplayTag 对应的 Firing / Reloading / Equipping / Dead 表现状态。
- 依赖当前 Pose 的 AimIK / LeftHandIK 动态计算。
- 对缓存 Weapon 弱引用有效性的廉价检查。
- 必要时验证缓存 Weapon 是否仍等于 `Equipment.CurrentWeaponActor`；不一致时只请求重新收敛，不能让缓存覆盖 Equipment。

### 9.5 允许的唯一小型重试

事件发生时 Attach、Socket 和 AnimClass 已满足，但某个依赖当前骨骼世界 Transform 的计算在该帧暂时不可用时，可以保留：

```text
bool bStaticBindingRebuildPending
```

规则：

- 只表示下一次普通动画更新再尝试一次静态 Binding。
- 不承载 Weapon 身份，不复制，不演化成多状态机。
- 永久缺失 Socket 不进入 Pending，而是关闭对应 IK。
- 成功、Unequip、Owner 失效或 AnimInstance Uninitialize 时立即清除。

## 10. 动画蓝图切换的明确边界

### 10.1 谁决定切换

- Equipment：决定当前逻辑武器何时改变。
- Weapon Blueprint：配置该武器对应的第一、第三人称 AnimClass。
- Character Weapon Presentation：在本机调用 `SetAnimInstanceClass()` 并验证结果。
- AnimInstance：初始化后消费当前 Equipment 状态和表现完成事件，不自行决定换枪。

### 10.2 切换完成点

只有同时满足以下条件才算完成：

```text
Weapon Owner 正确
+ FP / TP 武器 Mesh 附着正确
+ Weapon 已激活
+ FP Mesh AnimClass 正确
+ TP Mesh AnimClass 正确
```

完成后才更新 `LastAppliedPresentationWeapon` 并发布 `OnWeaponPresentationChanged`。

### 10.3 SetAnimInstanceClass 后的状态回放

新的 AnimInstance 初始化时不能依赖“以后一定会来一个事件”。它必须主动读取：

```text
Owning Character
→ Equipment.CurrentWeaponActor
→ 当前 Character Presentation 后置条件
```

如果已经完成，立即建立静态 Binding；如果尚未完成，由 Character 完成事件或单次 Pending 补做。

### 10.4 Unequip 与死亡

本轮保持上一 AnimClass，不设置 `nullptr`，但必须清空武器专属 Binding。这样可以：

- 保留死亡蓝图和当前无武器行为。
- 避免销毁本应接收清空事件的 AnimInstance。
- 把是否新增 Unarmed AnimBP 留给独立视觉设计。

## 11. NPC 边界

当前 NPC 不经过玩家 Equipment 完整链路；Weapon Owner 初始化后仍可能直接通过 `IShooterWeaponHolder::AttachWeaponMeshes()` 走兼容路径。

本轮规则：

- 不宣称玩家的 `OnWeaponPresentationChanged` 已覆盖 NPC。
- 不为了形式给 NPC 强行新增 EquipmentComponent。
- 不删除 NPC 仍依赖的 WeaponHolder 接口。
- 玩家事件收束完成后，单独审计 NPC Spawn、Attach、Activate、死亡和 AnimClass 需求，再决定是否复用同一 Presentation 入口。

若本轮公共接口修改会影响 NPC，必须补 NPC Characterization Test；不得用玩家测试替代。

- Pickup 首次 Equip 失败时回滚本次 Add。

阶段门：

阶段门：

- `LastAppliedPresentationWeapon` 无任何 Gameplay 读取方、复制或公开 Getter。

阶段门：

## 13. 自动验证矩阵

### 13.1 纯逻辑与幂等

- Equip 相同 Weapon 两次不产生第二次逻辑变化。
- Ensure 相同且后置条件完整时无额外副作用。
- CurrentWeaponActor 变化时 Previous / Current 正确，包括 Unequip。
- ActiveWeaponInstanceId OnRep 不触发逻辑事件或重复表现应用。
- LastAppliedPresentationWeapon 永远不能改变 Equipment 当前值。

### 13.2 Inventory 生命周期

- Pickup Add 成功、Equip 失败时完整回滚。
- Remove 当前武器：Equipment Clear 先于 Destroy。
- Remove 非当前武器：当前表现不变。
- ClearInventory：一次逻辑清空、所有 WeaponActor 最终销毁。
- 重复 Clear / Remove 不崩溃、不重复广播错误状态。

### 13.3 网络

- Dedicated Server + 2 Clients：服务器、Owner、Observer CurrentWeapon 一致。
- Listen Server + Remote Client：监听主机和远端表现一致。
- 模拟 CurrentWeaponActor 先于 Weapon Owner 到达，Ready 后能补做表现。
- OwnerOnly 的 ActiveWeaponInstanceId / Inventory 不参与 Observer 表现完成。
- Unequip、死亡和重生后没有旧武器重新附着。

### 13.4 动画

- Rifle / Pistol 第一人称 AnimClass 正确。
- Rifle / Pistol 第三人称 AnimClass 正确。
- SetAnimInstanceClass 产生新 AnimInstance 后静态 Binding 能重新建立。
- 无武器和死亡时 Weapon 专属 Binding 清空。
- Rifle AimIK / LeftHandIK 视觉不回退。
- Pistol 不错误启用 Rifle 左手 IK。
- 移动、跳跃、后退、Fire、Reload、Equip Montage 状态不回退。

### 13.5 代码边界静态检查

- Ability、Inventory、Equipment、UI 不引用 `LastAppliedPresentationWeapon`。
- AnimInstance 不写 Equipment 或 Inventory。
- AnimNode AnyThread 路径不访问 UObject。
- 没有新增 Revision、Result enum、重复 CurrentWeapon 字段或第二套逻辑状态机。

## 16. 风险与回退

### 风险 1：逻辑事件早于 Weapon Owner 可用

处理：逻辑事件不承诺表现已经完成；保留 `HandleWeaponActorReady()` 的幂等补偿。

### 风险 2：SetAnimInstanceClass 替换实例后丢失订阅

处理：新 AnimInstance 在 `NativeInitializeAnimation()` 主动订阅并从 Equipment 回放当前状态，不能只等下一次事件。

### 风险 3：重复 Activate 产生 HUD 或动画副作用

处理：Character 在调用现有入口前检查私有缓存和完整后置条件；重复成功调用直接返回。

### 风险 4：Unequip 后仍保留上一 AnimClass

处理：这是本轮明确保留的既有行为，但 Weapon 专属 Binding 必须清空。若视觉不接受，再单独增加显式 Unarmed AnimClass，不在本轮临时传 `nullptr`。

### 风险 5：Inventory 删除顺序影响客户端 FastArray 回调

处理：分别验证服务器事件、Owner FastArray Remove 和远端 Equipment OnRep；不假定三者共用同一通知入口。

### 风险 6：玩家方案误伤 NPC

处理：保留 NPC WeaponHolder 兼容路径；所有公共接口变更都做 NPC 编译与最小行为测试。

每个阶段必须是独立提交。出现回归时优先回退当前阶段，不通过增加第二套状态或兼容布尔掩盖问题。

## 17. 完成定义

本计划只有同时满足以下条件才可归档：

- Inventory 仍是拥有关系和弹药的唯一事实来源。
- Equipment.CurrentWeaponActor 仍是当前逻辑装备的唯一事实来源。
- Character 私有表现缓存没有复制、公开 Getter 或 Gameplay 读取方。
- Pickup Add/Equip 失败事务一致，Inventory Remove/Clear 不再先 Destroy 当前武器。
- 逻辑装备事件只在真实 CurrentWeapon 转移时发布。
- 本机表现完成事件只在 Attach、Activate、AnimClass 后置条件满足时发布。
- BeginPlay、RepNotify 和 Weapon Ready 的重复入口全部收敛到同一个幂等表现函数。
- 动画蓝图切换职责明确：Equipment 决定时机、Weapon 提供 Class、Character 应用、AnimInstance 消费。
- ThirdPerson AnimInstance 不再逐帧扫描静态 Weapon / Mesh / Attach / Socket Signature。
- AimIK / LeftHandIK 动态计算和服务器权威射击结果不变。
- Rifle、Pistol、Unequip、死亡、重生和快速切枪视觉验收通过。
- Editor Build、Focused Automation、Dedicated 与 Listen 网络测试通过。
- 每个提交都包含同提交中文开发记录，最终文档与导航同步。
